## 样式浮点输入与 IEEE 位模式

`native_xml_import` 进一步增加 7 个浮点字段，scope 更新为 `native_xml_scalar_writes`，共 45 个字段。主输入函数 `0xd9276..0xd92bc` 依次读取根属性 `GroundPlaneColor.R/G/B`、`GroundPlaneHeight`、`GroundPlaneTransparency`；三个颜色分量名称来自 `0x61beb8` 指针表中的 ASCII `R/G/B`，按 `0x52d0f0` 的 `%hs.%hs` 格式拼接，不能当作整数颜色字节。覆盖表另在 `0xd9968` 读取 `Transparency`，在 `0xd99e3` 读取 `HLineTransparencyThreshold`。

## 样式名称与 Usages 位集合

`native_xml_import.fields` 增加 `Name` 与 `EnvironmentName`，共 47 个字段，scope 更新为 `native_xml_field_writes`。环境名称在 `P3DKJ.dll 0xd91c4` 读取；非空时 `0xdb4e0` 将文本复制到对象偏移 `0xb8`，缺失则保持空字符串，不据此加载或猜测环境资源。原始 XML 中的文本继续保留。

根 `Usages` 在 `0xd9a7a` 读取后，交给 IAT `0x521b08`，即 `P3DKJJC.dll` ordinal 280（RVA `0x3d80`），下界参数为 0、上界参数为 `UINT32_MAX`。输入目标是 `0xd8fa8` 调用 ordinal 170 所构造的初始空、默认 false 的位集合。它读取范围表达式并置位，没有给范围中的数字赋予枚举名称。

原生流程先只跳过开头空格和 Tab，然后要求当前位置为 ASCII 数字，再以空格或逗号分段并按 `%u-%u` 扫描。两个端点逆序时交换；只扫描到一个值则为单点。每段结束只跨过一个分隔符，再调用 `P3DDC.dll` ordinal 472（RVA `0x23070`）对剩余文本作 `iswspace` 修剪。因此 `1,,3` 只得到 1，`1- 3` 得到 1 和 3，`1<TAB>3` 只得到 1；分隔符之后的换行可以被修剪，整个文本开头的换行却会停止读取。库保留原始有序 token、未处理后缀及停止原因。

- `0x60000` 按无符号槽位索引取对象：空槽和越界返回空，不跳到下一个对象。
- `0x60050` 顺序跳过空对象，调用 P3DDC ordinal 503 比较名称。该导出 `0x11840` 转发到 UCRT `_wcsicmp`。当前 C locale 实测 `Alpha/alpha/ALPHA` 匹配第一个对象，`Ä/ä` 不相等；空名称、长 UTF-16 名称同样按原生字符串行为查询。
