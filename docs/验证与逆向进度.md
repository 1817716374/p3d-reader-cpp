### 属性 22900 / 组 0 / 索引 1 的证据

分析对象为 R1.18 `ROOT/P3DKJ.dll`；以下地址是相对于镜像基址的 RVA，不依赖装载地址。

- `0x394230` 的读取路径按组合键 `0x59740000` 和索引 `1` 选择记录，检查数据至少 8 字节后拷贝一个 QWORD。
- `0x3948b0` 的写入路径使用同一组合键与索引，并写入 8 字节。

- `0x3946e0` 包含登记缺失时的运行时服务查找，不能仅凭文件标识推定已经取得处理器。

库暴露 `registration_key`、按实际查询顺序排列的 `registration_lookup_keys`、尚未确定用途的 `unassigned_word_at_4` 和原生未消费的 `trailing_bytes`。状态保持 `partial`，`runtime_resolution` 保持 `not_evaluated`。不足 8 字节的输入报错；其他组和索引不套用此结构。

## 显示样式索引与源表（2026-09-29，第二轮）

属性 `(group=0,key=20080,index=0)` 是文件显示样式列表的有符号 32 位索引。R1.18 `P3DKJ.dll` 的 `0x4b43c5` 要求载荷恰好 4 字节，并在 `0x4b43cc` 写入运行时对象偏移 `0x148`；`0x5facf` 对该值作符号扩展并调用 `0x5fa40`。跨文件处理 `0x5f7ff` 对负索引直接停止查询。写入路径 `0xda7df` 至 `0xda814` 从样式对象偏移 `0x10` 取得编号并写回同一属性。

`0x5fcc0` 创建列表对象，其虚表 RVA `0x529708` 的 RTTI 名称为 `LiteShowStyleListFileData@platform@p3d`。`0x60000` 按索引访问列表；`0x5f7d0` 跨文件按样式名称查找、复制或重新编号。因此不能把 `20080` 当作全局对象 ID。

Lite 表登记键为 `0x597e0000`（`0x603b9`），普通表为 `0x006f0000`（`0xdd199`），二者均经 `0xdd1f0` 进入 `0xdcbd0` 读取列表。列表上界读取于 `0xa9890`，对应保留的 native base 偏移 40 的有符号 DWORD；循环在 `0xdcdb2` 使用包含上界的比较。列表项来自同一图形记录的属性 `(0,22903,index)`。源项按索引保留，缺少的槽位不按名称重新排序或压缩。

`Document::display_style_sources()` 和检查器文档转储新增 `display_style_sources`，关联文件 SSYS/SSYSA 中的表头、登记标记和样式 XML，给引用保留源候选及名称。输出采用稀疏目录，每项保留属性索引，不按声明上界分配空槽。重复表头和重复索引保留所有来源；超出声明上界的源项继续保留，但不作为有效范围内的候选；模型中的同号记录不参与文件表头匹配。未知 XML 属性和子节点保持原样。

这里尚未模拟原生登记顺序和样式转换，不输出最终显示绑定。`0x5fa40` 在访问 Lite 列表前调用 `0xdbaa0`，该函数在 Lite 列表为空时复制普通列表，并修改渲染模式与覆盖项；直接以普通 XML 覆盖当前场景将丢失这一步行为。结果保持 `partial`、`runtime_resolution=not_evaluated`，引用状态 `source_candidates` 只表示存在来源候选。

## 普通样式转 Lite 的已确认字段修改

`0xdbb2e` 至 `0xdbb46` 对普通样式的副本执行三组修改：运行时偏移 `0x48` 的 DWORD 变为 `(原值 & ~0x79) | 6`；偏移 `0x50` 的 DWORD 清除 `0x47`；偏移 `0x54/0x58` 的两个 DWORD 与偏移 `0x60` 的 DOUBLE 清零。XML 写出路径 `0xd9f10` 确认了对应字段：显示模式为 6，`DisplayVisibleEdges` 关闭；`VisibleEdgeColor`、`VisibleEdgeWeight`、`Transparency`、`Material` 的覆盖开关关闭；可见边颜色、线宽和透明度的存储值归零。材质编号、隐藏边、阴影、填充色等其他值不因此清除。

XML 字段名在 DLL 初始化时从 ASCII 常量还原；`0x474c50` 至 `0x474c66` 对偶数位置减 3、奇数位置减 1。通过初始化赋值与序列化引用关联，确认 `0x6403f0=DisplayMode`、`0x6403f8=DisplayVisibleEdges`、`0x640378=VisibleEdgeColor`、`0x640388=VisibleEdgeWeight`、`0x640398=Transparency`、`0x6403c0=Material`。字段含义来自指令链，不依赖样例中的数值猜测。

普通源表的 XML 项新增 `lite_copy_projection`，在独立副本中展示这组已确认修改，并保留原树、未知 XML 字段和未改变的材质编号。它的 `status=conditional` 只表示：若此项已被原生成功导入、普通表被选中且 Lite 列表为空，这些修改将发生。它不是已经选择或应用的样式，也不是原生 XML 的重新序列化；XML 导入默认值、表登记顺序及资源重映射仍未模拟。缺失或重复的 `Flags/Overrides` 节点返回 `unresolved`；已有 Lite 项不重复套用转换。

## 样式 XML 的布尔与整数输入规则

源样式项新增 `native_xml_import`，还原 R1.18 `P3DKJ.dll` 的 XML 输入函数 `0xd90a0` 中已确认的 38 个布尔及整数字段，并提供偏移 `0x48/0x50` 的两个完整标志字。结果仍为 `partial`；浮点字段、环境名称和 Usages、显示处理器登记以及最终资源绑定尚未包含。源 XML 与条件 Lite 投影保持独立。

`Name` 在 `0xd915c` 读取且失败即退出；`Flags`、`Overrides` 分别在 `0xd92ed/0xd980d` 取得，缺失即退出；`Overrides.DisplayMode` 在 `0xd988c` 读取，失败同样退出。上述必需内容缺失或无效时不发布导入字段，返回 `rejected`。重复 XML 区段保守返回 `unresolved`，尚不模拟 XPath 多匹配选择。

`0xd9371..0xd980a` 确认 25 个开关。`VisibleEdgeStyle`、`VisibleEdgeWeight`、`HiddenEdgeLineStyle`、`HLineTransparency` 在属性缺失或无效时默认 true，其余默认 false。空 Flags 的覆盖标志字因此为 `0x582`，不能全部清零。显示模式只写入主标志字低 6 位，隐藏边线型只写入位 8..10；结果分别保存扫描得到的 `value` 和截断后的 `stored_value`。`0xd9a27` 确认无效／缺失的隐藏边线宽恢复为 65535；其他已建模整数默认零。Material 为无符号 64 位，不能通过有符号值或浮点数中转。

实际执行未修改的 `SHARE/p3dlibxml2.dll`（SHA-256 `ca24cc124168dd90958f79e72d2af9dbca1dd937338ce6dd07fb0500cf21270a`）的 `P3DXmlNode::getAttribute` 导出，对合成 libxml 节点进行 48 组输入对照：成功返回 0、缺失返回 `0x1004`、无效返回 `0x1005`；失败时输出清零。布尔读取位于 RVA `0x51e0`，仅接受不区分 ASCII 大小写的完整 `true/false`，不去掉空白，也不接受 `1/0`。无符号数按十进制扫描前缀，因此 `42tail` 得 42、`0x10` 得 0；32 位结果截断 64 位中间结果，负数按模取反，超出无符号 64 位的幅值饱和到最大值。实现采用显式整数运算，不依赖宿主 `scanf` 的溢出或 locale 行为。

每个字段报告 `read_status` 与 `default_applied`，避免把缺失、无效与有效的 false/0 混为一谈。原始字符串仍在 `xml_tree` 中。`DisplayHandler` 的数值可读取，但 `0xd8370` 所查询的运行时登记表未执行，不因存在该数值宣称处理器可用。

测试中的合成输入及官方返回值保存在 `tests/display_style_xml_oracle.hpp`；回归本身不需要官方 DLL。可在 Windows x64 上用外置 DLL 复现观测：

工具另外记录浮点扫描结果，供后续实现使用；它不会把这部分观测标成库已支持的字段。

## 样式浮点输入与 IEEE 位模式

`native_xml_import` 进一步增加 7 个浮点字段，scope 更新为 `native_xml_scalar_writes`，共 45 个字段。主输入函数 `0xd9276..0xd92bc` 依次读取根属性 `GroundPlaneColor.R/G/B`、`GroundPlaneHeight`、`GroundPlaneTransparency`；三个颜色分量名称来自 `0x61beb8` 指针表中的 ASCII `R/G/B`，按 `0x52d0f0` 的 `%hs.%hs` 格式拼接，不能当作整数颜色字节。覆盖表另在 `0xd9968` 读取 `Transparency`，在 `0xd99e3` 读取 `HLineTransparencyThreshold`。

原始 `p3dlibxml2.dll` 的浮点 getter RVA `0x5310` 在读取前清零目标值，使用 RVA `0x12588c` 处的 `%lg` 格式；与已有材质 XML 浮点扫描器一致。本轮复用该实现，并通过官方 DLL 的 90 组输入逐位对照，涵盖十进制／十六进制、数字后缀、残缺指数、溢出、次正规数、负零及 NaN 特殊位模式。探测工具直接读取 DOUBLE 目标的八字节内容，避免在观察信号 NaN 时先经浮点计算改变其位模式。

缺失或无效的地面颜色、高度、地面透明度及覆盖透明度为零；因此地面颜色不能沿用构造函数中的初值。只有透明度阈值在读取失败后由 `0xd99fe..0xd9a08` 恢复为 0.3（位模式 `3fd3333333333333`）。成功读取的零、负零、NaN、Infinity 均不触发该默认值。

浮点字段提供 `value`、`read_status`、`default_applied`、`ieee754_hex` 和 `conversion`；非有限 `value` 为含类别、符号和位模式的对象，可无损写入标准 JSON。`conversion` 记录扫描结果和被忽略的后缀，默认值的位模式单独保存在字段的 `ieee754_hex`。不支持的非文本输入为 `unresolved`，不会假冒已确认的原生失败，也不自动填入默认值。当前尚不模拟宿主修改 locale 后的其他扫描规则。

本轮 158604 项 Debug 检查通过。12 个官方文件中 154 项样式均产生 45 个字段；新增 1078 个浮点读取均有效。剔除新增字段及对应范围说明后，原先全部样式目录与上一轮一致，原始 XML、条件 Lite 投影、引用候选及几何／记录计数没有变化。环境名称、Usages 和运行时登记／绑定仍未完成，不将标量读取成功视为全样式导入成功。
