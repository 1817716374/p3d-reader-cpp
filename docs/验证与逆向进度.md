# 验证与逆向进度

## 2026-09-29：Windows 与官方公开样例基线

起点提交：`782548e96a6c57c9d1fb7d46b739b6ee750bbd0e`。

官方来源为 [BIMBase 浏览器产品页](https://product.pkpm.cn/productDetails?productId=40)。本轮取得 R1.18 安装包，大小 367447936 字节，SHA-256 为 `8a1d709118b9f67f0c7d2b1c49b71c5c702a22e552b61ebcb13ee5d6cb3505f3`，Authenticode 签名有效，签发主体为北京构力科技有限公司。解包取得 17 个 P3D DLL 和 12 个 P3D 文件，包括 WelcomeFile 下的三个公开案例、三维模板和图纸模板。专有二进制及模型不随仓库再分发。

LLVM-MinGW 20260922 / CMake 4.4.3 的首次 Debug 构建发现 Manifold 头文件缺少 `<iosfwd>`。测试还发现单元素 `Json({0})`、`Json({existing_json})` 的构造重载歧义，改为显式数组；深层错误输入测试在 Windows 使用 16 MiB 栈。并发测试固定输入及浮点环境，避免将主线程和工作线程的 x87 精度差异误判为共享状态污染，不放宽结果相等检查。

BFA 公式替换修复了 libc++ 将字符串替换参数经由 `c_str()` 传递导致的 NUL 截断，改用带显式长度的匹配格式化，继续遵循原有 `$` 替换规则。

### 真实文件基线的边界

12 个官方文件均完成读取，基线下案例 1 有 377 个构件、64890 个展开三角面；案例 2 有 1804 个构件、231964 个展开三角面；案例 3 以线和文字为主，三角面数量不能代表内容覆盖率。这些是库输出的计数，尚未逐项与官方程序输出核对。

本轮两类属性解码加入后，Debug 回归的 157997 项检查全部通过。12 个文件均成功读取，与初始基线相比，场景及记录计数没有变化。图形属性合计 25475 条：13956 条已结构化、3617 条部分解析、7902 条仅保留原始或二进制表示。此统计仅针对顶层 `graphics_records.attributes`，不包含嵌套字段和运行时几何诊断，不能换算为整个格式的解析百分比。

案例 1 的场景摘要 `unknown` 为零，但属性仍有 912 条 `opaque`，因此该摘要不是格式完整率。其中 407 条为 `(group=0, key=22900, index=1)`，本轮确认其登记引用前缀；其余字段、处理器业务语义和运行时绑定仍需研究。不能把从 `opaque` 改为 `partial` 算作完全解析。

### 属性 22900 / 组 0 / 索引 1 的证据

分析对象为 R1.18 `ROOT/P3DKJ.dll`；以下地址是相对于镜像基址的 RVA，不依赖装载地址。

- `0x394230` 的读取路径按组合键 `0x59740000` 和索引 `1` 选择记录，检查数据至少 8 字节后拷贝一个 QWORD。
- `0x3948b0` 的写入路径使用同一组合键与索引，并写入 8 字节。
- `0x394620` 的登记表查询先按偏移 2 的 WORD 查外层表，再按偏移 0 的 WORD 查内层表。
- `0x3946e0` 包含登记缺失时的运行时服务查找，不能仅凭文件标识推定已经取得处理器。

库暴露 `registration_key`、按实际查询顺序排列的 `registration_lookup_keys`、尚未确定用途的 `unassigned_word_at_4` 和原生未消费的 `trailing_bytes`。状态保持 `partial`，`runtime_resolution` 保持 `not_evaluated`。不足 8 字节的输入报错；其他组和索引不套用此结构。

官方 DLL 为仅按序号导出；本轮 LLVM PE 工具对空名称表的零 RVA 报错。分析时仅在单独副本中将两个长度为零的表指针指向已有导出地址表，代码段不变，原 DLL 保留原样；该副本不用于执行。

### 属性 20031 / 组 3 / 索引 0 的证据

同一 `P3DKJ.dll` 的 SHA-256 为 `37fc96b97d230ba31619af4fba09ee11b2a38bfffca616621f11b240079f5901`。写入路径 `0x4ea4a1` 至 `0x4ea4c5` 使用组合键 `0x4e3f0003`、索引 0 和长度 8；读取路径 `0x4ea6d6` 选取同一属性，`0x4ea80e` 要求长度恰好为 8，否则走不带此键的列表。

有效值在 `0x4ea867` 以偏移 0 的无符号 DWORD 为第一比较项，`0x4ea86e` 以偏移 4 的有符号 DWORD 为第二比较项，用于有序表查找；随后将几何对象加入对应列表。公开案例 1 的 237 条此类属性均为 `0000c05dffffffff`，解码为 `first_unsigned=0x5dc00000`、`second_signed=-1`。字段不是两个浮点数，也不能简单合并成无符号 64 位标识。

库暴露 `native_geometry_grouping_key`，保留 `partial` 和 `component_semantics=unresolved`。尚未推断字段与图层、材质等业务对象的关系。其他组和索引不套用此结构，长度不等于 8 时报告解码错误，属性层继续保留原始 payload。

## 可复现的外部语料审计

需要 Python 3.11+；模型保存在仓库外部。示例：

```powershell
python tools/audit_corpus.py D:/codex/data/bimbase-r1.18 `
  --inspector D:/codex/build/p3d-debug/p3d-inspect.exe `
  --output D:/codex/results/corpus-audit
```

工具逐文件保留 SHA-256、命令、退出状态、标准输出、错误输出、文档转储和属性分类表，报告固定标注格式完整性尚未建立。`structured` 仅表示已产生结构字段，不代表字段业务含义、材质绑定、几何或全部版本完整。

## 后续验收

1. 保持合成回归通过，真实语料新增解码不得丢失原始字段、记录身份和引用关系。
2. 扩展官方版本与公开样例，按记录类型、属性键、版本及几何类别统计缺口。
3. 针对高频未知属性记录 DLL 证据、实现结构与语义，并增加最小回归。
4. 对构件、坐标、曲面、材质、属性、结构树和引用逐项与官方读取结果核对。
5. 未解释字节、需要外部上下文的关系及未验证版本继续明确报告，不能以单一成功退出码宣称完全解析。
