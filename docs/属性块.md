# 通用属性块

`<p3d/property_blocks.hpp>` 提供 `decode_property_data_block(bytes, limits)`，读取原生 `DataBlock` 的类型化存档。`Document::binary_fields()` 中相应的属性块也使用同一读取器。

```cpp
#include <p3d/property_blocks.hpp>

const auto block = p3d::decode_property_data_block(bytes);
const auto& tokens = block.at("tokens");
for (const auto& field : block.at("property_structure").at("fields")) {
    const auto name = field.at("name");
    for (const auto& index : field.at("value_token_indices")) {
        const auto& token = tokens.at(index.get<std::size_t>());
        // 按 token 的类型读取值；二进制值由 binary_base64 提供。
    }
}
```

根的 `namespace`、`class_name` 是保存的类身份，`source_storage` 保留完整输入。`tokens` 是原始顺序的类型和值，`offset` 相对于当前属性块起点。支持布尔值、int32、double、int64、字符串、二进制、三维点和二维点。布尔 token 保留数值字节 `value` 和既有的 `kind` 标签，同时通过 `native_kind: boolean`、`boolean_value` 提供已确认的类型解释。非有限浮点值另保留原始位模式。

`property_structure.fields` 按保存顺序列出属性名、声明命名空间、类型、数组标记和源范围。重复名称保留为独立项，不按名字覆盖。`value_token_indices` 指向同一块的 `tokens`，不会再次复制大块二进制值。`Placement` 与 `BaseTransform` 使用原生专有布局，分别引用四个值 token；普通属性则保留 `array_flag_token_index`、`type_name` 等字段。

数组保留原始 `declared_count` 和计数 token。基本类型数组通过 `value_token_indices` 引用各值；结构数组的 `elements` 保留每次出现的位置、源条目 token、字节计数及独立的 `data_block`。`stored_entry_offset` 是写入器保存的条目起始字节偏移，`stored_entry_offset_matches_position` 说明它与实际位置是否一致；原生读取器不使用这个值跳转，库也不会据此重排或合并条目。嵌套块有自己的 token 序号和相对偏移，不与父块混用。同内容的独立条目不会合并。

`value_status: not_serialized` 表示已确认的原生布局只保存声明，没有写入对应值，例如当前版本的 `dateTime` 分支和非基本类型的标量分支。它不是空值或默认值；库不会根据工程常识填值，也不自动实例化外部 schema。

`property_structure.status: structured` 仅表示该块的字段布局已读完。它不证明 schema 存在、原生赋值成功、实体引用有效或运行时默认值已确定。字段布局不一致时返回 `partial`、已读前缀及原因，全部类型化源数据仍保留。未知类型码、截断的类型化载荷或顶层字节／token 预算耗尽会抛出异常，不尝试猜测下一个边界。

`PropertyBlockLimits` 控制 token、字段、实际数组元素、嵌套深度和累计处理字节数。嵌套块与父块共享预算，默认深度上限为 32；子块失败会使外层结构保持 `partial`。未写入值的 `dateTime` 声明不会按其计数分配元素。每次调用拥有独立状态，可在不同线程中读取独立输入。
