# 格式说明

本文说明文件结构、库中的数据组织方式及其 API 表达。具体字段布局以对应解码实现为准。

## 从文件到场景

```text
P3D 文件
  → OLE/CFB 容器、目录和源流
  → 索引、流解压
  → DEX 属性对象 / 原生元素记录 / 图形属性与命令 / XML 等记录
  → 对象图、结构树、材质和源几何定义
  → NativeScene：定义、实例、构件元数据
```

容器由 `core.cpp` 读取，处理 FAT / DIFAT、短流及目录结构。流路径保留为字符串数组；文件中的索引用于解析模型与逻辑流名称，不应依赖固定目录名。

`Document::streams()` 同时提供原始缓冲区、解压缓冲区和压缩起点。压缩起点的缺省值是 `size_t(-1)`，表示该接口没有记录压缩起点。未压缩流可共享同一缓冲区。

## 属性与二进制叶

DEX 对象包含类 ID、对象 ID、字符串表、属性树及源位置。树中的二进制叶继续保存原字节，并按字段名、根对象类型及必要上下文选择解码器。

解码结果可能是设计参数、嵌套属性、缓存几何、内嵌材质、BGFB、二进制 JSON、NBFX XML 或其他复合结构。`binary_fields()` 提供对象来源及叶路径，便于定位尚未确定的内容。

`StructStandardFloorModel.DesignPara` 的解码结果在 `fields` 中保留全部成员的偏移和原始数值，在 `named_values` 中提供已确认的板厚、板钢筋保护层厚度、柱／梁／剪力墙／板／斜杆混凝土强度等级及柱／梁／墙主筋类别。混凝土等级数值配有 `display_value`，主筋类别配有 `enum_label`；未知枚举值保留数值并标记 `enum_status: unknown_value`。未命名成员仍标记为 `unassigned`。字段名称由本库定义，字段上的 `unit: mm` 仅说明该设计参数的单位，不用于推定几何坐标单位。

承台截面的 `pilecap_section_cereal` 解码保留 `members` 中的原生成员位置、数值及存储视图，并在各参数块的 `named_values` 中提供已确认的含义，包括桩的混凝土等级、定位参数，承台类型、平面形状、阶数、顶面偏心，以及配筋的级别、直径、间距与布置宽度。一阶或二阶且高度数量一致时，`step_heights` 按下阶到上阶排列；其他形式保留原数组并标记 `unsupported_step_layout`。未标注单位的字段不自动推定单位。

枚举必须按所属参数类型解释。例如标准层主筋代码 `0` 表示 HPB300，而承台配筋代码 `0` 表示 HPB235；桩基础混凝土代码 `3` 表示 C30，标准层混凝土数值 `30` 表示 C30。库返回的 `enum_label` 仅适用于所在字段，不能作为同名字段的全局对照表。

桩截面参数按 `section_shape` 区分矩形的 `section_width`、`section_height` 和圆形的 `section_diameter`，尺寸单位为毫米，`pile_length` 为米，`rotation` 为度。未识别的截面类型不套用这些尺寸名称。`layout_preset_index` 是原生桩数与承台形式选择列表的索引，不是桩数。

桩截面类型 `5`、`6` 另提供 `section_outer_diameter` 和 `section_wall_thickness`，单位为毫米；其原生内半径关系为“外径 / 2 − 壁厚”。两种类型各自的工程分类名称尚未确认，类型枚举仍标记为未知。此壁厚解释不套用于其他截面类型，也不据此替换文件中的几何。

桩截面类型 `7` 提供 `first_circle_radius`、`second_circle_radius` 和 `circle_center_spacing`，单位为毫米。原生局部坐标中的两个圆心沿 X 轴分别位于 `-circle_center_spacing / 2` 和 `+circle_center_spacing / 2`；半径按这两个圆的原生顺序返回，不换算为直径。类型 `7` 的 `0x1f0` 表示圆心间距，与类型 `5/6` 在同一成员位置存储的壁厚含义不同。工程分类名称仍标记为未知。

承台参数中的 `pile_layout` 提供原生桩数和桩位，`cap_profiles` 提供按下阶到上阶排列的轮廓，坐标和半径单位为毫米。多边形轮廓返回 `vertices`；圆形轮廓的原生三元组为 `[半径, 0, 0]`，以 `kind: "circle"` 和 `radius` 返回。未识别的形式保留在 `source_values`，原有 `primary_points`、`secondary_point_arrays` 仍可访问。数量不一致时返回对应的 `mismatch` 状态，不根据数量字段截断或补齐源数组。这些参数描述源截面，不自动替代场景几何。

`AssemblyLinkModel.CerealDatas` 中的 `link_merge_set` 提供节点连接归并方式、编号方式，以及 `collections` 中的楼层分组 `floor_groups` 和连接分组 `link_groups`。每个分组的 `values` 保留原生整数成员及其顺序，包含重复值；原生版本 0 的分组载荷不保存分组名称。`display_control` 提供构件、焊缝、螺栓和钢筋的显示模式。两个参数块都保留原始 `enum_codes`，并提供 `fields` 和 `named_values`；枚举标签按各字段分别解释。`storey_design_flags` 保留按原生装配楼层顺序排列的设计状态字节，不把数组下标当作楼层对象 ID。这些显示设置作为元数据返回，不自动过滤场景内容。

同一对象身份出现多条记录时全部保留。内容一致的副本与内容冲突的副本有不同状态，不通过覆盖字典隐藏差异。属性对象与场景构件之间的联系由绑定和关系记录表达。

## 变电站设计参数

`ElecParaData.CerealDatas` 中的 `collections` 保留变电站设计参数的原生集合顺序。集合元素通过 `entries` 访问，映射按键值条目返回，保留原始顺序及重复键。非空集合包括材料参数、整数映射、节点、杆件、柱参数、桁架梁参数、桁架梁、人字柱、梁柱分组及轴网记录；版本 1 的外层记录还提供 `changed_joints`。节点的 `Pt3D_ST` 数据提供 `position`，并按版本保留节点荷载；杆件记录保留关联的两个点和杆件荷载。

元素的 `native_type`、`version` 和成员位置描述原生存储结构。仅首次出现的同类型元素带有 `cereal_version`，其作用域覆盖整个参数载荷，包括嵌套元素。尚未确认类型或业务含义的数值成员同时提供 `storage_uint32` / `storage_uint64` 及整数、浮点存储视图；存储视图不表示已确认字段类型或单位。这些设计记录不自动转成额外的场景几何。

柱参数、桁架梁及人字柱的 `members` 是按序列化顺序排列的数组；`native_member_offset` 是成员在原生对象中的位置，`offset` 是数据在参数载荷中的字节位置。嵌套参数仍按各自版本读取，不能用外层记录的版本替代。原生桁架梁的 `0x138`、人字柱的 `0x1a0` 均连续序列化两次，库保留两次出现的值，不按相同成员位置合并。

`TrussBeamPar` 版本 2 只保存版本信息，不保存后续成员；空 `members` 表示成员没有序列化，不表示所有参数为零。版本 0、1、3 仍使用各自的非空布局。

已确认的数值成员另提供 `name`、`value` 和 `storage_type`。`SubsColPar` 包括 `column_section_count`、`column_type` 和 `fire_wall_height`；柱类型中已识别 `0`（人字柱）及 `1`（格构柱），其他代码保留数值并标记 `enum_status: unknown_value`。字段只在源版本包含该成员时出现，不为旧版本补默认值。`HumanColumn` 的两个点分别命名为 `start_point`、`end_point`，`rotation` 单位为弧度（`rad`）；这些定位参数不自动施加到已有场景几何上。

柱参数中的 `domain_column_parameters`、`domain_beam_parameters` 保留整数键和双精度数组，并通过 `native_property_name` 标明对应的原生领域属性 `colParam`、`beamParam`；防火墙高度对应 `fireWallH`。这些对应关系仅适用于 `SubsColPar`，不作为任意同名用户属性的解析规则。数组仍按原长度返回，不截断、补齐或重新格式化为字符串；未确认的数组项含义及长度单位不填入推定名称或单位。

版本 5 及以上的 `SubsColPar` 还提供 `bar_segments_by_elevation`：键为 `upper_elevation`（高度上界），值为 `segment_index`（杆件段序号，`index_base: 1`）。原生使用方式是以梁端点 Z 坐标寻找不小于该高度的首个上界，再选择有序杆件列表中的对应段。段序号不是构件 ID；库保留原始顺序、重复键和非正序号，不自动排序、修正或建立对象引用。高度单位仍由来源坐标约定决定。

`section_parameters.collection` 提供截面记录 `PSXsectAndMatType`。其中 `section_group` 按截面类型展开扩展数组、三个字符串及截面成员，支持专用布局与原生通用布局。`section_type` 是原生截面类型码，已确认的类型另提供原生简称 `section_type_label`，`serialized_length` 是组内有效长度；800 字节块中超出该长度的部分以 `unused_capacity.source_bytes` 保留。组内字段的 `offset` 相对于 `section_group.offset`，由 `offset_basis: section_group_start` 标识；外层记录和材质成员的位置仍相对于参数载荷。字符串的 `source_bytes` 始终保留原字节。

截面类型 `31` 至 `35` 的名称还取决于 `section_subtype`，其来源是原生成员 `0x8` 中的有符号 16 位代码。支持的子类型包括工、槽、等边／不等边角钢及其组合方向；`section_type_label` 保留原生方向符号、空格和重复名称。同名不表示同一子类型，调用方仍应保留两个类型码。未确认的子类型不填入名称，对应成员标记 `enum_status: unknown_value`。类型 `201`、`202` 分别提供原生名称“矩型钢混凝土”“圆管型钢混凝土”，不将其尺寸成员解释为子类型。

## 图纸设置

`PSDrawingManager` 和 `SubsDrawingManager` 的 `CerealDatas` 按原生图纸类型返回 `records`。每条记录的 `fields` 提供已确认的字段名称、原生成员位置、数值及枚举标签，`named_values` 提供按名称访问的数值。原有数值数组和标志字节仍然保留。

已命名的设置包括图幅、图框样式、比例分母、文字高度，以及各图纸类型的梁柱画法、标注距离和节点出图选项。比例字段 `*_scale_denominator` 表示 `1:N` 中的 `N`。图幅与图框样式是不同枚举，例如图幅 `0` 和图框样式 `1` 都对应 A0；未知枚举值保留原值并标记 `unknown_value`。这些设置作为元数据返回，不驱动几何生成或内容过滤。

平面、立面、柱脚及连接图记录支持版本 0 和版本 1，节点图及变电站图纸记录支持版本 0。版本 1 中新增的节点编号显示方式、拼接节点标注起点仅在源记录包含时返回。尚未确认含义的参数保留在原始数值字段中，不填入推定名称或默认值。

## 几何定义、实例和块

图形属性中的命令流描述几何、变换和样式。已支持的源网格直接转入数组，参数化曲线和曲面按采样策略重建；源命令和载荷仍可通过底层接口访问。

命令 28 的样式载荷按 16 位标志选择字段，读取顺序遵循原生布局。除材质 ID、颜色索引、线宽、线型和透明度外，还返回填充色索引、填充模式 `fill_mode`、子项索引 `subitem_index`、打包颜色，以及尚未命名的 `field_*` 字段。`field_0040`、`field_1000` 分别是填充模式与子项索引的兼容视图。子项索引不自动等同于材质分配中的部件索引。打包颜色保留为 `true_color_packed`，其低三字节按 R、G、B 返回 `true_color_rgb`；最高字节通过 `true_color_unassigned_high_byte` 保留，不推定为透明度。

`line_style_modifiers` 按自身的 32 位标志返回可选成员。`fields` 保留名称、掩码、源偏移、原生成员偏移和整数存储值；64 位标量另外提供 `float64_view`。`named_values` 提供缩放、虚线及间隔缩放、起止宽度、移位、分数相位、多线索引及多线数据类型码。居中移位、真实尺度和两种转角规则按原标志位返回，冲突位同时保留。切换线型会清除上一线型的修饰参数；同一命令附带的新修饰参数随后生效。

线型法向与旋转分别保存在 `orientation_vector`、`orientation_quaternion`，均为源载荷值；原生绘制会在四元数存在时以转置旋转矩阵的第三行覆盖法向，本库不把这组线型方向用于变换几何。未确认的标志位和剩余字节分别保存在 `unassigned_flag_bits`、`trailing_bytes`。兼容字段 `unassigned_doubles` 仅为连续存储视图，不表示载荷全部由双精度字段组成。

命令 40 是可变长度的样式扩展。`extension_flags` 的位 0、1、2 分别选择渐变填充块、按图层继承标志和图层 ID，按此顺序保存；没有出现的字段不清除之前的状态。`layer_id` 会进入实例及图元的 `style`，包括源数据中的特殊值。`by_layer` 分别说明颜色、填充色、线型、线宽是否使用按图层继承的标志，未确认位继续保留；库尚未求出继承后的最终值。

`fill_style_block` 返回渐变角度、白色强度、移位、模式码、标志及最多八项位置和 RGB 颜色，源颜色字节也单独保留。已知渐变模式包括线性、曲线、圆柱、球形、半球形。数值使用源值，不自动裁剪范围或推定角度单位；`unassigned_scalars` 是这三个已命名数值的兼容视图。短块按原生规则补零后提供结构视图，长度为零表示清除。填充及继承数据保存在 `style.native_symbology_extension`，渐变不能简化为一个普通调色板颜色。

命令 29 的 `curve_identifier` 是可变长度的原生曲线标识容器，包含类型、标识字节和可选的复合绘制状态。适用类型额外提供 `topology`，保留拓扑类型及一、二或四字节宽度的无符号 ID 数组；原生类型 0 至 3、99 不提供此拓扑视图。复合绘制状态保留原字节，并在 `compound_draw_state_decoded` 中展开功能码、尚未命名的 16 位成员及奇数长度的尾字节。兼容字段 `identifier` 仅是特定长度载荷的 64 位存储视图，不能作为构件 ID、材质部件编号或全局几何身份。

SMCA 共享定义按源流、记录偏移和属性序号建立身份，构件的原生引用在模型作用域内解析。源记录身份只用于已有的定义关系，不用于寻找形状相同的独立构件。

原生块定义包含成员及名称引用，嵌套块携带变换链。多个同名候选、缺失定义和循环均明确记录。活动场景未引用的块成员仍保留在块库目录及定义集合中。

定义、实例与渲染图元不是一一对应：一个构件可能有多个实例，一个定义也可能包含多个面、线或文字范围。调用方应使用 `for_each_primitive()` 或逐范围处理，不能把“构件数”等同于“网格数”。

导引放样支持折线、圆弧和椭圆弧边界，包括一周的整圆、整椭圆。折线按累计弦长参数化；圆弧按不超过 120° 的有理二次段构造，保留权重。周期圆锥曲线在源参数零处打开，保留源角度接缝及七控制点表示。边界经过次数提升与节点对齐后，使用原生分段控制点混合系数构造 Coons 控制网；三控制点边界按原生规则额外提升一次次数。控制网为从源命令重建的临时数据，不新增源几何身份。

两个截面的开放或闭合类型必须一致。闭合截面有 N 个源边段时需要 N 条导引，最后一片回接第一条导引；无封口的开放截面需要 N+1 条导引，最后一条定义末端边界。开放截面从命令 20 的路径块读取，闭合区域从命令 21 读取，不按首尾坐标相等与否改写源边界类型。开放曲面的每行顶点保留两端，不添加闭合边或封口面；构造说明中的 `profile_closed` 标记源截面类型。开放截面与内环组合、带封口的开放截面目前明确返回未支持。

单条导引可以由连续的折线和圆弧、椭圆弧命令组成。各条导引的源命令数一致时，原生逐次连接为等参数区间；不一致时，逐次按去齐次控制多边形的长度分配区间。这是逐次连接规则，不能将三段以上的导引直接改成全局等分，也不能用圆弧长度替代控制多边形长度。使用的规则保存在曲面构造 `notes` 的 `composite_guide_parameterization` 中。

命令 55 的 `guide_group_count` 和 `guide_counts` 保留导引分组。多环截面的外环及内环按源顺序对应上下截面和各自的导引组，不按几何距离寻找配对。内环侧面保留源轮廓方向；封口使用带孔多边形三角化。组数量、曲线数量或边界端点不匹配时报告未知项，不返回已生成的部分放样。多环构造条目通过 `source_ring_index`、`source_guide_group_index` 标明来源。

相邻曲面片共用导引方向的采样参数。指定弦高时，依据正权重有理曲面的导数上界细分，并在 `notes` 的曲面构造条目中通过 `surface_to_mesh_error_bound` 记录曲面侧面到三角网格的误差上界。该上界针对本库重建的曲面，不包含未重现的原生曲线拟合容差处理，也不是封口面误差证明。控制网、生成网格及多环封口的总顶点数受 `Tessellation::max_segments` 限制，预算不足时报告未知项。

## 结构树与材质

对象图分别组织源结构树和模型树，保留节点、边、根及解析状态。块树单独保存在场景元数据中。原生可见性和视图规则尚未全部验证，因此这些结构不自动等价于某个视图的最终渲染列表。

材质定义有模型或全局作用域，源颜色索引、扩展颜色、材质参数与贴图引用分别保留。图元的外观摘要不替代原始材质定义，也不等于已经完成 glTF PBR 转换。

`inline_materials()` 返回复合载荷中的内嵌材质。其 `material.is_valid` 是原生有效标志；`encoding: inline_material_v1` 是库的格式标识，不代表载荷中保存了版本号。`name` 是材质名，`display_name` 是显示名；没有显示名扩展的旧载荷以材质名作为回退，并标记 `display_name_source: name_fallback`。显式保存的空显示名仍保留为空。

`parameters` 按原生顺序提供 `color`、`transparency`、`specular_color`、`specular_factor`、`glow_color`、`glow_factor`、`ambient_factor`、`diffuse_factor`、`roughness_factor`、`reflect_factor`、`refract_factor`。每项包含原始 `flag`、布尔 `enabled` 和数值 `value`；关闭某项不会丢弃其保存的数值，也不会把原生系数直接换算为其他渲染系统的参数。

内嵌材质的 `map_unit`、`map_mode` 保留原生有符号枚举，并为已确认值提供 `map_unit_name`、`map_mode_name`。未知枚举标记为 `unknown_value`。`uv_scale`、`uv_offset` 是二维数组，`rotation_degrees` 使用角度单位。`texture_references` 分别保留 `pattern` 和 `bump` 路径，凹凸强度通过 `bump_factor` 返回；空路径和被关闭的普通贴图引用同样保留。库不查找外部图片、不计算这些映射的 UV，也不据此生成缺失贴图。后续未知扩展以 `unassigned_suffix_hex` 保留，不能视为已解释。

显示名之后的 `0xABCE` 扩展保存以 NUL 结尾的 UTF-16 JSON 字符串，长度为包含终止符的字节数。`extended_data.text` 保留原始文本，`source_bytes` 保留包含终止符的原字节；`json_status` 为 `parsed`、`empty` 或 `invalid_json`。有效 JSON 另提供通用 `value` 视图，不预设业务字段。需要保留重复键、空白和数值文本形式时，应使用原始文本或字节。

嵌入图片位于图形属性键 `0x5981`（22913）中，外层沿用属性数据封装：形式 1、2 直接存放载荷，形式 3 使用压缩数据。解封装后的布局为 256 字节 UTF-16 文件名区、32 位文件大小、32 位原生贴图类型及原始文件字节。`decoded.filename_field` 保留完整文件名区，包括终止符之后的剩余容量；`file_data` 提供图片原字节，库不解码或重新编码图片。`native_map_type` 保留完整数值，`attribute_group_matches_map_type` 核对其低 16 位是否与属性组一致。该数值不直接视作其他材质系统的贴图通道。

属性键 2006 是带封装的 UTF-16 字符串属性，`decoded.text` 提供字符串，`data` 保留包含终止符的原始字节。属性组及索引保持源值，不根据字符串内容推定业务字段。

属性组 4、键 10001 保存原生高级材质分配。索引 0 是不含终止符的 UTF-16 材质名，编码标识为 `advanced_material_name`；其他索引通过 `advanced_material_json` 保留 UTF-8 JSON 文本、原字节和通用 JSON 值。索引 1 的角色为 `part_material_names`，键是有符号部件索引的十进制字符串，值是材质名；索引 2 的 `material_part_index` 按材质名组织部件索引。源字符串、重复键和数值写法以 `text`、`source_bytes` 为准，不以 JSON 视图替代源载荷。

索引 1、2 还返回结构化的 `entries`。索引 2 的原生形状为 `{"材质名":{"19":"19"}}`：内层键和值均为同一个部件索引字符串。每项保留 `source_key`、`source_value`，提供 `part_index`、`material_name` 及形状检查状态。部件索引遵循有符号 32 位整数的规范十进制格式；`01`、`-0`、越界值不会被改写为另一个有效键。异常成员仍保留，未知属性索引不推定角色。该反向索引不用于覆盖正向表，也不用于推断部件与三角形的关系；`geometry_mapping_status` 明确为 `not_established`。

图层组合的属性组 0、键 4、索引 0 通过 `layer_group_overrides` 返回按源顺序保存的覆盖表；组 1、键 4、索引 0 通过 `layer_group_sync_state` 返回同步模式。模式 0 为 `sync_use_override`，1 为 `always_unsync`，2 为 `always_sync`，其他数值保留且名称为 null。这些结果可从 `graphics_records()` 的属性解码结果读取。

覆盖表首先保存一个 u32 项数，每项为 u32 图层 ID、u32 位数及该位数个 u16 存储字。原生存储长度确实为位数乘 2 字节，不能按通常的位图压缩长度跳读；实际位图只使用前 `ceil(bit_count / 16)` 个字的有效位。`source_storage` 保留全部存储字，`packed_words`、`set_property_bits` 提供有效位图视图。属性位 11、12、14、25、26、32、35 分别为颜色、线型、线宽、显示、打印、冻结和透明度的覆盖标记，其他置位保留于 `unassigned_property_bits`。标记表示该属性具有组合内覆盖，不是属性值本身，也不等同于“隐藏”或“冻结”；最终显示仍需结合图层值、同步模式、模型链接及视图条件。

原生类型 47、子类型 33 保存根模型的显式视图链接顺序，`native_records()` 的对应项通过 `view_link_sequence` 展开。偏移相对于含四字节流前缀的 `data`：偏移 38 为 u16 原始 `sequence_flag`，偏移 40 为 u32 项数，偏移 44 起为 u64 ID 列表。`entry_ids` 保留源顺序、重复值和零值，不按数值排序、不改写为其他对象 ID。`entries` 提供同序的逐项解释：零值为当前模型自身（`current_model`），非零值为模型链接（`model_link`），`source_index` 与 `source_id` 保留来源。原生运行时还会根据当前链接列表补入或删除条目；本库未执行此协调过程，标记 `runtime_reconciliation: not_evaluated`。`sequence_flag` 的用途尚未确认，原始值继续保留。长度错误写入该项的 `decode_error`，不丢弃后续记录。

原生类型 49、子类型 1 的图层记录通过 `native_records()[i].layer_definition` 读取，支持内部版本 1 至 7 的公共布局。`layer_id` 是图层表内的 u32 标识，与外层记录的 u64 `id` 不同；不同表中的相同图层 ID 不能直接合并。结果与记录的 `stream`、`offset` 一起使用，不自动将同名图层或同号图层关联到其他模型。

`name` 和 `description` 来自原生字符串链接键 1、2；重复键按源顺序更新名称视图，全部条目仍保留于 `strings`，包含原始偏移、键、标志、长度、尾部存储和逐项错误。该图层读取路径使用原生代码页参数 1200：无前缀字节逐个扩展为同值字符，`FF FE 01 00` 采用同样的窄字节形式，其他 `FF FE` 及 `FF FD` 形式读取 UTF-16LE；名称视图在首个空字符处结束。不能把此路径的规则直接套到所有原生字符串。未确认的字符串键不赋予业务名称。外层 `links` 和 `data` 保留完整原始内容。

图层的 `display`、`print`、`frozen` 分别读取偏移 46 的 u16 状态字位 5、6、14。`access_mode` 为位 12 至 13，并按原生读取规则将旧位 4 合入最低位；`locked` 对应 `access_mode == 1`，不能将所有非零模式解释为锁定。原始 `state_flags` 与其他 `unassigned_state_bits` 同时提供。

`by_layer_symbology` 包含图层颜色索引、带符号线型值和无符号线宽值。偏移 76、80 的旧颜色和扩展颜色都保留：扩展值非零且与旧值兼容时使用扩展值，否则退回旧值；小于等于 `0xfffffffd` 的扩展值以低 8 位作兼容检查，`0xfffffffe`、`0xffffffff` 按原值比较。这里返回索引，不自动换算为 RGB。`transparency` 为偏移 84 的原生 float32 值，不改写范围；非有限值返回 null 和 `transparency_error`，`transparency_source_bits` 始终保留源位模式。版本 4 至 7 的 `business_code` 为偏移 92 扩展字右移 3 位后的低 16 位，其他版本返回 null，未分配位继续保留。

图层记录中尚未确认的范围通过 `unassigned_ranges` 保留源偏移和载荷。版本 0 及大于 7 的版本返回 `unsupported_version`；已支持版本的长度错误写入 `decode_error`。图层自身的值不等同于某个组合或视图中的最终值，`view_visibility` 仍为 `not_evaluated`。

### 图层表及模型关联

原生类型 10、子类型 1 的记录通过 `layer_table` 提供表头。偏移同样包含四字节流前缀：36 为 u32 子记录数，40 为未命名 u16 字段，42 为 u16 原始表标志，44 为 u64 选择值。选择值 0 表示本地表（`local`），`0xfffffffffffffffc` 表示图层组合（`layer_group`），`0xfffffffffffffffe` 表示嵌套模型链接（`nested_model_link`）；直接链接以其原生 ID 表示。尚未确认的 `0xffffffffffffffff`、`0xfffffffffffffffd` 保留为 `unassigned`。选择值不同于该表外层记录的 `id`。

图层组合名称来自字符串链接键 10，名称视图选用第一个同键链接，全部字符串仍保留。嵌套链接路径保存在应用号 `0x56f1` 的链接中：载荷包含 u32 未命名字段、u16 键、u16 标志、u32 项数及 u64 ID 列表。键 1 为引用路径，按原生顺序保留于 `linkage_paths`；`path_linkage_index` 指向第一个键 1 条目。不会因其损坏而自动改用后面的同键路径。原始路径、重复 ID、尾部存储和逐项错误均可读取，路径缺失明确返回 `path_status: missing`。

`Document::layer_tables()` 返回一次建立的只读关联目录：

| 字段 | 内容 |
| --- | --- |
| `tables[i].native_record_index` | 表头在 `native_records()` 中的数组索引 |
| `tables[i].member_record_indices` | 表内图层记录在 `native_records()` 中的数组索引，保持原生顺序 |
| `tables[i].attribute_record_indices` | 同作用域、同原生记录 ID 的 `graphics_records()` 候选索引 |
| `tables[i].override_bindings` | 覆盖表条目到本表图层记录的引用，按图层 ID 匹配 |
| `tables[i].sync_attributes` | 同步属性的来源记录和属性数组索引 |
| `model_references` | 模型到图层组合表的原生 ID 引用及候选表索引 |
| `unassigned_layer_record_indices` | 未能归入已确认表边界的图层记录索引 |

表内成员必须满足声明数量、连续记录边界、相同源流及图层子记录类型；不满足时 `membership_status` 为 `invalid`，不会跨流拼接成员。属性匹配通过文件索引将 SSYS/SSYSA、SMG/SMGA、SMC/SMCA 容器对应起来，保留上级作用域；同号记录不会跨容器配对。属性记录或图层 ID 有重复时保留全部候选，分别标记 `ambiguous_attributes`、`ambiguous_layer`；找不到覆盖条目对应的图层时标记 `missing_layer`。`override_bindings` 中的 `attribute_index` 是属性数组的位置，`entry_index` 是覆盖表条目的位置，均不是源属性的原生索引值。

模型头的原生类型 47、子类型 32 在偏移 492 保存 u64 图层组合表 ID。`models()[model_id].layer_group_references` 保留此值及模型头流路径、记录偏移；短头返回 `unsupported_header`，0 表示无关联。`layer_tables().model_references` 只匹配系统容器中的图层组合表原生记录 ID；返回 `resolved`、`none`、`missing`、`ambiguous`、`invalid_table` 或 `unsupported_header`，不按名称推测关联。所有数组索引均仅在所属 `Document` 内有效。

这些接口提供保存于文件中的关联。组合的部分属性可通过下述 `group_states` 求值；链接继承和视图条件叠加后的最终图层状态尚未计算，`inheritance_status` 为 `not_evaluated`。

### 图层组合属性同步

`layer_tables().group_states` 返回图层组合的派生属性及原生来源，不改写 `native_records()`。组合表与本地图层表均位于 SSYS 系统容器；在同一文件作用域中，选择值为 0 的本地表唯一且双方成员边界有效时才求值。图层用各表内的 `layer_id` 对应；派生成员按无符号图层 ID 排序。

同步先对齐成员集合：文件中新增的图层加入组合，组合中独有的旧图层退出派生成员。这一步在三种同步模式下都会执行；退出的原生记录索引保留在 `excluded_group_record_indices`，原始记录不删除。

| 同步模式 | 已存在的组合图层属性 |
| --- | --- |
| `sync_use_override`（0） | 设有覆盖位时使用组合值，否则使用文件图层值；没有该层覆盖条目时同步全部已支持属性 |
| `always_unsync`（1） | 使用组合值 |
| `always_sync`（2） | 使用文件图层值，忽略覆盖位 |

缺失同步属性使用原生默认模式 0，`sync_state_source` 为 `native_default`。未知模式、损坏属性、歧义表或记录返回明确的未求值状态，不根据名称或数组次序选择候选。

当前求值属性为 `color_index`、`line_style`、`line_weight`、`display`、`print`、`frozen` 和 `transparency`，其覆盖属性位分别为 11、12、14、25、26、32、35；底层覆盖表也提供 `overrides.transparency`。每层的 `properties[name]` 返回 `value`、`property_bit`、`native_record_index` 及 `selection`（`file_sync`、`group_value` 或 `new_file_layer`）。`override_source` 在使用覆盖位图时指明属性记录、属性数组及条目索引。

`group_table_index` 和 `file_table_indices` 指向目录中的 `tables`。每层保留 `file_record_indices` 与 `group_record_indices`；重复 ID 不自动合并，歧义仅阻止受影响图层求值。`status: evaluated_supported_properties` 仅表示上述七类属性已求值；部分失败为 `partially_evaluated`，无法建立来源为 `not_evaluated`。非有限透明度返回 null，并在属性上保留错误。

名称同步包含独立的名称表更新规则，尚未求值，`name_synchronization` 为 `not_evaluated`；其他样式、链接继承及视图裁剪也未包含在该结果内。`display` 不能直接作为最终视图可见性，`view_visibility` 仍为 `not_evaluated`。

原生链接长度支持三种形式：头标志不含 `0x1000` 时固定为 8 字节；含 `0x1000` 且不含 `0x4000` 时为 `(低 8 位 + 1) × 2` 字节；同时含两标志时，字数为 `低 8 位 × 2^位8至11`，再乘 2 得到字节数。扩展形式检查至少两字且不超过 65,535 字，并检查完整载荷边界，适用于较长的引用路径等链接。

## 显示与辅助坐标系属性

属性组 0、键 22634 的 `display_style_reference` 保存 32 位显示样式条目 ID。组 0、键 22626 的 `clip_volume_settings` 保存首个原始字及 `forward`、`back`、`cut`、`outside` 四个区域的标志和样式 ID。`display`、`snap`、`locate` 分别表示显示、捕捉、定位状态；原始标志和未命名位仍保留。它们作为元数据返回，不用于自动裁剪或过滤几何。

组 0、键 109 的 `section_clip_data` 保存左、右、前、后、上、下六个裁剪开关，以及 `perspective_up`、上下高度、前后深度和旋转矩阵。`serialized_rotation` 保留文件中的 3×3 矩阵，`rotation` 按原生读取规则在右侧乘以绕 X 轴正向 90° 的旋转；原始标志、未命名位和附加状态字保留。组 1、键 109 的 `section_clip_frame` 保存原点及方向，方向不自动单位化。这两个属性独立返回，不推定不同记录之间的裁剪配对关系。

支持的图形记录在构件 `metadata.display_state` 中返回公共显示头的原始状态字和 `permanently_invisible`。当前已确认类型为 19、20、21、37、40、44、52、54、62、97，状态字位于源记录 `data` 的字节偏移 36，永久隐藏对应掩码 `0x0400`。其他位保留为 `unassigned_bits`。未支持的类型或过短的头返回 `unsupported_header`；`view_visibility: not_evaluated` 表示尚未合并图层、链接、裁剪等视图条件。

属性组 1、键 22295 的普通布局以零值头开始，解码标识为 `auxiliary_coordinate_system`，提供坐标系类型、视图独立标志、`origin`、`scale`、按行保存的 3×3 `rotation` 及 64 位 `element_id`。末尾扩展保存在 `extra_data`，存在时标记为 `opaque`。辅助绘图坐标系不自动视作构件变换，也不据此推定地理坐标参考系统。

盒体命令 30 的 `origin0`、`origin1` 是上下底面的中心，标记为 `origin_convention: face_centers`。底面顶点分别按中心加减半尺寸乘以对应轴向量计算；上下底面可以具有不同尺寸和偏移。
