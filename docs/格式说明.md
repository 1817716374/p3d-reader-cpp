# 格式说明

本文说明文件结构、库中的数据组织方式及其 API 表达。具体字段布局以对应解码实现为准。

## 从文件到场景

```text
P3D 文件
  → OLE/CFB 容器、目录和源流
  → 索引、流解压
  → DEX 属性对象 / 原生元素记录 / 图形属性与命令 / XML 等记录
  → 对象图、结构树、材质和源几何定义
  → NativeScene：定义、实例、构件元数据
```

容器由 `core.cpp` 读取，处理 FAT / DIFAT、短流及目录结构。流路径保留为字符串数组；文件中的索引用于解析模型与逻辑流名称，不应依赖固定目录名。

`Document::streams()` 同时提供原始缓冲区、解压缓冲区和压缩起点。压缩起点的缺省值是 `size_t(-1)`，表示该接口没有记录压缩起点。未压缩流可共享同一缓冲区。

## 模型单位

类型 47、子类型 32 的模型头提供 `model_unit_state`，模型索引中的对应结果见 `models()[id].units`。单位字段按原生模型头读取规则解码，不根据构件尺寸猜测。作用域为 `native_model_header_unit_state`；偏移包含记录开头的四字节流前缀，`record_offset` 则是记录在解压模型头流中的起点。

| 字段 | 记录内偏移 | 表达 |
| --- | --- | --- |
| 存储单位编码 | 68 | uint32 |
| 第一、第二显示单位编码 | 76、80 | uint32 |
| 第一显示单位分子、分母 | 84、92 | float64 |
| 第二显示单位分子、分母 | 100、108 | float64 |
| 每存储单位的数据值因子 B | 228 | float64 |
| 存储单位分子 N、分母 D | 236、244 | float64 |

每个编码取低三位为 `base_key`，位 3–5 为 `system_key`；完整值仍保留在 `packed_flags`，未确认的编码不擅自命名。两个显示单位名称仍可从模型的字符串属性 19、20 查看，名称不参与下面的比例计算。非有限源浮点数保留类型、符号和 `ieee754_hex` 位模式，不转换成字符串单位或默认值。

相邻偏移 252 的 float64 保存在 `unassigned_adjacent_value`；已确认模型头读取器会复制该值，但本单位换算路径不使用它，暂不赋予单位含义。模型头恰好从流偏移 4096 开始时，`unit_fields_at_10e4` 仍提供四个连续源值供对照。

SDK 的米到模型数据值转换计算为 `(N · B) / D`；`meters_per_data_unit` 是库派生的倒数。原生材质绝对投影将存储单位与第一显示单位的 `base_key` 比较，不比较 `system_key`。基类相同且两组分子、分母都严格大于零时，因子为 `((N · B) · 显示分母) / (显示分子 · D)`；否则直接使用 B。第二显示单位不参与这一投影因子。计算保留原生乘除次序，不为避免溢出擅自重排表达式。

源字段解码状态与因子可用性分别报告。有限结果为 `computed`，`positive` 表明是否大于零；非有限算术结果不作为可用系数发布。正无穷通过原生严格正数比较，NaN 不通过，所以不把所有非有限输入统一视为同一分支。模型坐标上下文只采用正且有限的米制倒数；零、负值和异常源数据仍保留在单位定义及因子结果中。存在多条候选模型头时保留 `unit_records`，不猜活动记录。

## 原生依赖链接

用户链接头置位 `0x1000` 且应用号为 `0x56D0` 时，`native_records()[...].links[...].decoded` 提供 `native_dependency_link`。源 `payload`、链接次序、重复项和偏移始终保留。载荷头包含 `owner_code`、`relation_code`、`flags`、`entry_count` 四个 uint16；前两个编码不按工程名称解释。`reference_format` 来自标志位 10–13。标志位 0 使依赖索引输入跳过该链接，格式编号大于 8 也不会进入引用分派；源内容仍保留。

| 格式编号 | 源条目布局与已确认的引用规则 |
| --- | --- |
| 0 | 8 字节元素 ID；`owner_code == 10000 && relation_code == 4` 使用逆序所有者路径，不能作为独立本地 ID 列表求值 |
| 1 | 16 字节条目，前 8 字节为元素 ID；后半部分保持未命名 |
| 2、3 | 分别为 40、48 字节条目；选择码 2、8 产生两组目标和所有者引用，其他选择码产生一组；每组另包含对所有者引用对象自身的本地依赖 |
| 4、5 | 分别为 16、24 字节条目；包含目标 ID 和所有者引用 ID，格式 5 中间的 8 字节保持未命名 |
| 6 | 单个可变长路径，载荷偏移 8 的 uint32 是路径长度，ID 从偏移 24 开始；与头部的迭代次数分开保留，只在首轮解释路径 |
| 7 | 24 字节紧凑条目，ID 的高、低 uint32 依次存储；选择码 0–3 展开为 40 字节描述，包含参数重排及条件角度归一化 |
| 8 | 16 字节条目；有符号模型索引为 -1 时选择系统所有者，其他值按模型索引查找，元素 ID 位于条目偏移 8 |

`entries[].references` 按原生分派次序提供引用描述；`lookup` 区分当前所有者、经引用对象取得的所有者及模型索引。格式 6 的路径位于 `owner_path`，格式 0 的特殊路径通过 `lookup_rule` 标识。所有 ID 保持 uint64，包括 0、最大值和重复值，不主动合并。依赖引用并不等于结构树的父子关系，也不直接确定最终活动材质。

引用的 `lookup_profile` 区分实际入口的查找范围，不能仅凭 `lookup: current_owner` 假设引用只存在于本模型：

| 查找规则 | 已确认的顺序 |
| --- | --- |
| `owner_system` | 先查当前所有者的 ID 索引；未得到对象且当前所有者不是系统时，再查系统索引 |
| `owner_system_file` | 先执行上述查找；仍未得到对象且当前所有者为系统时，继续执行文件级查找：系统在先，模型按有符号模型索引升序，返回首个非空对象 |
| `reference_path_owner_system` | 先定位所有者引用并展开其路径，再在获得的目标所有者中执行 `owner_system`；路径与相关文件的载入状态尚未求值 |

格式 0、1 的普通引用，以及格式 8 选定所有者后的引用使用 `owner_system_file`。格式 8 指定的模型不存在时，不会把空所有者改成系统所有者。成对引用中的目标经所有者引用 ID 为零时，也使用 `owner_system_file`；而额外产生的所有者引用对象自身只使用 `owner_system`。这些索引入口本身不检查对象的运行时删除位；路径对象读取和后续依赖登记的过滤属于其他步骤，不能混为同一规则。成对目标的元素 ID 或所有者引用 ID 为 uint64 最大值时，`target_lookup` 为 `skipped_maximum_id`，但对应源 ID 和额外的本地依赖仍保留；普通直接 ID 查找不套用这项提前退出规则。

格式 7 的 `entries[].expanded_selector` 提供紧凑参数的原生展开结果。`descriptor` 是独立的 40 字节描述，`field_mappings` 列出条目内源偏移、描述内目标偏移、长度与源字节；未确认业务名称的参数槽保持 `parameter_semantics: not_fully_assigned`。源选择码 2 且条目偏移 12 的 uint16 为零时，偏移 16 的 double 按 `2π` 取余，负余数加 `2π`，负零保留。归一化前后的数值位于 `normalization`。需要归一化的非有限角度标为 `invalid`，不生成伪有效描述；只做字节搬移的参数则保留包括 NaN 载荷在内的原始位模式。源链接和未使用范围均不改写。

`write_flag_projection` 描述原生写入函数接受载荷后对标志执行的规则：清除掩码 `0x78`，保留其他位。它提供条件派生值，不表示库已执行写入，也不表示该链接通过了写入长度或布局检查。被清除各位的独立含义尚未全部确认。写入函数另有扩展数据长度参数，并按 8 字节边界补零；仅凭链接末尾的零字节无法区分扩展数据与填充，因此未获得扩展长度依据时仍保留尾部未知范围。

`decoded` 仅表示本接口的结构字段已读取；仍有未命名位或字节时为 `partial`，截断或不支持的布局为 `invalid`。`unassigned_flag_bits` 与 `unassigned_ranges` 保留未知部分，后者的偏移以链接载荷起点为基准。格式 7 的未知紧凑选择码不生成猜测引用。`runtime_resolution: not_evaluated` 表示尚未结合模型载入顺序、对象注册与回调求值；因此不能把引用描述当成已解析到活动对象的关联。

## 原生所有者引用路径

原生类型 47、子类型 20 且记录基部偏移 36 的 uint16 签名为 `0x56E6` 时，记录提供 `owner_reference_path`；同类型的其他应用记录不标记为引用路径。在用户链接 `0x56D0` 中，读取器选择 `owner_code == 10000 && relation_code == 4` 的第一条匹配链接，选择先于载荷格式和长度检查。`matching_links` 保留匹配次序及被遮蔽的后续项；损坏的首项不会自动换成后项。无法读全的早期匹配键会阻止确定选择，而不会越过它猜测后续项。

`selected_linkage_index` 和 `selected_linkage_offset` 对应源 `links`；`steps` 按实际处理次序提供路径操作。这里的 `status: resolved` 仅表示路径操作已读取，作用域为 `path_program_if_record_is_resolved`，并不表示已定位到目标对象。`runtime_resolution` 明确保持 `not_evaluated`。

| 路径格式 | 处理顺序 |
| --- | --- |
| 0 | 从最后一个 ID 到第一个 ID，逐个定位并递归展开引用，使用展开结果更新当前所有者；空路径保留已有所有者，未设置时采用当前所有者 |
| 6 | 外层项数必须为 1，载荷偏移 8 的路径长度必须有效；从最后一个 ID 展开到第二个 ID，再以第一个 ID 定位最终目标，最终目标本身不更新当前所有者 |

其他通用依赖格式不能用于这个路径入口。路径读取也不应用通用依赖索引的标志位 0 禁用规则，因此必须分别检查 `owner_reference_path` 与链接的 `decoded`，不能用其中一个替代另一个。

### 其他原生应用记录

类型 47、子类型 20 的 `0x56DF`、`0x5704` 签名通过 `application_record` 提供已确认的记录头信息。它们与 `0x56E6` 引用路径是不同记录，不能合并解释。

`0x56DF` 的 `version` 和 `declared_storage_length` 分别来自基部偏移 38、40 的有符号 16 位整数。`decoder_input` 从偏移 42 延伸至原生基部字数所指定的结束位置。声明长度传给版本适配器，不能用来裁短资源解码器的输入；末尾字节也不自动标记为填充。`conversion.attempt_versions` 描述版本分派：版本 0～7 先尝试当前版本，失败后仅在版本大于 0 时尝试前一个版本；成功即停止，全部失败则调用默认初始化。其他版本直接走默认初始化分支。

这里仅还原记录头、输入边界和分派规则，资源转换及载荷字段含义尚未实现。`conversion.status` 为 `not_evaluated`，记录状态为 `partial` 或 `unsupported`；这些状态不表示已经生成可用的默认配置，也不表示确定了当前生效的记录。

`0x5704` 是原生所有者保存和查找的应用标记。其签名后的字节保留在 `unassigned_ranges`，链接仍由记录的 `links` 提供。空链接不能据此解释为整个所有者没有属性。运行时所有者关联仍未求值。

`resolve_and_expand_reference` 步骤会递归处理所定位的记录；`resolve_and_append_target` 步骤使用目标的运行时父链，若目标带子项位 `0x80`，先追加沿父链找到的第一个不带该位的祖先，再追加目标。找不到这样的祖先时只追加目标。这与直接使用源文件的物理记录邻接关系不同。每步保留 ID 的载荷偏移、原始索引及完整 uint64，查找范围为 `owner_system`，路径读取拒绝运行时删除位 `0x8`，首个未解决步骤会终止路径处理。实际模型切换、类型 13 引用的载入及运行时父链仍需上下文，库不会自行加载外部模型文件。

## 原生容器输入顺序

`Document::file_header()` 提供 `P3DSIndexes` 第一段压缩文件头的已确认字段。`header_payload` 保留完整解压内容；已确认的原生读取长度为 1552 字节，超出部分另列为 `header_payload_suffix`。`source_id_counter` 位于解压头偏移 296，类型为 uint64，是文件持久化的 ID 分配计数器，不能用现有记录中的最大 ID 替代。`source_header_flags` 位于偏移 784，原始位值保留，未确认的各位不赋予业务名称。

原始索引流偏移 12 的 20 字节控制头以初值 `0x26` 作累积异或编码，展开为 `decoded_control_header`。其中前两字节为 `control_flags`，其余字节保留于 `unassigned_control_bytes`。通常首次读取会采用压缩头的计数器，并把控制标志按位或入头部标志；`initial_probe` 返回该结果。若控制位 `0x0002` 置位，首次无辅助参数的探测路径改为初始化空头：计数器为零、头部标志为 2。这只描述首次探测分支，不能把它当成后续完整加载必然使用的状态。控制头截断或普通头长度不足时不会提供已确认的首次读取结果。除列出的字段和读入规则外，文件头其他内容仍保留为原始数据。

`Document::native_input_containers()` 返回文件中已有流的 `P3D-SSYS`、`P3D-SMC`、`P3D-SMG` 容器，各容器独立求值。结果的 `scope: container_input_if_opened` 表示以该容器被打开为前提，不决定模型加载顺序、运行时注册、活动目录或可见性。容器路径和流名通过文件索引解析；相同编号在不同容器中分别处理。

原生块头占原始流的前 16 字节。第一个解码字节为源字节异或 `0x26`，后续各字节为当前源字节异或前一个源字节。解码后的布局为：

| 偏移 | 字段 | 输入规则 |
| --- | --- | --- |
| 0 | u32 `record_capacity_hint` | 分配记录容量的提示值；为零则跳过块内记录，非零时读取至记录读取器停止，不按该值截断 |
| 4 | u32 `control_flags` | 位 0 为 `stop_after_block`；其余位保留在 `unassigned_control_bits` |
| 8 | 8 字节 `unassigned_tail` | 原样保留解码值，尚不赋予业务含义 |

`decoded_header` 保留全部解码后的头字节，原始编码仍在 `streams()[stream_index].raw`。当分配实际发生时，有符号容量值不大于零会改用列表默认容量；此条件以 `capacity_uses_list_default` 表示，但零值跳过记录，因此自身不会触发分配。最后一块还可能采用列表最小容量，接口不把提示值宣称为最终分配量。

`blocks` 按源流顺序保留，`input_order` 按 `$1`、`$2`、… 的逻辑编号提供 `block_number`、`logical_name` 和指向 `blocks` 的 `block_index`。不能按 CFB 流名排序或跳过编号缺口。遇到终止标志、缺失别名、缺失流或无效块头后停止；`stop` 记录原因，后续流的 `reachability` 保持 `not_reached`。块头不足 16 字节的返回码为 `0x14007`；完整块头的位 0 置位时返回 `0x12003`，否则返回零。这些是块读取器的控制码，不是整个文件 API 的返回码。

每块的 `record_input` 独立描述以该块被读取为前提的记录输入。`roots` 只包含完整成功的根记录及其 `input_tree`；子树中的后代不会再成为独立根。计数器在每块从零开始，具体过滤与子树计数规则见后文。容量为零时状态为 `skipped`。后续根读取失败时状态为 `read_error`，保留先前成功的根和 `failed_input_tree`，不发布失败根的部分子树。块内读取错误不会覆盖块头的继续标志，因此不能据此直接判定后续块不可达。

记录载荷当前支持原始头之后的压缩块（`compression_offset == 24`）及只有 16 字节头的空块；其他封装的记录输入标为 `unresolved`。`record_input.status: resolved` 仅表示该记录载荷的子树输入已解析。运行时标志与 ID 调整仍未在此接口求值，明确标记 `runtime_registration: not_evaluated`，不能把 `reachability: reached` 或成功根直接当成最终活动对象。

### 空列表的输入准备

容器的 `list_preparation` 在 `input_order` 上进一步应用文件加载路径的列表准备规则。其 `scope: empty_list_before_runtime_registration` 限定初始列表为空，不能用来模拟向既有场景追加或导入对象。

系统容器需要先遇到类型 46、子类型 8 且未带 `0x0008` 的完整根记录。之前的其他根及其整棵子树列入 `skipped_roots`，不进入准备结果；找到的根记录通过 `bootstrap_root_record_index` 返回。此状态跨输入块保持，缺少初始化记录时 `system_bootstrap_found` 为 `false`。其他两类模型容器不应用这条系统初始化条件。

`list_preparation.roots` 保留通过初始化条件的根，每项的 `headers` 按前序给出根及其后代的头部准备结果，`native_record_index`、`parent_record_index` 指向原始记录。`input_*` 是类型 13／24 等输入转换之后、列表准备之前的值；`output_*` 是列表准备后的值，均不改写源字节。

文件加载调用先运行头部校验，再继续处理其返回的错误，因此 `validation.return_code_ignored_by_file_loader` 为 `true`。不得把其中非零 `return_code` 当作该根被丢弃的依据：

| 条件 | 头部校验返回码 | 基础字数处理 |
| --- | --- | --- |
| 类型为零 | `0x11002` | 提前返回，不调整 |
| 转换后的记录字数大于 65535 | `0x11015` | 提前返回，不调整 |
| 总记录字节数小于类型要求的最小值 | `0x11016` | 先增大不足的基础字数，再返回 |
| 总记录字数小于调整后的基础字数 | `0x11017` | 保留调整结果 |

这些规则不同于更早的记录读取过滤；已在读取入口被跳过或导致读取停止的记录不会重新出现于准备结果。`minimum_base_bytes` 按类型、子类型及扩展头的维度位选择，单位为字节；`output_base_word_count` 单位为两字节字。库保留原有较大基础长度。系统容器和类型 54 不要求匹配模型维度；其他扩展头需要模型状态时，`dimension_match: requires_model_context`，`return_code` 为 `null`，但已确认的长度和标志转换仍可读取。

准备过程清除 `0x0008`，为类型 10 至 32 设置 `0x0040`，为类型 33 至 63 清除该位；其他类型保留该位。实际后代设置 `0x0080`，根清除该位。复合记录的 `descendant_count_update` 按已接受后代重新计数，排除读取时跳过的记录；计数字段位于不含流前缀的普通头偏移 32 或扩展头偏移 104。写入位置超出转换后记录长度时，`written` 为 `false` 并清除复合位，保留来源关系供检查。数值按原生有符号正值条件写入，非正值写零。

`status: partial` 表示部分头部或输入载荷尚不能准备；不明载荷可能改变列表初始化状态，因而不会继续推定后续根。`headers` 不表示完整业务载荷已经转换，也不执行 ID 分配、重复 ID 处理或运行时注册。最终活动材质表和块选择仍不能只凭此结果确定。

### 系统输入的 ID 分配

`Document::native_input_containers()` 的系统容器另提供 `system_id_assignments`。其作用域为 `first_system_input_with_empty_id_registry`：采用普通文件头读入的计数器、从空系统 ID 索引开始，并按已准备根的输入顺序求值。它不执行运行时回调，不推定模型加载顺序，不用于追加到既有对象索引，也不替代最终材质或块引用解析。空头探测分支或不完整文件头会返回 `unresolved`，不会用零计数器冒充正常加载状态。

每个根的处理分两遍。第一遍按前序处理根和全部后代：零源 ID 先递增计数器再赋值；非零源 ID 原样保留，并把计数器提高到二者较大值。第二遍才注册这些准备后的 ID：若非零 ID 已被先前记录占用，递增计数器作为新 ID，并重新检查。因此不能把两遍合并成逐节点“分配后立即注册”。

`roots[].records` 保留 `native_record_index`、`parent_record_index`、`source_id`、`prepared_id`、`assigned_id`。`collisions` 列出遇到的冲突 ID 及占用它的源记录下标。`registry` 是此限定过程产生的非零 ID 索引，按 ID 排序，不能用其顺序代替原始输入顺序。根上的三个计数器字段分别表示处理前、整棵子树准备后、注册后的状态；外层提供初始和最终计数器。

每次输入还分配独立的 `input_occurrence_index`；索引项同时保留 `block_number`，冲突项保留先前占用者的输入序号。如果不同逻辑块重复指向同一个源流，源记录下标可以相同，但这两次输入不会因来源相同而被合并。

计算保持 uint64 回绕行为。递增溢出产生零时，该节点的 `registration_status` 为 `unindexed_zero_id`，不进入 ID 索引；原生注册返回码为 1，调用方仍继续。成功注册的状态为 `registered`，返回码为零。这些状态仅针对上述限定的 ID 索引过程；源 `native_records()[].id` 不会被改写。运行时回调、旧对象替换和后续模型输入仍标为未求值；`status: resolved` 不表示整个系统对象注册或最终活动选择已经完成。

### 系统初次输入的材质表

系统容器的 `initial_material_table` 求值普通文件初次输入到空系统列表时的材质表选择。`status` 为 `selected`、`absent` 或 `unresolved`。选择沿逻辑块输入后的根记录顺序进行，取首个类型 10、子类型 18 的根；初始化标记之前被拒绝的表、跳过的记录以及嵌套表不会参与根表选择。源记录标志与运行时对象标志是两个不同字段，不能直接将源标志套入运行时过滤掩码。

`selected` 时，`table` 给出 `native_record_index`、`root_input_index`、`block_number`、`input_occurrence_index`、`source_id` 和 `assigned_id`；`members` 按载入顺序给出接受的直接成员及其输入身份。重复 ID 使用注册后的结果，不按源 ID 合并。不同逻辑块重复指向同一物理流时，输入序号仍区分各次载入。未确定的列表准备或 ID 分配返回 `unresolved`，不会据此宣称没有材质表。

此结果限定于系统初次输入，提供已选择的表和成员；后续宿主操作、外部资源上下文、名称查找及最终材质覆盖不在此结果中。用 `native_record_index` 可关联 `materials().native_catalog_tables` 与 `native_catalog_records`，无需另建合并目录。

### 系统初次输入的属性挂接

系统容器的 `initial_attribute_input` 按 `P3D-SSYSA` 属性存储、`P3D~MPH` 主头及逻辑 `$1`、`$2` 等块求值。主头的第二个 uint32 是块数；属性块头解码后的第一个 uint32 是记录数。该路径不使用原生元素块的容量提示和末块标志规则；单个物理块缺失或记录头损坏不会取消后续块的读取。

`attachments` 给出已挂接集合，每项的 `target` 包含分配后的 `id`、`native_record_index`、`input_occurrence_index` 和原生 `block_number`。定位对象使用 `system_id_assignments.registry`，属性记录与对象的块号不同仍可挂接。属性来源以 `stream`、`offset` 和 `record_ordinal` 标识；`attributes` 保留源读取顺序、字段、载荷及通用解码结果。`trailer_bit_0` 保留读入集合的尾标志，未赋予业务名称。

每个集合的 `lookup` 提供初次加载后的精确键查找：`sorted_source_ordinals` 是排序后的源条目序号；`keys` 按组合键 `(key << 16) | group` 和 `index` 的无符号顺序分组，每组给出 `matching_source_ordinals` 和 `selected_source_ordinal`。查找比较不使用源序号、载荷或尾标志。集合总条目数不超过 5 时反向查找，超过 5 时取排序后的首个匹配项。排序遵循原生的插入、分区及堆回退规则；同键条目的原始相对顺序不保证保留，不能统一用“第一条”或“最后一条”代替。该视图求值精确组合键和索引，不表示通配枚举接口或后续宿主对属性集合的修改。

已选材质表成员的 `material_attribute` 沿输入身份引用挂接集合中组 0、键 20014、索引 0 的实际选中条目。`selected` 时使用 `attachment_index` 和 `source_ordinal` 定位 `initial_attribute_input.attachments[].attributes[]`；`absent` 表示该次输入没有可用集合或对应键，`unresolved` 表示输入或查找前提不足。属性被选中不代表其载荷是有效材质定义，材质内容解码及资源目录登记仍需分别判断。

`blocks[].records` 记录每一步的读取动作。属性计数为零时读取尾字但不创建集合；非零计数创建集合，条目循环采用计数的低 16 位。对象已有集合时返回失败且不消费正文，外层继续按声明记录数读取，因此下一次记录头可能落在该正文中。未找到 ID 时从 24 字节记录头后跳过声明长度，不能用源解析器的完整记录长度替代。读取到的记录标志不参与这一挂接筛选。

总体 `status: resolved` 表示上述输入过程已确定，仍需查看各块的 `completed`、`stopped`、`not_loaded` 状态和未消费字节。`absent` 表示没有对应属性存储，`not_loaded` 表示未能读取主头，`partial` 保留已确定的挂接并在不确定点停止，`unresolved` 表示前提不足。缺少逻辑别名可能触发原生索引新增名称，本库不猜测该名称；不完整正文、未确认的包装或不完整 ID 分配也不会被当成正常空集合。结果限定于初次系统输入，不包含后续宿主修改、属性处理器执行和最终材质覆盖。

### 材质目录初次登记

`Document::native_material_catalog(options)` 在每个系统容器已选表和实际属性选择的基础上，求值该表向空材质目录的登记过程。它按直接成员输入顺序读取名称、资源描述和组 0／键 20014／索引 0 的属性；不以成员的源元素类型是否为 49 作为额外登记条件。名称或资源读取失败、缺少该属性时跳过当前成员。未确定的读取或资源事实会停止后续登记，返回 `partial`，避免未知的前项改变后续去重结果。

登记先查同名资源：非空目录名称按所选字符串比较规则比较，还要求主上下文相等、`descriptor_mode` 相同、资源成员名相等；第二上下文不参与此判定。随后才查相同 ID 和 ID 索引上下文键。零 ID 参与查重，`UINT64_MAX` 跳过 ID 查重但仍参与名称与资源查重；空名称跳过名称查重但仍参与 ID 查重。重复项返回拒绝，已有条目不被替换。该过程执行原生的目录复用规则，不改写源记录或合并几何。

`entries` 为接受顺序，保留输入身份、分配后 ID、名称、资源描述和实际选中属性。`input` 中的 `action` 为 `registered`、`rejected_duplicate_name_resource`、`rejected_duplicate_id_context`、读取失败或属性缺失对应的跳过动作，以及 `unresolved`。拒绝项给出 `existing_entry_index`；`unvisited_member_count` 表示因不确定而尚未求值的成员数。`absent` 和 `unresolved` 分别表示没有表和不能确定选表。

作用域是 `single_system_table_with_empty_material_catalog`。默认 `string_comparison: crt_c_locale`，调用方可提供其他区域设置的比较函数；这一选择不宣称原建模进程必然采用 C 区域设置。当前资源上下文可以保持符号身份，比较外部上下文时需提供确定的索引键与比较键。接口不搜索文件，不把缺失的外部信息解释为查找失败，也不模拟其他提供者已加载的目录、运行时缓存或最终图元材质覆盖。

### 材质附加属性

材质对象读取器在 XML、名称和资源描述读取成功后，还请求组 0／键 20091／索引 0 和组 0／键 22906／索引 0。前者解压后复制为附加缓冲；本库以 `material_auxiliary_buffer` 暴露，其内容用途尚未确认。后者以 `material_auxiliary_records` 暴露，解压后的记录没有集合计数，读取器按每条记录开头的 32 位字节数前进，直至缓冲末尾。

记录偏移 4 的 32 位值为版本。版本 2 的头长为 64 字节，其后是变长载荷。原生集合键由偏移 19 的无符号字节与偏移 16 的无符号 16 位值组成，先比较前者，再比较后者。相同键的后项会重置并替换前项，包括用空载荷替换非空载荷；其他版本不登记，按记录长度跳过。此处的替换规则与材质目录登记时拒绝重复项的规则不同。

`records` 保留源顺序和替换关系，`selected_record_indices` 是当前有效记录的键顺序。原生复制的其他字段暂列于 `unassigned_fields`，不赋予未经确认的名称或单位；64 字节原始头保留在 `header`，因此非有限浮点数的位模式也不会丢失。头内偏移 22 的 16 位值及偏移 44 至 63 的字节未被此读取器使用，单列为 `ignored_header_fields`，不要求它们全为零。长度为零、读取头截断、版本 2 头长不足或载荷越界时，库返回 `partial` 和未消费长度，保留已确定的结果及完整解压数据。其他版本只读 8 字节前缀，其长度跳过缓冲末尾时直接结束输入；`native_cursor` 保留该逻辑位置，`consumed_bytes` 不超过实际缓冲长度。记录结构和键处理已解析，不表示变长载荷及所有头字段的用途均已确认。

## 显式多边形网格通道

图形命令 25 分别保存顶点、法线、UV 数组，以及三组有符号的角点索引。头部 `num_per_face` 大于 1 时，索引按固定宽度分组，各组遇零结束有效角点；其余槽保持在源索引数组中。值为 0 或 1 时，零索引分隔多边形。非零索引取绝对值后减一访问对应数组，法线索引的负号不翻转法线方向。可选索引数组为空时不自动使用顶点索引。

第三组参数索引可以用于 UV、颜色或同时用于两者。`param_index_usage` 为 `uv`、`color`、`uv_and_color`、`unused` 或 `no_indices`，描述原生读取器依据池是否存在而选择的用途，索引合法性仍由各通道检查。没有 UV 池时，不以空 UV 数组验证参数索引，也不生成 `face_uvs` 或 `face_uv_indices`；索引继续保留在源数组及源多边形的 `uv_indices` 中，供颜色通道读取。两种池均缺失时，非空参数索引标为 `unused`，不进行无效查表。角点数量与分隔槽的一致性检查仍然保留。

`index_bindings.normal_indices` 和 `index_bindings.uv_indices` 分别描述可选索引的范围检查。`status` 为 `no_indices`（无索引）、`pool_absent`（无对应数组）、`mapped`（索引在范围内）或 `invalid_indices`（存在越界索引）；`unavailable_read_positions` 给出越界项在源索引数组中的零基位置，包含分隔槽占用的位置。源数组缺失时不执行查表，原索引仍保留。`mapped` 只表示索引范围有效，不保证法线变换或最终外观可求值。

可选法线或 UV 索引越界时，库保留源值、有效顶点拓扑及其他通道，仅将受影响三角形的对应索引条目置空，并在 `Geometry::unknown` 中记录通道及源位置。一个参数索引可能对 UV 越界、对颜色仍有效，两者独立判断。点索引越界、非空索引数组数量不一致、零分隔槽不匹配仍属于解码错误，不套用可选通道的恢复方式。

第二个头字段 `reported_point_index_count` 为保存的点索引总数，包含分隔槽；`point_index_count_matches_header` 表明它与实际数组数量是否一致。`flags`、`reported_indices` 保留为兼容别名，其中 `flags` 的旧名称不代表它是位标志。

三角化沿用源多边形角点对应关系，`Geometry::face_normal_indices` 和 `face_uv_indices` 分别引用独立的法线与 UV 数组，不要求它们与 `faces` 中的顶点索引相等。源数组按原顺序保存，包括重复值和未使用项；多个命令合并只调整数组基址，不增加源文件不存在的共享关系。

`normals` 是应用当前几何变换后的逆转置结果，保持非单位长度；`source_normals` 保留命令局部的原始值。不可逆或不可表示的法线变换返回空项，索引不被删除。镜像改变三角形绕序时，顶点、法线和 UV 的角点顺序同步交换，法线不再额外乘以行列式符号。UV 数值不随空间变换改变。

UV 数组之后的 `mesh_channels` 按下表读取，各字段均以 u32 数量开头：

| 字段 | 每项编码 | 含义 |
| --- | --- | --- |
| `float_colors` | 3 × float32 | 原生 FloatRgb 数组，值不作截断或颜色空间转换 |
| `color_indices` | int32 | 独立保存的有符号颜色索引 |
| `illumination_name` | UTF-16 单元 | 原生命名字符串；非空指针的数量包含末尾 NUL，数量 0 表示未保存字符串 |
| `face_uv_points` | 2 × float64 | 附加逐面角点 UV |
| `face_smoothing_groups` | int32 | 逐面平滑组原值，不推定额外位含义 |
| `face_material_ids` | uint64 | 逐面材质标识列表，零值和完整 64 位值均保留 |

`fields` 提供相对于该扩展区的偏移、数量、步长及状态。后三个字段允许在边界处省略，标记为 `omitted`；截断的计数或负载标记为 `truncated_count`、`truncated_payload`，后续字段不再猜位置。`raw_hex` 始终保留整个扩展区，`remaining_hex` 保存已消费位置之后的字节。未知后缀、未终止或无法转换为 UTF-8 的名称使整体状态为 `partial`；截断使其为 `invalid`，已完整读取的前缀仍可访问。名称原始单元单独保存在 `illumination_name_utf16_hex`，首次 NUL 之后的内容也不丢弃。

`illumination_texture` 解释名称的纹理资源引用语义，`reader_profile` 为 `bimbase_2025_poly_export_texture_lookup`。该原生回调对空指针及精确字符串 `~` 直接返回无纹理，其余名称进入资源查找，并使用 `P3d_Pattern` 搜索路径设置。库分别返回 `absent`、`disabled_sentinel` 和 `lookup_requested`；未完整读取、未终止或编码损坏的名称返回 `unavailable_name`。保存了 NUL 的空字符串与未保存名称不同；首个 NUL 后的单元只保留源值，不参与名称判断。

`lookup_requested` 时，`reference` 提供 `filename`、`reference_kind: mesh_illumination`、`source_field` 和 `search_path_setting`。名称保持原样，不去空白、展开目录、猜测扩展名或按材质名称匹配。资源可能仍需调用方的上下文与搜索路径才能获取；此接口不查找或加载图片。`scope: lookup_if_invoked` 表明这是回调被调用时的选择规则，不保证所有绘制路径都会调用它。`runtime_texture_id_serialized: false` 表明命令 25 未保存该运行时纹理句柄，不能把它与逐面材质 ID 混同。后续扩展损坏不会抹去已完整读取的名称引用。

`bindings` 区分原始保存方式与已确认的读取器行为，`reader_profile` 为 `bimbase_2025_command25`。这一路原生读取器跳过独立的 `color_indices`，在 FloatRgb 数组存在时实际采用第三组参数索引；`color_index_source` 因此为 `param_index_array`。源颜色索引仍原样返回，库不擅自替换这一路读取器的选择。范围不合法的颜色引用标记为 `invalid_reader_indices`，不会越界查表。

零分隔布局中，附加逐面通道按非空源面的顺序对应，空分隔段不消耗条目。`face_uv_points` 必须与这些面所有角点总数相等，按面、角点顺序连续分配，不使用顶点索引；平滑组和材质列表按非空面数检查。数量不符时保留数组并报告 `count_mismatch`。固定宽度布局若带零填充，且其非空面与零分隔读取结果逐角点一致，也支持这些对应；否则标记为 `not_evaluated_for_fixed_width`。`bindings.polygons` 以源多边形序号定位已确认的对应；没有可用对应时为空数组，不分配逐面空对象。

几何图元范围的 `mesh_channels.source` 保留上述数据；`triangles` 与该范围的三角形等长，每项提供 `source_polygon`、`source_corners`、颜色和附加 UV 的源池索引，以及可空的材质标识和平滑组。`source_material_index` 是绑定到源 `face_material_ids` 的零基下标，无法对应时为空，源重复 ID 的下标仍不同。三角化和镜像保持角点对应，合并实例只调整图元范围的位置，不去重源池。此信息不覆盖普通 `face_uvs` 或范围样式，也不等于完成最终材质继承、目录查找或平滑法线生成。

场景访问时，`PrimitiveView::mesh_material_references` 按此源列表逐项给出 ID、状态及材质定义候选索引；`expanded()` 的图元范围提供同名 JSON 数组。解析按实例所属模型作用域查找，无本地候选时查全局；歧义不回退，零 ID 不查表，缺失引用不被删除。源列表数量不符或有多余项时，仍解析这些条目的定义引用，不因此伪造逐面对应。同一源几何的不同模型实例可以得到不同候选。

### 原生三角化输入选择

`mesh_channels.native_triangulation` 描述 `bimbase_2025_triangulate2` 路径的输入选择；`evaluation` 为 `input_routing_only`，不表示已运行原生三角化或生成最终外观。该路径只收集非空、以零结束的面，不使用固定宽度头字段，末尾未终止的角点数由 `ignored_unterminated_corner_count` 给出。

该路径要求逐面材质列表非空、存在已终止的面，并且附加 UV 数量等于这些面的总角点数。满足条件时使用 `face_uv_points`，法线由三角形及平滑组生成，不使用普通 UV 池或显式法线池。不满足时，`status` 分别为 `no_face_materials`、`no_terminated_faces`、`face_uv_count_mismatch`；扩展不完整时为 `unavailable_extension`。这些状态只描述该路径，不能据此删除其他路径能够重建的源几何。

该实现复制的材质项数来自**平滑组数量**，随后将复制结果调整为面数：不足补零，多余截去。`requested_material_copy_count`、`copied_material_count`、`unused_source_material_count`、`discarded_copied_material_count` 和 `zero_padded_material_count` 记录各个数量。复制数量超过保存的材质列表时，库返回 `unsafe_material_copy`，不执行越界读取。原生面点查找直接使用减一后的有符号索引，遇负索引时返回 `unsafe_signed_point_lookup`，不把普通几何的绝对值查表规则套到该路径。

只有平滑组数量等于面数且至少一个组号大于零时，`normal_mode` 才是 `smoothing_groups`；否则为 `flat_triangles`。启用分组后，零组仍使用平面法线，其他组按完整的有符号整数相等匹配，包含负组号。同组按位置逐分量容差 `1e-7` 收集顶点，累加单位三角形法线后再单位化，不按材质或 UV 分组。零模长使用原生 `(1, 0, 0)` 回退。位置匹配采用独立的有序索引，保持输入次序及容差比较，不对源顶点作合并，也不将近点关系扩展为传递闭包。

路由可用且源面布局吻合时，几何范围的 `mesh_channels.normal_evaluation` 提供法线计算状态。`status: computed` 表示已对库生成的三角形应用上述法线算法；`triangle_input: library_triangulation` 和 `native_glu_triangulation: not_evaluated` 明确区分法线算法与厂商 GLU 三角化。多边形三角化差异可能影响结果，不能据此宣称厂商完整三角化路径已复现。

每个 `triangles[j].native_triangulation` 提供三个 `source_corner_normals` 和 `corner_normals`：前者为命令局部坐标中的派生值，后者已随几何和实例作逆转置变换，不再次单位化。镜像时两组值均跟随三角形角点交换。奇异变换或不可表示的变换结果使对应 `corner_normals` 项为空，局部值仍保留；算术失败则通过 `normal_evaluation.status: invalid` 报告，不发布部分计算值。派生法线不覆盖源显式法线池、索引或图元样式。

`triangulate_native_mesh()` 执行这条原生路径中的 GLU 三角化及后续索引网格导出。每个非空源面独立作为一个轮廓，奇偶填充规则、边界模式关闭、容差参数 `1e-6`，法向由三角化器自动选择。边界回调使输出固定为独立三角形。源逐面 UV 在输入阶段由双精度转单精度，新交点的 UV 置零；结果的 `source_corner: null`、`generated: true` 区分这些派生角点。原始源面和源 UV 不被改写。

`triangles` 保存注册前的角点及面属性，`buffers` 则提供注册后的 `points`、`normals`、`uvs`、`faces` 和 `face_material_ids`。两种法线模式采用各自的原生复用规则：

- 平滑模式先分别注册双精度位置与 UV，逐分量容差分别为 `1e-7`、`1e-6`。三角形法线使用注册后的代表位置；按平滑组累加的角点法线再进入独立的双精度法线表，容差为 `1e-7`。最终以位置、法线、UV 三个注册索引组成精确匹配的顶点键，再按首次插入顺序导出单精度数组。浮点导出后数值相同的不同顶点键仍分别保留。
- 非平滑模式从注册前的双精度角点计算单位三角形法线，将位置、法线和 UV 转为八个单精度分量，以单精度 `1e-6f` 容差整体注册，按首次插入顺序导出。它不先执行平滑模式的位置合并。

容差匹配保留有序树查找与插入顺序，既不使用网格量化，也不对近点关系求传递闭包。各个缓冲的顶点索引对齐；完整 64 位材质 ID 按面单独导出，不参与任何顶点键。因此不同材质的面仍可共享顶点，UV 或法线不同的角点则可分开。这些表只属于该消费路径的派生输出，不改变源数据或其他定义的共享关系。

此接口使用内置 SGI GLU 三角化器，不依赖系统绘图环境。它不自动替换普通 `Geometry` 三角化结果，也不承诺与任意版本系统 GLU 在所有数值边界上逐字节相同；材质与外观的最终绑定仍需单独处理。

输入选择可有界解析时，`status` 为 `mapped`，`polygons` 提供所选 `material_id`、`source_material_index` 和 `normal_group`。补零材质的源索引为空；平面法线的组键为空。仅当原生面与源多边形布局吻合时才填写 `source_polygon`，并把该项传递到范围内各三角形的 `native_triangulation`。原始 `bindings` 及其材质标识不被改写。这仍不是逐面材质与范围样式、部件目录、视图规则之间的最终覆盖结果。

## 属性与二进制叶

DEX 对象包含类 ID、对象 ID、字符串表、属性树及源位置。树中的二进制叶继续保存原字节，并按字段名、根对象类型及必要上下文选择解码器。

解码结果可能是设计参数、嵌套属性、缓存几何、内嵌材质、BGFB、二进制 JSON、NBFX XML 或其他复合结构。`binary_fields()` 提供对象来源及叶路径，便于定位尚未确定的内容。

参数化构件载荷中的 `geometry_packets[].geometry` 提供 BGFB 源几何描述。BIMBase / PKPM 在该封装中使用自己的联合类型编号：类型 20 为 `P3DSweptBody`，包含 `profile`、`path` 和 `capped`；类型 21 为 `P3DSectionLoft`，包含底截面 `section0`、顶截面 `section1`、嵌套的 `guide_groups` 和 `capped`。不能用公开 BGFB 模式中同编号的悬链线或局部曲线解释这两个类型，也不能按表长度猜测类型。导引组保留两级数组及源顺序。

BGFB 表省略的布尔字段按默认值 `false` 返回，`_present_fields` 区分显式保存和省略的字段；未保存的引用返回 null。扩展表中的额外字段槽由 `_unknown_field_slots` 列出，完整原始几何包仍保留。字段必须完整落在所属表内，嵌套数组也检查计数、偏移与源缓冲区范围。源参数化描述的读取不自动执行布尔运算或替代场景接口使用的图形缓存。

`SectionLoft` 可显式将源放样重建为 B 样条侧面。两个截面的源边界类型和直接成员数量必须匹配：Open 需要 N+1 条导引，Outer/Inner 需要 N 条；奇偶区域先对应外环，再按源顺序对应内环及导引组。所有导引先统一次数和节点，各片侧面再处理对应的两条截面边界。三控制点边界的额外升阶发生在截面节点兼容处理之前，不能在合并节点后重新判断。控制点数量决定原生分段混合系数，提前展开成完整 Bézier 段可能改变曲面。

开放 B 样条在有效节点域归一化后参与构造。升阶使每组节点重数增加次数差，保持连续阶数；按节点左侧的齐次多项式及新节点的对称函数计算控制点，源控制点不改写。已归一化曲线的节点容差为 `max(1e-14, 1e-10 / max(1, L))`，L 为去齐次控制多边形长度；一组兼容曲线取其中最小容差。对应节点组及重数已匹配时，只将组值取平均，控制点不变；其他情况按相邻节点差聚合、取平均，并按最大重数插入节点。内部重数不统一扩大到完整 Bézier 重数。

原生放样与裁剪使用不同的曲线转换入口。放样对线段、折线和圆锥曲线专门转换，对源 B 样条取得其保存的曲线对象；Akima、InterpolationCurve 和 TransitionSpiral 在该入口返回空对象。即使这些类型可以生成用于求值或裁剪的拟合 B 样条，也不能据此认定原生放样会使用该拟合结果。

放样中的周期 B 样条请求在节点参数零处打开，而不是将比例参数零代入源节点域。普通打开对局部 K 个齐次控制点执行循环节点插入，再按源节点位置移动控制点和权重、拼接一周节点并归一化；K 为阶数。接缝原重数为 m 时新增 K−m 个控制点，内部节点重数不变。不重新生成源外围节点，也不把整个曲线先展开为两周。特殊闭合表示若满足原生节点布局及端点检查，则从前方去掉 `floor(K/2)` 个外围节点，从后方去掉 `K−1−floor(K/2)` 个外围节点，N 个源控制点及权重保持不变。原生特殊端点检查按存储的加权 XYZ 逐分量比较，容差为 `min(1, R×1e-5)`；R 来自去齐次控制点的最大轴向跨度，计算该跨度时忽略绝对值不大于 `1e-12` 的权重。有理首末权重差还须严格小于 `1e-10`。此检查不等于原始截面的首尾闭合检查。

周期打开的节点容差先取“有效节点域长度 × `1e-10 / max(1, 去齐次控制多边形长度)`”。顺序检查有效域中的相邻节点差；差值严格大于 `1e-5` 且严格小于当前容差时，将容差改为该差值的十分之一，最后取不小于 `1e-14`。查找从请求参数零开始：节点与当前参数之差不大于容差时，当前参数更新为该源节点值并累计重数；已匹配后遇到超出容差的节点即停止。已有节点值不合并或覆盖，新增节点使用最后匹配的值。后续循环起点查找仍相对于请求参数零，不相对于吸附后的值。

通用打开组装节点后，按新的有效节点域归一化，并显式将最后 K 个节点设为 1；前端外围节点不作相同的夹持填充。因此，同一容差组中存在多个不同源节点时，结果可能仍具有非夹持的前端。此情况不能通过擅自把前 K 个节点清零来处理。有效域长度小于 `1e-10` 时，原生此归一化步骤不执行；当前侧面构造明确拒绝该分支。

特殊闭合布局的端点检查失败时，使用通用循环打开，而不是仍按特殊布局保持控制点不变。若零处已经精确具有 K 重节点，则不新增控制点；按 `floor(K/2)` 左移控制点和权重，节点提取范围与特殊直接打开相同。其他情况先执行上述容差查找及局部插入。该原生回退不是首尾吸附或形状修复，也不保证与源曲线采用特殊周期索引求值的结果一致。

同一组导引的直接成员数不同时，原生按控制多边形长度连接，并根据转换前源曲线的首尾决定是否尝试关闭。B 样条的源首尾分别取比例参数 0 和 1，不能用打开后的节点零接缝替代。关闭检查先要求首末权重差严格小于 `1e-10`，再对存储的加权 XYZ 使用 `D < M×1e-8 + 1e-8`；D 是端点差的最大绝对分量，M 是端点坐标的最大绝对值。检查失败保留开放曲线，后续仍参与导引兼容。二阶两控制点曲线直接保持原样；其他二阶闭合曲线去掉末控制点、补齐周期外围节点，重新打开时末点取自源首控制点。

高阶关闭先尝试解除两端夹持，按节点比例反解端部齐次控制点，再检查前后 K−1 个重叠控制点；控制点数须至少为 2K−1。重叠 XYZ 的距离不得大于 `1e-10×max(0, 所有变换后加权坐标分量)`，有理权重使用有方向的“前权重减后权重不大于 `1e-10`”检查。成功时保留前 N−K+1 个控制点及完整节点数组，形成普通周期表示。失败时恢复原开放控制点，用其节点构造 N+2K−1 个特殊闭合节点，再按特殊打开规则处理。这些步骤不会按形状重新拟合或建立额外源共享关系。

BGFB 联合类型 3 的 `BsplineCurve` 按 `order`、`closed`、`poles`、`weights`、`knots` 读取。`order` 是次数加一，`poles` 每三个 double 表达一个控制点；有理曲线的 XYZ 是已乘权重的齐次分子，权重单独保存。设控制点数为 N、阶数为 K，开放曲线节点数为 N+K，闭合曲线为 N+2K−1，有效参数区间是 `knots[K−1]` 至 `knots[节点数−K]`。空节点数组与省略节点均触发原生均匀节点生成；源字段保持原值，生成结果只由求值对象的 `knots()` 提供。

闭合曲线按 N 对控制点索引取模。若 `knots[K−1]` 精确为零，以该位置为中心的近零节点连续段恰好有 K 个，右侧恰好有 `floor(K/2)` 个，则 `point_at()` 的求值索引还要回移 `floor(K/2)`；近零判断为绝对值不大于 `1e-7`。此特殊接缝规则只改变求值索引，不旋转或复制源控制点数组。`_spline` 显式记录相关语义和数组检查结果，`BsplineCurve` 提供开放、闭合及有理曲线求值，包括内部全重节点形成的不连续位置。

原生导数查询另行调用带控制点和权重检查的特殊节点判定，使用与周期打开相同的首尾检查规则；仅节点排列符合时并不足以启用索引回移。`native_derivatives_at()` 按此路径将比例 f 映射为源节点参数 `u=a+(b−a)f`，开放曲线夹到 `[a,b]`，闭合曲线对严格越界参数作周期归约。内部重复节点选右侧非空区间，精确末端选左侧。

导数查询使用源节点容差进行递推分母检查，分母小于容差时失败，相等时允许。该容差按有效节点域长度、去齐次控制多边形长度和节点间距计算，与上述周期打开的容差公式相同。有理容差查询的去权重及重新加权作用于工作副本，原始数据不变。齐次多项式导数超过次数后为零，但笛卡尔导数按商法则继续递推：`C[n]=(H[n]−Σ binomial(n,j) W[j] C[n−j])/W[0]`，求和 j 从 1 到 n。因此不能把高阶有理导数直接清零。结果针对源节点参数 u，原生调用没有再乘 `(b−a)^n`。

单条 B 样条的原生 Frenet 参考系先请求三阶齐次导数，有理位置及一、二阶导数由展开的商法则计算。以一阶导数归一化为 T，二阶导数长度和一、二阶导数叉积长度均须不小于 `1e-5`；阶数还须至少为 3，曲率 `|D1×D2|/|D1|³` 不小于 `1e-12`，才保留导数给出的 N、B。这里的导数长度检查是针对源节点参数的绝对阈值，不可替换为相对夹角或单独的曲率检查。

上述条件不满足时，原生以去齐次控制点的源顺序计算闭合控制多边形法向，包含末点到首点的一条边。未归一化法向的长度小于 `1e-5` 时改用参考轴：归一化切向的 X、Y 绝对值都严格小于 `0.01` 时选 Y 轴，否则选 Z 轴。随后 `N=normalize(参考方向×T)`、`B=T×N`。这条路径的向量归一化保留零向量；因此原生计算成功并不保证得到非退化基。`native_frame_at()` 分别报告方法与基的退化状态，保留矩阵，不将源控制多边形法向误当作实际曲面法向。

CurveVector 的参考系查询保留直接子项顺序。偏好 1、2 先收集首个成功子项的起点和起始单位切线 A，以及最后成功子项的终止单位切线 B。`|A×B|² <= (|A|²×1e-24)×|B|²` 时视为平行；不平行时以 A、B、A×B 建立矩阵，再保留第 0、2 列方向进行正交化。平行时只有偏好 1 采用 A 的参考轴三元组，偏好 2 继续局部搜索。这条首尾路径忽略矩阵正交化的失败返回值。嵌套 CurveVector 不提供父数组的首尾切线。

局部搜索先检查各子项比例 0 处的 D1、D2：须 `|D2| >= |D1|×1e-6`，且无向较小夹角 `atan2(|D2×D1|, abs(D2·D1)) >= 1e-8`，才尝试第 0、1 列正交化。失败时按 D1、D2、D3 的顺序选取首个长度不小于三者长度之和乘 `1e-15` 的方向，再依次检查后续子项。后续子项也须先取得有效导数方向，随后优先以两子项的起点位移构成平面，再尝试其导数方向，沿用上述相对长度和夹角阈值。长度之和为零时无有效方向。嵌套数组在到达它时递归执行默认局部搜索，不参与相邻子项的导数配对；所有局部搜索失败后，才按顺序查询直接子项的单曲线参考系。

上述首尾路径中的 B 样条点及切线使用独立混合函数递推，不使用高阶导数查询的节点容差和首尾控制点检查。比例参数映射为 `(1−f)a+fb`，包括闭合曲线在内均夹到节点域；特殊节点排列仅按节点本身决定循环索引偏移。有理求值中 W 为零时临时用 1 替代，随后按商法则求切线，再乘节点域长度；这不改变源权重，也不代表其他求值接口允许分母奇点。首尾方向归一化使用零向量改为 X 轴的规则，与单条 B 样条 Frenet 路径的零向量处理不同。

线段及点列的高阶导数回调将 D2、D3 清零；椭圆弧回调计算 D1、D2 并将 D3 清零。LineString 和 PointString 均能在此参考系查询路径提供点及切线，不应套用其他转换接口的忽略规则。点列最终参考系从起段查找不近重合的参考点，近重合阈值为 `距离平方 < (两点各坐标平方之和+1)×1e-20`，不预先删除源点。三个参考点建立的两向量长度须互相严格大于另一长度乘 `1e-12`，归一化向量叉积长度须严格大于 `1e-12`；未找到第三参考点时使用首个有效方向的参考轴三元组。零长度线段的最终参考系是平移后的单位矩阵，完全重合的点列则返回失败。

BGFB 联合类型 16 的 `InterpolationCurve` 保存 `fitPoints`、`order`、`closed`、`knots`、两端切线及四个整数选项。原生 BGFB 读取路径未传入表中的 `startTangent`、`endTangent`，转换入口也未使用保存的 `order` 和 `knots`，而是固定调用三次 C2 插值并重新计算节点。库保留完整源表，同时通过 `InterpolationCurve` 提供派生 B 样条；`_interpolation` 报告这一转换路径，不能把派生节点误认为源数组。

点准备按源顺序移除与最后保留点距离平方严格小于 `(1e-5)²` 的相邻近点，不全局去重，也不跳过 `DBL_MAX` 断开标记。若剩三点且首尾距离不大于 `1e-5`，去掉最后一点；若最终只有两点，距离须大于 `1e-5`，并强制为开放曲线。对于其余闭合输入，首尾距离大于 `1e-5` 时追加源首点，否则保留原末点、不吸附；追加或保留闭合点后恰为四点时仍转为开放表示。准备完成后最多 4998 点。源点索引、过滤原因和闭合追加状态均可查询。

设准备后的点数为 N。开放曲线总按累计弦长生成 `t[0]=0` 至 `t[N−1]=1` 的参数，具有 N+2 个控制点，节点为四个 0、`t[1]…t[N−2]`、四个 1。有效闭合曲线具有 N−1 个周期控制点，末点只作为闭合标记；`isChordLenKnots` 非零时采用弦长参数，否则采用均匀参数。内部节点向两端按周期 1 延伸，完整节点数为控制点数加 7。闭合标记参与弦长计算，但周期插值方程使用前 N−1 个点，参数 1 的位置为首点。

开放曲线的两点情形生成直线三次控制点。更多点时，`isNaturalTangents` 非零表示端部二阶导数为零；否则从端部三个点生成 Bessel 条件。以起端为例，令 `h0=t[1]−t[0]`、`h1=t[2]−t[1]`，导数为 `((2h0+h1)/(h0(h0+h1)))×(P1−P0) − (h0/(h1(h0+h1)))×(P2−P1)`，首控制柄是 `P0+h0×导数/3`；末端按反向点列对称计算。

自动 Bessel 条件下，准备点数至少四个、首尾距离严格小于 `1e-5` 且 `isColinearTangents` 非零时，再将两端控制柄沿 `首控制柄−末控制柄` 的单位方向对齐，各自到端点的长度保持不变；方向为零则保留零方向。自然端部条件和周期闭合条件不使用该修正。`isChordLenTangents` 仅作用于显式切线分支，因此在上述 BGFB 读取路径中不生效。开放方程用三对角系统、闭合方程用周期三对角系统求解，工作量与内存随点数线性增长，保留原生控制点数量和周期顺序。

BGFB 联合类型 17 为 `TransitionSpiral`。原生读取路径使用 `detail` 中的变换、活动区间 `fractionA/fractionB`、两端方位角、曲率及 `spiralType`，不使用 `constructionHint`、`extraData` 或 `directDetail`。工厂只创建类型 10 至 14。设方位角为 θ₀、θ₁，源曲率绝对值为 a、b；θ₁>θ₀ 时两个有效曲率均取正号，否则均取负号。长度 `L=abs((θ₁−θ₀)/((a+b)/2))`，方位角差不按整周归约；原生初始化要求 `(a+b)/2 >= abs(θ₁−θ₀)×1e-20`。零平均曲率产生不可定义的长度，本库明确拒绝；相同方位角和非零平均曲率产生零长度底层曲线。

对非零 L，令底层参数 `t=s/L`，有效曲率为 `k(t)=k₀+(k₁−k₀)g(t)`，方位角为 `θ(t)=θ₀+L×(k₀t+(k₁−k₀)G(t))`。五种函数如下，G 是从零起的积分：

| spiralType | g(t) | G(t) |
| --- | --- | --- |
| 10 | t | t²/2 |
| 11 | 3t²−2t³ | t³−t⁴/2 |
| 12，t≤1/2 | 2t² | 2t³/3 |
| 12，t>1/2 | 1−2(1−t)² | 1/2−(1−t)+2(1−t)³/3 |
| 13 | (1−cos(πt))/2 | t/2−sin(πt)/(2π) |
| 14 | t−sin(2πt)/(2π) | t²/2+(cos(2πt)−1)/(4π²) |

底层局部位置是 `L×∫₀ᵗ(cos θ(u), sin θ(u), 0)du`，经源 `DTransform3d` 得到三维位置。活动区间只改变比例参数映射，不重新放置原点，也不裁到 `[0,1]`。`TransitionSpiral::evaluate()` 采用自适应 Simpson 积分，以被积向量四阶导数界控制截断误差，并计入源 XY 仿射线性部分的放大；类型 12 在 1/2 分段，避免跨越分段导数。报告中的误差界不包括浮点和三角函数舍入。`native_fit()` 另行重建原生拟合 B 样条；单纯解码不执行拟合，`_spiral.native_bspline_conversion` 为 `not_evaluated`。

原生缓和曲线缓存的采样入口对区间 A 至 B 使用 `n=int(abs(θ(B)−θ(A))/0.04+0.9999999999)`，正奇数再加一，零改为一；按局部距离均分为 n 段，输出初点及各段终点。每段用四点 Gauss 分别计算整段积分 I₁ 和两个半段积分之和 I₂，以 `I₂+(I₂−I₁)/255` 累加坐标，并累加 `max(abs(Δx),abs(Δy))/255` 作为原生误差估计。此固定采样不自动增加跨分段点或按估计误差重新细分。

活动区间的采样以零向量起步，再单独按同一规则积分 0 至 A，将偏移加到所有点。端部方位角分别与首、末相邻采样点的前进弦方向做点积；负点积时方位角加 π。端部曲率为零时，传给拟合器的半径参数为 0，否则为曲率倒数；反向活动区间不额外翻转半径符号。源变换在拟合之后作用于控制点，`native_fit_input()` 因此返回局部采样点和约束。采样入口使用最多 2000 点的缓冲区，而后续拟合的点数加二不得超过 1000；两个限制独立保留。

拟合以局部 XY 累计弦长作为初始参数，在首末区间各加入一个辅助节点。两端一阶导数取 `(cos θ, sin θ)`，二阶导数取 `(-sin θ/r, cos θ/r)`，半径参数为零时二阶导数取零。每轮求解带端部条件的分段三次曲线，再以每段 20 个等长子区间的 Simpson 积分更新原采样点参数。最多迭代 30 次；每个原区间的弧长变化最大值严格小于初始总弦长的 `1e-6` 倍时结束。最终使用本轮更新前的拟合节点及端部导数，生成阶数 4、非有理、开放 B 样条，再变换控制点。N 个原采样点得到 N+2 个拟合节点、N+4 个控制点。

辅助节点按首端、末端顺序重设；只有两三个采样点时，末端方程覆盖与首端共用的行。仅两个采样点时，弧长更新按原生分支累计前两个辅助区间。库保留这些分支，不改用一般插值器，也不把反向拟合替换为正向控制点倒序。迭代收敛条件只衡量参数变化，不是拟合曲线与底层曲线的几何误差界。

缓和曲线的原生曲面裁剪转换取得拟合 B 样条的完整 `[0,1]` 参数区间；端点查询同样在该缓存的比例 0、1 处求值，不重新积分底层曲线。`BsplineSurface::trim()` 遵循这个表示选择，再以控制点包围范围细分成 UV 折线；裁剪报告单独记录缓和曲线转换来源，并明确偏差界不覆盖底层曲线到拟合缓存的差异。

BGFB 联合类型 19 的 `AkimaCurve.points` 保存 XYZ 点列，原生转换要求输入 6 至 5000 点。先取原点列去掉首尾各两点后的最大坐标轴跨度 R，范围计算跳过任意坐标为 `DBL_MAX` 的点；再移除 X 为 `DBL_MAX` 的断开标记点，并按源顺序移除与最后保留点的距离平方严格小于 `max(1e-28, (R × 1e-5)²)` 的相邻近点。范围计算和点过滤中的断开标记检查不同，不能把三个坐标的过滤条件混用。转换后的保留点数 M 仍须至少为 6；不对非相邻点去重。

保留点以 P₀…P₍M−1₎ 编号，实际插值区间为 P₂ 至 P₍M−3₎。令 Lᵢ 为相邻点的弦长，Dᵢ 为其单位方向。点 Pᵢ 的切线逐坐标计算：对该坐标的 `a=D[i−2]`、`b=D[i−1]`、`c=D[i]`、`d=D[i+1]`，令 `left=abs(b−a)`、`right=abs(d−c)`；若两权重之和小于 `1e-5`，取 `(b+c)/2`，否则取 `(right*b+left*c)/(left+right)`。计算后的切线不再次单位化。区段的三次 Bézier 控制点是 `P[i]`、`P[i]+T[i]*L[i]/3`、`P[i+1]−T[i+1]*L[i]/3`、`P[i+1]`。

各段拼成阶数 4、非有理、开放 B 样条，共 `3×(M−5)+1` 个控制点。内部节点按实际插值段的累计弦长除以总弦长生成，每个重复三次，两端分别四个 0 和 1。`AkimaCurve` 同时提供完整源点、保留点的源索引及派生曲线；解码表中的 `_akima` 表达转换状态及来源，不替换源 `points`。物理首尾重合不改变派生曲线的开放节点表示。

BGFB 联合类型 14 为 `BsplineSurface`。`numPolesU × numPolesV` 必须等于 XYZ 控制点数量，有权重时其数量也必须相同。`orderU`、`knotsU`、`closedU` 与对应的 V 字段分别采用上述单方向节点和周期索引规则；控制点及权重的原生一维索引为 `v × numPolesU + u`。有理曲面先将两个方向基函数的乘积与已加权 XYZ、权重分别组合，最后进行齐次除法。`BsplineSurface` 的比例接口按各自实际有效节点区间求值，保留非归一化源节点，不依赖运行时快捷求值所用的末节点等于 1 的假定。

`boundaries` 保存独立的裁剪曲线树，原生读取器将其附加到曲面后，再按 `holeOrigin != 0` 设置外边界禁用标志，因此默认外边界启用状态应由 `holeOrigin == 0` 判断，不能仅以是否存在裁剪树决定。源 `holeOrigin` 整数不被改写；`numRulesU`、`numRulesV` 独立写入对应方向参数。

裁剪树的 `CurveVector.type` 为 0/1/2/3/4/5，分别表示 None、Open、Outer、Inner、ParityRegion、UnionRegion。原生曲面裁剪入口直接接收 Outer、Inner；Open 的首尾满足 `距离平方 < (首点模平方 + 尾点模平方 + 1) × 1e-20` 时转作 Outer。ParityRegion、UnionRegion 均递归收集子曲线数组，非数组成员和 None 不成为边界。这里不能按 UnionRegion 的名称将重叠环做几何并集：曲面内部判定对收集到的环采用奇偶规则，重复环也不去重。

Open 的闭合检查发生在环成员转换之前，使用原树中首个可求值起点及最后一个可求值终点；子曲线数组递归提供端点，非空 PointString 也能提供端点，单点 PointString 的首尾均为该点。随后，环的直接成员分别转换为 B 样条。直接成员为 CurveVector 或 PointString 时，其原生转换接口返回失败，该成员不加入裁剪曲线链。这与 ParityRegion/UnionRegion 中递归收集子数组是不同的处理位置，不能把环内的数组任意展开为额外裁剪环。本库将这些已确认的原生忽略项记为 `native_trim_conversion_unavailable`，仍保留完整源成员；未知曲线类型继续报告未支持，不能套用此忽略规则。

存在有效环时，远离边界的有效性等于 `outer_boundary_active XOR 环内奇偶性`；没有有效环时原生判定直接返回有效，不再使用 `holeOrigin`。折线分支采用沿 V 方向的射线与半开 U 区间交点计数。`BsplineSurface::trim()` 按这些收集和填充规则生成独立的派生 UV 折线，并通过 `BsplineTrim::classify()` 查询区域。B 样条按节点区间提取局部齐次 Bézier 段，圆弧转换为有理二次段，然后按控制点包围范围细分；原始节点和控制点仍保持不变。此接口使用调用方边界带宽和显式不确定状态，不复刻原生所有边界容差、接缝修补或网格生成行为。

有理边界在齐次坐标中细分。内部控制权重为零或混合正负号，并不直接证明曲线分母为零；只有分段控制权重具有一致非零符号时，才能用对应笛卡尔控制点的包围范围判定该段精度。无法在预算和数值精度内得到有限分段时，返回不完整状态，而不是修改权重。

`StructStandardFloorModel.DesignPara` 的解码结果在 `fields` 中保留全部成员的偏移和原始数值，在 `named_values` 中提供已确认的板厚、板钢筋保护层厚度、柱／梁／剪力墙／板／斜杆混凝土强度等级及柱／梁／墙主筋类别。混凝土等级数值配有 `display_value`，主筋类别配有 `enum_label`；未知枚举值保留数值并标记 `enum_status: unknown_value`。未命名成员仍标记为 `unassigned`。字段名称由本库定义，字段上的 `unit: mm` 仅说明该设计参数的单位，不用于推定几何坐标单位。

承台截面的 `pilecap_section_cereal` 解码保留 `members` 中的原生成员位置、数值及存储视图，并在各参数块的 `named_values` 中提供已确认的含义，包括桩的混凝土等级、定位参数，承台类型、平面形状、阶数、顶面偏心，以及配筋的级别、直径、间距与布置宽度。一阶或二阶且高度数量一致时，`step_heights` 按下阶到上阶排列；其他形式保留原数组并标记 `unsupported_step_layout`。未标注单位的字段不自动推定单位。

枚举必须按所属参数类型解释。例如标准层主筋代码 `0` 表示 HPB300，而承台配筋代码 `0` 表示 HPB235；桩基础混凝土代码 `3` 表示 C30，标准层混凝土数值 `30` 表示 C30。库返回的 `enum_label` 仅适用于所在字段，不能作为同名字段的全局对照表。

桩截面参数按 `section_shape` 区分矩形的 `section_width`、`section_height` 和圆形的 `section_diameter`，尺寸单位为毫米，`pile_length` 为米，`rotation` 为度。未识别的截面类型不套用这些尺寸名称。`layout_preset_index` 是原生桩数与承台形式选择列表的索引，不是桩数。

桩截面类型 `5`、`6` 另提供 `section_outer_diameter` 和 `section_wall_thickness`，单位为毫米；其原生内半径关系为“外径 / 2 − 壁厚”。两种类型各自的工程分类名称尚未确认，类型枚举仍标记为未知。此壁厚解释不套用于其他截面类型，也不据此替换文件中的几何。

桩截面类型 `7` 提供 `first_circle_radius`、`second_circle_radius` 和 `circle_center_spacing`，单位为毫米。原生局部坐标中的两个圆心沿 X 轴分别位于 `-circle_center_spacing / 2` 和 `+circle_center_spacing / 2`；半径按这两个圆的原生顺序返回，不换算为直径。类型 `7` 的 `0x1f0` 表示圆心间距，与类型 `5/6` 在同一成员位置存储的壁厚含义不同。工程分类名称仍标记为未知。

承台参数中的 `pile_layout` 提供原生桩数和桩位，`cap_profiles` 提供按下阶到上阶排列的轮廓，坐标和半径单位为毫米。多边形轮廓返回 `vertices`；圆形轮廓的原生三元组为 `[半径, 0, 0]`，以 `kind: "circle"` 和 `radius` 返回。未识别的形式保留在 `source_values`，原有 `primary_points`、`secondary_point_arrays` 仍可访问。数量不一致时返回对应的 `mismatch` 状态，不根据数量字段截断或补齐源数组。这些参数描述源截面，不自动替代场景几何。

`AssemblyLinkModel.CerealDatas` 中的 `link_merge_set` 提供节点连接归并方式、编号方式，以及 `collections` 中的楼层分组 `floor_groups` 和连接分组 `link_groups`。每个分组的 `values` 保留原生整数成员及其顺序，包含重复值；原生版本 0 的分组载荷不保存分组名称。`display_control` 提供构件、焊缝、螺栓和钢筋的显示模式。两个参数块都保留原始 `enum_codes`，并提供 `fields` 和 `named_values`；枚举标签按各字段分别解释。`storey_design_flags` 保留按原生装配楼层顺序排列的设计状态字节，不把数组下标当作楼层对象 ID。这些显示设置作为元数据返回，不自动过滤场景内容。

同一对象身份出现多条记录时全部保留。内容一致的副本与内容冲突的副本有不同状态，不通过覆盖字典隐藏差异。属性对象与场景构件之间的联系由绑定和关系记录表达。

## 变电站设计参数

`ElecParaData.CerealDatas` 中的 `collections` 保留变电站设计参数的原生集合顺序。集合元素通过 `entries` 访问，映射按键值条目返回，保留原始顺序及重复键。非空集合包括材料参数、整数映射、节点、杆件、柱参数、桁架梁参数、桁架梁、人字柱、梁柱分组及轴网记录；版本 1 的外层记录还提供 `changed_joints`。节点的 `Pt3D_ST` 数据提供 `position`，并按版本保留节点荷载；杆件记录保留关联的两个点和杆件荷载。

元素的 `native_type`、`version` 和成员位置描述原生存储结构。仅首次出现的同类型元素带有 `cereal_version`，其作用域覆盖整个参数载荷，包括嵌套元素。尚未确认类型或业务含义的数值成员同时提供 `storage_uint32` / `storage_uint64` 及整数、浮点存储视图；存储视图不表示已确认字段类型或单位。这些设计记录不自动转成额外的场景几何。

柱参数、桁架梁及人字柱的 `members` 是按序列化顺序排列的数组；`native_member_offset` 是成员在原生对象中的位置，`offset` 是数据在参数载荷中的字节位置。嵌套参数仍按各自版本读取，不能用外层记录的版本替代。原生桁架梁的 `0x138`、人字柱的 `0x1a0` 均连续序列化两次，库保留两次出现的值，不按相同成员位置合并。

`TrussBeamPar` 版本 2 只保存版本信息，不保存后续成员；空 `members` 表示成员没有序列化，不表示所有参数为零。版本 0、1、3 仍使用各自的非空布局。

已确认的数值成员另提供 `name`、`value` 和 `storage_type`。`SubsColPar` 包括 `column_section_count`、`column_type` 和 `fire_wall_height`；柱类型中已识别 `0`（人字柱）及 `1`（格构柱），其他代码保留数值并标记 `enum_status: unknown_value`。字段只在源版本包含该成员时出现，不为旧版本补默认值。`HumanColumn` 的两个点分别命名为 `start_point`、`end_point`，`rotation` 单位为弧度（`rad`）；这些定位参数不自动施加到已有场景几何上。

柱参数中的 `domain_column_parameters`、`domain_beam_parameters` 保留整数键和双精度数组，并通过 `native_property_name` 标明对应的原生领域属性 `colParam`、`beamParam`；防火墙高度对应 `fireWallH`。这些对应关系仅适用于 `SubsColPar`，不作为任意同名用户属性的解析规则。数组仍按原长度返回，不截断、补齐或重新格式化为字符串；未确认的数组项含义及长度单位不填入推定名称或单位。

版本 5 及以上的 `SubsColPar` 还提供 `bar_segments_by_elevation`：键为 `upper_elevation`（高度上界），值为 `segment_index`（杆件段序号，`index_base: 1`）。原生使用方式是以梁端点 Z 坐标寻找不小于该高度的首个上界，再选择有序杆件列表中的对应段。段序号不是构件 ID；库保留原始顺序、重复键和非正序号，不自动排序、修正或建立对象引用。高度单位仍由来源坐标约定决定。

`section_parameters.collection` 提供截面记录 `PSXsectAndMatType`。其中 `section_group` 按截面类型展开扩展数组、三个字符串及截面成员，支持专用布局与原生通用布局。`section_type` 是原生截面类型码，已确认的类型另提供原生简称 `section_type_label`，`serialized_length` 是组内有效长度；800 字节块中超出该长度的部分以 `unused_capacity.source_bytes` 保留。组内字段的 `offset` 相对于 `section_group.offset`，由 `offset_basis: section_group_start` 标识；外层记录和材质成员的位置仍相对于参数载荷。字符串的 `source_bytes` 始终保留原字节。

截面类型 `31` 至 `35` 的名称还取决于 `section_subtype`，其来源是原生成员 `0x8` 中的有符号 16 位代码。支持的子类型包括工、槽、等边／不等边角钢及其组合方向；`section_type_label` 保留原生方向符号、空格和重复名称。同名不表示同一子类型，调用方仍应保留两个类型码。未确认的子类型不填入名称，对应成员标记 `enum_status: unknown_value`。类型 `201`、`202` 分别提供原生名称“矩型钢混凝土”“圆管型钢混凝土”，不将其尺寸成员解释为子类型。

## 图纸设置

`PSDrawingManager` 和 `SubsDrawingManager` 的 `CerealDatas` 按原生图纸类型返回 `records`。每条记录的 `fields` 提供已确认的字段名称、原生成员位置、数值及枚举标签，`named_values` 提供按名称访问的数值。原有数值数组和标志字节仍然保留。

已命名的设置包括图幅、图框样式、比例分母、文字高度，以及各图纸类型的梁柱画法、标注距离和节点出图选项。比例字段 `*_scale_denominator` 表示 `1:N` 中的 `N`。图幅与图框样式是不同枚举，例如图幅 `0` 和图框样式 `1` 都对应 A0；未知枚举值保留原值并标记 `unknown_value`。这些设置作为元数据返回，不驱动几何生成或内容过滤。

平面、立面、柱脚及连接图记录支持版本 0 和版本 1，节点图及变电站图纸记录支持版本 0。版本 1 中新增的节点编号显示方式、拼接节点标注起点仅在源记录包含时返回。尚未确认含义的参数保留在原始数值字段中，不填入推定名称或默认值。

## 几何定义、实例和块

图形属性中的命令流描述几何、变换和样式。已支持的源网格直接转入数组，参数化曲线和曲面按采样策略重建；源命令和载荷仍可通过底层接口访问。

命令 28 的样式载荷按 16 位标志选择字段，读取顺序遵循原生布局。除材质 ID、颜色索引、线宽、线型和透明度外，还返回填充色索引、填充模式 `fill_mode`、子项索引 `subitem_index`、打包颜色，以及尚未命名的 `field_*` 字段。`field_0040`、`field_1000` 分别是填充模式与子项索引的兼容视图。子项索引不自动等同于材质分配中的部件索引。打包颜色保留为 `true_color_packed`，其低三字节按 R、G、B 返回 `true_color_rgb`；最高字节通过 `true_color_unassigned_high_byte` 保留，不推定为透明度。

`line_style_modifiers` 按自身的 32 位标志返回可选成员。`fields` 保留名称、掩码、源偏移、原生成员偏移和整数存储值；64 位标量另外提供 `float64_view`。`named_values` 提供缩放、虚线及间隔缩放、起止宽度、移位、分数相位、多线索引及多线数据类型码。居中移位、真实尺度和两种转角规则按原标志位返回，冲突位同时保留。切换线型会清除上一线型的修饰参数；同一命令附带的新修饰参数随后生效。

线型法向与旋转分别保存在 `orientation_vector`、`orientation_quaternion`，均为源载荷值；原生绘制会在四元数存在时以转置旋转矩阵的第三行覆盖法向，本库不把这组线型方向用于变换几何。未确认的标志位和剩余字节分别保存在 `unassigned_flag_bits`、`trailing_bytes`。兼容字段 `unassigned_doubles` 仅为连续存储视图，不表示载荷全部由双精度字段组成。

命令 40 是可变长度的样式扩展。`extension_flags` 的位 0、1、2 分别选择渐变填充块、按图层继承标志和图层 ID，按此顺序保存；没有出现的字段不清除之前的状态。`layer_id` 会进入实例及图元的 `style`，包括源数据中的特殊值。`by_layer` 分别说明颜色、填充色、线型、线宽是否使用按图层继承的标志，未确认位继续保留；库尚未求出继承后的最终值。

`fill_style_block` 返回渐变角度、白色强度、移位、模式码、标志及最多八项位置和 RGB 颜色，源颜色字节也单独保留。已知渐变模式包括线性、曲线、圆柱、球形、半球形。数值使用源值，不自动裁剪范围或推定角度单位；`unassigned_scalars` 是这三个已命名数值的兼容视图。短块按原生规则补零后提供结构视图，长度为零表示清除。填充及继承数据保存在 `style.native_symbology_extension`，渐变不能简化为一个普通调色板颜色。

命令 29 的 `curve_identifier` 是可变长度的原生曲线标识容器，包含类型、标识字节和可选的复合绘制状态。适用类型额外提供 `topology`，保留拓扑类型及一、二或四字节宽度的无符号 ID 数组；原生类型 0 至 3、99 不提供此拓扑视图。复合绘制状态保留原字节，并在 `compound_draw_state_decoded` 中展开功能码、尚未命名的 16 位成员及奇数长度的尾字节。兼容字段 `identifier` 仅是特定长度载荷的 64 位存储视图，不能作为构件 ID、材质部件编号或全局几何身份。

SMCA 共享定义按源流、记录偏移和属性序号建立身份，构件的原生引用在模型作用域内解析。源记录身份只用于已有的定义关系，不用于寻找形状相同的独立构件。

原生块定义包含成员及名称引用，嵌套块携带变换链。多个同名候选、缺失定义和循环均明确记录。活动场景未引用的块成员仍保留在块库目录及定义集合中。

定义、实例与渲染图元不是一一对应：一个构件可能有多个实例，一个定义也可能包含多个面、线或文字范围。调用方应使用 `for_each_primitive()` 或逐范围处理，不能把“构件数”等同于“网格数”。

导引放样支持折线、圆弧和椭圆弧边界，包括一周的整圆、整椭圆。折线按累计弦长参数化；圆弧按不超过 120° 的有理二次段构造，保留权重。周期圆锥曲线在源参数零处打开，保留源角度接缝及七控制点表示。边界经过次数提升与节点对齐后，使用原生分段控制点混合系数构造 Coons 控制网；三控制点边界按原生规则额外提升一次次数。控制网为从源命令重建的临时数据，不新增源几何身份。

两个截面的开放或闭合类型必须一致。闭合截面有 N 个源边段时需要 N 条导引，最后一片回接第一条导引；两个源截面均须通过首尾重合检查，即使未请求封口也不例外。开放截面需要 N+1 条导引，最后一条定义末端边界。开放截面从命令 20 的路径块读取，闭合区域从命令 21 读取，不按首尾坐标相等与否改写源边界类型。开放曲面的每行顶点保留两端，不添加连接首尾导引的侧面；构造说明中的 `profile_closed` 标记源截面类型。

封口由命令 56 的封口标志控制，并要求曲面上下端的边界分别首尾重合。原生判断使用严格不等式 `|a-b|² < (|a|² + |b|² + 1) × 1.0000000000000001e-20`，其中 a、b 是各端边界的起点与终点，使用曲面构造坐标；该容差独立于调用方的弦高设置。类型为开放路径但两端边界都满足该条件时，也可生成封口，仍保留 N+1 条导引及各自的内部形状。任一封口边界不满足条件时，报告几何错误，不输出该放样体的部分网格；不会补一条直线来闭合真正开放的端面。开放截面与内环组合尚未支持，封口仍受平面多边形三角化的支持范围约束。

每片曲面的四个角点按源边段与相邻导引的固定对应检查，三个坐标分量的差分别不得超过 `1e-5`。此检查不按欧氏距离求值，也不自动搜索或翻转错序导引。复合导引接缝另用严格条件 `D < M × 1e-8 + 1e-8`，D 为两端点坐标差的最大绝对分量，M 为两端点所有坐标的最大绝对值。通过连续性判断后，连接处保留前一段的末控制点及权重，省去后一段的首控制点；原始命令数据保持完整。未通过该判断的接缝属于不连续曲线连接，当前明确报告未支持，不能用一个共享端点替代。角点对齐、复合接缝和首尾闭合的容差各自独立，均不由弦高参数调整。

单条导引可以由连续的折线和圆弧、椭圆弧命令组成。各条导引的源命令数一致时，原生逐次连接为等参数区间；不一致时，逐次按去齐次控制多边形的长度分配区间。这是逐次连接规则，不能将三段以上的导引直接改成全局等分，也不能用圆弧长度替代控制多边形长度。使用的规则保存在曲面构造 `notes` 的 `composite_guide_parameterization` 中。

命令 55 的 `guide_group_count` 和 `guide_counts` 保留导引分组。多环截面的外环及内环按源顺序对应上下截面和各自的导引组，不按几何距离寻找配对。内环侧面保留源轮廓方向；封口使用带孔多边形三角化。组数量、曲线数量或边界端点不匹配时报告未知项，不返回已生成的部分放样。多环构造条目通过 `source_ring_index`、`source_guide_group_index` 标明来源。

相邻曲面片共用导引方向的采样参数。指定弦高时，依据正权重有理曲面的导数上界细分，并在 `notes` 的曲面构造条目中通过 `surface_to_mesh_error_bound` 记录曲面侧面到三角网格的误差上界。该上界针对本库重建的曲面，不包含未重现的原生曲线拟合容差处理，也不是封口面误差证明。控制网、生成网格及多环封口的总顶点数受 `Tessellation::max_segments` 限制，预算不足时报告未知项。

## 结构树与材质

对象图分别组织源结构树和模型树，保留节点、边、根及解析状态。块树单独保存在场景元数据中。原生可见性和视图规则尚未全部验证，因此这些结构不自动等价于某个视图的最终渲染列表。

材质定义有模型或全局作用域，源颜色索引、扩展颜色、材质参数与贴图引用分别保留。图元的外观摘要不替代原始材质定义，也不等于已经完成 glTF PBR 转换。

`materials().native_catalog_records` 保留原生类型 49、子类型 18 的材质目录记录，包含没有对应 XML 定义的记录。每项携带源流、记录 ID、记录偏移和 `native_record_index`；`strings` 保留应用号 `0x56d2` 的字符串附加项、源链接下标、链接偏移及完整载荷。用户附加项载荷由 uint16 键、未命名 uint16、uint32 字符串字节数及原生编码字符串组成；键按低 16 位识别，未命名成员保存在 `unassigned_word`。`suffix_hex` 保存声明的字符串字节数之外的尾部，包括对齐字节。字符串项的 `decoded` 仅表示文本成功解码，不表示未命名成员或尾部已有完整语义。

键 `1` 的角色为 `catalog_name`，键 `3` 为 `resource_reference`；其他键保留为 `unassigned`。这两个字段各自取第一条匹配用户附加项，并提供 `entry_index`、`status`、`value`；状态区分 `missing`、`decoded` 和 `invalid`。重复项仍保存在 `strings` 中，选择状态为 `shadowed`；首条损坏不改用后面的值。原生目录读取时，缺少资源字符串会使用当前资源上下文，显式空字符串会使资源引用解析失败，二者不可混同。文本保持源值；库不执行原生转换缓冲上限、目录加载或资源上下文求值，`resource_lookup_status` 为 `not_performed`。

`materials().native_catalog_tables` 保存类型 10、子类型 18 的原生材质表。`declared_descendant_count` 是全部后代记录数，普通头位于源记录偏移 36，标志 `0x20` 置位时位于偏移 108；具体位置记录在 `descendant_count_source_offset`。计数之外的扩展头和尾部保存于 `unassigned_ranges`。`member_record_indices` 只包含直接成员，按源顺序排列；嵌套复合记录的后代不提升到外层。`members` 同时给出原生记录下标和 `catalog_record_index`，非类型 49／子类型 18 的成员仍保留，后者为 null。成员关系要求后代记录同流、连续，且嵌套范围不能超过父范围；无效表给出 `membership_status: invalid` 和错误原因，不发布部分成员关系。原生读取器依据后代计数重建子链并补设 `0x80` 子标志，因此源记录缺少该位不会导致归属失败；这些记录列在 `unflagged_descendant_record_indices` 中，源标志不改写。有效表为 `resolved`，仅表示保存的归属已解析。

目录记录的 `table_memberships` 通过 `table_index`、`member_index` 反向关联上述表。数组为空表示没有建立有效的直接表归属，可能是表外记录或相关表损坏；目录记录本身仍完整保留。系统初次输入的选表及接受成员见 `native_input_containers()[].initial_material_table`。源表上的 `runtime_selection: not_evaluated` 则针对后续原生资源上下文中的活动选择，不应自行把多个表合并为同一材质目录。

材质表和目录记录的 `initial_load_filter` 描述原生文件读取入口的过滤条件。`record_word_count` 是源记录头声明的字数，按两字节计；`source_prefix_word` 是记录前四字节。判断顺序如下：

- 字数大于 65535：`status: read_error`，`reason: record_word_count_exceeds_limit`，原生错误码 `native_error_code: 73733`（`0x12005`）。此条件先于前缀和标志检查。
- 前缀非零：`skipped`，`reason: nonzero_prefix`。
- 标志 `0x08` 置位：`skipped`，`reason: flag_0008`。通用子记录读取还会跳过类型 0 或字数小于 16 的记录。
- 其余为 `accepted`。正常和跳过状态的 `native_error_code` 为 null。

`descendant_counter_effect` 区分物理读取器的后代计数行为：前缀非零为 `not_incremented`，读取错误为 `not_reached`，其他为 `incremented`，包括随后被元素读取器跳过的记录。源字段不因入口过滤而删除。`accepted` 仅表示通过这一入口条件，不表示目录加载成功、已进入活动表或最终材质已经选定。

表的 `initial_load_members` 根据上述计数和递归读取规则重建输入成员。其 `scope: table_input_if_reached` 明确表示以该表被读取到为前提，不判定整个文件能否加载到此处。`start_counter` 包含本输入块中截至表头的零前缀记录；`target_counter` 按原生 32 位无符号加法计算，保留溢出后的比较行为。读取器等完整子记录返回后才检查目标，因而末尾跳过记录或嵌套子链可能使 `end_counter` 超过目标；不能简单过滤源 `members` 得到这个结果。

`initial_load_members.status: resolved` 时，`members` 和 `member_record_indices` 给出重建后的直接成员，字段含义与源归属视图相同。`consumed_record_indices` 记录递归读取涉及的全部源记录，`skipped_record_indices` 记录其中被跳过者。表自身被过滤时为 `skipped`；读取超限为 `read_error`；数据不足、转换所需字段截断或跨流、断开的记录边界为 `invalid`。失败状态不发布部分成员，但保留已读取下标及错误原因。源范围出现非零前缀时，外层 `membership_status` 为 `invalid`，避免把不计数的物理记录误报为源成员；这不妨碍单独求值 `initial_load_members`。目录的 `table_memberships` 仍只反向引用源归属视图，不代表重建输入成员或运行时活动目录。

输入读取过程中，类型 13、24、62 的原生转换对父子关系的影响保存在 `record_conversions`。每项通过 `native_record_index` 定位源记录，`compound` 和 `descendant_count` 描述转换后用于读子链的分类与数量。源字节不改写。

`initial_load_members.nodes` 按前序保存所有成功读入的后代，各项的 `native_record_index`、`parent_record_index` 均指向原生记录数组，`compound` 表示其复合分类。直接成员仍使用 `member_record_indices`／`members`，不把孙级记录提升为直接成员。`root_topology` 保存表头经输入规则解释后的分类和后代数。读取失败时不发布部分 `nodes`。

- `type_24_extended_header_removal`：带 `0x20` 标志时移除 72 字节扩展头、清除此标志，记录总字数和基础字数各减 36；后代计数从源偏移 108 移到转换后偏移 36。没有扩展头时 `applied: false`，保留普通计数。输出头字段以 `output_*` 表示，计数来源以 `descendant_count_source_offset` 和 `descendant_count_source_bytes` 表示。
- `type_13_legacy_layout_upgrade`：按顺序检查源偏移 160 的 u32、342/344 的 u16 是否为零、346 的 u16 条目数是否不超过 2500，以及基础字数是否为 `172 + 8 × 条目数`。全部满足才有 `applied: true`，输出基础和总字数各增 12，标志保留。普通头的后代计数仍来自偏移 36；旧布局同时带 `0x20` 时，升级后计数来自源偏移 64 的 u16，后两字节补零，不能沿用源偏移 108 的旧值。`legacy_entry_count` 保留参与升级判断的条目数。
- `type_62_matrix_repair`：原生转换只处理源偏移 164 开始的九个双精度矩阵值，不改变记录类型、标志或后代数，因此输入子链中始终为叶记录。`matrix_source_offset`、`matrix_value_count` 给出矩阵来源。

上述视图解析转换对输入成员关系的影响。类型 13、62 的 `payload_reconstruction: not_evaluated` 表示此视图没有生成完整升级载荷或执行退化矩阵修复；不应从成员关系成功推断几何转换已完成。类型 62 的矩阵解析及输入修复由原生记录的 `block_transform` 单独提供。

### 块引用输入变换

原生类型 62 的 `block_transform` 保存 `source_matrix` 和输入规则求得的 `matrix`，均为 4×4 行主序仿射矩阵。九个线性系数位于源偏移 164，三个平移值位于偏移 236；源值和原始字节不改写。`reader_profile` 为 `bimbase_2025_block_transform_input`，`scope: record_input_if_accepted` 表明这是该记录被原生读取器接受时的变换规则，不负责活动记录或块定义选择。

首先以最大绝对系数缩放进行可逆性检查；必要时使用列正交化因子判断，不能仅按绝对行列式大小修复。通过检查时 `repair: unchanged`，保留原有旋转、镜像、剪切和非均匀缩放。检查失败后按列 0、1、2 的顺序处理平方长度小于 `1e-6` 的列，用另外两列的单位向量叉乘补齐方向，并恢复其原长度；另外两列长度相等时，新列也采用这个长度。`repaired_column_indices` 记录执行顺序；每次处理会更新后续步骤的输入。该路径成功时为 `short_columns`。

仍未通过可逆性检查时，执行原生补全秩规则，`repair: rank_augmentation`。列正交化最多执行十轮；每轮按列对 0/1、1/2、0/2 旋转，收敛阈值为 `1e-14`。以三个结果列长度之和乘 `1e-12` 判断缺失方向：秩零使用单位线性矩阵，秩二通过另外两列的几何平均长度叉积补齐缺失方向，秩一按原生三轴构造调用规则补齐。`rank_before_augmentation` 和 `rank_factors_converged` 分别保存补全前的分类及因子迭代状态；这些字段不用于保证最终矩阵的条件数。平移不参与修复。

`status: resolved` 表示矩阵字段及该输入规则已求值。截断、非有限数值或计算超出双精度可表示范围时为 `invalid`，附有 `error`，原生记录和源字节仍保留。该结果在解析记录时缓存；场景块定义条目及引用链通过 `input_transform` 提供同一结果，`matrix` 和实例组合采用有效矩阵。块定义缺失或歧义与矩阵状态分开报告，不因矩阵可用而任取块定义。

### 块定义输入子链

`NativeScene::metadata["native_block_definitions"]` 保存系统流中的类型 32 块定义。`native_record_index` 定位原生头，`input_tree` 使用与材质表相同的输入过滤、记录转换和递归后代计数规则。普通头从源偏移 36 读取数量，`0x20` 扩展头从偏移 108 读取；这个数量包括全部后代，不是直接子项数。

`input_tree.scope: record_input_if_reached` 以读取到该块头为前提，未判定整个系统容器的加载状态。成功时，`member_record_indices` 是直接子项，`nodes` 是全部已接受后代的前序列表，并给出每项的 `parent_record_index`。消费记录、跳过记录、计数及转换信息的含义与材质表输入视图相同。

块定义的 `direct_child_source_keys` 提供直接子项来源；`children` 保存成功读入的全部后代，按前序排列，通过 `parent_source_key` 保留实际父级。场景按这份经过过滤的列表处理块几何；嵌套记录仍保留独立源身份，不因 ID 或内容相同而合并。源头被跳过或子链无效时，块定义及 `input_tree` 的状态保留，`children` 为空，不将部分几何注册为可展开块。这里还不等同于完成运行时块名称选择、可见性及显示继承规则。

XML 材质项的 `native_catalog_candidates` 是上述目录记录数组的下标，按对应原生流的作用域前缀和记录 ID 关联。重复原生记录全部列为候选，不按名字去重或任取一条作为已解析的目录；这个来源关联不以表归属过滤记录。兼容字段 `native_strings` 仍提供旧的字符串摘要；需要完整来源、异常及重复记录时应使用 `native_catalog_records`。目录查找本身还涉及资源上下文，数值 ID 或名称匹配不等于最终运行时材质选择。

目录的 `resource_reference.interpretation` 提供原生项目资源规则。对 `$(_P3DPROJECT)\` 开头的引用，`project_member_name` 为移除目录和最后扩展名后的名称，`extension` 保留原扩展名大小写；不会额外删除名称中的 `-Palette`。前缀及 `pal` 扩展名按 ASCII 不区分大小写匹配，但前缀末尾必须是反斜杠。主上下文 `primary_context` 为 `current_resource_context`；扩展名为 `pal` 时，`secondary_context_rule` 为 `palette_lookup_or_primary_context`，并提供仅含末级文件名的 `lookup_request`，原生搜索设置名为 `P3d_Material`。查找成功使用解析出的调色板资源，失败使用主上下文。其他项目资源的第二上下文直接使用主上下文。

目录的 `catalog_name.reader` 与 `resource_reference.reader` 提供原生目录专用字符串读取结果。它们使用 512 个 UTF-16 单元的缓冲区，报告 `success`、`missing`、`failure` 或 `unresolved`，并给出可确定的 `native_getter_return_code`。`reader.value` 是首个 NUL 前的实际读取文本；外层 `value` 继续保留通用源字符串解码结果，两者不相互改写。无标记字节及 `FF FE 01 00` 形式按无符号字节扩宽；`FF FE` 和 `FF FD` 的目录读取分支复制 UTF-16LE 单元，其中 `FF FD` 不套用通用源字符串的压缩双字节编码转换。不支持的字节序标记使读取失败。

缓冲区边界遵循原生实现：未终止的 510 个单元可成功补零，511 个单元会触发末项置零并返回失败；最后复制单元本身是零时另行判断。UTF-16 分支可能在固定缓冲区末项为零时忽略更长尾部而成功，字节扩宽分支仍检查是否读完。`output_utf16_units` 保留复制区域经过末项处理后的单元，`ignored_text_suffix` 保留首个 NUL 后可表示的文本；无效单元仍可从单元数组及源字节取得。无法安全确定的截断、标记越界和零单元复制边界保持 `unresolved`。

资源解释不执行查找，`lookup_status` 始终为 `not_performed`。原生读取成功后的空引用标记 `rejected_empty_reference`；缺少资源字段或确定的读取失败则使用 `scope: resource_reader_failure_fallback`，`reader_fallback` 区分两种原因。对新建目录描述对象，这个分支设置当前主资源上下文和空成员名，不发起路径查找；第二上下文保持 `secondary_context_initial_state: unset`，读取它时使用 `default_resource_service`，不能直接视为主上下文。无法确定读取结果或有效文本时为 `unavailable_text`。其他未确认资源形式、盘符、协议及超限路径分量继续报告 `unresolved_*`。源值始终保留，项目上下文规则不等于完整目录查找或最终材质覆盖。

材质库形式 `$(_P3DLIB)|库资源|成员路径` 的 `kind` 为 `library_resource`。`library_reference` 是外层库资源，`member_source` 保留成员原文，`member_path` 是去掉一层嵌套库包装后的成员路径，`member_name` 去掉其目录和最后扩展名。嵌套包装中的库资源另存为 `discarded_nested_library_reference`，不会替换外层库，也不会递归剥除更多层。原生目录载入入口的主上下文仍是当前资源上下文，第二上下文由 `library_resource_service` 提供；`lookup_request` 使用外层库引用和 `P3d_Material` 设置，不推定库查找失败时的回退结果。

库形式按原生分隔位置读取：第二个竖线从第一个竖线后两个字符处开始寻找；后续竖线仍可属于成员文本。前缀与第一个竖线之间的额外文本保存在 `prefix_suffix`。单独的 `$(_P3DLIB)` 得到空库引用和空成员名；缺少必要分隔符时返回 `unresolved_library_syntax`，不模拟原生无效下标回绕。前缀中小写 `i` 与大写 `I` 的比较依赖原生区域设置，无法确定时返回 `unresolved_prefix_locale`。库资源本身作为不透明引用保留，成员路径的盘符、协议及超限分量仍受前述未确定状态约束。

普通路径若具有 `pal` 扩展名，`kind` 为 `palette_resource`，查找请求保留完整源路径。其 `primary_context` 尚未求值，`context_cases` 给出三个原生分支：查找失败时两个上下文均为当前资源上下文；查找成功且当前材质表存在同名资源成员时，主上下文保持当前、第二上下文使用解析出的调色板；查找成功且不存在同名资源成员时，两个上下文均使用该调色板。`matching_resource_member` 描述待判断条件：比较材质记录键 `3` 的资源字符串拆出的成员名，采用原生受区域设置影响的不区分大小写比较，不使用键 `1` 的材质目录名称。库不擅自将这个条件视为成立或不成立。

`descriptor_mode` 是资源描述的模式值，参与原生目录项的重复判定。普通调色板查找成功且没有匹配资源成员时为 1，其余两个调色板分支为 0；在条件尚未确定时，该字段为 `null`，对应值保存在 `context_cases`。项目资源、库资源、普通文档或无扩展名引用，以及资源字符串读取失败后的默认描述，均明确使用 0。被拒绝的引用不提供有效模式值。比较目录项时不能只比较名称、资源成员名和主上下文而忽略该字段；它也不等同于文件扩展名或第二上下文类型。

普通 `p3d` 扩展名或空扩展名走 `current_context_resource`，两个上下文均使用当前上下文，不发起该 P3D 文件的查找。其他非空扩展名返回 `rejected_extension`；这描述材质资源读取分支，不表示源字符串或文件已被删除。判断依据是扩展名是否为空，不能改成文件名是否为空：例如 `.pal` 仍使用普通调色板的成员存在性条件，`name` 则使用当前上下文。盘符、协议及超限分量继续报告未确定状态，所有请求均不执行。

原生记录的用户附加项（头部位 `0x1000` 置位）中，应用号 `0x41`、载荷首部键 `0x1000e` 表示构件材质引用。键是小端 uint32，随后是小端 uint64 材质标识；常规项共 16 字节，包含 4 字节附加项头。`native_records()[].links[].decoded` 以 `encoding: native_element_material_reference` 提供完整 `material_id`，`material_id_offset: 8` 相对附加项起点。标识中的零值与全一值均原样保留，不据此推定按层继承等外观规则。

`reader_selection` 描述同一原生记录内的匹配顺序：第一条为 `first_match`，其余为 `shadowed`。所有条目均保留，不去重；第一条损坏时也不替换为后续条目。完整 12 字节载荷标记 `decoded`，有额外后缀时标记 `partial` 并保留 `unassigned_suffix_hex`；键完整但标识截断时标记 `invalid`、提供 `decode_error`，标识为空。`payload` 始终保留完整源字节。应用号、键或用户标志不匹配的附加项不套用此结构。

`materials().native_element_references` 汇集这些引用，保留 `stream`、`native_record_index`、`record_id`、`record_offset`、`linkage_index`、`linkage_offset` 及 `reference`。两个 offset 均相对原生流起点；数组下标指向 `native_records()` 及其 `links`。同 ID 的不同记录或不同流仍分别返回。这是构件级源引用及读取顺序，不代表已完成材质目录解析、部件覆盖或最终外观求值。

用户链接 `0x4F5A` 是另一种原生材质名称引用。链接起点 `+4` 的 u16 保存写入时的名称字节数，`+6` 开始保存 ANSI 零终止字符串。原生 getter 忽略该长度字段，直接读取至首个零字节；库仅在当前链接内寻找终止符，越界时报告 `invalid`。`declared_byte_length`、`actual_byte_length`、`declared_length_matches` 保留长度差异；终止符后的字节作为 `ignored_suffix` 保存，不武断归为格式填充。一个已确认的写入分支使用 48 字节链接并将名称截为至多 29 字节，但这不是读取器的通用长度限制。

该链接的 `decoded.encoding` 为 `native_element_material_name_reference`，同类首条匹配为 `first_match`，其余为 `shadowed`；选择先于内容校验，损坏首条不改用后续同类名称。名称与数值引用各自保留选择状态，不能用二者在源链中谁先出现来决定优先级。

原生名称转换使用 Windows `GetACP()` 对应的代码页，而非 BOM 或固定 UTF-8 编码。ASCII 子集可直接得到 `material_name`；其他字节返回 `requires_ansi_decoder`，由调用方根据来源环境提供转换函数给 `decode_native_material_name()`。`name_bytes` 保留零终止符之前的完整字节，`source_bytes` 保留完整载荷；长度和原字节不会因为转换而改变。转换函数须返回有效 UTF-8，异常或无效结果报告 `invalid`。

`materials().native_element_name_references` 汇集这类名称引用，来源字段与数值引用相同。已确认的名称查找按原生目录顺序、不区分大小写且受区域设置影响地收集同名候选，逐个尝试加载，取第一个加载成功的结果；空名称不匹配。已确认的一条构件查找路径在数值 ID 查询适用且 ID 不为 `UINT64_MAX` 时直接查数值引用，该次查找失败不会再自动转为名称查询。上下文不适用或没有可用数值 ID 时才进入名称分支。最终目录上下文和加载结果尚未求值，源引用不能直接当作最终材质绑定。

XML 材质的 `settings.semantics.parameters` 提供颜色、透明度、高光颜色与系数、自发光颜色与系数、环境光、漫反射、粗糙度、反射和折射系数。每项保留 `source_keys`、`value`、`status`，并以 `enabled` 和 `enabled_source` 表达原生启用规则。`Flags` 的位 2、6、3、9、21、7、4、5、8 分别控制颜色、透明度、高光颜色、高光系数、自发光颜色、漫反射、粗糙度、反射和折射；环境光和自发光系数在原生材质接口中恒启用。未命名位保存在 `settings.semantics.flags.unassigned_bits`。关闭参数不丢弃数值，缺少 `Flags` 不推定启用状态。XML 的 `transmit` 对应透明度，`finish` 对应原生粗糙度系数，不自动换算为其他渲染器的参数。

`settings.maps[].semantics` 按源 `Type` 区分普通贴图（1）、凹凸贴图（2），以及原生 PBR 的 albedo、normal、roughness、metallic、AO（31 至 35）。未知类型保留数值，不猜测通道或色彩空间。`mapping_mode` 对已知的参数化、高度投影、平面、立方体、球面和圆柱映射提供名称；`mapping_unit.value` 保留 `pattern_scalemode`，其 `sdk_size_mode` 表达原生接口的零为相对尺寸、非零为绝对尺寸的分类。它不表示具体长度单位。

每个贴图还提供 `uv_scale`、`uv_offset`、`rotation_degrees`、`scale_z`、`offset_z`，以及 `projection` 中的原始行向量与 `matrix_rows`。矩阵按 `origin_uv_pro_matrix_xa/ya/za` 三个源向量逐行排列，不转置、不单位化；关闭投影仍保留矩阵。普通贴图的 `PatternFlags` 最低位对应 `use_image_alpha_channel`，不套用到凹凸或 PBR 贴图。`pattern_weight` 仅属于普通贴图，`bump_factor` 仅属于凹凸贴图。`pattern_off` 为零表示启用，非零表示关闭。

上述语义视图只解释显式保存的属性，不补构造器默认值，不合并重复贴图或过程纹理层。`status` 为 `decoded`、`missing`、`partial` 或 `invalid`；不完整向量的 `value` 为 null，各分量仍可通过 `components` 查看。原始字符串、未知参数、XML 层次及重复节点继续由 `source_parameters`、`xml` 和 `tree` 保留。这些设置不等于已经求得 UV、着色结果或最终外观。

`settings.map_bindings` 表达同一材质内的原生贴图引用关系。只有材质的直接 `Map` 子节点进入原生表，标签支持 ASCII 大小写；更深层的 Map 仍保留在 `maps` 中，但标记 `outside_native_table`。表键是 `Type` 的 32 位存储值，按有符号整数排序；类型零不创建条目。同类型的后一个节点替换前一个节点，旧节点以 `superseded` 和 `replaced_by_map_index` 保留。此选择规则不是根据文件名或参数相似性合并贴图。

`map_link` 是同一材质内的类型引用。缺失值、整数读取失败和对自身的引用按原生规则归零；引用链无目标时，按有符号类型顺序清除当前条目的引用。一次清除可能使后续条目能引用到该条目，因此不能同时清空所有悬空链。`entries` 提供原始引用、归一化值、有效值、直接目标及 `terminal_map_index`。循环链、不能确定的输入及其受影响条目会明确报告，不生成猜测的最终来源。Map 的 `Type` 缺失或整数读取失败时跳过该节点，不使其他已确定条目的关联变成未知。

每个有效条目通过 `texture_layers_source_map_index` 和 `texture_mapping_source_map_index` 指向纹理层及映射参数的来源。普通引用沿链共享终点的原生纹理层；原生类型 30 保留自己的层内容，只从终点取得映射方式、尺寸模式、旋转、缩放及偏移。`projection_frame_source_map_index` 指向投影偏移、角度和缩放三元组的来源，对应 `maps[].semantics.projection_frame`；`map_settings_source_map_index` 指向本条目的启用、权重及显式投影矩阵。所有索引均引用本材质的 `settings.maps`，不指向图片、几何或其他材质。此接口表达原生关联和来源，不展开过程纹理、重写源参数或计算最终 UV。

`maps[].texture_layers.entries` 按 XML 子节点顺序列出带 `LayerType` 属性的直接子节点，不要求标签为 `Layer`，不展开更深层的过程纹理。`child_index` 和 `xml_path` 指回源树；`source_parameters` 保留全部源属性。`semantics.type` 区分源字符串、类型词 `token`、类型表索引 `token_id` 与原生读取后的 `reader_type`，这几个编号不能互换。

层类型包括 IMAGE、PROCEDURE、GRADIENT、LXOPROCEDURE、CELL、TEXTURE_REPLICATOR，以及混合操作、GAMMA、TINT、组起止和透明背景组起止标记。读取器区分大小写：寻找小写 `layer` 后，用空格分隔类型词和剩余参数。未知类型词和 DISSOLVE、ATOP、IN、OUT 会回退为 IMAGE，并以专门的 `status` 标明。`argument` 保留修剪边缘空白后的完整剩余字符串；根据实际读取分支标记为纹理引用、组名或不读取，纹理引用不解析为本机路径。区域设置可能影响的非 ASCII 边缘空白报告为 `locale_dependent_whitespace`，不猜测原生修剪结果。

`semantics.parameters` 提供当前层类型实际读取的具名参数。纹理提供者包含映射、缩放、偏移、角度、不透明度、图像 gamma、过滤类型及过滤数值；GAMMA 读取 `layer_gamma`，TINT 读取 `layer_color` RGB。其他源属性仍保留，但不冒充该操作的有效参数。零值和缺失值不替换为运行时默认值。

`semantics.data_flags` 同时保留 `LayerDataFlags` 的源值与 `reader_value`：源位 9 移至运行时位 11，源位 10、11 被清除，其余位保留。`semantics.flags` 返回 `LayerFlags` 的三个低位及未命名高位；`reader_applies` 表示该类型分支是否读取这些标志。BRIGHTNESS、CONTRAST 和 CELL 分支不读取 `LayerFlags`。位值展开不代表每一位的业务意义均已确定。

`texture_layers` 是源层视图。`reader_applicability` 表示源 Map 的读取分支是否采用这些子层：`read`、`skipped` 或 `unresolved`；`reason` 给出原因。它描述读取本节点、尚未处理 `map_link` 的阶段，不代表最终材质可见性或共享后的内容。`activation_status` 和 `composition_status` 仍为 `not_evaluated`，库不配对组标记或执行混合及最终采样。

`settings.reader_profile` 描述材质 XML 文件读取器的版本选择。`material_version` 缺失或整数读取失败时采用模式 0；读取失败仍保留在 `version.status` 中，`mode_source` 为 `failed_read_uses_zero`。模式 0 的单贴图类型字段是 `layer_state`，非零模式使用 `layer`。此版本与 XML 外部压缩封装版本不同，也不表示所有旧版参数名已完成转换。键 20014 的材质 XML 读取器要求有根节点，不要求根节点名称一定是 `Material`；源节点名称继续完整保留。

材质 XML 整数字段按原生 UCRT 的十进制 `%d`／`%u` 转换规则读取：跳过 C 区域设置的空白，可带正负号，读取连续十进制数字，忽略后缀。例如 `9tail` 读取为 9，`0x10` 读取为 0。中间值按有符号或无符号 64 位范围饱和，再取 32 位结果；无符号转换也接受负号。整数结果中的 `source_text` 保留原值，`conversion` 给出格式、消费字节数、忽略的后缀、饱和标志及目标位模式。无整数可赋值时为 `invalid`，而不是成功读取零；非字符串的调用方输入为 `unresolved`。普通整数参数读取失败时不写入目标，`material_version`、`map_link` 和单贴图类型各自执行已确认的零值或构造值回退，不能统一替换为零。该规则限定于已识别的材质 XML 整数读取入口，不表示所有浮点和矢量读取规则已复现。

`settings.initial_parameters` 提供材质参数构造后、根节点数值读取完成时的状态，作用域为 `constructor_and_root_numeric_attributes_before_version_conversion`。它包含标志和 37 个颜色、系数、计数及开关字段，尚未执行后续版本转换或求得最终渲染状态。每个参数给出 `constructor_value`、实际使用的 `source_key`、`source_read`、`read_status` 和该阶段的 `value`。`written` 表示已确定赋值，`not_written` 表示保留构造值，`unresolved` 表示该值尚不能确定；总体 `partial` 不抹去其他已确定字段。

参数构造的标志为 `0x182001`；颜色通道初始为白色，`exit_color` 为零；`ambient`、`diffuse` 为 0.5，`finish`、`specular`、`reflect_fresnel`、`refraction_roughness` 为 0.05，`refract` 为 1，`front_weighting` 为 50，三个采样计数为 64。其余已列数值及开关的构造值见对应字段。根节点读取数值时不以激活标志作为赋值条件，整数开关通过非零判断转换，`back_face_culling` 保留完整有符号整数。RGB 读取必须三个分量都成功才覆盖整个颜色，缺失或读取失败的分量不会与构造值拼成新颜色。

已识别的材质 XML 浮点入口采用 C 区域设置、默认舍入模式下的 `%lg` 读取规则。它接受十进制和十六进制前缀、大小写不敏感的 `inf`／`infinity`／`nan`，保留忽略的后缀；例如 `2suffix` 为 2，`0x1.8p1` 为 3。出现指数标记后必须有指数数字，`1e+` 整项读取失败，不回退为 1。越界可赋值为带符号无穷大，下溢可赋值为带符号零；这些情况与无数字可赋值的失败不同。`conversion` 记录消费字节数、后缀、范围结果和 `destination_bits_hex`。非字符串输入仍为 `unresolved`。这不包含采用其他读取入口的预设内容文本。

普通有限浮点值仍为 JSON 数字。非有限值以对象保存：`floating_point` 为 `nan` 或 `infinity`，`negative` 保存符号位，`ieee754_hex` 保存 16 位十六进制 IEEE 754 binary64 位模式。矢量中的非有限分量采用相同表示。原生成功赋值的非有限数可处于 `decoded`／`written` 状态；这些状态表示读取结果已确定，不表示可用于有限坐标计算。`nan(snan)`、`nan(ind)` 和普通 NaN 的原生位模式分别保留，序列化不会把它们变成 `null`。

模式 0 使用原生旧名称表，其他模式使用当前名称表。字段直接从原属性集合取值，不进行连锁重命名；例如模式 0 的 `transparent_color` 读取 `translucent_color.r/g/b`，而 `translucent_color` 读取 `anisotropy.r/g/b`。这些看似不一致的名称保留在 `source_key`，库不按名称含义自行纠正。无法确定浮点词法转换时，结果保持 `unresolved`，不能把它当成读取失败后保留构造值。后续版本转换可能再次覆盖这些参数及贴图关系。

`settings.version_conversion` 在根参数和初次 Map 链接读取结果上执行原生版本转换。版本号按有符号整数比较，作用域为 `root_parameters_and_map_topology_before_provider_evaluation`。根参数转换按顺序执行：版本不大于 2 时复制透射与半透明颜色；不大于 4 时修正标志、发光颜色、折射粗糙度及 Fresnel 系数；不大于 5 时复制反射颜色并清除标志位 `0x400`；不大于 6 时再用 `reflect` 覆盖 `reflect_fresnel`。`root_parameters.operations` 保留中途被后续赋值覆盖的操作，源值仍在 `initial_parameters`。

贴图转换使用独立对象身份：版本不大于 2、类型 1 贴图启用时，新建或替换类型 14 并尝试链接类型 1；原标志含 `0x1000` 时，继续建立类型 12→1、13→12。版本不大于 3、位移距离非零且类型 2 存在时，建立类型 15、复制类型 2 的指定状态和本地纹理层，再删除类型 2。此复制不会复制显式投影矩阵轴，构造器也不写入这些轴，`matrix_axes_status` 明确记录这一点，不假定它们是单位矩阵；复制的链接若等于目标类型 15 则清零。版本不大于 5 时，已有类型 12、1 分别触发类型 4、26 的新建或替换，尝试链接来源并复制启用状态；来源未启用也会执行这两项转换。

上述类型 2→15 的状态复制包含独立的 `linked_option`，不包含 `origin_uv_pro_matrix_on`；新对象的真正矩阵开关保持构造值 false。`settings_copy_scope` 中的 `linked_option` 表示这一独立状态，不表示矩阵启用。矩阵轴和矩阵开关都不会因为其他状态已复制就自动继承来源。

链接设置失败时保留新对象的零链接。删除类型 2 不会把其他对象对它的引用自动改为类型 15；转换后的悬空链接通过纹理层访问器回退到自身容器，链接值本身不清除。版本小于 8 时，对遍历到的有效纹理层容器逐层 OR `0x800`；类型 30 仍持有本地层，另有从链接终点复制首层映射的操作。`local_layers.origin` 区分源读取、原生构造和本地层复制；复制来源不等于共享归属，也不表示提供者内部所有参数均已求值。

`map_topology.status: partial` 时，`objects` 和 `operations` 只保留可确定的处理前缀，`active_object_ids` 为空，不作为最终表使用。未知版本、影响分支的未知参数或循环链接均不通过猜测补全。转换后根参数与贴图拓扑的 `resolved` 仅针对所声明的作用域，仍不表示最终材质覆盖、纹理加载或着色已经完成。

`maps[].initial_layer_state` 重建本地层序列及 XML 标志状态。每个新 Map 先构造一层：数据标志为 `0x800`，启用为 true，另外两个布尔位置为 false。层集合对每个直接元素调用层读取器；有效层后只要还有兄弟元素，就立即构造下一层。因此空集合、全部节点被跳过的集合仍有一层；有效层后若只剩被跳过的节点，也会保留末尾默认层。`source_layer_child_index` 为空的默认层没有对应的源层节点。无法确定读取器接受结果时，`layer_count` 为 null，`layers` 只保留可确定的前缀。

单提供者的启用值来自 Map 的 `pattern_off` 读取结果；`Flags` 先覆盖数据标志，随后成功读取的 `enable_antialiasing` 只替换位 `0x800`，其实际旧版本源键仍由 `numeric_reader` 给出。类型 1 的 `PatternFlags` 位 0 写入 `option_bit_1`；其他支持类型由原生类型表选择 `BumpFlags`、`SpecularFlags`、`ReflectFlags` 等字段，位 0 写入 `option_bit_2`。表中没有对应项的类型不会读取相似字段，包括 PBR 类型 31–35。字段的整数转换和失败保留遵循实际 getter。

集合层的 `LayerDataFlags` 把源位 `0x200` 移至 `0x800`，清除原 `0x200`、`0x400`、`0x800` 后合并结果；缺失或读取失败时保留构造标志。适用分支的 `LayerFlags` 位 0、1、2 分别写入启用状态及另两个布尔位置，不与数据标志混合；CELL 等不读取该字段的分支保留布尔构造值。Map 级的 `Flags`、启用及抗锯齿读取规则不会套到层集合分支。

`version_conversion.layer_containers` 在上述状态上复制本地层，并对拓扑指定的有效容器逐层应用版本标志更新。未使用的本地容器不会因为所属 Map 有链接就一并修改；新建复制的容器保留层数量、默认尾层及各布尔值，并记录 `copied_from_object_id`。该视图仅包含层序列和已确认的标志状态，不包含完整提供者参数、混合公式或纹理像素求值，必须单独检查其 `status`。

`initial_projection_state` 和版本转换后的 `local_projection_states` 描述本地投影参数。构造时投影偏移和角度三个分量均为零，缩放三个分量均为 1，权重为 1，`linked_option` 与 `origin_uv_pro_matrix_on` 为 false。偏移、角度及缩放仅在完整矢量读取成功时赋值；源缩放的零分量替换为 1。类型 1、2 的权重分别取 `pattern_weight`、`bump_map_scale`，其他类型保留构造值。来源字段、旧模式键名和未确定的转换结果继续保留。

显式矩阵的开关与轴数据独立读取。三个轴各自完整读取成功才写入对应临时矢量，随后原生矩阵构造无条件执行，把三个矢量连续复制到矩阵存储，不因开关关闭而跳过。缺失或读取失败的轴分量会留下未赋值的原生临时数据，输出标记 `indeterminate_native_temporary`；无法确定的转换标记 `unresolved_read`，已确认的其他轴仍保留。仅三个轴均确定时提供完整 `storage_values`；其中可包含非有限值对象，`all_components_finite` 另行表示这些已知分量是否全为有限数。新构造而未经 XML 矩阵读取或未复制矩阵的对象标记 `not_initialized_by_constructor`；以上无法提供完整矩阵值的情况使该投影子视图保持 `partial`。

单提供者且类型不为 1 时，专属标志字段读取成功、原始 `map_link` 非零才把该字段位 0 写入 `linked_option`。此判断发生在自链接清零之前，不能用规范化后的链接值替代。类型 1 的对应标志只写入层选项，层集合不执行此单提供者规则。它们都不覆盖 `origin_uv_pro_matrix_on`。`linked_option` 的进一步求值含义尚不按名称推定。

`version_conversion.projection_getters` 给出版本转换后活动贴图的原生投影访问器返回值。拓扑中的 `projection_frame_source_object_id` 指明偏移、角度、缩放的共同来源；沿链接找到终点时读取终点的三个本地参数。类型 30 同样遵循此规则，其本地纹理层容器不改变投影参数的来源。访问器独立读取调用对象自己的显式矩阵、矩阵开关和 `linked_option`，不随投影参数一起继承。矩阵访问器按存储顺序返回三个矢量，不额外转置。

若旧版转换删除了链中的目标，原生投影查找失败，每个调用对象分别回退到自己的本地参数。例如 A→B→已删除对象时，A 读取 A 的本地投影，B 读取 B 的本地投影；A 不读取 B 的回退结果。`frame_resolution` 标记这一情形，原始非零链接不因此清除。已替换或删除的对象仍可在本地状态视图中查看，但不在活动访问器结果中求值。

访问器视图保留各参数的 `source_object_id`、来源赋值状态及矩阵有限性。未使用的本地投影值未知时，不阻止已确定的链接终点值返回；终点值未知时也不抹去调用对象自己已确定的矩阵。循环链接或无法确定的拓扑不产生猜测终点。此视图的作用域仅为 `map_projection_getters_after_version_conversion`，不代表组合变换、逐点 UV、提供者采样或最终着色已经求值。

`prepare_material_projection` 实现作用域 `native_projection_preparation_mapping_modes_3_to_7`。输入包括访问器返回的偏移 O、缩放 S、角度 A，以及原生几何上下文的参考点 P、尺寸向量 D、参考矩阵 B。角度使用度，乘以 `0.017453292519943295` 转为弧度；以列向量约定构造 `R = Rx(Ax) · Ry(Ay) · Rz(Az)`，输出方向矩阵为 `B · R`。不改变源角度范围，也不将不同顺序的旋转视为等价。

非零 `scale_mode` 使用模型单位因子 u：类型 6 将 D 改为 `(Dx/u, u, Dz)`；类型 5 将三个分量分别除以 u；类型 3、4、7 将三个分量设为 u。零 `scale_mode` 保持输入尺寸。随后仅类型 3 计算 `D = abs((Rz · Ry · Rx) · D)`，绝对值逐分量取；该运算会发生分量抵消，不等同于旋转后的包围盒范围。相对模式再计算 `O = D ⊙ O`，非零模式保持 O；输出原点为 `P + O`。

准备接口直接保留缩放 S，不执行下游的零缩放修正或求逆；`layer_data_flag_bit_2` 保留有效首层数据标志位 2 的整数结果。输出中的 `reference_dimensions` 是上述处理后的 D，不自动用它替换投影缩放。这里只实现已确认的准备分支，其他映射类型不套用该算法；源显式矩阵也不参与此步骤。几何参考上下文和 u 的自动选择、下游逐点坐标公式尚未统一实现。三角函数及浮点运算受平台数学库的舍入影响，不承诺跨平台逐位相同。

`resolve_material_projection_transform` 继续执行映射类型 3–7 的变换矩阵构造。将 S 中精确等于零的分量改为 1，求方向矩阵 Q 的原生逆矩阵 N，再得到 `T = diag(1/Sx, 1/Sy, 1/Sz) · N`。这是按行缩放，不是按列缩放；尺寸 D 和原点不参与这一矩阵运算。

求逆先用最大绝对元素归一化，归一化行列式绝对值大于 `1e-8` 时使用余子式法；否则沿原生的列正交分解路径计算，最多十轮，收敛阈值为 `1e-14`。分解后列平方长度要求最大值大于零、最小值严格大于最大值的 `1e-26` 倍，条件指标还须大于 `1e-15`。零矩阵、未收敛或未通过秩条件时，原生逆矩阵结果为单位矩阵，调用端继续缩放；输出明确保留失败原因，不将失败描述为成功求逆。中间溢出等非有限运算另行返回未求值状态。

在准备及计算完成后，本地 `origin_uv_pro_matrix_on` 为真则用本地显式矩阵替代 T，为假则使用 T。显式矩阵不沿 Map 链接继承，其三个连续向量按源存储顺序成为输出三行，不在此处转置或应用 S。未知开关、未知或非有限的已启用显式矩阵不会回退到 T。该接口的作用域为 `native_projection_transform_mapping_modes_3_to_7`，不包含最终逐点映射、纹理采样和图层混合。

`prepare_material_projection_sampling` 继续处理非零几何类型分支的渲染状态。类型 3、4/7、5 分别对应投影标志 8、16、32；类型 6 按已解析的层数据位 2 选择 64 或 128。非零 `scale_mode` 再添加标志位 1。渲染参考点经仿射变换的线性部分与平移部分分别舍入为 float，相加后再次舍入，得到 `render_origin`；用前一步的投影原点减去该值。尺寸精确为零时其逆尺寸设为 1，其他值取倒数，负值保留。

二维 UV 矩阵的源状态由 `layer_mapping_getters` 提供。普通链接使用终点首层的映射参数和数据标志；类型 30 保留自己的层容器、资源及数据标志，仅从链接终点复制首层的映射类型、尺度模式、角度、缩放和偏移。旧版转换调用该访问器时的复制另体现在本地 `layer_containers` 中；随后读取访问器也执行同样的映射字段选择。悬空链回退到调用对象，循环链保持未确定。

层的映射类型、尺度模式、角度默认零，三维缩放默认全 1，偏移默认全零。二维缩放赋值只在 XY 完整成功时执行，并把 Z 清零；之后独立的 `scale_z` 成功读取会原样覆盖 Z，显式零保持零。字段失败不擅自覆盖先前值，构造值、赋值来源和不确定状态分别保留。

`build_material_uv_transform` 将角度按度转弧度，使用数据标志位 4 决定 U 符号、位 0 决定 V 符号。设源缩放为 `(Sx,Sy)`，单位系数为 f：各分量绝对值不大于 `1e-10` 时使用系数 1；其他情况下，ElevationDrape 或非零尺度模式使用 `1/(f·S)`，普通相对模式使用 `1/S`，再乘对应翻转符号得到 a、b。两行线性部分为 `(a·cosθ,a·sinθ)`、`(b·sinθ,-b·cosθ)`。

普通分支直接以源 XY 偏移作为二维矩阵平移。ElevationDrape 先计算 `q=offset·f+elevation_origin`，然后 U 平移为第一行线性部分与 q 的点积取负，V 平移为 1 减去第二行线性部分与 q 的点积。非零尺度模式且调用阶段几何投影成功时，再将两行线性系数乘 `registration_unit_factor`，平移不变；这与后续渲染几何比例是两个独立步骤。单位系数及活动模型选择尚需显式上下文，不能默认等于 1。

模型的 `material_mapping_units_before_reference` 提供二维贴图的单位分派。设主单位因子 U 为 `material_projection_unit_factor`，第一、第二显示单位的分子/分母分别为 n₁/d₁、n₂/d₂。基类型相同且四个分量均严格大于零时，次单位比例 R 为 `(d₁·n₂)/(n₁·d₂)`；其他情况 R=1。尺度模式 0 返回 1，模式 1 返回 U，模式 2 返回 U/R。

模式 3–6 分别使用原生单位表中的米、毫米、英尺、英寸：目标分子/分母依次为 `1/1`、`1000/1`、`10000/3048`、`10000/254`，基类型均为 1。第一显示单位基类型为 1 且 n₁、d₁ 均严格为正时，因子为 `((n₁·目标分母)/(d₁·目标分子))·U`；否则回退 U。单位系统位保留，但不参与这些基类型相等判断。负数或大于 6 的尺度模式在单位查询中走 U 回退。

非零尺度模式且映射类型不是 ElevationDrape 时，再将上述因子乘实际引用链比例；其他情况不读取该比例。模型单位推导与引用链上下文选择分别表达，不能把“选择了一个模型”视为已确认引用比例。运算保留原生乘除顺序；正无穷通过正数条件后，某个中间比例可能非有限而最终除法得到有限零，各结果按自身状态报告，不通过改变运算顺序掩盖溢出。

相对映射中心为 `(0.5,0.5)`。绝对映射将二维 UV 矩阵每行的两个线性系数乘以单精度渲染几何比例，平移不变；各行中心再分别除以该行两个线性系数的欧氏长度。中心和矩阵属于准备状态，球面和圆柱分支是否使用中心由各自公式决定。

`sample_material_projection` 先将顶点舍入为 float，减去调整后的原点再舍入，然后按三维投影矩阵逐行求值，每个结果分量再次舍入。需要法线的分支用同一矩阵变换单精度法线，不使用逆转置。设投影点为 `(x,y,z)`、逆尺寸为 `(a,b,c)`、中心为 `(h,k)`，二维仿射变换前的公式为：

| 映射 | 坐标规则 |
| --- | --- |
| DirectionalDrape | `(x·a+h, y·b+k)` |
| Cubic / Solid | 选法线绝对值最大轴；相等时 X 优先于 Y、Y 优先于 Z。X 面使用 `(±y·b+h,z·c+k)`，Y 面使用 `(∓x·a+h,z·c+k)`，Z 面使用 `(±x·a+h,y·b+k)`；符号取决于选中法线分量的正负 |
| Spherical | 将投影点按三维长度归一化；`u=atan2(y,x)/(2π)`，负 u 变为 `1-abs(u)`；`v=1-acos(z)/π`。零长度点保持原值。绝对模式再将 u、v 分别乘 `π/a`、`π/(2a)` |
| Cylindrical 侧面 | 经包含 z 的三维长度归一化后按球面相同规则求 u。相对模式 `v=z·c+k`，绝对模式 `u*=π/a`、`v=z·b+k` |
| Cylindrical 端盖 | 仅在端盖标志有效且法线 Z 绝对值严格大于 X、Y 两者时使用；正负端盖不翻转。相对模式为 `(x·a+h,y·a+k)`，绝对模式为 `(x·b+h,y·b+k)` |

上述公式说明数学关系；实现保留原生混合精度，不能用全双精度公式替代所有中间步骤。角度函数和角度归一化使用 float，比例常量分别为 float 的 `0.15915493667125702`、`0.31830987334251404`；绝对模式的 π 系数先按 double 求商，再转为 float。分支结果再次按二维仿射矩阵计算，最终 U、V 存为 float，接口以 double 容器返回这些值。不裁剪、取整或自动消除 UV 接缝，也不承诺不同数学运行库逐位一致。

Map 和纹理层的 `numeric_reader` 提供已确认的数值读取过程。`parameters` 以当前参数名标识读取位置，`source_keys` 和 `source_attribute_base` 指明该模式实际读取的 XML 属性；例如模式 0 的 `image_gamma` 读取源 `reflect_color`，不会把相似名称视为同义词，也不会逐项改名后再次读取。`status/value` 是这些源属性的解码结果，`write_status/reader_value` 是结合父级分支及读取条件后的写入结果。使用版本相关参数时应采用这一视图；原有 `semantics` 和 `source_parameters` 继续保留按源字段名称查看参数的方式。

`write_status` 为 `written`、`not_written` 或 `unresolved`，不表示最终着色启用。普通 Map 的投影字段在层集合分支判断前读取；单提供者参数及子层参数受各自读取条件约束。投影缩放三个分量中的零值替换为 1；二维 `pattern_scale` 和独立 `scale_z` 不套用此规则。`pattern_offset` 必须完整读取 XY 后才读取 Z，Z 缺失或读取失败时本次写入使用零；因此其 `value` 是二维源值，成功写入的 `reader_value` 是三维值。单独存在的 Z 不会产生偏移写入。`pattern_off` 返回零表示启用的布尔结果，`origin_uv_pro_matrix_on` 和 `enable_antialiasing` 返回非零为真的结果；源整数另保留在 `value`。

此视图描述已确认的显式写入，不补完整对象的构造状态，不计算矩阵组合、链接后的继承或最终 UV。无法确认的数值转换和字段名选择报告未确定；模式 0 的最后一个原始投影矩阵行名称没有可用名称表项，标记为 `unavailable_mode_zero_table_entry`，不生成猜测属性名。

`maps[].reader_path` 区分 `layer_collection`、`single_provider`、`skipped` 及未确定分支。直接源 `Filename` 的文件主名为 `layers`、扩展名为 `pma` 时采用层集合，比较不区分 ASCII 大小写；Map 自身的 `M633`、`M541` 和 `M556` 在此分支不读取。层集合逐个读取直接元素子节点，无效的层标记不能让嵌套参数包生效。其他已确定的文件名走单提供者分支；缺失或零 Map 类型、位于原生直接 Map 表之外的节点标记为跳过。

单提供者的 `single_provider_type_before_preset` 保留源字段及单独的 `reader_value`：缺失字段使用原生构造类型 1，显式 6 转为 4，显式 0 根据第一资源引用的扩展名选择 1 或 2，Map 类型 30 再覆盖为 5。之后的预设分支仍可能改写类型。`first_resource_reference` 提供默认资源服务返回的引用、源值、转换规则和 `path_parts`；后续预设及参数包选择使用转换后的引用。缺失 `Filename` 时资源列表为空；存在但内容为空时仍创建资源，二者通过 `resource_created` 区分。

默认资源引用通常保持原样。存在首个 `<…>` 标记且标记能够按有符号十进制前缀读取时，`marker` 保存前缀、整数、后缀及原始标记内容；空标记 `<>` 表示 -1。正数规范为 `<整数>`，负数规范为 `<>`；零值省略标记及后缀，空前缀返回空引用。以精确小写 `http:` 开始的有效复合引用只返回前缀，此规则不包含 `https:` 或大写变体。例如 `wood.pma<0>image.jpg` 返回 `wood.pma`，因此读取 wood 预设。无效整数标记保留原引用；超出有符号 32 位范围或可能依赖区域设置的标记报告未确定，不据此选择材质分支。

资源转换限定于 `native_default_resource_service`，不调用宿主扩展服务，不解析整数标记的业务用途。它不会重新执行源 `Filename` 的层集合入口判断：转换后才得到 `layers.pma` 的单提供者仍属于单提供者。原始引用、层参数与追加引用列表继续保留源写法；`lookup_status: not_performed` 表示库未查找或加载外部资源。

层的 `semantics.reader_path` 是“该层读取器被调用时”的局部分支；是否实际读取还需检查层自身的 `reader_applicability`。纹理提供者直接对 `LayerType` 的引用参数作词法拆分：扩展名 `pma` 优先选择内置预设或 `pma_user_data`；其他扩展名下，提供者 3、4 选择 `M633`，7 选择 `M541`，其他类型不读取这两个包。预设的主名及过程类型由 `preset` 返回，`grad1d` 把提供者改为 3，其他已识别预设改为 4，结果见 `provider_type_after_dispatch`。`type.reader_type` 仍保留类型词最初选择的编号。旧式内容参数使用独立的 `legacy_parameters` 视图，不套用现代 `M633` 参数表。

词法路径视图保留源引用，仅用于解释读取分支，不定位文件。它处理原生逻辑前缀及 Windows 路径分量，并按 UTF-16 单元检查原生每分量 260 字符缓冲区的边界；超过边界时原生拆分结果清空，报告 `native_buffer_limit_clears_parts`。可能受区域设置影响的非 ASCII 名称比较保持未确定。`LAYEREDPROCEDURALNAME` 不被擅自转换为 `layers.pma`。

贴图及纹理提供者层的 `semantics.additional_texture_references` 解释 `M556` 中的追加资源引用。`entries` 保留原生追加顺序、重复项和空项；`append_index` 是本字段内的零基顺序，不是全局纹理编号，也不是最终资源容器的槽位。`value` 是解码后的不透明引用，`source_fragment` 及 `source_byte_offset`、`source_byte_count` 对照 UTF-8 源属性字符串，保留原有引号与转义写法。

`M556` 使用原生字符串列表语法：引号外的空格、制表符和逗号分隔引用；引号内可含这些字符。反斜杠在引号前按奇偶数量处理，其他位置保持原样。连续逗号可以产生空项，尾逗号本身不增加末项；未闭合引号仍按原生规则读取并标记 `unterminated_quote`。这不是 CSV 或 JSON，不能直接套用通用列表分割器。缺失、空列表与无效源值分别报告，不尝试加载资源。

材质定义的 `texture_references` 汇集源引用：先保留原有 `Filename` 节点，再追加 `LayerType` 主引用和 `M556` 追加引用。新增项通过 `source_attribute`、`reference_kind`、`map_index` 与 `layer_child_index` 标识来源；后者为 null 时表示 Map 本身。它是引用清单，不是最终采样顺序；应结合源层及 `map_bindings` 读取原生关联，不能按文件名去重或将引用清单索引当作材质槽位。

贴图及纹理层的 `procedures.entries` 提供直接子节点 `M633` 中的过程参数包。原生查询选择第一个大小写完全匹配的 `M633`，即使该节点的类型无效，也不改选后面的同名节点；后续节点以 `selection: later_matching_node` 保留。`M634` 是过程对象类型编号，与 Map 的 `Type` 及 `LayerType` 类型编号不同。

编号 1–70 的参数读取结构由 `parameters` 表达，区分浮点数、无符号 32 位源值及 RGB 三元组。过程颜色使用大写后缀 `.R/.G/.B`；不能用其他材质参数的小写分量名替代。`source_type` 描述源字段类型，不替代枚举、开关或着色器业务含义。未知参数通过 `unmapped_source_parameters` 保留，未知类型不会套用其他类型的参数表。`Mxxx` 字段保持原名，不推定单位或工程意义；不填充缺失的构造默认值。

过程类型 10 另有 `channels`，按源子节点顺序选择最多五个通道，不按标签名重排；额外通道标记 `outside_native_channel_limit`。每个通道选择第一个 `M635` 子节点，再按其子节点顺序返回 `control_entries`。`M171` 被原生读取后丢弃，不用于决定控制项数量；`M173` 与 `M174` 写入同一选择字段，后者存在且有效时覆盖前者。`reader_selector` 保留所选源字段；源值无效时不猜测结果。控制项的 `M211` 显式为零时，`reader_value` 为 1，原始 `value` 仍为零；缺失时不补默认值。

`procedures.activation_status` 与 `evaluation_status` 当前均为 `not_evaluated`。参数读取结构已识别不代表过程纹理的完整业务含义、公式或最终采样结果已还原；其完整原始子树仍保留在 `tree`。

`replicators.entries` 提供直接 `M541` 纹理复制器参数包，同样选择第一个大小写完全匹配的节点，不以更晚的同名节点补齐缺失字段。`M542`–`M547`、`M550`–`M553` 为浮点数；`M548`、`M549`、`M554`、`M555` 为无符号 32 位源值。`M548`、`M549` 的 `reader_value` 是非零转真后的布尔值，原始 `value` 保留整数。参数的未确认业务名、单位及复制采样规则不作推定。

`replicators.initial_state` 的作用域为 `M541_reader_output_from_empty_attachment`，结合父级读取分支确定是否构造对象。构造值为：`M542`、`M543`、`M544` 分别是 25、50、80；`M545`–`M547` 为 0；`M548`、`M549` 为 false；`M550`、`M551` 为 2000、500；`M552`、`M553` 为 100；无符号整数 `M554`、`M555` 为 40000、100。缺失字段及已确认的整数或浮点读取失败保留构造值；无法确定的转换保持未知。后面的同名节点不补齐第一个节点的字段。

原生复制本地纹理层时，已存在的复制器会新建复制器对象和内部设置对象，全部 14 个参数按值复制；源复制器不存在时清空目标附件。`copy_policy` 的这一规则仅针对复制到新纹理层，不概括所有运行时赋值操作，也不表示整个纹理层中的资源都采用同一种复制方式。版本转换输出的 `local_layers.replicator_copies` 给出独立参数副本，`source_layer_child_index` 为空表示单提供者，其他值对应源层集合中的直接子节点下标；参数复制不等于复制器的采样与生成规则已经求值。

`procedures`、`replicators` 和追加纹理引用的 `reader_applicability` 区分源读取分支采用、跳过与未确定。`read` 表示调用相应读取器，仍需检查包内 `selection`、字段 `status` 及类型范围；不保证存在有效参数对象，也不等于过程已经完成求值。

贴图和层的 `legacy_parameters` 解释旧式 `.pma` 内容记录。`entries` 对应直接元素子节点，`source_content` 按原生 `getContent` 合并该元素内的文本、后代文本及后代尾随文本；不包含本元素外的尾随文本。具名预设从第一个下划线后取记录内容，再用第一个普通空格分出字段名和数值文本。前缀不限定为预设名称；字段名和枚举字符串区分大小写，不作额外修剪。缺失空格时，原生读取器把字段名自身也当作数值文本。缺失下划线、未知字段或没有内容读取函数的预设，均保留原记录及跳过原因。

已识别预设使用各自的内容字段表。浮点数及有符号 32 位整数按数字前缀读取，尾随文本保留；整数越界按原生规则夹至 32 位边界。没有数字前缀的标量结果为零，并标记 `no_numeric_prefix_uses_zero`。颜色按连续三个浮点数扫描，失败时只写入之前成功扫描的分量。非有限值、浮点越界及受区域设置影响的数值前缀保留源文本并报告不完整结果，不填造有限值。

每条记录的 `value` 表示数值转换结果，`reader_value` 表示原生转换后写入的值。例如 boards 的 `crack_width` 乘以 100，clouds 的 `thickness` 乘以 20；原生拼写 `morter_width` 保持不变，不替换为另一个字段。`reader_scale` 只说明数值转换，不据此推定单位。brick 的 `bond_type` 按完全匹配的 Running、Stack、One-third、Flemish、Common、Dutch、English 分别写入 0–6；未知值不覆盖之前的有效值。

`legacy_parameters.parameters` 表示按源顺序应用显式记录后已确定的标量和颜色参数值，`source_entry_indices` 指向写入来源。颜色按分量记录来源，后来的不完整颜色可以只覆盖部分分量。渐变数组条目保留最近一次源记录，数组间的相互作用以 `gradient_controls` 为准。它与仅列举源属性的 `procedures.parameters` 含义不同；原记录始终可从 `entries` 找回。自定义 `pma_user_data` 保留直接元素内容的有序字符串列表，包括空项，不擅自赋予业务字段含义。

`grad1d` 的 `input`、`u_x_offsets`、`x_colors` 另由 `gradient_controls` 表达。原生构造五组独立控制点，每组初始位置为 0、1，前四组初值为 1、0，第五组为 1、1。位置记录清空五组列表，并为每个位置新建五个点：前四组值为零，第五组为 1。颜色三元组依次写入已有点，第一分量同时写入第 0、1 组，第二、第三分量写入第 2、3 组，第 4 组保持原值。组的业务名称尚未指定，不把它们直接命名为目标渲染器通道。

渐变列表按原生扫描消耗的长度加一个字符向前移动，不折叠连续分隔符。后续位置记录会替换先前颜色结果，后续颜色记录只覆盖已有点；不足三分量、颜色超出点数、扫描失败等情况报告不完整状态，不扩容或模拟原生越界访问。控制点分别标记构造来源、位置记录来源和数值记录来源；`reader_selector` 与 `input_selector` 保留已确认的原生编号。该视图表达内容读取后的控制数据，不执行插值或纹理采样。

`inline_materials()` 返回复合载荷中的内嵌材质。其 `material.is_valid` 是原生有效标志；`encoding: inline_material_v1` 是库的格式标识，不代表载荷中保存了版本号。`name` 是材质名，`display_name` 是显示名；没有显示名扩展的旧载荷以材质名作为回退，并标记 `display_name_source: name_fallback`。显式保存的空显示名仍保留为空。

`parameters` 按原生顺序提供 `color`、`transparency`、`specular_color`、`specular_factor`、`glow_color`、`glow_factor`、`ambient_factor`、`diffuse_factor`、`roughness_factor`、`reflect_factor`、`refract_factor`。每项包含原始 `flag`、布尔 `enabled` 和数值 `value`；关闭某项不会丢弃其保存的数值，也不会把原生系数直接换算为其他渲染系统的参数。

内嵌材质的 `map_unit`、`map_mode` 保留原生有符号枚举，并为已确认值提供 `map_unit_name`、`map_mode_name`。未知枚举标记为 `unknown_value`。`uv_scale`、`uv_offset` 是二维数组，`rotation_degrees` 使用角度单位。`texture_references` 分别保留 `pattern` 和 `bump` 路径，凹凸强度通过 `bump_factor` 返回；空路径和被关闭的普通贴图引用同样保留。库不查找外部图片、不计算这些映射的 UV，也不据此生成缺失贴图。后续未知扩展以 `unassigned_suffix_hex` 保留，不能视为已解释。

显示名之后的 `0xABCE` 扩展保存以 NUL 结尾的 UTF-16 JSON 字符串，长度为包含终止符的字节数。`extended_data.text` 保留原始文本，`source_bytes` 保留包含终止符的原字节；`json_status` 为 `parsed`、`empty` 或 `invalid_json`。有效 JSON 另提供通用 `value` 视图，不预设业务字段。需要保留重复键、空白和数值文本形式时，应使用原始文本或字节。

嵌入图片位于图形属性键 `0x5981`（22913）中，外层沿用属性数据封装：形式 1、2 直接存放载荷，形式 3 使用压缩数据。解封装后的布局为 256 字节 UTF-16 文件名区、32 位文件大小、32 位原生贴图类型及原始文件字节。`decoded.filename_field` 保留完整文件名区，包括终止符之后的剩余容量；`file_data` 提供图片原字节，库不解码或重新编码图片。`native_map_type` 保留完整数值，`attribute_group_matches_map_type` 核对其低 16 位是否与属性组一致。该数值不直接视作其他材质系统的贴图通道。

属性键 2006 是带封装的 UTF-16 字符串属性，`decoded.text` 提供字符串，`data` 保留包含终止符的原始字节。属性组及索引保持源值，不根据字符串内容推定业务字段。

属性组 4、键 10001 保存原生高级材质分配。索引 0 是不含终止符的 UTF-16 材质名，编码标识为 `advanced_material_name`；其他索引通过 `advanced_material_json` 保留 UTF-8 JSON 文本、原字节和通用 JSON 值。索引 1 的角色为 `part_material_names`，键是有符号部件索引的十进制字符串，值是材质名；索引 2 的 `material_part_index` 按材质名组织部件索引。源字符串、重复键和数值写法以 `text`、`source_bytes` 为准，不以 JSON 视图替代源载荷。

索引 1、2 还返回结构化的 `entries`。索引 2 的原生形状为 `{"材质名":{"19":"19"}}`：内层键和值均为同一个部件索引字符串。每项保留 `source_key`、`source_value`，提供 `part_index`、`material_name` 及形状检查状态。部件索引遵循有符号 32 位整数的规范十进制格式；`01`、`-0`、越界值不会被改写为另一个有效键。异常成员仍保留，未知属性索引不推定角色。该反向索引不用于覆盖正向表，也不用于推断部件与三角形的关系；`geometry_mapping_status` 明确为 `not_established`。

图层组合的属性组 0、键 4、索引 0 通过 `layer_group_overrides` 返回按源顺序保存的覆盖表；组 1、键 4、索引 0 通过 `layer_group_sync_state` 返回同步模式。模式 0 为 `sync_use_override`，1 为 `always_unsync`，2 为 `always_sync`，其他数值保留且名称为 null。这些结果可从 `graphics_records()` 的属性解码结果读取。

覆盖表首先保存一个 u32 项数，每项为 u32 图层 ID、u32 位数及该位数个 u16 存储字。原生存储长度确实为位数乘 2 字节，不能按通常的位图压缩长度跳读；实际位图只使用前 `ceil(bit_count / 16)` 个字的有效位。`source_storage` 保留全部存储字，`packed_words`、`set_property_bits` 提供有效位图视图。属性位 11、12、14、25、26、32、35 分别为颜色、线型、线宽、显示、打印、冻结和透明度的覆盖标记，其他置位保留于 `unassigned_property_bits`。标记表示该属性具有组合内覆盖，不是属性值本身，也不等同于“隐藏”或“冻结”；最终显示仍需结合图层值、同步模式、模型链接及视图条件。

原生类型 47、子类型 33 保存根模型的显式视图链接顺序，`native_records()` 的对应项通过 `view_link_sequence` 展开。偏移相对于含四字节流前缀的 `data`：偏移 38 为 u16 原始 `sequence_flag`，偏移 40 为 u32 项数，偏移 44 起为 u64 ID 列表。`entry_ids` 保留源顺序、重复值和零值，不按数值排序、不改写为其他对象 ID。`entries` 提供同序的逐项解释：零值为当前模型自身（`current_model`），非零值为模型链接（`model_link`），`source_index` 与 `source_id` 保留来源。原生运行时还会根据当前链接列表补入或删除条目；本库未执行此协调过程，标记 `runtime_reconciliation: not_evaluated`。`sequence_flag` 的用途尚未确认，原始值继续保留。长度错误写入该项的 `decode_error`，不丢弃后续记录。

原生类型 49、子类型 1 的图层记录通过 `native_records()[i].layer_definition` 读取，支持内部版本 1 至 7 的公共布局。`layer_id` 是图层表内的 u32 标识，与外层记录的 u64 `id` 不同；不同表中的相同图层 ID 不能直接合并。结果与记录的 `stream`、`offset` 一起使用，不自动将同名图层或同号图层关联到其他模型。

`name` 和 `description` 来自原生字符串链接键 1、2；重复键按源顺序更新名称视图，全部条目仍保留于 `strings`，包含原始偏移、键、标志、长度、尾部存储和逐项错误。该图层读取路径使用原生代码页参数 1200：无前缀字节逐个扩展为同值字符，`FF FE 01 00` 采用同样的窄字节形式，其他 `FF FE` 及 `FF FD` 形式读取 UTF-16LE；名称视图在首个空字符处结束。不能把此路径的规则直接套到所有原生字符串。未确认的字符串键不赋予业务名称。外层 `links` 和 `data` 保留完整原始内容。

图层的 `display`、`print`、`frozen` 分别读取偏移 46 的 u16 状态字位 5、6、14。`access_mode` 为位 12 至 13，并按原生读取规则将旧位 4 合入最低位；`locked` 对应 `access_mode == 1`，不能将所有非零模式解释为锁定。原始 `state_flags` 与其他 `unassigned_state_bits` 同时提供。

`by_layer_symbology` 包含图层颜色索引、带符号线型值和无符号线宽值。偏移 76、80 的旧颜色和扩展颜色都保留：扩展值非零且与旧值兼容时使用扩展值，否则退回旧值；小于等于 `0xfffffffd` 的扩展值以低 8 位作兼容检查，`0xfffffffe`、`0xffffffff` 按原值比较。这里返回索引，不自动换算为 RGB。`transparency` 为偏移 84 的原生 float32 值，不改写范围；非有限值返回 null 和 `transparency_error`，`transparency_source_bits` 始终保留源位模式。版本 4 至 7 的 `business_code` 为偏移 92 扩展字右移 3 位后的低 16 位，其他版本返回 null，未分配位继续保留。

图层记录中尚未确认的范围通过 `unassigned_ranges` 保留源偏移和载荷。版本 0 及大于 7 的版本返回 `unsupported_version`；已支持版本的长度错误写入 `decode_error`。图层自身的值不等同于某个组合或视图中的最终值，`view_visibility` 仍为 `not_evaluated`。

### 图层表及模型关联

原生类型 10、子类型 1 的记录通过 `layer_table` 提供表头。偏移同样包含四字节流前缀：36 为 u32 子记录数，40 为未命名 u16 字段，42 为 u16 原始表标志，44 为 u64 选择值。选择值 0 表示本地表（`local`），`0xfffffffffffffffc` 表示图层组合（`layer_group`），`0xfffffffffffffffe` 表示嵌套模型链接（`nested_model_link`）；直接链接以其原生 ID 表示。尚未确认的 `0xffffffffffffffff`、`0xfffffffffffffffd` 保留为 `unassigned`。选择值不同于该表外层记录的 `id`。

图层组合名称来自字符串链接键 10，名称视图选用第一个同键链接，全部字符串仍保留。嵌套链接路径保存在应用号 `0x56f1` 的链接中：载荷包含 u32 未命名字段、u16 键、u16 标志、u32 项数及 u64 ID 列表。键 1 为引用路径，按原生顺序保留于 `linkage_paths`；`path_linkage_index` 指向第一个键 1 条目。不会因其损坏而自动改用后面的同键路径。原始路径、重复 ID、尾部存储和逐项错误均可读取，路径缺失明确返回 `path_status: missing`。

`Document::layer_tables()` 返回一次建立的只读关联目录：

| 字段 | 内容 |
| --- | --- |
| `tables[i].native_record_index` | 表头在 `native_records()` 中的数组索引 |
| `tables[i].member_record_indices` | 表内图层记录在 `native_records()` 中的数组索引，保持原生顺序 |
| `tables[i].attribute_record_indices` | 同作用域、同原生记录 ID 的 `graphics_records()` 候选索引 |
| `tables[i].override_bindings` | 覆盖表条目到本表图层记录的引用，按图层 ID 匹配 |
| `tables[i].sync_attributes` | 同步属性的来源记录和属性数组索引 |
| `model_references` | 模型到图层组合表的原生 ID 引用及候选表索引 |
| `unassigned_layer_record_indices` | 未能归入已确认表边界的图层记录索引 |

表内成员必须满足声明数量、连续记录边界、相同源流及图层子记录类型；不满足时 `membership_status` 为 `invalid`，不会跨流拼接成员。属性匹配通过文件索引将 SSYS/SSYSA、SMG/SMGA、SMC/SMCA 容器对应起来，保留上级作用域；同号记录不会跨容器配对。属性记录或图层 ID 有重复时保留全部候选，分别标记 `ambiguous_attributes`、`ambiguous_layer`；找不到覆盖条目对应的图层时标记 `missing_layer`。`override_bindings` 中的 `attribute_index` 是属性数组的位置，`entry_index` 是覆盖表条目的位置，均不是源属性的原生索引值。

模型头的原生类型 47、子类型 32 在偏移 492 保存 u64 图层组合表 ID。`models()[model_id].layer_group_references` 保留此值及模型头流路径、记录偏移；短头返回 `unsupported_header`，0 表示无关联。`layer_tables().model_references` 只匹配系统容器中的图层组合表原生记录 ID；返回 `resolved`、`none`、`missing`、`ambiguous`、`invalid_table` 或 `unsupported_header`，不按名称推测关联。所有数组索引均仅在所属 `Document` 内有效。

这些接口提供保存于文件中的关联。组合的部分属性可通过下述 `group_states` 求值；链接继承和视图条件叠加后的最终图层状态尚未计算，`inheritance_status` 为 `not_evaluated`。

### 图层组合属性同步

`layer_tables().group_states` 返回图层组合的派生属性及原生来源，不改写 `native_records()`。组合表与本地图层表均位于 SSYS 系统容器；在同一文件作用域中，选择值为 0 的本地表唯一且双方成员边界有效时才求值。图层用各表内的 `layer_id` 对应；派生成员按无符号图层 ID 排序。

同步先对齐成员集合：文件中新增的图层加入组合，组合中独有的旧图层退出派生成员。这一步在三种同步模式下都会执行；退出的原生记录索引保留在 `excluded_group_record_indices`，原始记录不删除。

| 同步模式 | 已存在的组合图层属性 |
| --- | --- |
| `sync_use_override`（0） | 设有覆盖位时使用组合值，否则使用文件图层值；没有该层覆盖条目时同步全部已支持属性 |
| `always_unsync`（1） | 使用组合值 |
| `always_sync`（2） | 使用文件图层值，忽略覆盖位 |

缺失同步属性使用原生默认模式 0，`sync_state_source` 为 `native_default`。未知模式、损坏属性、歧义表或记录返回明确的未求值状态，不根据名称或数组次序选择候选。

当前求值属性为 `color_index`、`line_style`、`line_weight`、`display`、`print`、`frozen` 和 `transparency`，其覆盖属性位分别为 11、12、14、25、26、32、35；底层覆盖表也提供 `overrides.transparency`。每层的 `properties[name]` 返回 `value`、`property_bit`、`native_record_index` 及 `selection`（`file_sync`、`group_value` 或 `new_file_layer`）。`override_source` 在使用覆盖位图时指明属性记录、属性数组及条目索引。

`group_table_index` 和 `file_table_indices` 指向目录中的 `tables`。每层保留 `file_record_indices` 与 `group_record_indices`；重复 ID 不自动合并，歧义仅阻止受影响图层求值。`status: evaluated_supported_properties` 仅表示上述七类属性已求值；部分失败为 `partially_evaluated`，无法建立来源为 `not_evaluated`。非有限透明度返回 null，并在属性上保留错误。

名称同步包含独立的名称表更新规则，尚未求值，`name_synchronization` 为 `not_evaluated`；其他样式、链接继承及视图裁剪也未包含在该结果内。`display` 不能直接作为最终视图可见性，`view_visibility` 仍为 `not_evaluated`。

原生链接长度支持三种形式：头标志不含 `0x1000` 时固定为 8 字节；含 `0x1000` 且不含 `0x4000` 时为 `(低 8 位 + 1) × 2` 字节；同时含两标志时，字数为 `低 8 位 × 2^位8至11`，再乘 2 得到字节数。扩展形式检查至少两字且不超过 65,535 字，并检查完整载荷边界，适用于较长的引用路径等链接。

## 显示与辅助坐标系属性

属性组 0、键 22634 的 `display_style_reference` 保存 32 位显示样式条目 ID。组 0、键 22626 的 `clip_volume_settings` 保存首个原始字及 `forward`、`back`、`cut`、`outside` 四个区域的标志和样式 ID。`display`、`snap`、`locate` 分别表示显示、捕捉、定位状态；原始标志和未命名位仍保留。它们作为元数据返回，不用于自动裁剪或过滤几何。

组 0、键 109 的 `section_clip_data` 保存左、右、前、后、上、下六个裁剪开关，以及 `perspective_up`、上下高度、前后深度和旋转矩阵。`serialized_rotation` 保留文件中的 3×3 矩阵，`rotation` 按原生读取规则在右侧乘以绕 X 轴正向 90° 的旋转；原始标志、未命名位和附加状态字保留。组 1、键 109 的 `section_clip_frame` 保存原点及方向，方向不自动单位化。这两个属性独立返回，不推定不同记录之间的裁剪配对关系。

支持的图形记录在构件 `metadata.display_state` 中返回公共显示头的原始状态字和 `permanently_invisible`。当前已确认类型为 19、20、21、37、40、44、52、54、62、97，状态字位于源记录 `data` 的字节偏移 36，永久隐藏对应掩码 `0x0400`。其他位保留为 `unassigned_bits`。未支持的类型或过短的头返回 `unsupported_header`；`view_visibility: not_evaluated` 表示尚未合并图层、链接、裁剪等视图条件。

属性组 1、键 22295 的普通布局以零值头开始，解码标识为 `auxiliary_coordinate_system`，提供坐标系类型、视图独立标志、`origin`、`scale`、按行保存的 3×3 `rotation` 及 64 位 `element_id`。末尾扩展保存在 `extra_data`，存在时标记为 `opaque`。辅助绘图坐标系不自动视作构件变换，也不据此推定地理坐标参考系统。

盒体命令 30 的 `origin0`、`origin1` 是上下底面的中心，标记为 `origin_convention: face_centers`。底面顶点分别按中心加减半尺寸乘以对应轴向量计算；上下底面可以具有不同尺寸和偏移。
