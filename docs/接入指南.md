# 接入指南

本指南介绍如何在 C++ 工程中使用解析库。代码中的文件路径是示例，请替换为实际输入。

原生依赖引用可从 `document.native_records()` 的 `links[].decoded` 读取：先检查 `encoding == "native_dependency_link"`，再检查 `status`。`entries[].references` 保存已确认的引用描述；跨所有者引用还提供 `owner_reference_id`，模型引用提供 `model_index`。路径形式单独保留，不能把所有 ID 都并入结构树。`dependency_index_input` 只说明该链接是否满足原生依赖索引的入口条件；活动对象解析仍须结合 `runtime_resolution` 的状态。未解释字节及格式细节见[原生依赖链接](格式说明.md#原生依赖链接)。

格式 7 的紧凑参数还提供 `entries[].expanded_selector`。使用 `descriptor` 前检查该子对象的 `status == "resolved"`；外层链接的 `partial` 可能只是仍存在未命名位或范围，不能替代子对象的有效性检查。需要对照原值时读取 `field_mappings[].source`，角度归一化不会修改源载荷。

处理引用时同时保留 `lookup_profile`：普通元素引用与额外产生的所有者依赖可能具有相同 ID，却允许不同的查找范围。`owner_system` 包含模型未命中后的系统回退；`owner_system_file` 还允许系统所有者入口继续查其他模型。`target_lookup: skipped_maximum_id` 只表示成对目标的原生提前退出，不应删除整个条目或合并同 ID 的其他引用。实际目标仍需载入上下文，查找规则本身不是活动对象解析结果。

类型 47、子类型 20 的 `owner_reference_path` 单独提供引用路径。先检查 `status`，再按 `steps` 的顺序处理；其中最终目标步骤不能当作所有者切换步骤。`selected_linkage_index` 可用于访问原始链接。这个接口描述原生路径程序，尚不提供外部模型载入或活动目标定位；格式及边界见[所有者引用路径](格式说明.md#原生所有者引用路径)。

同类型的其他已识别应用签名通过 `application_record` 暴露头字段和原生输入规则。`0x56DF` 的声明长度与 `decoder_input` 范围各有用途，调用方不要据声明长度截掉输入尾部。这部分仍是部分解析，不能用版本分派信息替代尚未实现的载荷转换，详见[其他原生应用记录](格式说明.md#其他原生应用记录)。

需要转换 BFA 驱动关系时，将 `BfaTree` 的 `value.decoded` 对象传给 `resolve_bfa_driven_references`，并显式提供上下文：

```cpp
p3d::BfaDrivenContext context{editing_component_id, registry_is_complete};
auto references = p3d::resolve_bfa_driven_references(decoded_bfa, driven_id, context);
```

`registry_is_complete` 表示该组件项目的全部注册节点和父关系都已提供，不是文件成功打开或字节全部读完。资料不足时传入 `false`，保留未解决状态。按 `input_handle_source_indices` 读取已经构造的输入句柄；若 `inputs_status` 为 `native_early_return`，只使用返回的前缀，不跳过失败项后继续拼接后面的输入。句柄构造、属性存在性和公式求值是不同层次，详见[格式说明](格式说明.md)。

## 1. 构建与安装

基本构建方式见 [README](../README.md#构建)。CMake 开关如下：

| 选项 | 默认值 | 作用 |
| --- | --- | --- |
| `P3D_BUILD_TOOLS` | `ON` | 构建 `p3d-inspect` |
| `P3D_BUILD_TESTS` | `ON` | 构建合成测试并注册 CTest |
| `CMAKE_BUILD_TYPE` | 由 CMake 决定 | Ninja 单配置构建建议显式指定 `Release` 或 `Debug` |

仅需静态库时，可以在配置阶段传入 `-DP3D_BUILD_TOOLS=OFF -DP3D_BUILD_TESTS=OFF`。非 Windows 构建使用系统 iconv 处理 GB18030。

安装已经构建的库：

```sh
cmake --install build --config Release --prefix install
```

调用工程的 `CMakeLists.txt`：

```cmake
cmake_minimum_required(VERSION 3.20)
project(my_app LANGUAGES CXX)
find_package(p3d CONFIG REQUIRED)
add_executable(my_app main.cpp)
target_link_libraries(my_app PRIVATE p3d::reader)
```

配置调用工程时，通过 `-DCMAKE_PREFIX_PATH=<安装目录的绝对路径>` 指定库的位置。仓库的 [examples](../examples/consumer.cpp) 提供了独立调用程序，包含 Windows 中文命令行路径处理。

## 2. 文档与场景的生命周期

```cpp
p3d::Options options;
options.threads = 4;
options.decode_binary_fields = true;
p3d::Document document(std::filesystem::u8path(u8"example.p3d"), options);
auto scene = document.native_scene();
```

`Document` 在构造时读取并解析文件。`objects()`、`native_records()` 等返回文档拥有的只读引用，使用期间应保持文档存活。`native_scene()` 返回拥有自身数据的场景，可独立保留；每次调用都会重新构建场景，不是隐式缓存接口。

原生记录的 `modification_time` 提供文件保存的实体最后修改时间，读取 `milliseconds` 前检查 `finite`。该数值使用本地时间基准，完整源位模式和记录内偏移同时保留；它不随调用机器的时区自动转换。单独读取八字节时间字段时，可包含 `<p3d/native_metadata.hpp>` 并调用 `decode_native_modification_time(bytes)`，长度不符返回 `not_evaluated`。详细偏移和数值约定见[原生记录的修改时间](格式说明.md#原生记录的修改时间)。

`for_each_primitive()` 传入的 `PrimitiveView` 是临时视图。几何和范围指针借用场景数据；回调过程中不要修改场景，离开回调后不要保存对 `view` 本身的引用。

单流大小限制默认 256 MiB，调用方可通过 `Options::max_stream_bytes` 调整。此限制不是整个文档的内存预算。需要完整二进制叶解码时，保持 `decode_binary_fields = true`。

模型单位从 `document.models()` 读取。每个模型的 `unit_records` 保留模型头中的单位记录及源位置；只有一条记录时另提供 `units`。`units.storage_unit`、`display_unit_1`、`display_unit_2` 分别保留存储单位和两个显示单位的编码及分子、分母。不要根据单位名称字符串反推比例。

需要核对模型初次输入的对象身份时，可调用 `document.native_model_id_assignments(model_storage, initial_id_counter)`。存储路径应指向同时容纳 SMC／SMG 子容器的模型目录，计数器应是开始这次加载时的实际值。接口自动按控制列表、图形列表的顺序共用索引；检查 `status` 后读取 `registry`，按 `input_occurrence_index` 和容器路径保持来源身份。原始文件头计数器、场景树父子关系或文件中最大的 ID，都不能直接替代尚未确定的加载上下文。此接口不自动挂接属性，详见[模型 ID 登记](格式说明.md#模型控制记录与图形记录的-id-登记)。

在相同上下文下调用 `document.native_model_attribute_input(model_storage, initial_id_counter)`，可读取 `attachments` 中已确定的属性集合及其登记目标。该接口保留控制属性先于图形记录的时序，也保留两个属性容器间“对象已有集合”的状态。用 `target.native_record_index` 定位源记录，以 `target.input_occurrence_index` 区分输入身份；不要重新按原始 ID 连接。属性来自哪个容器与目标属于哪个列表是两个独立信息。详见[模型属性挂接](格式说明.md#模型初次输入的属性挂接)。

`units.factors.data_units_per_meter` 是米到存储值的转换系数；`meters_per_data_unit` 是其倒数。有限且大于零时，模型的 `coordinate_context.unit_status` 为 `decoded_native_unit_factor`，可读取 `coordinate_context.scale_to_meters` 或 `length_scale_to_meters`。库保持原始几何坐标，不自动乘该系数；地理坐标系仍需另外确认。缺失、重复或不支持的模型头，以及不可用的比例，均通过状态说明，不使用固定毫米假设。

材质绝对投影使用另一系数 `units.factors.material_projection_unit_factor`。按实际投影上下文选择模型，检查该系数的 `status == "computed"` 后，可将其 `value` 赋给 `MaterialProjectionContext::absolute_unit_factor`。该数值已经由库按源单位比例计算；不要用 `scale_to_meters` 替代。这里解析的是文件模型头状态，不包含运行时模型单位修改或跨模型上下文的自动选择。

二维贴图单位另见 `units.factors.material_mapping_units_before_reference`，按尺度模式 0–6 提供相对、主单位、次单位、米、毫米、英尺和英寸的系数及分支依据。`secondary_to_primary_display_ratio` 保留两个显示单位之间的原生比例。这些系数尚未乘引用链比例；不要直接把它们当作完整引用场景的映射单位系数。

模型的 `coordinate_records` 保存坐标状态及源记录位置；仅有一条时，另提供 `coordinates`。`coordinates.model_kind` 区分物理、图纸和绘图模型，并保留原始类型值。`reference_origin.source_value` 是完整源坐标，`reference_origin.value` 已按模型标志处理 Z 分量；`auxiliary_origin.value` 是引用规则可能使用的另一组坐标。这些字段不自动确定地理坐标系，也不改写几何顶点。

`reference_origin_correction(reference_input, context)` 查询引用原点修正。将实际被引用模型的 `coordinates` 赋给 `ReferenceOriginContext::model_coordinates`；这表示已选定连接的模型。确认引用尚未连接时，可明确设置 `model_attached = false`。元数据缺失本身不能证明引用未连接。

辅助原点可能还需要两个原生上下文条件：`auxiliary_origin_gate` 为零才允许进入该路径，`auxiliary_origin_suppressed` 为真时阻止该路径。它们是原生引用／模型状态的查询结果，不是调用方任意选择的处理选项。库尚未从全部引用关系中自动恢复这两个条件；需要它们而未提供时返回 `not_evaluated`。主要原点已足够决定结果、路径明确被禁用，或源辅助原点确为零时，不要求无关条件。

返回 `status == "computed"` 时，`offset` 是待从引用平移点减去的修正量。`native_return_code` 为 0 表示选取了非零原点并执行缩放、旋转，为 1 表示无需修正；浮点下溢可能使前者的结果也为零。该接口使用 `reference_input` 中已解析的基础矩阵和比例，不包含完整引用链变换。

## 3. 读取几何与原生实例

引用基础坐标可从 `reference_input.affine_inputs` 读取。需要仿射矩阵时，调用 `reference_affine_transform` 并提供 `ReferenceAffineContext`：`origin` 沿用原点修正上下文，`provider_id` 必须来自已确定的扩展状态。高 16 位非零时，还需 `provider_scale_available`；查询成功时另需 `provider_y_scale`。这些状态不能根据参数缺失自行填零或假。默认 `force_z_scale = true` 与引用链查询一致；局部查询关闭该选项时，须提供 `model_z_scale_enabled`。

检查结果 `status == "computed"` 后读取 4×4 行矩阵 `matrix`。若 `native_translation_sentinel` 为真，平移列保存原生特殊值，不能作为普通几何坐标使用。`origin_correction` 保留独立查询结果及未能求值的原因。

确认了引用对应的完整持久属性集合后，可调用 `reference_extension_input(attributes)` 获取初始扩展状态；相关图形记录也提供同名字段。检查 `status == "decoded"` 后，`scale_provider.id` 可赋给仿射上下文的 `provider_id`。这一步自动处理精确属性键、重复项、长度拒绝和初始默认值，但不代替属性目标关联，也不适用于未合并的运行时修改。提供者启用时，其实际比例查询仍需继续求值；扩展包其他参数仍有未解释部分。

同一结果中的 `indexed_resources` 是文件资源目录索引，`object_references` 是先查连接模型、未命中再查系统索引的对象 ID，两者不能混用。对象引用可能先指向所有者引用路径，仍需检查目标解析状态。`parameter_source` 用于区分已接受的主包与初始默认状态；`status == "decoded"` 不代表这些资源或裁剪对象已经定位。

已确定连接模型和初次输入计数器时，可调用 `document.native_model_object_lookup(model_storage, initial_id_counter, id)` 查询登记对象。检查 `status == "selected"` 后，从 `selected_scope`、`target` 读取来源；`missing` 表示两个完整索引均未命中，`not_evaluated` 表示上下文不足。这一步不执行运行时删除过滤、所有者路径展开或几何变换，不能直接把返回的记录当作最终裁剪几何。

需要展开初始登记图中的所有者路径时，调用 `document.native_model_reference_path(model_storage, initial_id_counter, id)`。仅在 `status == "resolved"` 时使用完整的 `collected` 和非空集合的 `target`，按 `lookup_scope`、`input_occurrence_index` 区分输入身份；不要对重复追加的对象去重。失败结果中的 `collected` 只是已处理前缀。该查询不执行运行时加载回调或推定类型 13 引用的目标模型，详见格式说明中的作用域限制。

类型 13 原生记录中的 `reference_target.model_selection` 会自动给出 `file_default_model`、`model_id` 或 `model_name` 选择条件。先检查其 `status`，再读取对应 ID 或名称；名称可同时提供 UTF-8 和原生 UTF-16 码元。选择条件已确定不代表目标文件和模型已定位，不要直接按当前文件中的同名模型建立关系。默认模型 ID 可从已选目标文档的 `file_header().initial_probe.default_model_id` 读取，但仍须遵守该头部探测状态的限制。

已取得正确目标文件且引用尚未连接模型时，可包含 `<p3d/reference_model.hpp>`，通过 `initial_reference_model_query(record, requested_load_mask)` 构造初次输入查询，再调用 `resolve_reference_model(query, file_context, model_context)`。`file_context` 提供该文件的默认模型编号及实际目录；`model_context` 提供该文件的模型缓存、专用槽和必要的构造结果，值使用调用方对象图身份。仅在 `status == "matched"` 时读取 `object_index`；`unresolved` 是缺少上下文，不能当成模型不存在。也可分别调用 `select_reference_model` 和 `lookup_native_model`，在取得所需模型状态后继续处理。挂接和模型内容加载仍是后续步骤，详见[目标模型查找](格式说明.md#文件取得后的目标模型查找)。

已确认实际连接关系时，将引用节点的 `connected_root_known` 设为 `true`，`connected_root` 填为目标模型在同一图中的下标，并使 `root_present` 与其是否为空保持一致。随后使用 `match_reference_model(query, graph, reference_index)` 或后代搜索，即可共享目标节点的文件和模型信息；无需逐个复制这些字段。`reference_connected_root` 查询连接目标，`reference_parent_root` 查询父链所属模型，二者用途不同。填写关系只是在解析结果中记录身份，不会执行原生挂接回调，详见[连接根模型](格式说明.md#连接根模型的身份与反向引用)。

如果已经确定所有者路径的收集对象、终端下标、运行时所有者类别及引用链，可用 `owner_reference_path_transform` 计算路径矩阵。引用链仍按当前引用到宿主排序，但该路径内部使用 `compose_owner_reference_chain_transforms` 的左乘规则，不能先用普通链组合结果代替。终端下标为零时，还须提供对象变换接口的已知查询结果。检查返回的 `status`；只有 `computed` 才提供可用 `matrix`。详见[所有者引用路径的变换](格式说明.md#所有者引用路径的变换)。

已确定引用链时，将各项仿射查询结果按原生当前引用到宿主的顺序传给 `compose_reference_chain_transforms`，停止引用本身不加入序列。接口保留原生右乘顺序，`contains_native_translation_sentinel` 提醒是否遇到含特殊平移值的输入；它不负责自动选取目标模型、搜索宿主、解析扩展提供者或检测原始引用图的环。单项矩阵与组合接口的范围见[引用仿射构造与链组合](格式说明.md#引用仿射构造与链组合)。

引用加载中的祖先重复判断可通过 `<p3d/reference_recursion.hpp>` 的 `reference_ancestor_repetition()` 单独求值。提供此次检查时的两组引用标志、原记录的 `reference_target` 和 `ReferenceRepetitionContext`；宿主数组从当前宿主到上级排列，保留被跳过项的层级。仅在确认全部父链都已给出时设置 `complete_ancestor_chain`。设置开关、查找文件字符串、实际默认模型状态及宽字符比较语义均须来自已确定的上下文，不能从同名文件推测。只在返回 `status == "resolved"` 时读取 `repeated`；具体匹配规则见[引用祖先链的重复判断](格式说明.md#引用祖先链的重复判断)。

```text
NativeScene
├─ definitions：源几何定义，每份定义有 source_key、source、geometry
├─ elements：构件元数据与实例列表
│  └─ instances：定义索引、变换、源几何 ID、样式和引用来源
└─ metadata：对象图、模型、材质、块目录、错误及其他场景数据
```

`Geometry::vertices` 使用 double；`faces` 为从 0 开始的三角形顶点索引。线、点类图元和文字分别通过 `lines`、`texts` 及图元类型表达。

显式多边形网格的法线、UV 使用独立数组，不能用顶点索引直接访问：

| 字段 | 用法 |
| --- | --- |
| `normals` | 与当前几何坐标一致的法线数组；每项为 `optional<Point3>`，无法变换时为空 |
| `source_normals` | 与 `normals` 同序同长度的原始法线，保持命令局部坐标和值 |
| `uvs` | 原始二维 UV 数组 |
| `face_normal_indices`、`face_uv_indices` | 与 `faces` 等长；每项为可空的三角形角点索引，分别指向上述 `normals` 和 `uvs`，从 0 开始 |
| `face_uvs` | 与 `faces` 等长的展开 UV，便于无需独立索引的调用方使用 |

源数组中的重复值、未引用项和索引复用均保留。多个网格按命令顺序拼接数组并调整索引，不自行合并相等数据；`NativeScene` 中已有的共享定义仍由实例引用。上述命令网格未提供某一角点索引通道时，相应面条目为空，即使存在数组也不借用顶点索引；库不生成缺失的法线或 UV。一个有效法线索引可能指向空的派生法线项，调用方须同时检查两层 `optional`。独立的 BGFB `mesh_bgfb_polyface()` 入口遵循其原生法线／UV 等长回退规则，并在 `report.attribute_bindings` 中报告索引来源，详见[格式说明](格式说明.md)。

可选索引引用缺失数组或越界时，受影响三角形的对应 `face_normal_indices` 或 `face_uv_indices` 为空；有效几何和其他通道继续返回。越界位置可从命令的 `decoded.index_bindings` 以及 `Geometry::unknown` 查询。命令中的原始索引保持源值，不能当作已验证的数组下标直接使用。

命令及实例变换作用于法线时，采用线性部分的逆转置，忽略平移，不自动单位化；`source_normals` 始终保持原值。奇异变换、非有限输入或不可表示的计算结果使受影响的 `normals` 项为空，但源值、面和索引仍保留。浮点病态矩阵不具有额外精度保证。`PrimitiveView` 借用定义坐标的数据；自行烘焙实例时应应用相同的法线变换，或使用 `expanded()` 的已放置结果。

网格的颜色、命名字符串、附加逐面 UV、平滑组和逐面材质列表可从命令解码结果的 `mesh_channels` 读取。包含非空扩展或扩展诊断的几何图元范围也携带 `mesh_channels`；全空扩展不生成逐三角形附加元数据。其 `source` 保存完整源通道和对应状态，`triangles[j]` 对应范围内第 j 个三角形。下面的 `range` 表示一个图元范围：

```cpp
if (range.contains("mesh_channels")) {
    const auto& extra = range.at("mesh_channels");
    const auto& source = extra.at("source");
    for (const auto& triangle : extra.at("triangles")) {
        const auto& materialId = triangle.at("material_id"); // null 或完整 uint64
        const auto& colorIndices = triangle.at("color_indices");
        if (!colorIndices.is_null()) {
            const auto& rgb = source.at("float_colors").at(colorIndices.at(0).get<std::size_t>());
            // rgb 是第 0 角点的源颜色；库没有转换颜色空间。
        }
    }
}
```

这些池的索引属于当前图元范围的 `mesh_channels.source`，不属于 `Geometry::vertices` 或普通 `uvs`。`face_uv_point_indices` 引用附加的 `face_uv_points`，材质标识和平滑组分别从源面传递到其三角形；它们不自动替换范围样式、主 UV 或法线。数量不符和未支持的对应会返回空项，并可从 `source.bindings` 及几何 `unknown` 检查原因。自行烘焙 `PrimitiveView` 的镜像时，还应同步交换附加角点索引的第 1、2 项；`expanded()` 已完成此操作。

颜色网格可以没有主 UV。此时命令的 `param_index_usage` 可为 `color`，第三组源索引仍负责颜色查表，而 `Geometry::face_uvs` 和 `face_uv_indices` 对应项为空。不要仅凭源多边形中存在 `uv_indices` 就访问空 UV 池；重建接口已经区分这些用途。颜色引用无效时保留源颜色与几何，并通过 `bindings.color_status` 报告问题。

若需要了解原生三角化路径如何选择这些通道，可读取 `source.native_triangulation`。先检查 `status == "mapped"`；`normal_mode` 给出平面或平滑组规则，`polygons` 给出该路径选择的材质与组键。布局吻合时，`triangles[j].native_triangulation` 直接定位相应源面。这个选择可能与源材质条目不同，例如缺少平滑组时原生路径会补零材质；源条目仍保存在原有字段中。

`mesh_channels.normal_evaluation.status == "computed"` 时，可从 `triangles[j].native_triangulation.corner_normals` 读取三个派生角点法线；空项表示变换后不可用。`source_corner_normals` 保留命令局部坐标值。`expanded()` 会处理实例变换和镜像角点交换；使用 `PrimitiveView` 自行烘焙时，应同步对这组值应用逆转置和角点交换。派生值来自对库现有三角形应用原生平滑规则，尚不代表原生 GLU 三角化结果相同，也不自动替换源法线和范围外观，详细条件见[格式说明](格式说明.md#原生三角化输入选择)。

在需要单独读取原生网格消费路径的三角化结果时，也可调用：

```cpp
auto result = p3d::triangulate_native_mesh(mesh_command.at("decoded"));
if (result.at("status") == "triangulated") {
    const auto& buffers = result.at("buffers");
    const auto& points = buffers.at("points");
    const auto& normals = buffers.at("normals");
    const auto& uvs = buffers.at("uvs");
    for (const auto& face : buffers.at("faces")) {
        // face 的三个零基索引同时访问 points、normals、uvs。
    }
    for (const auto& triangle : result.at("triangles")) {
        const auto& corners = triangle.at("corners");
        // 每个角点提供 point、uv、source_corner 和 generated。
    }
}
```

输入须是操作码 25 的解码结果，并满足 `mesh_channels.native_triangulation` 的输入门槛。结果是命令局部坐标中的独立三角形，保留源多边形、材质 ID 和法线组键。原角点 UV 先转为单精度；自交等情况生成的新角点没有源角点下标，UV 按原生回调置零。接口不依赖系统 GLU、OpenGL 或绘图上下文，多个调用使用各自的三角化器。

`buffers` 提供该路径完成位置、UV、法线注册后的索引网格。`points`、`normals`、`uvs` 等长，由 `faces` 中的零基索引共同访问；分量按原生输出转为单精度，JSON 数字保留转换后的值。`face_material_ids[i]` 对应第 `i` 个三角形，材质不参与顶点复用键。`triangles` 仍保留注册前的角点和来源，用于追溯生成交点及源面。平滑分支与非平滑分支的注册容差、精度和复用键不同，见[格式说明](格式说明.md#原生三角化输入选择)。

该输出使用命令局部坐标，不自动替换 `Geometry`，尚不完成材质定义、部件和视图样式之间的最终绑定。可通过第二个参数调整计算容量上限，默认 3,000,000；它用于限制输出及单次轮廓的输入/交点存储，不是文件格式限制。失败返回 `status: invalid` 和原因，不发布部分三角形或缓冲。


每个 `PrimitiveView` 对应一个图元范围：

| 字段 | 用法 |
| --- | --- |
| `element_index`、`instance_index`、`definition_index` | 回到场景中定位构件、实例及共享定义 |
| `source_range` | 读取 `channel`、`start`、`count`，确定本范围覆盖的面、线或文字 |
| `geometry` | 读取定义坐标下的几何数组 |
| `matrix` | 按 `matrix[row][column]` 存储，以列向量计算 `M × [x,y,z,1]` |
| `winding_reversed` | 烘焙该实例变换时，是否需要交换三角形第 1、2 角点及对应 UV、法线索引 |
| `topology` | `triangles`、`polylines`、`points` 或 `annotations` |

遍历三角形范围的示例，假设 `scene` 已按上文创建：

```cpp
scene.for_each_primitive([&](const p3d::PrimitiveView& view) {
    if (view.topology != "triangles") return;
    const auto& geometry = *view.geometry;
    const auto& range = *view.source_range;
    auto start = range.at("start").get<std::size_t>();
    auto count = range.at("count").get<std::size_t>();
    for (std::size_t i = start; i < start + count; ++i) {
        auto triangle = geometry.faces.at(i);
        auto uv = geometry.face_uvs.at(i);
        if (view.winding_reversed) {
            std::swap(triangle[1], triangle[2]);
            if (uv) std::swap((*uv)[1], (*uv)[2]);
        }
        // geometry.vertices[triangle[k]] 是定义坐标。
        // 烘焙时还需应用 view.matrix；保留实例时交给下游场景处理。
    }
});
```

同一个定义可以被多个实例使用；请勿直接修改共享顶点以应用某个实例的变换。`scene.expanded()` 会按需生成展开后的逐构件 JSON。使用该结果时，不要再次烘焙同一变换。

`source_key`、模型 ID、对象 ID 和定义索引都具有文档作用域。合并多个文件时，应额外加入调用方自己的文档身份。

### BGFB 源曲线与 B 样条

`binary_fields()` 中的参数化几何包可以包含 `_type: "BsplineCurve"` 表。将该表传给 `BsplineCurve::from_bgfb()`，可读取控制点、权重、节点并在源坐标系内求值：

```cpp
// table 是已解码 BGFB 树中的一个 BsplineCurve 表。
auto curve = p3d::BsplineCurve::from_bgfb(table);
auto middle = curve.point_at(0.5);
auto homogeneous = curve.homogeneous_at(0.5); // 加权 XYZ 与求值后的 W
auto domain = curve.knot_domain();
```

对象拥有自己的数据，可脱离文档使用；只读求值可由多个线程同时调用。`poles()` 和 `weights()` 保留源控制点顺序。有权重时，源 XYZ 已经乘过权重，不能再次相乘；空权重表示非有理曲线。零或负控制点权重不会被删除。

`source_knots()` 保留源节点；`knots()` 返回用于求值的节点，源未保存节点时按原生规则生成。`closed()` 是源闭合标志，`periodic_pole_shift()` 表达原生特殊接缝的控制点索引偏移，不改变源数组。`point_at()` 和 `homogeneous_at()` 接受 `[0, 1]` 内的有限比例参数；比例映射到源有效节点区间，内部重复节点取右侧值，终点取左侧值。接口不会在闭合曲线上自动循环越界参数。

解码表的 `_spline` 提供数组检查状态、控制点坐标约定、节点来源、参数区间及周期索引偏移。`status: valid` 只说明通过结构及数值检查，不保证每个参数都有有限笛卡尔坐标，也不保证源闭合标志与几何首尾相符。无效数组保留原字段并返回 `status: invalid` 与错误信息；显式构建对象会抛出异常。求值后权重为零时，`homogeneous_at()` 保留齐次结果，`point_at()` 抛出异常。

需要原生曲线查询使用的位置与导数时，可调用：

```cpp
auto derivatives = curve.native_derivatives_at(0.5, 3);
auto point = derivatives[0];
auto tangent = derivatives[1];
```

返回数组依次为位置、一阶至指定阶数的导数。输入仍为比例参数，但导数针对**源节点参数**；若要得到针对比例参数的第 k 阶导数，应乘以 `(domain[1] - domain[0])` 的 k 次方。接口支持曲线阶数 2 至 26、导数阶数 0 至 24，有理曲线的高阶导数不因超过多项式次数而清零。

该接口遵循原生查询的越界约定：开放曲线夹到端点，闭合曲线按周期归约，精确上端点保留左侧值。内部重复节点取右侧导数。特殊闭合节点布局还须通过原生首尾控制点和权重检查，才使用对应的索引偏移；因此不满足这些检查的源表，其结果可能与仅按节点布局求值的 `point_at()` 不同。周期归约使用有界运算，不保证与原生反复加减周期的浮点舍入逐位一致。

原生节点容差由控制多边形长度与源节点间距决定，不能任意设为零。容差检查失败、控制权重或求值权重为零、非有限计算以及超出支持阶数时抛出异常，不改用差分近似。用于容差计算的权重转换只作用于本次调用的工作副本，源数组保持不变，可并发查询。

单条 B 样条的原生参考坐标系可用 `curve.native_frame_at(fraction)` 查询。返回对象的 `frame` 是按行存储的 4×4 仿射矩阵：前三列依次为切向、法向、副法向，第四列为曲线上位置。`method` 区分 `derivative_frame`、`control_polygon_frame` 和 `axis_fallback_frame`；原生导数、曲率或控制多边形法向不满足相应条件时，会依次进入这些回退路径。`tangent_magnitude` 针对源节点参数，`curvature` 在原生回退分支中为零，不据此推断源曲线是直线。

`status: computed` 表示完成了该原生计算路径，仍须检查 `basis_status`。零切线等情况会得到 `degenerate`，库保留其退化矩阵，不补造坐标轴。非有限计算或节点容差失败则抛出异常。此接口计算单段曲线的参考系，不代表复合曲线会最终选择这段曲线，也不自动确定材质投影范围。

这些接口对源曲线直接求值，不自动将设计操作数追加到活动场景，也不生成 B 样条曲面或布尔运算的网格。复合对象中的源路径和实例变换仍由各自的记录提供。

对于 `_type: "CurveVector"` 的完整源表，使用 `p3d::native_curve_frame(table, preference)` 查询复合曲线的原生参考坐标系。`preference` 默认为 0：按子项顺序尝试局部导数、后续子项的起点或导数方向，最后尝试单曲线参考系。1 优先采用首尾切线，平行时用参考轴补足；2 在首尾切线不平行时使用它们，否则进入局部搜索。其他整数与 0 使用同一路径。

```cpp
auto result = p3d::native_curve_frame(curve_vector, 2);
if (result.at("status") == "computed") {
    auto frame = result.at("frame").get<p3d::Matrix4>();
    auto sources = result.at("source_paths");
    // 同时检查 basis_status；computed 不保证矩阵非退化。
}
```

返回矩阵仍按行存储，前三列是选定基向量，第四列是参考原点。`source_paths` 是相对于输入表的 JSON Pointer，指出实际提供参考数据的子曲线；`method` 区分首尾、局部导数、后续起点、后续导数及图元回退。原生执行了矩阵正交化时另有 `square_normalization_success`；某些原生分支忽略该步骤失败，因此它可以为 false 而整体仍为 `computed`。嵌套 CurveVector 仅在局部搜索时按默认模式递归，不展开成一条折线，也不直接提供父数组的首尾切线。

接口支持线段、LineString、PointString、椭圆弧、B 样条，以及通过各自原生转换得到 B 样条的 Akima、InterpolationCurve、TransitionSpiral。`native_failure` 表示已经覆盖的原生搜索未找到参考系；`not_evaluated` 表示所需路径存在不支持的图元、非法输入、未定义的空子项调用、数值溢出或其他求值限制，附带 `reason` 和 `source_path`。这两种状态都不包含替代矩阵。查询保留源树与源数组，可并发调用；它不自动确定活动模型、投影范围或最终 UV。

对于 `_type: "AkimaCurve"` 表，可按原生插值规则取得派生 B 样条：

```cpp
auto akima = p3d::AkimaCurve::from_bgfb(table);
const auto& original = akima.source_points();
const auto& retained = akima.retained_point_indices(); // 原点列中的零基索引
const auto& spline = akima.bspline();
auto point = spline.point_at(0.5);
const auto& conversion = akima.report();
```

源点列须为 6 至 5000 点，按原生断开标记和相邻近点规则过滤后仍须至少 6 点。过滤只作用于派生曲线；`source_points()` 保留所有源点，`report().ignored_points` 提供被过滤点的源索引及原因。保留点列的首尾各两个点用于端部切线，实际插值端点是保留点列的第 3 点及倒数第 3 点，其原数组索引也包含在报告中。

`bspline()` 是开放、非有理、三次的派生曲线。其控制点和节点由转换生成，不是 P3D 内另存的一套数组；节点按实际插值区段的弦长累计归一化。BGFB 表中的 `_akima` 提供转换摘要，失败时记录 `status: invalid` 和错误，源 `points` 不被替换。Akima 曲线也可作为 `BsplineSurface::trim()` 的边界成员；不会自动追加到活动场景或作为其他参数化操作的完整求值结果。

对于 `_type: "InterpolationCurve"` 表，可取得开放或周期闭合的三次插值曲线：

```cpp
auto interpolation = p3d::InterpolationCurve::from_bgfb(table);
const auto& original = interpolation.source();       // 完整传入表
const auto& points = interpolation.prepared_points();
const auto& indices = interpolation.prepared_point_indices(); // 对应源点零基索引
const auto& parameters = interpolation.parameters();
auto point = interpolation.bspline().point_at(0.5);
const auto& conversion = interpolation.report();
```

`source()` 保留源字段，`prepared_points()` 表达原生相邻近点过滤和闭合准备后的点列，`parameters()` 给出对应的归一化插值参数。若原生规则追加闭合点，该点的索引仍指向源首点，报告中的 `closure_point_appended` 为 true。周期曲线最后一点是闭合标记，参与弦长参数计算；其位置即使只与首点近似重合也不改写，派生曲线在参数 1 处回到首点。

该接口遵循 BGFB 读取路径：派生曲线固定为阶数 4、非有理 B 样条；源 `order`、`knots`、`startTangent`、`endTangent` 不参与此路径的转换。开放曲线总按弦长生成参数，周期曲线由 `isChordLenKnots` 选择弦长或均匀参数。开放端部采用自动 Bessel 条件或 `isNaturalTangents` 指定的零二阶导条件，满足原生条件时还可按 `isColinearTangents` 对齐端部控制柄。`isChordLenTangents` 在此读取路径中不生效。报告分别提供有效闭合状态、节点间距、端部条件和未参与转换的字段，不能仅根据源 `closed` 或 `order` 推断派生表示。

过滤及闭合准备后最多 4998 点；无效输入、不可表示的距离、塌缩参数区间或无法求解的系统会抛出异常。BGFB 解码表中的 `_interpolation` 提供转换摘要，失败时记录 `status: invalid` 和错误，同时保留源字段。此曲线也支持 `BsplineSurface::trim()` 的边界转换；派生控制点与节点不是额外的源几何记录。

对于 `_type: "TransitionSpiral"` 表，可求值底层缓和曲线：

```cpp
auto spiral = p3d::TransitionSpiral::from_bgfb(table);
auto value = spiral.evaluate(0.5, 1e-8, 65536);
const auto& point = value.point;
const auto& derivative = value.derivative;
double bearing = value.local_bearing;
double curvature = value.local_curvature;
double error = value.quadrature_error_bound;
```

支持原生 BGFB 工厂接受的 `spiralType` 10 至 14。`source()` 保留传入表，`length()` 返回仿射变换前整条底层曲线的长度，`report()` 提供有效曲率和长度。原生工厂依据两端方位角的大小关系确定两个曲率的符号，方位角不按一周折返；不能直接使用源曲率符号推断转向。

`evaluate()` 的比例参数在 `[0,1]` 内，映射到源 `fractionA` 至 `fractionB`，支持反向及超出底层 `[0,1]` 的源区间。`point` 为经源仿射变换后的三维位置，仍相对于底层曲线参数零点定位，不以活动区间首点重新归零。`derivative` 为三维位置对 API 比例参数的导数，包含源区间方向和仿射缩放；`local_bearing`、`local_curvature` 为变换前底层曲线的方位角和有符号曲率。

坐标用数值积分计算。第二个参数约束变换后坐标中的积分截断误差，`quadrature_error_bound` 返回该误差界，`intervals` 返回实际积分区间数；误差界不包含浮点运算及三角函数舍入。第三个参数限制区间数量，预算不足、精度耗尽或数值溢出会抛出异常，不静默返回超出约束的近似值。零长度但有效的原生底层曲线返回变换原点和零导数。

源 `constructionHint`、`extraData`、`directDetail` 不参与这个 BGFB 读取路径。解码表中的 `_spiral` 提供源语义检查摘要，失败保留原字段并报告 `invalid`。底层求值与拟合 B 样条是两个独立接口；解码表的 `native_bspline_conversion: not_evaluated` 表示尚未执行拟合。

若需读取原生缓存拟合器的输入，可调用 `spiral.native_fit_input()`。它返回仿射变换前的 `local_points`、派生采样点对应的 `source_fractions`、活动区间起点的 `local_origin_offset`、经过原生方向检查的 `endpoint_bearings` 和 `endpoint_radii`。这些数组由原生规则生成，不是文件中另存的点列。采样只在显式调用时计算，返回 `bspline_fit_status: not_evaluated`，不会把采样折线当作已拟合曲线。

该接口使用原生固定角步长及四点 Gauss 积分修正，`stroke_error_estimate` 与 `origin_error_estimate` 分别是活动段及原点偏移积分的原生局部误差估计，不是误差保证，也不包含曲线拟合、仿射放大或浮点舍入误差。需要约束坐标积分截断误差时，使用前述 `evaluate()`。采样缓冲区最多 2000 点；后续原生拟合器另有 998 点上限，通过 `fits_native_point_limit` 表达，通过该数量检查不表示拟合一定成功。可传入总积分区间预算，默认 100000，预算包含活动段与原点偏移计算，超出则抛出异常。

若需重建原生拟合 B 样条，可显式调用：

```cpp
auto fit = spiral.native_fit();
auto fitted_point = fit.curve.point_at(0.5);
const auto& poles = fit.curve.poles();
const auto& knots = fit.curve.knots();
const auto& fit_report = fit.report;
```

`curve` 为已经应用源仿射变换的三维 B 样条。`report` 提供迭代次数、原采样点数、辅助节点的局部 XY 坐标 `expanded_local_points`、归一化拟合参数 `expanded_parameters`、归一化前的总参数长度 `parameter_length`，以及收敛阈值和最大区间长度变化。`updated_source_parameters` 为最后一次弧长更新后的原采样点参数，尚未归一化；原生最终转换使用这次更新之前的辅助节点，因此两组参数的总长度不必相等。

拟合参数来自迭代弧长，不能当作 `evaluate()` 的底层活动区间比例参数。拟合收敛不保证指定的几何误差；两三个采样点时还保留原生辅助节点和边界方程的特殊分支。退化区间、超过 998 个采样点、数值不可表示或 30 次内未收敛时抛出异常；不会返回替代折线。该接口可接受与 `native_fit_input()` 相同的积分预算。`BsplineSurface::trim()` 会自动使用这个拟合表示转换缓和曲线边界；与活动场景的完整求值关联仍未提供。

对于 `_type: "BsplineSurface"` 表，可读取双方向的源 B 样条曲面：

```cpp
auto surface = p3d::BsplineSurface::from_bgfb(table);
auto point = surface.point_at(0.25, 0.75);
const auto& u = surface.u();
const auto& v = surface.v();
const auto& trim = surface.boundaries();
bool outer = surface.outer_boundary_active();
```

`u()`、`v()` 和曲线的 `direction()` 返回只读 `BsplineDirection`，提供阶数、控制点数量、闭合标志、源节点、有效节点、参数区间和周期控制点索引偏移。曲线原有的同名便捷接口仍可使用。曲面控制点与权重以 `v索引 × U控制点数 + u索引` 顺序保存，U 方向连续；有理曲面的 XYZ 仍是已加权坐标，两个方向完成齐次组合后才除以最终权重。

曲面的两个比例参数都在 `[0, 1]` 内，分别映射到各自完整的有效节点区间；显式节点不会被改写为 `[0, 1]`。支持一般阶数、非均匀节点及一个或两个方向的周期闭合。`homogeneous_at(u, v)` 提供齐次结果，`point_at(u, v)` 在最终权重为零或结果非有限值时抛出异常。

`boundaries()` 保留源裁剪曲线树，`hole_origin()` 保留源整数；`outer_boundary_active()` 按该整数是否为零返回默认外边界的启用状态。`num_rules_u()`、`num_rules_v()` 提供源方向规则数量。`_spline` 给出每个方向的节点语义和 `trim_region_evaluation: not_evaluated`。上述点求值针对底层曲面，不判断点是否位于裁剪后的有效区域，也不自动生成带孔网格；不要仅凭求值成功丢弃裁剪树或将整个参数矩形视为有效表面。

需要查询裁剪区域时，显式指定源 UV 坐标中的容差：

```cpp
auto region = surface.trim(1e-6, 100000); // UV 边界带宽、派生线段总预算
const auto& report = region.report();
const auto& loops = region.loops();
auto location = region.classify({0.25, 0.75});
if (location == p3d::TrimLocation::Inside) {
    // 此 UV 位于有效区域内，并且离源裁剪边界足够远。
}
```

`loops()` 是按源环顺序生成的闭合 UV 折线，支持线段、折线、圆弧、B 样条、Akima、InterpolationCurve 和 TransitionSpiral 边界。它不改写源曲线、不合并重复环，也不生成三角网格。`report().loops` 提供相对于 `boundaries()` 的 JSON Pointer `source_path`、源/有效边界类型、折线索引和 `deviation_bound`。连续环的末点未回到起点时，`implicit_closing_segment` 记录派生闭合边的 `from`、`to`（使用该接口的 UV 坐标）；无需添加时为 `null`。闭合边参与边界带查询、奇偶填充和线段预算，源曲线树不被补写。Open 类型仍须先通过原生首尾闭合检查，不能借此把任意 Open 路径变成裁剪环。该偏差界由局部有理 Bézier 控制点包围范围与浮点余量计算，使用普通浮点运算，不是区间算术证明。

TransitionSpiral 按原生规则使用拟合 B 样条做端点检查和边界转换。报告中的 `curve_conversions` 记录相对于 `boundaries()` 的曲线 `source_path`、`source_type`、`representation: native_fitted_bspline`、控制点数及拟合迭代次数。此时 `deviation_reference: converted_boundary_curves` 表示折线偏差界针对转换后的边界曲线，`bounds_underlying_spiral_error: false` 表示不包含缓和曲线拟合相对底层积分曲线的误差。同一次裁剪只计算一次同一源对象的拟合；不同源对象不会因此合并。拟合失败也会使对应环报告错误和不确定状态。

`classify()` 返回 `Inside`、`Outside`、`BoundaryBand` 或 `Indeterminate`。`BoundaryBand` 表示落在调用方指定的源边界容差带内，不等于原生精确边界布尔值；重复环相互抵消后，其源曲线附近仍可返回边界带。近似误差影响判定时返回 `Indeterminate`。任一有效环未成功转换时，报告为 `incomplete`，所有查询均返回 `Indeterminate`；错误和原生规则忽略的节点分别列在 `errors`、`ignored` 中。

`ignored` 中的 `native_trim_conversion_unavailable` 专指已确认原生不会转换为裁剪曲线的直接 CurveVector、PointString 成员，包含源类型和路径；它不表示源数据被删除，也不用于掩盖未知曲线类型。Open 的闭合判断在这个过滤步骤之前执行，因此被忽略成员的端点仍可能改变源路径是否被接收。零权重或混合符号的内部控制点允许继续细分，原权重保持不变；是否成功以最终报告为准。

`trim()` 的查询坐标须在曲面的实际有效节点区间内，边界带宽也使用源 UV 单位。需要与 `point_at()` 或网格参数配合时，使用 `surface.trim_normalized(1e-6)`：它先将裁剪曲线的齐次控制点映射为曲面比例参数，再按该坐标系中的容差离散，查询范围为 `[0, 1]²`。两个接口均通过 `parameter_domain()` 返回 U、V 查询区间；报告的 `coordinate_space` 分别为 `source_uv`、`surface_fractions`，`source_knot_domain` 保留映射所用的源区间。它们都不改写源边界，也不跨周期接缝展开。无有效裁剪环时按原生规则返回 `Inside`。解析记录中的 `trim_region_evaluation` 不随这次独立求值改变，应检查返回对象的 `report().status`。

需要离散曲面时，可显式生成派生三角网格：

```cpp
p3d::BsplineMeshOptions options;
options.uv_tolerance = 1e-6; // 裁剪边界折线的 UV 近似容差
options.max_uv_edge = 1.0 / 32; // 派生三角形的最大 UV 边长
auto mesh = surface.mesh(options);
if (mesh.report.at("status") == "complete") {
    // mesh.vertices：三维曲面位置
    // mesh.parameters：与顶点一一对应的曲面比例参数，不是材质纹理 UV
    // mesh.faces：三角形顶点索引，UV 中按逆时针排列
}
```

`max_trim_segments`、`max_vertices` 和 `max_triangles` 控制计算预算。遇到未支持的参数化、数值问题或预算耗尽时，报告为 `incomplete`，`reason` 说明原因，三个几何数组均为空；有效区域本来为空时则可以返回 `complete` 和空网格。无效的选项值抛出异常。

网格支持孔洞和奇偶裁剪，并对片内共享边一致细分。内部节点重复次数等于对应方向的阶数时，按该节点分片，断裂两侧使用精确源节点的单侧值；即使 UV 相同也保留各片独立顶点，不跨断裂生成三角形。两个方向的断裂交点可保留四个不同位置。裁剪支持开放、单向周期和双向周期曲面，也支持非归一化节点域：先调用 `trim_normalized()`，然后与单位参数域求交；`uv_tolerance`、`max_uv_edge` 和输出 `parameters` 均使用曲面比例参数。收集到的 Outer/Inner 连续边界链包含末点到起点的隐式直线边；内部成员之间的间隙仍会使转换失败。零或混合符号的曲面权重需要通过下述分母非零判定。

`report.trim` 保留边界转换状态；`discontinuity_knots.u/v` 列出原始节点坐标中的内部分片位置，`patch_count` 为参数矩形数量，`meshed_patches` 为裁剪后含三角形的片数。`refinement_iterations` 为各片细分轮数的最大值。顶点和三角形预算作用于整个结果；参数矩形数量也不得超过 `max_triangles`。`world_space_error_bound` 为 `null`，表示没有三维弦误差保证。网格不会自动加入活动场景或生成放样封口，周期接缝顶点也不会自动焊接。源曲面和裁剪树保持不变。

`trim_domain_policy: source_uv_clipped_to_active_domain` 表示按保存的边界位置裁切。例如外边界禁用、以裁剪矩形内部为有效区域时，若归一化后的矩形横跨 `u=0.8…1.2`，网格只保留 `u=0.8…1` 的部分，不额外生成 `u=0…0.2` 的区域。源数据若在接缝两侧分别保存闭合环，两侧都会按奇偶规则处理；重复环不去重。`periodic_trim_unwrapping: not_performed` 表示没有取模或最短跨缝重解释，`periodic_seam_vertices: separate_parameter_coordinates` 表示 `u=0` 与 `u=1` 等不同参数位置保留独立顶点，即使它们的三维坐标重合。

网格报告的 `denominator` 说明有理分母检查。`method: source_weight_sign` 表示源权重严格同号，`polynomial` 表示非有理曲面；含零或混合符号权重时使用 `bernstein_interval_subdivision`，按有效节点矩形提取 Bernstein 权重并做向外舍入的区间细分。只有各片分母都可确认不为零，`status` 才是 `verified`。`verified_knot_rectangles`、`visited_cells`、`work_steps` 提供判定范围与工作量；失败还提供 `reason`。`BsplineMeshOptions::max_denominator_steps` 默认 1000000，用于限制节点提取和分母细分工作，不改变源权重或网格精度。它为零时仍可使用严格同号或非有理曲面的快速路径。判定尚未利用裁剪区域排除域外奇点，不能将失败直接理解为可见区域一定无效。

### 曲面参数曲线的原生采样

需要按原生规则对已经选定的曲面参数曲线采样时，使用独立头文件 `p3d/pcurve.hpp`：

```cpp
#include <p3d/pcurve.hpp>

p3d::PCurveStrokeOptions options;
options.uv_tolerance = 0.001;
options.spatial_tolerance = 1e-5; // 曲面坐标的长度单位
auto strokes = p3d::sample_native_pcurve(surface, parameter_curve, options);
if (strokes.report.at("status") == "complete") {
    for (const auto& sample : strokes.samples) {
        auto uv = sample.parameter; // X/Y 为曲面比例参数，Z 也保留
        auto point = sample.position;
    }
}
```

`parameter_curve` 是 `BsplineCurve`，其 X/Y 必须已表达为曲面比例参数；接口不自动判断它属于哪个曲面，也不把源节点域 UV 擅自解释为比例参数。曲面本身允许非归一化节点：接口会准备节点归一化的私有求值副本，并重新按该副本判定闭合控制点索引约定；`surface_knot_preparation` 区分 `normalized_copy` 和 `already_normalized`。这不是把原生底层采样函数直接用于任意节点域。输入曲线、曲面、属性及共享关系保持不变。此接口不替换 `trim()`、`trim_normalized()` 或 `mesh()` 的派生离散策略，也不负责区域树转换、闭合填充或三角化。

二阶曲线按保存的控制点次序逐段处理，闭合曲线包含最后到第一点的段；该原生分支不应用控制权重，也不使用 `minimum_points`、`start_fraction` 和 `end_fraction`。每段先按曲面高重数节点的交点分段，再夹持段端点的 X/Y 到 `[0,1]`，Z 保留。随后两个半区间分别以两段起步，按曲面三维采样误差增加段数。高阶曲线包含有理求值，使用指定的曲线比例区间，先分成 `max(2, minimum_points)-1` 个区间，再结合参数点和三维点的采样误差细分；此分支不会改写曲线采样点的 UV。高阶曲线的有限比例区间可以超出 `[0,1]`，曲线点求值夹持到有效端点；这也适用于闭合曲线，不套用另一条求导路径的周期回绕。高阶曲线得到的 UV 超出 `[0,1]` 时，返回的 `parameter` 保留该 UV，仅曲面点求值中的参数夹持到有效域。

`uv_tolerance`、`spatial_tolerance` 非正时分别采用原生缺省值 `0.001`、`1e-7`。`max_points` 限制工作点数组大小，包含传入的前一点；`max_evaluations` 包含重采样被替换的尝试。库预算耗尽、非有限数值或未支持的求值返回 `incomplete` 和空 `samples`，原因保存在 `reason`。无效选项抛出异常。

如果调用方正在追加**同一条原生采样流**，可通过第四个参数传入上一调用末尾的 `PCurveSample`。原生规则根据参数距离或三维距离省略重复起点；返回数组只包含新追加点，不会再返回传入点。`omitted_starts` 记录省略次数。该机制不推断模型关联，不合并其他曲线或实例。

`status: complete` 表示此采样流程结束，须另看 `sampled_tolerances_met`。每个 `intervals` 条目给出最终段数、采样误差及 `stop`：满足采样容差、达到原生 2048 段上限，或有符号参数步长小于 `1e-5`。二阶分支不检查参数点的误差，对应 `sampled_uv_error` 为 `null`。原生上限结束时可能仍未满足采样容差；反向区间的负步长同样触发步长停止条件。误差只比较相邻三个采样点，不能排除点间曲线偏离，因此 `continuous_error_bound` 始终为 `null`，即使采样容差已满足也不能当作连续曲线误差保证。

`interval_parameter` 标明报告中的 `offset`、`length` 属于整条高阶曲线的比例参数，还是二阶分段后的局部比例参数。二阶条目还提供 `source_pole_segment` 和 `pole_fraction_range`，可追溯到源控制点段及其被节点切分的位置；闭合曲线最后一段连接末控制点与首控制点。

`point_evaluation: native_clamped_blending` 表示点求值采用这条原生调用链的基函数规则，曲线和曲面阶数最多为 26。`clamped_surface_evaluations` 统计曲面求值时遇到域外 UV 的次数。参数曲线的有理分母恰好为零时，原生点求值把本次除数改成 1，返回齐次分子；`curve_zero_weight_fallbacks` 和 `curve_zero_weight_fallback_fractions` 记录次数与曲线比例参数，包含被重采样替换的尝试。它们不修改源权重，也不表示相应有理曲线在数学上存在有限值。曲面点求值没有该回退，零分母仍导致 `incomplete` 和空结果。普通 `point_at()` 与原生求导接口保持各自的定义。

### 已准备边界环的原生采样

已确认曲面与边界环的关联、完成曲线转换时，可按环提交整条 B 样条曲线，保留源成员次序：

```cpp
std::vector<std::vector<p3d::BsplineCurve>> prepared_loops;
// 填入各环成员：曲线须已打开，X/Y 为曲面比例参数；曲线自身节点域不必为 [0,1]。
p3d::PCurveLoopStrokeOptions options;
auto result = p3d::sample_native_pcurve_loops(surface, prepared_loops, options);
if (result.report.at("status") == "complete") {
    for (const auto& loop : result.loops) {
        // parameter 的 X/Y 对应原生边界缓存坐标；三维位置和参数 Z 也保留。
    }
}
```

此接口处理重新采样阶段，不负责从 `CurveVector` 选择环、转换源图元或打开周期曲线。闭合曲线返回 `incomplete`；原本已开放曲线保留自己的有效节点域，不强制归一化其节点。不能将一条高阶源曲线任意拆成多个 Bézier 成员后认为采样结果不变。曲面节点允许非归一化，接口仅准备一次私有曲面副本，并在成员间共用本次计算的节点分段表。

环级容差默认均为 `-1`。**仅当两者都严格小于零时**，UV 容差采用 `0.01`，三维容差采用曲面控制点包围盒对角线长度的 `0.0001` 倍。有理控制点先除以保存的权重，负权重和很小的非零权重同样参与；带原生断点哨兵坐标 `DBL_MAX` 的控制点不参与范围扩展。`control_range` 给出范围、对角线和跳过的哨兵点数。这是控制点范围，不是曲面精确包围盒。自动范围中的零权重或非有限计算返回未完成；调用方可以显式指定容差，但这不会消除曲面求值自身的奇点。零尺寸范围的三维容差回退为 `1e-7`。只有一个负容差或任意零容差时不启动包围盒规则，各非正容差分别回退为 `0.001` 和 `1e-7`。报告容差均为最终有效值。

同一环内传递末点，以原生参数距离或三维距离规则省略后继起点；进入下一个环时重置状态。空环保留为空结果，重复成员和重复环保留各自结果。接口不重排、不补内部断口、不添加末尾闭合边，也不做填充或三角化。`loops[].members` 记录成员下标、新增点的 `sample_offset` / `sample_count` 及单曲线采样报告。

`max_points`、`max_evaluations` 是整个调用共享的预算，前一点不会重复计入全局点数，重采样尝试仍计入求值次数；`max_loops` 和 `max_curves` 限制输入规模。任一成员失败都会清空整个返回的 `loops`，原因和位置记录在 `reason`、`failed_loop`、`failed_curve`，已执行成员的诊断保留。这是本库避免返回残缺结果的策略，与原生可能留下部分边界缓存的行为有所不同。总 `sample_count` 是返回点数，`evaluations` 是实际求值次数。`sampled_tolerances_met` 聚合所有成员的结果；`complete` 仍不保证满足采样容差或连续三维误差界。

### 从曲面源边界树直接采样

`sample_native_surface_boundaries()` 读取 `BsplineSurface::boundaries()`，完成原生环选择、成员转换和节点零处的周期打开，将源节点域 UV 映射为曲面比例参数，再调用上述环级采样。调用方无需自行提取和组合成员：

```cpp
p3d::PCurveBoundaryStrokeOptions options;
options.sampling.spatial_tolerance = 1e-5;
auto result = p3d::sample_native_surface_boundaries(surface, options);
if (result.report.at("status") == "complete") {
    // result.loops：按源环与成员次序的参数点和三维点。
}
```

它接受 `LineSegment`、`LineString`、`BsplineCurve`、`EllipticArc`，以及由已有原生转换器生成 B 样条的 Akima、Interpolation 和 TransitionSpiral。每个源成员按完整转换结果采样，不拆成独立 Bézier 曲线。折线保留重复点和默认均匀节点；少于两个点的折线没有可转换结果。椭圆采用原生的轴长角度调整、分段数、控制点和权重构造，不能以等分源角度的普通离散替代。

Outer/Inner 直接成为候选环，Open 先检查原树首末端点，Parity/Union 递归选择子数组。环中的直接子数组和 PointString 不参与 B 样条转换，但它们可以参与 Open 的源端点判断。已确认原生忽略的成员及空环写入 `ignored`，未知类型和转换失败则返回 `incomplete`，不丢掉失败环后报告整体成功。`boundary_sources` 给出源路径、原边界类型、有效类型，以及每个成员的源类型、原节点域、闭合标志、打开诊断和准备后的控制点数。

开放 B 样条保留原节点域；周期曲线在源节点参数零处打开，再转换 UV 坐标。因此坐标映射不会提前改变原树闭合判断或周期接缝选择。有理坐标平移乘控制权重，源数据不改写。裁剪打开支持负权重和内部全重节点；不会把断裂曲线修成连续曲线。特殊接缝直接移除外侧节点，保留剩余节点区间及全部控制权重，包括零权重。普通周期分支需要按权重还原控制点以计算节点容差，因此零权重、倒数或距离溢出会失败；成功后进行齐次节点插入、控制点旋转和节点归一化。`prepared_curve_knot_domain` 给出打开后的实际节点域，`opening` 保留方法、接缝及插入诊断。打开成功仍不保证后续采样成功，也不解除放样接口自己的权重和连续性限制。

此入口产生**归一化后的边界重新采样**，不重建文件读取时的首次原始 UV 缓存；不自动添加网格阶段的末尾闭合边，也不替换 `trim()` / `mesh()` 的派生离散。`outer_boundary_active` 保留曲面的外框状态，空 `loops` 不能自行解释成空曲面。`sampled_tolerances_met` 和连续误差界的限制与环级接口相同。

`max_controls` 分别限制本次转换缓存及打开后输出的控制点总数；同一源对象供闭合检查和成员转换使用时复用转换，两个相同但独立的源记录仍分别处理。`max_tree_visits` 限制包括闭合检查在内的节点访问次数，`max_tree_depth` 限制深度，`max_integration_intervals` 限制缓和曲线拟合的积分工作。`sampling` 中的预算作用于整个结果。准备阶段的失败提供 `failed_source_path`；采样阶段的失败提供环和曲线下标，可结合来源表定位。

### 重建初次读取的边界缓存

`sample_native_initial_surface_boundaries(surface, options)` 重建文件读取器设置裁剪树时的首次采样。它与上述接口共用源区域选择、图元转换、周期打开和采样预算，但保留曲面的源节点及边界坐标，不先映射成比例参数。缺省采样容差对应原生读取路径；调用方也可通过 `options.sampling` 覆盖容差。没有边界或根成员数组为空时跳过采样，`sampling_performed` 为 false。

```cpp
auto initial = p3d::sample_native_initial_surface_boundaries(surface);
if (initial.report.at("status") == "complete") {
    // initial.loops 是初次缓存的采样结果；源曲面保持不变。
}
```

报告中的 `parameter_coordinates: initial_cache_uv`、`surface_knot_preparation: source_knots` 和 `boundary_coordinate_preparation: source_uv_unchanged` 标明该路径。高重数分段使用源节点数值；线性成员仍按原生规则把 UV 夹到 `[0,1]`，高阶成员保留求得的 UV。原生曲面点内核使用 `(1-u)*首有效节点+u`，并以 1 为节点上界，所以非单位节点域下的 `position` 是这次中间计算使用的位置，**不能代替源节点坐标的数学曲面求值**。例如 U 节点域为 `[0,2]` 的线性边界可在 U=1 处被截住；归一化后重新采样的结果会不同。

此接口不修改或替换源裁剪树，不提供最终网格。原生节点窗口无效、零求值分母、非有限计算和预算耗尽均返回未完成及空环；不会改用另一种坐标约定来掩盖失败。需要归一化后的原生边界采样时使用 `sample_native_surface_boundaries()`；需要底层曲面的数学位置时使用曲面求值接口并明确所用的参数域。

### BGFB 源放样侧面

将已解码树中的 `_type: "P3DSectionLoft"` 表传入 `SectionLoft::from_bgfb()`，可以取得源截面及导引构造的参数曲面：

```cpp
auto loft = p3d::SectionLoft::from_bgfb(table, 100000);
for (const auto& side : loft.sides()) {
    auto p = side.surface.point_at(0.5, 0.5);
    auto loop = side.loop_index;           // 源环的零基下标
    auto primitive = side.primitive_index; // 该环内源截面边段的零基下标
}
const auto& original = loft.source();
const auto& status = loft.report();
```

`sides()` 按源环、源边段的顺序返回 `LoftSide`。每片侧面都是 `BsplineSurface`，可以查询阶数、控制网、节点和权重。u 沿截面边段，v 从底截面指向顶截面；源数据由 `source()` 完整保留，派生控制网不表示文件中新增的几何定义或共享关系。此操作显式执行，不替换活动场景的图形缓存。

支持线段、折线、单周以内的圆弧/椭圆弧，以及开放、两端夹持或已支持周期表示的 B 样条边界。内部重复节点保留原连续阶数，支持不同次数和节点分布的截面、连续复合导引、开放截面以及按源外环/内环顺序组织的奇偶区域。边界顺序和方向依据源对应关系。具体类型和数值限制见[已知限制](已知限制.md)。

周期 B 样条按原生调用请求在节点参数零处打开，它不一定是源曲线的比例参数零。`report().curve_openings` 列出源路径、源节点区间、请求接缝 `seam_knot` 及其源比例参数、实际接缝 `effective_seam_knot`、打开方法及打开后控制点数。实际接缝可能因节点容差吸附而移动；其源比例参数可由源节点区间换算。`inserted_knot_count` 是实际新增节点数，`pole_rotation` 是对插入后控制点数组的循环左移量；这些计数尚未包括后续升阶和全组兼容。源周期标志、节点和控制点仍保留在 `source()` 中。

打开方法为 `strip_exterior_knots`、`cyclic_knot_insertion` 或 `cyclic_seam_fallback`。最后一种用于特殊闭合节点布局未通过原生端点检查时的通用循环处理，控制点和权重一起移动。该回退及非周期一致的外围节点处理遵循原生转换，不能假定其结果始终与源 `BsplineCurve::point_at()` 的曲线相同；调用方仍可单独求值源曲线。

按控制多边形长度连接的导引若满足原始首尾闭合条件，会按原生规则尝试关闭，再于节点参数零处打开。`report().guide_closures` 在发生此处理时记录源路径、各步骤的控制点数，以及 `linear_periodic_reopened`、`regular_periodic_reopened`、`special_periodic_reopened` 或 `retained_open` 方法。实际重新打开时，`opening` 提供该步骤的打开方法、实际接缝、插入和循环移动信息。`retained_open` 附有 `reason`，表示原生关闭检查未改变开放曲线，不表示丢弃导引。已闭合的单条源 B 样条只记录其原有打开过程。控制点数均不含后续全组兼容和侧面升阶；接缝控制点的取舍遵循原生表示转换，源数组仍保持原样。

第二参数限制单条准备曲线、单片曲面及全部侧面的控制点数；默认 100000。超出预算、源对应关系不符或遇到未支持分支时抛出异常，不返回部分侧面集合。对象拥有自己的数据，独立构造和只读求值可并发进行。

`from_bgfb()` 只重建侧面。`report().cap_status` 为 `not_requested` 或 `not_reconstructed`；源 `capped: true` 不能理解为已经生成封口。`status: valid` 也只表示侧面构造成功。需要封口边界时，可继续显式调用：

```cpp
auto caps = loft.cap_regions();
if (caps.report.at("status") == "complete") {
    // caps.bottom / caps.top：由侧面端部等参数曲线组成的 CurveVector 树。
    // 叶节点为 BsplineCurve，可继续用 BsplineCurve::from_bgfb() 求值。
}
```

该接口按源 `capped` 判断是否执行。`not_requested` 表示源未请求封口；`native_failure` 表示按原生首尾端点容差检查不能闭合；`incomplete` 表示预算或数值限制。只有 `complete` 同时返回底、顶两个区域，其他状态均为空，不保留单端的部分结果。`cap_regions(max_control_points)` 的预算覆盖两个端面的全部控制点，默认 100000；零预算抛出异常。

边界取自构造后的侧面：底端为 v=0，顶端为 v=1，不能直接用未处理的源截面代替。底端在每个环内反转曲线顺序和曲线方向，顶端保持侧面顺序；单环结果为 Outer，多环为 ParityRegion，首环为 Outer、后续为 Inner，不反转环之间的顺序。`report.boundary_curves` 给出每条派生曲线在结果树中的 `region_path`、`side_index`、`loop_index`、`primitive_index`、`surface_v` 和 `u_reversed`，用于追溯侧面参数。

封口等参曲线保留生成的零控制权重，`report.zero_weight_control_count` 给出底、顶两端已提取的零权重控制点总数。闭合检查沿源边界遍历次序求各曲线首末点；恰好为零的求值权重按原生点求值规则仅在除法时替换为一，曲线保存的权重保持零。`report.endpoint_zero_weight_fallbacks` 记录该检查中使用回退的端点次数。回退不是对数学奇点的修复，后续网格仍验证真实分母。未完成时计数只表示已处理部分。

`complete` 限定为封口边界区域构造成功。原生这一步只检查环的首尾，不检查所有内部连接、平面性或实体有效性；库不补闭合线，也不把非平面曲线强行投影。`mesh_status` 和 `planarity_status` 均为 `not_evaluated`。底、顶盖的三角化以及与侧面网格连接仍需另行处理。调用不修改 `source()`、侧面或 `report()` 中原有的侧面构造摘要。

放样保留非零的有符号齐次控制权重，不取绝对值或强制转换为正值。原生混合公式可以生成零控制权重，也可能生成存在奇点的曲面；构造报告的 `denominator_status` 为 `not_evaluated`，取得侧面参数不代表可以生成完整网格。`mesh()` 会先验证每个侧面有效参数域的分母，`report.side_denominators` 按侧面索引给出验证方法、状态及必要的工作量。分母为零、验证不确定或预算不足时，返回 `incomplete` 和空网格；验证预算 `max_denominator_steps` 必须大于零。封口边界为同号权重时使用控制凸包界；混合符号时按节点区间提取齐次 Bernstein 系数并自适应细分，同时验证分母非零和整条曲线到平面的距离。验证不充分时不会按采样点共面直接生成盖面。

要生成侧面及平面盖面的三角网格，可继续调用：

```cpp
p3d::LoftMeshOptions options;
options.max_uv_edge = 1.0 / 16;
options.join_tolerance = 1e-8;
options.planarity_tolerance = 1e-8;
options.max_denominator_steps = 1000000; // 每个侧面的分母验证预算。
options.max_planarity_steps = 1000000;   // 底、顶盖共享的区间验证预算。
auto mesh = loft.mesh(options);
if (mesh.report.at("status") == "complete") {
    // mesh.vertices / mesh.faces：整个派生表面的顶点和三角形。
    // mesh.parts：按 side、bottom、top 标明连续的三角形范围。
    // mesh.face_parameters：侧面三角形各角的曲面比例参数；盖面为 nullopt。
}
```

`mesh.parts[].native_face_indices` 是可选的放样实体面三元索引。使用前检查 `has_value()`；原生面构造失败时所有范围均为 `nullopt`，原因见 `mesh.report.native_face_indices`，不影响已成功生成的派生网格。也可单独调用 `loft.face_indices()`：检查结果 `report.status == "complete"` 后，`indices` 按原生枚举顺序给出底盖 `{-1,0,0}`、顶盖 `{-1,1,0}`，再给出侧面 `{0,i,0}`，其中 i 对应 `sides()[i]`，跨环连续编号。未请求封口时只有侧面；多环盖面仍各占一个面。面枚举顺序与网格输出范围的顺序不同，应使用索引关联。

`face_indices(max_cap_control_points)` 先构造下述原生面，再检查请求封口的成功条件：封口失败返回 `native_failure` 和空索引，预算或数值限制返回 `incomplete` 和空索引；未请求封口时不检查端面闭合。默认封口控制点预算为 100000，零预算抛出异常。枚举不要求盖面为平面，也不要求三角化成功。索引由已支持的放样结构按原生规则计算，仅在当前实体内有效，不是文件全局 ID、三角形序号或材质的图形条目编号。`material_part_mapping: not_established` 表示尚不能由该索引推定材质覆盖关系；`side_index` 保留源边段对应，不承诺派生网格与原生取面的曲面相同。

需要原生取面路径的曲面时，使用 `auto faces = loft.native_faces(max_cap_control_points)`。仅在 `faces.report.status == "complete"` 时使用 `faces.sides` 和 `faces.caps.bottom/top`；侧面仍按源环和边段排序，每片可用 `surface.point_at(u,v)` 求值。无封口时两个盖面为空，`cap_status` 为 `not_requested`。请求封口失败或任一侧面处理不能完成时，整个结果的几何均为空。此接口不三角化，也不改变 `sides()`、`cap_regions()` 或 `mesh()` 的派生几何。

该路径对 V 阶数为 2 的侧面按原生相对容差聚合近重节点，删除相应控制行。发生整理的侧面列于 `report.side_adjustments`，包含 `side_index`、删除的原 V 行索引、删除的原权重索引及是否重新乘权重。原生权重删除与控制点删除使用不同索引，替代曲面构造还会再次将存储的 XYZ 乘以权重；因此整理可能改变曲面，甚至使原本闭合的派生盖面不再通过原生闭合检查。库保留这些明确的数值行为，不把整理宣称为无损去重。原生索引可能越界、结果非有限或不能构成可求值曲面时，返回 `incomplete` 和原因，不读取越界内存。封口在整理后的侧面上构造，不能用 `cap_regions()` 的结果代替。

盖面的原生局部参数位置可用 `loft.native_cap_uv(top, u, v, max_control_points)` 查询，`top` 为真选顶盖，否则选底盖。检查结果 `status == "computed"` 后，读取 `point`、`u_direction`、`v_direction`，以及 `local_to_world`、`world_to_local`。方向是局部参数轴对应的向量，不自动单位化；该 UV 也不是材质纹理坐标。`native_failure` 表示没有所选盖面、原生封口失败或参考系选择失败，`not_evaluated` 附相关原因或下层报告，表示预算、未知分支或数值处理未能完成；非法预算或非有限 UV 输入抛异常。

查询先按默认偏好选择盖面曲线区域的参考系，在其局部坐标下计算 B 样条分段端点及导数极值范围，再应用原生二维范围归一化。`local_range_before_normalization` 和 `local_range` 分别给出处理前后范围；`origin_shifted`、`range_scaled` 记录是否移动原点及缩放。正常缩放时 U、V 轴分别使用 X、Y 跨度，第三轴使用两者的几何平均值；退化或极小跨度遵循原生不缩放分支。查询返回局部 z=0 的位置，不裁剪 UV，区间外参数可以外推。孔洞、边界包含关系及平面性均不在此查询中检查；非平面区域的查询位置也不能视为落在实际盖面上。

范围采用有理 Bézier 导数的数值极值求解，保持原生近零分段跳过、接近单位权重的导数分支及权重接受阈值；不使用控制点包围盒或网格采样范围。`range_method`、`root_parameter_tolerance` 说明数值方法，`native_root_solver_reproduced: false` 明示未逐指令复刻厂商多项式求根器，不保证逐位相同，也不提供三维误差界。默认控制点预算 100000，同时限制原生封口及本次范围分解的控制点总数；根区间处理预算为该值的 64 倍。预算耗尽或无可接受有限范围时明确报告未计算，不返回部分位置。

侧面采样包含原节点分段，同一源环内的公共导引使用相同的 V 参数列表，相邻侧面共用边界顶点。盖面直接使用侧面的端部顶点，按奇偶规则保留孔洞，并检查所有盖面边界段都被三角化保留。不会跨环或跨源构件按坐标去重。源 Open 截面保持独立的首、末导引；请求封口时仅连接其端面闭合点，不自动合并中间导引边或补侧壁。

`max_uv_edge` 只约束侧面三角形的 UV 边长，不提供三维弦误差保证。`join_tolerance` 和 `planarity_tolerance` 是几何坐标中的绝对距离，不自行推定为毫米；分别限制公共边顶点合并的位移和盖面边界曲线到平面的距离。`max_join_displacement` 报告测得的最大合并位移；`max_cap_plane_distance` 是采用控制凸包或区间验证得到的距离上界，并非精确最大偏差。`report.cap_planarity.bottom/top` 按盖面边界遍历顺序提供 `curve_index`、方法、状态及 `distance_bound`；区间方法还提供验证节点段数和 `work_steps`。底、顶两端的区间验证共享 `max_planarity_steps`，必须大于零。数值舍入无法证明距离界、分母奇点、细分深度或预算限制均返回未完成；零容差可能使数值上接近共面的混合权重边界无法通过验证。`cap_collinearity_distance` 是盖面共线点处理使用的浮点距离阈值，随坐标尺度计算且不超过 `join_tolerance`；共线点仍保留原位置和边界索引。`max_vertices`、`max_triangles` 控制整个输出预算；盖面边界恢复还有与剩余三角形预算成比例的搜索预算。`max_cap_control_points` 传给封口区域构造。选项非法抛出异常；预算、几何或数值处理失败返回 `incomplete`、原因和空输出数组。

`indexed_edge_topology` 提供 `boundary_edges`、`nonmanifold_edges`、`orientation_conflicts` 与 `closed_oriented_edges`。`complete` 表示指定精度下的派生表面网格已生成，不等于有效实体；即使索引边闭合，仍可能存在未检查的空间自交或顶点处接触。调用方应同时检查拓扑报告；`self_intersections: not_evaluated` 明示尚未检测空间自交。`parts.side_index` 指向 `sides()`，这些范围不是原生材质部件编号，侧面比例参数也不是材质纹理 UV。源解析对象、封口区域和活动场景缓存均保持不变。

## 4. 属性与结构树

场景已经带有对象图，无需为同一次读取再调用 `document.object_graph()`：

```cpp
const auto& graph = scene.metadata.at("document_graph");
const auto& hierarchy = graph.at("hierarchy");
for (const auto& element : scene.elements) {
    auto model = element.metadata.at("model_id").get<std::uint64_t>();
    auto id = element.metadata.at("element_id").get<std::uint64_t>();
    auto context = p3d::element_context(graph, model, id);
    // context：构件绑定、源树节点、模型树节点、模型属性对象和关联。
}
```

只需要属性、不需要重建几何时，可直接调用 `document.object_graph()`。

| 数据位置 | 内容 |
| --- | --- |
| `graph["objects"]` | 对象记录目录，每条记录保留 `property_tree` |
| `graph["object_index"]` | 对象身份、候选记录与解析状态 |
| `graph["bindings"]` | 构件与属性对象的源绑定 |
| `hierarchy["nodes"]`、`parent_edges`、`roots` | 源结构树 |
| `hierarchy["model_nodes"]`、`model_edges`、`model_roots` | 模型树 |
| `hierarchy["element_references"]` | 树节点指向构件的引用 |
| `cycle_affected_nodes`、`model_cycle_affected_nodes` | 两类树各自受循环影响的节点 |

`p3d::get_object(graph, class_id, object_id)` 返回对象候选记录的副本，状态可能为 `resolved`、`identical_copies`、`ambiguous` 或 `missing`。需要频繁访问大型属性树时，可以使用目录索引取得只读引用，避免反复复制。

结构树、模型树和块引用描述不同关系，不能因为名称或数字 ID 相同就合并。模型属性与关联对象也不会被静默继承为构件自身属性。

原生类型 62 的 `block_transform` 独立提供块引用变换，无需先找到块定义。检查 `status == "resolved"` 后，`source_matrix` 是保存值，`matrix` 是按原生输入规则处理退化情况后的有效值；`repair` 说明是否修复及所走分支。平移保持源值，正常镜像、剪切和非均匀缩放不作单位化。场景实例使用有效矩阵，块定义及引用链的 `input_transform` 保留解析详情。无效矩阵会给出错误原因，源记录仍可访问。

遍历 `scene.metadata["native_block_definitions"]` 时，先检查 `input_tree.status == "resolved"`。`direct_child_source_keys` 只列直接子项；`children` 包含全部已接受后代，各项的 `parent_source_key` 给出父级，因此不能把这个前序列表当作平面关系。`input_tree` 还保留跳过记录及失败原因。无效或被跳过的块头保留来源，但不提供部分几何作为可展开定义；原始记录始终可从 `native_records()` 访问。

## 5. 材质、颜色与贴图

`view.material_candidates` 索引 `scene.metadata["materials"]["definitions"]`。先检查 `view.material_status`：

| 状态 | 含义 |
| --- | --- |
| `resolved` | 已解析到唯一候选 |
| `missing` | 有引用，但没有找到定义 |
| `ambiguous` | 存在多个候选，不自动选择 |
| `unassigned` | 没有显式材质分配 |

数值 ID 引用先查模型作用域中的材质；没有该作用域候选时再查全局定义。若模型内有多个候选，不以全局定义掩盖歧义。颜色与样式摘要可读取 `view.appearance`、`view.style`，材质定义可读取 `document.materials()` 和 `document.inline_materials()`。

`view.mesh_material_references` 提供网格逐面材质列表的引用解析。每项为 `MeshMaterialReference`，包含 `material_id`、`status` 和 `candidates`；候选索引仍指向场景材质定义。该数组与 `view.source_range` 中 `mesh_channels.source.face_material_ids` 逐项对应，保留源顺序、重复值及未绑定到面的条目。不同模型中的实例分别使用自身作用域解析，不修改共享几何定义。`expanded()` 在每个含网格扩展的图元范围中提供同名 JSON 数组。

已绑定三角形的 `mesh_channels.triangles[j].source_material_index` 可以直接索引这个引用数组；无法对应时为空。原生路径补零后的材质没有源列表索引，不能用下标零代替空值。例如在图元回调中读取源面材质：

```cpp
if (view.source_range->contains("mesh_channels")) {
    const auto& extra = view.source_range->at("mesh_channels");
    for (const auto& triangle : extra.at("triangles")) {
        const auto& index = triangle.at("source_material_index");
        if (index.is_null()) continue;
        const auto& ref = view.mesh_material_references.at(index.get<std::size_t>());
        if (ref.status == "resolved") {
            const auto& material = scene.metadata.at("materials").at("definitions")
                                               .at(ref.candidates.front());
            // 在此读取完整材质定义。
        }
    }
}
```

这里的 `resolved` 只说明材质定义引用唯一，`unassigned` 表示源 ID 为零；它们不表示最终外观已求值，也不自动覆盖 `view.appearance`。逐面材质、范围材质及原生三角化路径所选材质保持各自来源。

XML 材质的 `definitions[].settings.semantics.parameters` 提供带来源的颜色、系数及启用状态；`settings.maps[].semantics` 提供原生贴图角色、映射方式、缩放、偏移、旋转及投影矩阵。读取数值前检查 `status`，并单独处理 `enabled`：关闭参数仍可能有有效数值，缺少启用标志时其值为 null。语义视图保留原生参数尺度，不进行其他材质系统的转换。完整参数与层次仍可从 `source_parameters` 和 `tree` 取得；贴图路径由调用方处理。

材质的原生目录名称和资源引用通过 `document.materials()["native_catalog_records"]` 读取。每个 XML 定义的 `native_catalog_candidates` 指向对应的原生记录；多个候选表示重复来源，不能直接选最后一个。目录记录的 `catalog_name` 和 `resource_reference` 各自提供状态、源值和 `strings` 中的条目下标；`missing`、空字符串和 `invalid` 应分别处理。原生资源字符串可能包含目录变量或其他资源表示，不能当成图片文件路径。库保留字符串和原始字节，资源定位由调用方负责；没有 XML 对应项的原生目录记录也可以独立遍历。

需要按原生表遍历时，使用 `document.materials()["native_catalog_tables"]`。先检查 `membership_status == "resolved"`，再按 `members` 的顺序读取；其中 `native_record_index` 指向原生记录，非 null 的 `catalog_record_index` 指向材质目录记录。目录记录的 `table_memberships` 提供反向下标。嵌套表的条目只属于各自直接父表，重复 ID 和表外记录均保留。无效表会提供错误原因，不能用全文件同 ID 记录替代其成员。

需要初次载入后的表时，调用一次 `document.native_input_containers()` 并保存返回值，在 `kind == "P3D-SSYS"` 的容器中读取 `initial_material_table`。检查 `status == "selected"` 后，使用 `table.native_record_index` 定位源表，按 `table.members` 遍历已接受的直接成员；每项的 `assigned_id` 是本次系统输入分配后的 ID，`input_occurrence_index` 区分重复载入。`absent` 表示该输入结果没有表，`unresolved` 表示尚不能确定。多个容器保留各自结果，调用方应按容器路径选择需要的系统范围。该接口不计算后续资源上下文和最终材质覆盖。

同一系统容器的 `initial_attribute_input.attachments` 提供初次挂接的属性集合。使用 `target.input_occurrence_index` 与表成员关联；`target.id` 是分配后的 ID，不能用源记录 ID 替代。属性载荷和通用解码结果位于每项 `attributes` 中，来源由 `stream` 与 `offset` 定位。先检查总体状态，再检查 `blocks` 中的停止原因：输入过程已确定也可能包含被原生规则拒绝或没有读到的源记录。需要文件中全部源属性时，继续使用 `graphics_records()`。

读取精确键对应的初始属性值时，在集合的 `lookup.keys` 中找到相同 `group`、`key`、`index`，再用 `selected_source_ordinal` 访问原 `attributes` 数组；不要自行对重复键取首项。已选材质表的成员直接提供 `material_attribute` 引用：检查 `status == "selected"`，用 `attachment_index` 定位集合，再用 `source_ordinal` 取属性及其 `decoded`。该引用遵循原生输入身份和查找规则，尚未计算资源目录冲突及最终材质覆盖。

需要实际登记后的初始目录时，调用 `document.native_material_catalog()`。每个系统容器返回独立结果，`entries` 按接受顺序列出条目，`input` 列出每个表成员的登记或拒绝原因。条目的 `source_attribute` 直接包含实际选中的材质属性载荷及 `decoded`，同时保留源流、记录偏移和属性序号；无需仅按材质 ID 猜测 XML 来源。源资源引用仍在 `source_resource_reference` 中。目录登记成功不代表材质载荷解码成功，也不代表图元最终采用该材质。

目录条目的具体材质内容从同一返回对象的 `initial_source_materials.entries` 读取。先检查单项 `status == "decoded"`，再使用 `material.settings`、`material.texture_references` 及名称、ID；`catalog_entry_index` 可回到所属目录条目，`source_record` 和 `material_attribute` 可定位原始记录与选中的属性。这个视图已通过登记 ID 和输入序号关联来源，无需按名称或源 ID 猜测配对。

`material.name` 不一定等于目录名称。原生对象名称赋值只接受首个零码元前不超过 30 个 UTF-16 码元的请求，超长时保留上次成功赋值的名称；两次请求都超长时保留构造时的空名称。查看 `name_source` 和 `name_assignment.steps` 可区分实际来源及拒绝原因，原请求分别保留在 `object_name`、`catalog_name`。名称赋值被拒绝不代表整个材质内容读取失败，`id` 仍来自目录。不要按这个限制修改名称查询的候选列表。

同一材质的 `material.embedded_texture_inputs.entries` 给出其挂接集合中实际选中的嵌入贴图输入。检查图片单项 `status == "decoded"` 后读取 `file.filename` 和 `file.file_data`；`source_attribute` 保留原始属性，`source_ordinal` 指向其来源。图片可能为 `skipped` 或 `unresolved`，因此材质源内容的 `decoded` 不能代替图片状态检查。接口保留名称原文，不生成绝对路径，也不执行图片缓存或 XML 贴图绑定。

`initial_source_materials` 描述初次输入下能够解码的材质源内容。跨资源上下文、既有运行时缓存和贴图后处理尚未自动执行，因此不能将 `decoded_entry_indices` 直接当作完整运行时材质枚举，再无条件交给构件覆盖接口。

条目的 `supplementary_attributes` 同时列出组 0／索引 0 下的键 20091、22906，分别表示材质读取器另外请求的二进制缓冲和附加记录集合。检查 `status == "selected"` 后读取 `source_attribute`；这里使用实际挂接集合的原生属性选择结果，不会合并同 ID 的其他源记录。这些是后续读取器的输入，不能据此认定材质对象已成功加载。键 22906 的 `decoded.native_input.records` 保留记录顺序，`selected_record_indices` 给出按原生键排序、重复项替换后的记录下标；若 `native_input.status == "partial"`，这些下标只代表已确定的前缀。完整解压载荷保留在 `decoded.data` 中。

键 22906 的版本 2 记录另提供 `image_dimensions.width_pixels`、`height_pixels`，表示保存的像素尺寸声明。记录的 `data` 仍保留原始编码缓冲；`image_encoding` 尚未确定，不应按宽高直接将这些字节解释成像素，也不应把这组记录与键 22913 的原图片文件字节混用。

该接口从空目录开始登记单个系统表。默认按 CRT 的 C 区域设置比较字符串，即仅转换 ASCII 字母大小写，其他 UTF-8 字符保持原值；结果中的 `string_comparison` 明确标注此规则。若要复现其他区域设置，通过 `MaterialCatalogOptions::case_equal` 提供确定且对称的字符串相等函数。库不猜测原建模进程的区域设置。

项目、库和普通当前上下文资源通常可以直接登记，调色板第二上下文尚未查找不阻止这些条目的登记。确实需要外部资源事实时，`resolve_resource(member, source_fields)` 可返回 `MaterialCatalogResource`，包含成员名、描述模式以及主上下文。主上下文未设置表示当前系统资源上下文；外部上下文分别提供原生 ID 索引使用的 `index_key` 和资源比较使用的 `comparison_key`。两种键可能因原生查找失败后的回退而不同，不能随意合并。若需比较当前上下文与外部上下文，还须提供 `options.current_context` 的这两个键；库不会自动把它们判为不同。回调返回空值或仍缺少判定事实时，结果为 `partial`，保留已登记前缀和停止原因，不猜测后续冲突。

材质 XML 的整数语义值遵循原生数字前缀读取规则，原文保留在 `source_text`，读取细节在 `conversion`。不要因原文带后缀或超出 32 位范围就自行判定原生读取失败。`status: invalid` 表示没有读出整数，但不同读取入口有不同后果：版本号和 `map_link` 回退为零，Map 类型读取失败会跳过节点，普通参数则保持未写入状态。查看 `reader_profile`、`map_bindings` 和 `numeric_reader` 的实际结果；这些规则尚不等于最终材质渲染状态。

需要构造默认值与根节点赋值结果时，读取 `settings.initial_parameters`。参数的 `value` 是该阶段的结果，`constructor_value` 是原生构造值，`source_key` 和 `source_read` 保留输入来源；先检查 `read_status`，遇到 `unresolved` 时不要自行用构造值替代。这个视图与只描述显式源属性的 `settings.semantics` 分开，尚不包含后续版本转换和最终贴图覆盖。

原生版本转换后的根参数位于 `settings.version_conversion.root_parameters`，其中 `parameters` 给出值及最初的来源参数，`operations` 保留赋值顺序。转换可能覆盖文件显式写出的值，例如版本不大于 6 时，`reflect_fresnel` 最终取 `reflect`。先检查 `version_conversion.status`；转换未能确定完成时，不会返回假定完成后的根参数。

同一视图的 `map_topology` 描述转换后的贴图对象与链接关系。`active_object_ids` 按原生有符号类型键排序，指向 `objects` 中的对象；这里的 `object_id` 是本视图内部标识，与文件 ID、`settings.maps[].index` 无关。用 `source_map_index` 找到源 Map，用 `replaced_by_object_id`、`local_layers` 和 `operations` 追溯替换或复制。`layer_container_owner_object_id` 表示有效纹理层容器的归属，新建贴图对象与其链接到的对象仍然是两个对象。`layer_flag_updates` 是对有效容器中各层标志执行的按位操作，不能当作完整的最终层标志。该视图尚不执行纹理提供者及着色求值。

查看具体层数量及标志时，读取 `maps[].initial_layer_state`，或版本转换后的 `version_conversion.layer_containers`。后者的 `containers[object_id]` 给出该对象本地容器的层序列；通过拓扑中的 `layer_container_owner_object_id` 选择实际使用的容器。检查这一子视图自身的 `status`，再使用 `layer_count`、`data_flags.value` 和 `enabled.value`。`option_bit_1`、`option_bit_2` 保留另外两个原生布尔位置及实际来源位，不统一假定它们具有相同的业务含义。层序列可能包含没有对应 XML 层节点的原生默认层，不能仅按源 `LayerType` 节点数计数。

每层的 `resource_inputs.entries` 提供有序的源资源请求，包括主引用、M556 追加项、空项和重复项。检查 `resource_inputs.status`：`resolved` 表示输入顺序和 `count` 已确定，`unresolved` 时只保留已确定前缀，`count` 为 null。这些是资源服务的输入，库不会生成绝对路径或把它们当作已加载图片。

通过 `version_conversion.layer_resource_getters.entries` 可查询活动材质通道的首层来源：

```cpp
const auto& converted = settings.at("version_conversion");
for (const auto& getter : converted.at("layer_resource_getters").at("entries")) {
    if (getter.value("first_request_status", "unresolved") != "known") continue;
    const auto owner = getter.at("layer_container_owner_object_id").get<std::size_t>();
    const auto& layer = converted.at("layer_containers").at("containers").at(owner)
                           .at("layers").at(getter.at("layer_index").get<std::size_t>());
    const auto& request = layer.at("resource_inputs").at("entries")
                              .at(getter.at("first_slot_index").get<std::size_t>());
    // request.source_value 是原始输入；service_entry 区分主、追加入口。
}
```

这里的对象编号、层编号和资源槽与嵌入图片的属性组号不同。普通链接会指向相同层容器，类型 30 的资源仍来自本地；按返回的来源关联读取，不自行按文件名合并。首项已知不等于整个资源序列或最终文件绑定已完成。

本地投影状态位于 `maps[].initial_projection_state`，版本转换后的状态位于 `version_conversion.local_projection_states.objects[object_id]`。`parameters` 包含构造值、实际赋值和来源；`matrix.axes` 分别保留三个轴，`storage_values` 按 `xa`、`ya`、`za` 的顺序连续存放各轴的 XYZ。先检查独立的矩阵状态，不要把缺失轴补为单位矩阵。`origin_uv_pro_matrix_on` 是真正的矩阵开关；`linked_option` 是另一个由专属标志字段和原始链接值决定的布尔状态，两者不能互相替代。这是本地存储状态，尚未执行完整的纹理坐标求值。

材质 XML 浮点值可能是普通 JSON 数字，也可能是非有限值对象，例如 `{"floating_point":"nan","negative":true,"ieee754_hex":"ffffffffffffffff"}`。先检查值的类型，再调用 `get<double>()`；对象形式保留原生位模式，可安全序列化。成功解码不意味着数值有限，完整投影矩阵另提供 `all_components_finite`。原生数字前缀、后缀和失败信息可从 `source_read.conversion` 查看。

需要版本转换后、沿原生链接读取的投影参数时，使用 `version_conversion.projection_getters.entries`。每项对应一个活动 `object_id`；偏移、角度和缩放的 `source_object_id` 指向链接终点，显式矩阵、矩阵开关及 `linked_option` 的来源仍是该对象本身。`frame_resolution: dangling_uses_local` 表示链接链失效后回退到调用对象自己的投影参数，链接值仍保留。分别检查参数及矩阵状态；该视图提供访问器返回值，`coordinate_evaluation: not_evaluated` 表示尚未执行完整的纹理坐标计算。

`prepare_material_projection(getter, context)` 可执行原生映射类型 3–7 的投影准备步骤，`getter` 为上述访问器结果的一项。`MaterialProjectionContext` 提供 `mapping_mode`、`scale_mode`、有效首层的 `layer_data_flags`，以及同一几何上下文的 `reference_point`、`reference_dimensions` 和 `reference_matrix`。后三项均为必填的可选值；非零 `scale_mode` 还要求 `absolute_unit_factor`。`Matrix3` 按行存储，作用于列向量。

返回 `status: prepared` 时，可读取 `orientation_matrix`、`origin`、`reference_dimensions`、`projection_offset` 和 `projection_scale`。缺少上下文、遇到非有限输入或运算结果时返回 `not_evaluated` 和具体 `reason`，不生成替代矩阵。几何参考量及模型单位因子目前需要显式提供，库尚未自动从所有几何类型中恢复这些上下文。此接口只完成准备步骤，保留 `point_mapping: not_evaluated`。

需要继续构造坐标变换矩阵时，调用 `resolve_material_projection_transform(getter, context)`，输入与准备接口相同。返回 `status: resolved` 后读取按行存储的 `matrix`；`matrix_source` 区分 `computed_transform` 和 `local_explicit_matrix`。`origin`、`reference_dimensions` 随结果保留，逐点映射仍需结合原生映射类型处理，不能仅将矩阵乘以位置就当成最终 UV。

逐点投影使用 `prepare_material_projection_sampling(resolved, render_context)` 与 `sample_material_projection(prepared, point, normal)`。支持类型 3（DirectionalDrape）、4（Cubic）、5（Spherical）、6（Cylindrical）和 7（Solid）。准备结果可供多个顶点重复使用；查询不修改状态，可并发读取同一个准备结果。

二维 UV 矩阵可通过 `build_material_uv_transform(layer_getter, uv_context)` 从源层状态构造。`layer_getter` 取 `version_conversion.layer_mapping_getters.entries` 中对应 `object_id` 的项；该项分别给出映射参数来源和数据标志来源，已处理原生链接、类型 30 的首层映射复制及旧版本转换。`mapping.parameters` 保留构造值和实际写入；其中 `pattern_scale` 为 XY，`scale_z` 独立保存 Z，`pattern_offset` 保留 XYZ。成功写入 XY 缩放会先把 Z 清为零，之后才读取独立的 Z 值。

`MaterialUvTransformContext` 的输入取自实际选择的模型和几何上下文：`mapping_unit_factor` 是原生贴图单位转换系数；ElevationDrape 还需要 `elevation_origin`。非零尺度模式要求用 `geometry_projection_succeeded` 明确调用阶段的分支；为真时还提供 `registration_unit_factor`，用于注册前的单位调整。不要把渲染 `geometry_scale` 提前乘入这些系数。相对映射的普通分支无需单位输入；缺少实际要使用的输入才返回未求值。

也可以让库从模型单位状态计算系数：将已选映射模型的 `units` 赋给 `mapping_model_units`，并在需要时提供 `mapping_reference_scale`；将已选注册模型的 `units` 赋给 `registration_model_units`。两者可能属于不同模型，库不会互相借用。已显式提供的 `mapping_unit_factor`、`registration_unit_factor` 分别优先于模型推导结果。

单独查询映射单位可调用 `material_uv_mapping_unit_factor(units, mapping_mode, scale_mode, reference_scale)`。尺度模式 0 原生返回 1，不需要模型或引用上下文；其余尺度模式在映射类型 1 时不乘引用比例，其他类型则必须提供已确定的比例，无缩放上下文也需明确给出 1。缺失模型、缺失必要引用比例或非有限计算返回 `not_evaluated`。`before_reference` 和 `reference_scale_applied` 区分模型单位计算与引用比例应用。

返回 `status: computed` 后，将 `matrix.get<p3d::Matrix2x3>()` 赋给 `render_context.uv_transform`。`before_registration` 保留注册单位调整前的矩阵，`registration_unit_applied` 记录是否执行该分支。接口不会根据文件中某个模型的位置或遍历顺序猜测活动模型。

`MaterialProjectionRenderContext` 必须由调用方提供与顶点一致的实际渲染上下文：

- `geometry_kind`：原生几何分支标记，零与非零分支分别使用以下对应输入。
- `reference_point`：两个分支都需要的渲染参考点，不是前一步 `MaterialProjectionContext` 的同名几何参考量。
- `reference_transform`：非零分支使用的参考点仿射变换。矩阵按行存储、作用于列向量，最后一行必须为 `(0,0,0,1)`；零分支不读取它。
- `vertex_linear_transform`、`vertex_translation`：零分支使用的渲染顶点线性矩阵 R 与平移 t。先将各分量舍入为 float，再以 double 计算新投影原点 `R·(origin-reference_point)+t`，并将投影矩阵 M 改为 `M·Rᵀ`。不要传入逆矩阵，也不要提前对 M 做同样的变换。非零分支不读取这两个输入。
- `uv_transform`：已完成调用阶段单位处理、尚未应用渲染几何比例的二维仿射矩阵。`Matrix2x3` 的两行分别计算 U 和 V，每行第三项是平移；不能用三维投影矩阵代替。
- `geometry_scale`：原生渲染几何比例；非零几何分支只在非零 `scale_mode` 时需要，零几何分支始终需要。它不是根据输入矩阵长度自动推断的值。

返回的 `geometry_kind` 保留原生分支标记。非零分支通过 `render_origin` 给出变换后的参考点；零分支分别保留舍入后的 `vertex_linear_transform`、`vertex_translation`，并用 `inverse_squared_scale` 给出该分支实际使用的比例平方倒数，不适用时为 1。两种分支都向 `sample_material_projection()` 提供准备结果；几何比例及矩阵调整已经完成，不应再次变换输入顶点或结果 UV。

```cpp
auto transform = p3d::resolve_material_projection_transform(getter, projection_context);
auto sampling = p3d::prepare_material_projection_sampling(transform, render_context);
if (sampling.at("status") == "prepared") {
    auto result = p3d::sample_material_projection(sampling, render_vertex, render_normal);
    if (result.at("status") == "computed") {
        auto uv = result.at("uv").get<p3d::Point2>();
        // uv 是该投影分支与二维变换计算得到的坐标。
    }
}
```

`point` 和 `normal` 使用渲染顶点坐标系；接口接受 double 容器，但按原生顶点缓冲的规则经过单精度舍入。类型 4、7 和带端盖的类型 6 必须传入法线；其他分支可以省略。圆柱端盖选择使用变换结果保留的 `layer_data_flag_bit_2`，不自行根据模型形状猜测。`projection_point`、`projection_uv` 分别保留三维投影点、二维仿射变换之前的 UV，`branch` 表明实际选择的面或映射分支。结果不会限制在 `[0,1]`。

缺少上下文、未支持的分支或非有限计算返回 `not_evaluated` 和 `reason`，不返回伪造 UV。库尚未自动建立所有材质、几何和渲染上下文的对应关系；外部贴图查找、像素采样、跨接缝的面处理和层混合仍是独立环节。

已取得活动变换设置阶段的 double 渲染矩阵 C 与平移 t 时，可调用 `<p3d/material_render_transform.hpp>` 中的 `derive_material_render_transform(C, t)`，计算对应的 `origin_basis_transform`、float `vertex_linear_transform`、`vertex_translation`、`normal_transform` 和 `normalize_transformed_normal`。成功结果的 `status` 为 `computed`，这些同名字段可填入平面投影上下文。C 必须是已经完成引用、视图等组合的渲染矩阵，不能直接以任意模型或对象矩阵代替。

结果同时提供 `geometry_scale_candidates.first_two_rows` 与 `all_three_rows`，分别按前两行、全部三行求最大长度；还有 `row_squared_lengths`、`minimum_squared_scale`、`mean_squared_scale` 和 `normal_row_alignment`。接口不自动选择 `geometry_scale`：原生外层状态决定使用哪个候选，部分图元处理路径还会临时覆盖矩阵和两个比例。调用方必须确认当前处于活动变换设置后的状态，或补入后续覆盖值；不能在所有投影前都重新从矩阵推算比例。

Planar（类型 2）使用 `<p3d/material_planar.hpp>` 中的 `prepare_material_planar_sampling(uv_transform, context)` 与 `sample_material_planar(state, point, normal, native_uv, face_frame)`。准备接口接收 `build_material_uv_transform()` 的类型 2 成功结果。`MaterialPlanarRenderContext::enabled` 必须明确：为假时按原生规则清除平面映射标志，使用 `parametric` 子上下文处理参数映射，已注册二维矩阵仍保留；未知状态不默认成启用或禁用。

启用平面映射时，提供 `geometry_kind`、渲染顶点矩阵 `vertex_linear_transform`、原点基变换 `origin_basis_transform` 和参考平移 `reference_translation`。非零几何分支还需要参考线性矩阵 `reference_linear_transform`、顶点平移 `vertex_translation`、法线矩阵 `normal_transform` 及 `normalize_transformed_normal`。这些输入表示不同的原生变换，不能互相替代或一律填单位矩阵；具体组合顺序见[格式说明](格式说明.md)。启用状态下不会额外应用参数映射的几何比例和两轴因子。

查询存在 `face_frame` 时，优先沿面坐标架投影，不需要法线；否则必须提供同一渲染坐标系的法线。启用 Planar 时忽略 `native_uv`，不会因为法线缺失而自动改用已有 UV。法线接近平行参考轴时由原生阈值决定回退，不以通用面朝向规则替代。

Planar 查询具有需要显式传递的原生状态：动态法线查询会更新二维偏移，后续面坐标架查询会读取该偏移。接口不修改输入，而在成功结果中返回 `next_state`，应将它传给同一处理序列中的下一次查询。

```cpp
auto state = p3d::prepare_material_planar_sampling(registered_uv, planar_context);
if (state.at("status") == "prepared") {
    auto result = p3d::sample_material_planar(state, render_vertex, render_normal);
    if (result.at("status") == "computed") {
        auto uv = result.at("uv").get<p3d::Point2>();
        state = result.at("next_state"); // 下一次查询使用更新后的偏移。
    }
}
```

独立处理序列可以持有独立状态并行求值；同一序列中有偏移依赖的查询应保留顺序。失败结果不返回 UV 或下一状态。动态分支还提供 `basis_u`、`basis_v` 和 `fallback_axis_used`；面坐标架分支不会更新偏移。`branch: planar_disabled` 表示转入参数映射，其实际坐标选择见 `parametric_branch`。

Parametric（类型 0）使用 `<p3d/material_parametric.hpp>` 中的 `prepare_material_parametric_sampling(uv_transform, context)` 和 `sample_material_parametric(prepared, point, native_uv, face_frame)`。准备接口直接接收 `build_material_uv_transform()` 的类型 0 成功结果。相对尺度模式无需额外渲染输入；绝对尺度模式要求 `MaterialParametricRenderContext` 明确提供 `geometry_scale` 与 `preparation_frame_present`。

准备阶段有坐标架时，提供 `preparation_frame`：库分别归一化它的两条轴，再乘几何比例，原点及二维 UV 矩阵保持不变。明确无坐标架时，则需 `use_parameter_factors`；为真时再提供原生 `parameter_factors` 两分量，为假时两分量按原生规则取 1。这两个因子分别乘几何比例后，调整 UV 矩阵的第一、第二列，平移不变。未知的坐标架存在状态不能当作“无”，也不能从网格包围盒猜参数比例。

逐点查询按以下优先级选择输入：

1. 存在 `face_frame` 时，按面坐标架投影；若准备结果已有归一化坐标架，则优先使用准备结果中的坐标架。
2. 无面坐标架但有 `native_uv` 时，使用原生二维 UV。
3. 两者都明确不存在时，使用渲染顶点 XY。

这里的 `native_uv` 是顶点或面角已有的二维坐标，不是贴图尺寸。可选参数为空明确表示对应原生数据不存在；未知是否存在时，应先保留未确定状态，不能以空参数触发回退。准备结果有坐标架也不会强制覆盖一个没有逐面坐标架的查询。所有分支最终应用二维 UV 矩阵，不需要法线，不限制结果范围。

`MaterialParametricFrame` 与 `MaterialElevationFrame` 是同一类型的两个名称，共享已确认的原生面坐标架结构和投影计算。查询的 `branch` 区分 `prepared_frame`、`per_face_frame`、`native_uv`、`vertex_xy`，`projection_uv` 保留最终二维矩阵之前的坐标。准备结果可重复和并发读取；几何分支为零或非零时，类型 0 使用相同的上述规则。

ElevationDrape（类型 1）使用 `<p3d/material_elevation.hpp>` 中的 `prepare_material_elevation_sampling(uv_transform, context)` 和 `sample_material_elevation(prepared, point, face_frame)`。第一个参数直接使用 `build_material_uv_transform()` 对类型 1 返回的成功结果，无需调用类型 3–7 的投影准备接口。

`MaterialElevationRenderContext` 要求明确的 `geometry_kind`。非零分支使用原生渲染参考点未经变换的 `reference_xy`，并读取 `texture_present`：明确无纹理时，两轴偏移均减去其向下取整值；有纹理时还需 `texture_axis_flags`，每轴零值保持偏移，非零值执行上述处理。缺少纹理状态不等于无纹理，这两个标志也不能直接用其他渲染库的寻址枚举替代。

零几何分支还要求 `preserve_registered_offset`、`geometry_scale` 和 `vertex_frame`。偏移保留标志为真时，直接保留注册矩阵的平移，不读取参考点或纹理状态；为假时按前述规则调整。两行线性系数随后乘以单精度计算的几何比例平方倒数。`vertex_frame` 是 `MaterialElevationFrame`，包含渲染顶点坐标系中的原点和两条按行存储的投影轴；此处不自动猜测单位坐标架。非零几何分支不读取这三个输入。

查询时，提供的 `face_frame` 优先于两种几何分支，先从点减去该坐标架原点，再沿两条轴投影。省略它明确表示无逐面坐标架：非零分支直接取顶点 XY，零分支使用准备时的 `vertex_frame`。所有分支最后应用准备后的二维 UV 矩阵；不需要法线，也不会把结果夹紧到 `[0,1]`。

```cpp
#include <p3d/material_elevation.hpp>

// elevation_context 必须来自与 render_vertex 一致的实际渲染上下文。
auto registered_uv = p3d::build_material_uv_transform(layer_getter, uv_context);
auto elevation = p3d::prepare_material_elevation_sampling(registered_uv, elevation_context);
if (elevation.at("status") == "prepared") {
    // 仅在原生逐面坐标架明确不存在时省略第三个参数。
    auto result = p3d::sample_material_elevation(elevation, render_vertex);
    if (result.at("status") == "computed") {
        auto uv = result.at("uv").get<p3d::Point2>();
    }
}
```

准备结果的 `offset_reduced`、`registered_offset_preserved` 和 `inverse_squared_scale` 分别说明两轴偏移处理、注册偏移保留及实际比例。查询的 `branch` 区分 `nonzero_geometry_kind`、`zero_geometry_kind`、`per_face_frame`；`projection_uv` 是二维仿射变换之前的坐标。准备结果可重复及并发读取。原生上下文的选择与关联仍需调用方明确提供；接口不会从纹理路径、模型包围盒或面法线反推这些输入。

`computed_transform` 保留求逆并按行缩放的矩阵、修正零分量后的缩放，以及 `inverse_succeeded`、`inverse_method`。原生求逆失败时会使用单位矩阵继续缩放，库保留这一行为和失败标记；这与缺少输入时猜测单位矩阵不同。显式矩阵开关为真时，最终矩阵使用调用对象自己的九个源分量，不再求逆、缩放或转置。开关或启用的显式矩阵未知时，最终状态为 `not_evaluated`，已算出的 `computed_transform` 仍可检查。任一所需计算出现非有限结果时不发布完整变换。

`initial_load_filter` 可识别材质表或目录记录在原生读取入口的接受、跳过或读取错误；检查 `status` 和 `reason`，不要把 `accepted` 当成已选定的材质。源记录完整保留。缺少源子标志的后代也会按计数建立归属，并列在表的 `unflagged_descendant_record_indices` 中；库不修改原始标志。

需要按原生输入过滤和递归计数重建成员时，检查表的 `initial_load_members.status == "resolved"`，再读取其中的 `members`。它可能与源表的 `members` 不同：非零前缀不计数，某些跳过记录仍计数，而且读取器要等完整子记录返回后才检查父表是否结束。失败时成员数组为空，错误状态及已消费、跳过的记录下标保留。这个结果以读取到该表为前提，仍不表示它是运行时活动表；源归属反向字段 `table_memberships` 不用于查询此输入视图。

`initial_load_members.record_conversions` 提供输入过程中类型 13、24、62 的转换分支和后代计数来源。遇到这些类型不会直接中止成员重建；旧布局升级可能改变计数的来源，库按转换后的规则读取子链。类型 13 升级时另提供 `upgraded_base`，其 `payload_reconstruction` 为 `base_reconstructed`。基础载荷不含属性尾部，其他转换的支持范围见各自状态和格式说明。

类型 13 原生记录的 `reference_input.layout` 提供布局判断；旧版升级后的完整记录在 `converted_record`，可用 `p3d::unbase64` 解码其 `base64` 字段。原始 `data`、`links` 保持源布局。`reference_input.transform.status == "computed"` 时，可读取 3×3 行主序 `matrix` 和 `scale`，并通过 `source_matrix_offset`、`source_scale_offset` 追溯源位置。该结果的范围是基础矩阵载入后、属性链接处理前，不包含最终引用链累计，也不能直接当作 `mapping_reference_scale`。需要最终引用上下文的接口仍应传入已确定的链比例。

引用的二维裁剪点在 `reference_input.clipping.boundary.source_points`。使用前检查 `loader_status == "accepted"` 和 `all_components_finite`；源文件中存在的点仍可能被原生点数规则拒绝。上下深度及开关在 `clipping.depths`，有限局部深度范围在 `depths.local_interval`。这些数据保留引用局部坐标，需要结合引用及视图上下文才能应用到场景；库不自动闭合边界或用局部深度生成世界裁剪体。

项目资源引用还可读取 `resource_reference.interpretation`。状态为 `decoded` 时，主上下文和第二上下文的选择规则分别给出；若有 `lookup_request`，其中 `reference` 与 `search_path_setting` 是调色板资源查找的输入，调用方可按自己的资源系统处理。查找请求中的末级名称可能与完整源引用不同，源目录和变量仍保存在 `value`。不要把请求存在视为资源已找到，也不要据此覆盖图元的材质。

需要原生目录实际使用的名称时，检查 `catalog_name.reader.status == "success"`，再读取 `reader.value`；资源文本同理由 `resource_reference.reader` 提供。`reader.value` 可能与外层通用源值不同。资源字段缺失或读取失败时，`interpretation.reader_fallback` 会说明默认分支，使用当前资源上下文及空成员名；这与成功读到空字符串后返回 `rejected_empty_reference` 不同。

材质库引用也通过同一 `interpretation` 读取，`kind` 为 `library_resource`。此时 `lookup_request.reference` 指向外层库资源，`member_name` 指定其中的成员；不要将二者拼成一个图片文件路径。`member_source`、`member_path` 及可选的嵌套库字段保留原生拆分过程，源引用始终可从 `value` 取得。检查 `status` 后再使用这些结果，库不会加载外部材质库。

普通 `.pal` 路径返回 `kind: palette_resource`。其 `context_cases` 按资源查找结果及当前材质表的资源成员匹配情况描述上下文选择；`primary_context` 为空表示尚未求值，不能以空值推定默认材质。成员匹配针对键 `3` 的资源引用，不针对材质显示名称。普通 `.p3d` 形式则使用当前上下文；不支持的普通扩展名返回 `rejected_extension`，源值仍然保留。

材质内的原生复用通过 `settings.map_bindings.entries` 读取。先检查 `selection` 与 `status`，再使用条目中的来源索引访问同一 `settings.maps` 数组；纹理层和映射参数可能来自不同条目，不能只取当前节点的 `Filename` 作为最终纹理。重复节点和被替换的记录始终保留。该关联结果不包含过程纹理求值，循环或无效引用必须由调用方处理。

XML 子节点中的纹理层通过 `maps[].texture_layers.entries` 读取，保留原有顺序及 `child_index`。每层的 `semantics` 提供类型、类型回退、引用字符串、具名参数及标志位；完整嵌套内容通过 `xml_path` 对照源 `tree`。层类型识别不等于该层已参与最终材质，调用方应同时检查父级的 `activation_status`、`composition_status` 及贴图引用来源。

需要收集外部资源时，读取材质定义的 `texture_references`，其中包含 `Filename`、纹理层主引用和 `M556` 追加引用。需要精确来源和顺序时，再查看对应贴图或层的 `semantics.additional_texture_references`；不要自行按逗号切分 `M556`。库保留相对路径、非文件引用、重复项和空项，不搜索目录、不下载或加载图片。

显式网格还可直接保存纹理资源名称，并不一定通过材质定义引用。读取命令的 `decoded.mesh_channels.illumination_texture`，或图元范围的 `mesh_channels.source.illumination_texture`：状态为 `lookup_requested` 时，`reference.filename` 是原始资源引用，`search_path_setting` 表达原生查找使用的设置名。其余状态区分未保存名称、`~` 禁用标记及不可用名称。调用方决定如何获取资源；不要把这个名称当作材质 ID，或把 `lookup_requested` 当成贴图已加载。

嵌套过程参数通过贴图或层的 `procedures.entries` 读取，纹理复制器参数通过 `replicators.entries` 读取。先检查各包的 `reader_applicability`，再检查条目的 `selection`、字段 `status`；过程参数还需检查 `type.status` 与 `reader_schema_status`。类型 10 的通道和控制项保持单独层次。`child_index` 对照各自父节点的源 `tree.children`，不是全局节点编号。参数表只提供已确认的读取结构，未命名参数和未求值状态应继续保留给上层处理。

纹理复制器的构造及赋值结果在 `replicators.initial_state`。`object_state` 区分没有对象、已构造和未确定；缺少 `M541` 时不会创建默认对象，而存在空 `M541` 时会创建带原生初值的对象。每个参数给出 `constructor_value`、`value`、`read_status` 和 `source_read`。原生版本转换复制本地层时，`local_layers.replicator_copies` 保留复制出的参数状态及源层的 `child_index`；这些复制器及内部设置属于新对象，不与来源共享。该子视图有独立的 `status`，贴图拓扑已确定不代表复制器参数也全部确定。

源 Map 的 `reader_path` 和层的 `semantics.reader_path` 可用于查看层集合、过程包、复制器或预设分支。`reader_applicability.status: read` 表示读取该源节点时会调用相应读取器；最终内容来源仍应结合 `map_bindings` 判断，不能以此代替外观求值。单 Map 的资源引用转换未确定时会返回 `unresolved`，库不会尝试在本机寻找贴图。

旧式预设使用同一贴图或层下的 `legacy_parameters`。`entries` 保留源内容记录及逐条转换结果，`parameters` 提供按源顺序写入后已确定的值；颜色的 `source_entry_indices` 分量可能来自不同记录。`grad1d` 的控制点在 `gradient_controls.channels`，同时区分构造值和记录写入值。使用前检查 `reader_applicability` 与 `status`；这些控制数据不代表库已经计算出过程纹理。

`document.material_assignments()` 单独返回原生按名称分配材质的属性，包含源流、记录 ID、记录偏移及属性序号、索引、偏移和原始载荷。组 4、索引 0 的 `decoded.material_name` 是构件级材质名；索引 1 的 `decoded.value` 保存部件索引字符串到材质名的 JSON，索引 2 保存材质名到部件索引集合的 JSON。有效 JSON 标记为 `json_status: parsed`，可解码时保留原始文本，完整字节始终保留在 `payload`；其他索引不推定用途。组 2 的旧式部件分配另返回 `legacy_part_material_name`，其属性索引就是源部件索引。

`document.materials()["assignment_rules"]` 描述原生图形构建时的材质顺序：高级部件名称引用、旧式部件名称引用、构件材质、图形条目自身材质。构件材质先查原生材质引用，再查高级名称引用；名称无法找到材质时继续回退。原生部件索引从 0 开始，按图形条目顺序递增；它不是三角形序号。原生名称比较不区分大小写，并受运行时区域设置影响。

构件级原生数值引用通过 `document.materials()["native_element_references"]` 读取。每项的 `reference.material_id` 保留完整 uint64；先检查 `reference.status`，并检查 `reader_selection` 是否为 `first_match`。重复项以 `shadowed` 保留；损坏的首条引用不会自动改用后续值。`partial` 表示材质 ID 已读取但仍有未解释的后缀，`invalid` 表示无法完整读取 ID。需要查看原始字节时，使用 `native_record_index` 和 `linkage_index` 访问 `document.native_records()[...]["links"][...]`。这些引用包含源流和偏移，不能只按构件 ID 合并，也不能直接当作图元最终材质。

`document.materials()["native_element_name_references"]` 返回 `0x4F5A` 名称链接及相同的来源索引。`reference.status == "decoded"` 时读取 `material_name`；`requires_ansi_decoder` 表示名称使用依赖来源环境的 Windows ANSI 字节。此时将 `p3d::unbase64(reference.at("source_bytes").at("base64").get<std::string>())` 得到的完整载荷传给 `p3d::decode_native_material_name(payload, ansi_decoder)`。`ansi_decoder` 的类型是 `std::function<std::string(const p3d::Bytes&)>`，收到不含长度字段、零终止符和尾部字节的名称字节，返回 UTF-8；代码页由调用方确定，库不使用当前机器的默认代码页猜测来源。也可直接使用源链接的 `payload` 字节。这些名称仍需在相应材质目录上下文中解析，不能按名称把不同资源中的材质合并。

活动构件也通过 `element.metadata["advanced_material_assignments"]` 提供这些属性。部件索引保持源值，不能直接当作三角形序号或几何定义索引。当前 `PrimitiveView::material_status` 和 `material_candidates` 仅描述数值 ID 引用；按名称的分配尚未自动绑定到定义或覆盖图元样式，调用方应同时读取上述原生分配记录。

已取得实际重建条目顺序时，可包含 `<p3d/graphics_material.hpp>`，调用 `resolve_rebuilt_graphics_materials(entries, attributes, context)` 计算每个条目的材质选择。`entries` 是传给原生图形构建过程的有序条目数组，每项含 `inline_material`（明确没有材质时为 `null`）；`attributes` 是该实体完整、已选定的原生属性集合，保持源顺序，含 `group/key/index/payload`。不要只传材质属性子集：原生重复键的选择还受完整集合长度与排序影响。

另一个入口 `<p3d/material_assignment_table.hpp>` 用于图层／颜色分配表。组 0、键 20015 的 XML 属性自动提供 `decoded.material_assignment_table`；也可调用 `decode_native_material_assignment_table(xml, text_context)`，在已确认来源区域设置时提供 `compare` 回调，完成不同图层／材质名称的比较和分配表规范化。相同字符串无需比较回调；无法比较时保留源条目并返回 `unresolved`，不能直接拿源条目顺序进行最终查找。

取得规范化表后，`lookup_native_material_assignment(table, query)` 接收 `NativeAssignmentQuery`：`layer_name` 为 UTF-16 图层名，`color` 为原生颜色值，`extended_colors` 为所属模型已加载的扩展颜色表，`text.uppercase` 提供来源运行时的单码元大写转换。扩展颜色表未加载时保持 `std::nullopt`，确定为空时传空向量；索引颜色查询无需此表。返回 `matched`、`not_found` 或 `unresolved`，命中项附带 `entry_index`、`pass`、`material_id`、`material_name`。`pass` 区分精确匹配与模式匹配，`material_loading` 仍为 `not_evaluated`。此入口不自行选择模型、加载材质或覆盖图元样式；调用方的比较回调须与源区域设置一致，并自行保证并发安全。

从已选模型头的属性集合选表，可调用 `select_native_material_assignment_table(attributes, requested_name, text_context)`。传入完整集合，保持源顺序、重复项及 `group/key/index/payload`；接口直接读取载荷，忽略调用方提供的解码注解。名称为空时选择原生排序后遇到的第一张表，否则按来源区域设置比较表名。返回 `selected`、`not_found` 或 `unresolved`；选中时提供 `source_ordinal`、`attribute_index`、`source_attribute` 和 `table`。表的选择与规则规范化状态分别报告，选中后仍须检查 `table.status`。模型头尚未完整加载时，不要用空属性数组代替未知集合。

`resolve_native_assignment_material(table, query, registered_catalog, context)` 将规则匹配接到材质目录加载。`registered_catalog` 与 `lookup_native_material_id` 接受的单个目录一致，必须属于已确定的项目，且已经完成所需目录更新。`NativeAssignmentMaterialContext::id` 设置 ID 路径的资源键、比较和加载回调；`compare_name`、`load_name` 设置名称路径，名称候选及其顺序直接取自同一目录。两个加载回调都接收原目录条目索引，但须分别使用各自原生查询的模型／资源上下文。结果为 `loaded`、`not_found`、`load_failed`、`rule_not_found` 或 `unresolved`，成功时给出调用方的 `material_index`，`rule` 和 `loads` 保留选择及加载过程。`rule_not_found` 仅表示当前表没有规则命中，外层父级／图层回退尚未求值。

分配表中的 `palette_references` 提供材质库引用，保留 `source_index`、`source_value`，并拆出 `reference_kind`、`library_reference`、`palette_path` 和 `palette_name`。单独处理引用文本可调用同一头文件中的 `decode_native_palette_reference(reference, text_context)`。`palette_name` 是原生路径拆分得到的文件主名；`palette_path` 保留前缀拆分后的路径，不转换为本机绝对路径。返回 `decoded` 只代表引用语法已解释，`rejected` 表示原生入口拒绝空文本，其他未确认情形返回 `unresolved`。资源获取由调用方决定；`resource_lookup` 和 `table_registration` 不表示已加载材质库。

`GraphicsMaterialContext::native_entity_material` 表示实体原生材质查询的完整结果，包含按 ID 的回退加载。`GraphicsMaterialResult` 的 `known = false` 表示未知；`known = true` 且无 `material_index` 表示确定没有加载结果；存在索引时指向调用方自己的成功加载材质集合。`lookup_name` 接收 UTF-16 名称和查询种类：`advanced_part/advanced_entity` 使用当前项目及开启更新的原生查询，`legacy_part` 使用所属文件及关闭更新的查询；回调应返回原生查询的首个成功加载结果，不能只匹配目录名称。`load_inline_material` 负责条目内联材质在所属项目中的转换。库不自行选择项目、搜索文件或获取贴图。

实体源记录到这个查询结果的选择过程可交给 `<p3d/entity_material.hpp>` 中的 `resolve_native_entity_material(native_record, entity_context)`。输入取自 `document.native_records()`，必须保留该实体完整、有序的 `links`；接口直接读取源载荷，不依赖可被编辑的 `decoded` 注解。所属项目应已确定。`entity_model_resource_available` 表示实体模型是否有效并能提供原生资源上下文，**不表示材质或材质表是否存在**；无法确认时保留 `std::nullopt`。

```cpp
p3d::NativeEntityMaterialContext entity_context;
entity_context.entity_model_resource_available = model_resource_available;
entity_context.lookup_id = load_entity_material_by_id;
entity_context.lookup_name = load_entity_material_by_name;
auto entity = p3d::resolve_native_entity_material(native_record, entity_context);
graphics_context.native_entity_material = entity.material;
auto bindings = p3d::resolve_rebuilt_graphics_materials(entries, attributes,
                                                      graphics_context);
```

`lookup_id` 接收完整 `uint64_t` ID 和 `NativeEntityMaterialIdQuery`：`primary_resource_update_true` 使用实体模型给出的资源上下文并开启更新，`fallback_resource_update_false` 使用所属项目对应的回退资源上下文并关闭更新。两者在已选所属项目的材质管理器中查询，回调须保留各自的资源索引和实际缓存／提供者加载过程，不能合并为一次全文件 ID 匹配。`lookup_name` 接收 UTF-16 名称，负责完整的主名称查询，包括项目准备、开启更新、全部候选加载及首成功结果选择。即使名称为空，该回调仍会被调用；仅在目录查询内部才适用空名称不匹配的规则。

选择规则为：模型资源上下文可用且首项 ID 不是全 `1` 时，尝试主 ID 加载；否则尝试首项名称。主查询明确返回空后，再按有效 ID 执行外层回退。**主 ID 加载失败不会转为名称查询。** 缺少回调、未知结果、损坏的已选引用或未知分支条件返回未确定，不能当作加载失败继续回退。名称按原 Windows ANSI 编码解释；非 ASCII 名称需提供 `ansi_decoder`，将首 NUL 之前的源字节转换为 UTF-8。库不会猜测来源代码页。

返回值的 `material` 可直接用于上例；`report.status` 为 `matched`、`not_found` 或 `unresolved`。`id_reference`、`name_reference` 提供选中链接的索引、存在时的源偏移及解释结果，未使用的分支为 `not_inspected`；`lookups` 记录已执行查询的先后、更新开关和加载结果。首项重复引用即使无效或含无效 ID 哨兵，也不会被后续同类引用替代。回调应保持本次实体与所属项目关系稳定，可按查询要求更新内部目录；库不重试回调，也不自动推断重建部件顺序。

返回的 `entries` 与输入逐项对应，提供 `entry_index`、`part_index`、`status`、`source`、可选 `material_index` 和 `lookups`。`resolved` 表示该条目在本轮查询中选定材质；`unassigned` 表示本轮所有查询均确定没有结果；`unresolved` 表示较高优先级仍未知，不能直接采用较低层。`selected_material_pointer` 分别为 `non_null`、`null`、`unknown`，描述本轮选择将交给样式处理的材质状态，不是运行时地址。结果的 `scope` 为 `rebuilt_graphics_material_selection`，`selection_phase` 为 `before_symbology_resolution`；后续原生样式处理仍可能补充材质，`draw_material_status` 保持 `not_evaluated`，不能把 `unassigned` 当作最终无材质。没有输出几何的条目仍占据原生部件编号，材质标识 0 也可以有效。回调应在同一查询快照中工作；并发调用时由调用方保证自身回调的线程安全。

此接口要求每条目均有可用的原生图形构建器。它不负责从序列化缓存恢复最终重建顺序，也不会据此改写 `PrimitiveView`。仅在已独立确认某个 `geometry_packets` 数组就是该构建过程的输入时，才可直接传入该数组；参数化组件的条目跳过、展开和重新排列不能靠数组下标猜测。

包含 `<p3d/material_lookup.hpp>` 后，可以用 `lookup_native_material_name(name, context)` 实现上述名称回调中的目录查询部分。`NativeMaterialNameContext::names` 是已选项目在必要更新完成后的完整、有序 UTF-16 材质目录；保留重名项，并设置 `catalog_complete = true`。`compare` 接收目录名称和查询名称，返回与源环境 `_wcsicmp` 相容的比较值；区域设置无法确认时返回 `std::nullopt`，不要自行用小写转换替代。双方名称均按首个零码元截断，空查询不匹配任何项。

```cpp
p3d::NativeMaterialNameContext lookup;
lookup.names = prepared_catalog_names;
lookup.catalog_complete = true;
lookup.compare = compare_source_locale;
lookup.load = load_catalog_entry; // 参数是 names 中的原始索引。
auto found = p3d::lookup_native_material_name(material_name, lookup);
if (found.at("status") == "loaded") {
    auto index = found.at("first_material_index").get<std::size_t>();
    // index 属于 load_catalog_entry 返回的成功加载材质集合。
}
```

`load` 返回 `GraphicsMaterialResult`，必须包含该目录项实际的缓存／提供者加载结果；可调用已有源读取接口，但仅有成功解码的 XML 不等于完整加载已经成功。库先收集所有同名候选，再按原目录顺序调用每个候选的 `load`，首项成功也不会提前停止；重复材质索引同样保留。因此不要在回调内部把未知候选当成失败或省略后续加载。

`candidate_indices`、`loads`、`material_indices` 分别保留候选顺序、加载轨迹和成功结果。`not_found` 表示没有同名候选，`load_failed` 表示候选均明确加载失败；对应的原生返回码均为 1，诊断码分别为 3、4。成功为 `loaded`，两种原生码均为 0。缺少上下文或回调异常时返回 `unresolved`，原生码保持 null；不能把这个状态当作可回退的原生未命中。已完成的加载前缀仍保留，`first_result_status == "matched"` 只确认首个结果，不表示后续加载已完成。回调调用顺序固定，不并行加载，也不自动重试已执行的回调。

这个入口从准备完成的目录开始，并以空结果列表执行查询。项目选择、需要时的目录更新，以及资源服务仍由调用方接入；不得把初次目录无条件代替之后已改变的活动目录。空名称的短路也不表示可以省略外层必要的项目准备。

按 ID 查询已准备的目录时，同一头文件提供 `lookup_native_material_id(id, registered_catalog, context)`。`registered_catalog` 是 `document.native_material_catalog(options)` 返回数组中已选定的一个完整目录对象，调用前应完成当前请求需要的项目选择和目录更新。它使用注册后的 `entries` 及其资源上下文，不能换成按材质名称整理的列表，也不能直接传入外层数组。

```cpp
p3d::NativeMaterialIdContext id_context;
// 省略 resource_index_key 表示所选目录的当前资源；显式空字符串是另一个已知键。
id_context.load = load_registered_entry; // 参数是 registered_catalog.entries 的索引。
auto found = p3d::lookup_native_material_id(material_id, registered_catalog, id_context);
if (found.at("status") == "loaded") {
    auto index = found.at("material_index").get<std::size_t>();
    // index 属于 load_registered_entry 返回的成功加载材质集合。
}
```

索引键由完整 64 位 ID 和资源 `index_key` 组成，`comparison_key`、材质名称及资源成员名称均不能代替它。`resource_index_key` 接收显式 UTF-16 查询键，按首 NUL 截断；未设置时，使用所选目录的 `current_context`。相同目录中的两个符号当前上下文、或完全相同的具体键，可直接确认相等。不同具体键需要 `compare` 提供与来源 `_wcsicmp` 及目录注册相容的纯比较函数；未知比较返回 `std::nullopt`。若需要在符号当前上下文和具体键之间比较，应在生成目录时通过 `MaterialCatalogOptions::current_context` 提供实际键，不能将未知当前上下文当成空字符串或其他文件的上下文。

`selected_catalog_index` 引用原目录的条目，可继续追溯其 `member`、`material_attribute` 和源记录；库不复制材质或重新编号。只有完整索引中唯一匹配的条目会传给 `load`，并且只调用一次。`loaded`、`not_found`、`load_failed` 分别表示加载成功、无匹配条目、选中条目明确加载失败，原生诊断码分别为 0、3、4。全 `1` 的无效 ID 哨兵在查询前返回 `invalid_identifier` 和诊断码 1，ID 0 仍有效。缺少上下文、比较或加载未知，以及同一键出现多个已注册条目时返回 `unresolved`，诊断码保持 null；不通过“取第一项”修复冲突。

此入口可用于 `NativeEntityMaterialContext::lookup_id`：`loaded` 转为 `{true, material_index}`，确定的 `not_found/load_failed/invalid_identifier` 转为 `{true, std::nullopt}`，`unresolved` 保留未知。两种实体 ID 查询仍须分别准备正确的资源上下文和更新状态；目录查询本身不会省略或合并外层回退。

参数构件的统一材质覆盖另用 `resolve_component_material_overrides(decoded_instance, context)`，输入是 `ParaCmptInstance` 的 `value.decoded`。例如，在已经取得完整原生材质列表，并确认 Noumenon 不含组件材质属性时：

```cpp
p3d::ComponentMaterialContext context;
context.material_names = loaded_material_names; // UTF-16，原生成功加载顺序
context.material_list_complete = true;
context.noumenon_material_known = true;
auto result = p3d::resolve_component_material_overrides(decoded_instance, context);
if (result.at("status") == "override_selected") {
    auto index = result.at("material_index").get<std::size_t>();
    // 使用与 loaded_material_names[index] 对应的材质。
}
```

存在 Noumenon 组件材质属性时，将其窄字符串源字节放入 `noumenon_material_name`；未知时保持 `noumenon_material_known = false`。非 ASCII 来源还需设置 `ansi_decoder`。`native_material_catalog()` 返回登记结果，不能未经实际加载就当作本接口要求的成功加载列表。结果只描述构件重建阶段的统一覆盖，后续实体／部件材质规则和派生图元对应仍需单独处理。

`uv_status` 区分 `explicit_source`、`absent`、`partly_explicit` 和 `not_applicable`。贴图文件名、路径和投影参数是源引用，库不拼接成本机绝对路径，不打开或下载图片。调用方负责资源定位、纹理打包以及到目标材质系统的转换。

`document.embedded_textures()` 返回文件中实际保存的嵌入图片记录。每项包含源流、记录 ID、记录偏移及属性身份；`material_candidates` 索引 `document.materials()["definitions"]`，`material_status` 表示 `resolved`、`missing` 或 `ambiguous`。候选按源流和记录 ID 关联，不按文件名合并；没有材质候选的图片记录也会返回。

```cpp
for (const auto& texture : document.embedded_textures()) {
    const auto& decoded = texture.at("decoded");
    if (decoded.value("encoding", "") != "embedded_texture_file") continue;
    auto filename = decoded.at("filename").get<std::string>();
    auto bytes = p3d::unbase64(decoded.at("file_data").at("base64").get<std::string>());
    // bytes 是原始图片文件字节；由调用方决定如何保存或交给图片解码器。
}
```

图片属性解析失败时，记录仍返回 `payload` 及 `decoded.decode_error`。文件名仅是源信息，不是库选择的输出路径。此接口按调用生成结果副本；需要反复处理时应保留一次调用的结果，或从 `graphics_records()` 直接读取属性，避免反复复制图片数据。

## 6. 曲线精度与线程

```cpp
p3d::Tessellation policy;
policy.chord_tolerance = 0.1;  // 源坐标单位；不是固定的毫米或米。
policy.max_segments = 100000;
auto precise_scene = document.native_scene(policy);
```

默认整圆 64 段。弦高控制作用于定义内部的曲线及变换；若实例存在缩放，需要按最大缩放折算目标世界坐标误差。达到分段上限时应查看异常或 `unknown`，不能假定要求已满足。

`Options::threads` 默认 1，内部最多使用 64 个工作线程，并受任务数量限制。多文件并发时应统一分配线程预算，避免每个文件都占满 CPU。只读访问已构造的数据不会启动后台工作。

## 7. 命令行与数据导出

```sh
# 结构记录、对象图和展开场景；输出父目录应已存在。
p3d-inspect example.p3d --threads 4 --dump output/document.json --graph output/graph.json --scene output/scene.json

# 导出所有原始流和解压流；工具创建此目录并生成 manifest.json。
p3d-inspect example.p3d --streams-dir output/streams
```

请使用构建目录中的可执行文件，或将其目录加入 `PATH`。`--dump` 导出结构化记录，不代替全流导出；`--native-summary` 输出原生场景统计，`--expanded-summary` 另执行显式展开并输出统计。JSON 写出使用给定路径，已有同名输出会被覆盖，应使用独立输出目录。

CLI 成功退出码为 0，抛出异常时向标准错误输出说明并返回 1。但某些字段错误被保存在结果中，所以退出码为 0 不代表所有字段都已理解。应按[已知限制](已知限制.md)检查诊断信息。

字节载荷通常表示为 `{ "base64": "...", "bytes": N }`；F6 叶使用 `binary_base64`。标准 JSON 文本把 NaN / Infinity 写为 null，原始字节仍保留；C++ 内存接口中的非有限浮点不因此改变。超过 2^53 的整数不应通过 JavaScript Number 往返。

完整 C++ 声明见 [reader.hpp](../include/p3d/reader.hpp)。

读取图层独立记录时，无需先重建场景：

```cpp
for (const auto& record : document.native_records()) {
    if (!record.contains("layer_definition")) continue;
    const auto& layer = record.at("layer_definition");
    if (layer.contains("decode_error") || layer.value("status", "") != "decoded") continue;
    // layer：名称、描述、图层 ID、状态、by_layer_symbology、透明度等。
    // 保留 record 的 stream、offset 和 id，以区分不同图层表的记录。
    // strings 中的错误独立于固定字段，读取名称时也需检查。
}
```

图层记录自身的属性与组合覆盖表分别保存；`display` 不是某个视图中的最终可见性。字段布局、版本范围及视图顺序项的含义见[格式说明](格式说明.md)。

沿原生图层表读取成员：

```cpp
const auto& directory = document.layer_tables();
for (const auto& table : directory.at("tables")) {
    if (table.at("membership_status") != "resolved") continue;
    for (const auto& index : table.at("member_record_indices")) {
        const auto& record = document.native_records().at(index.get<std::size_t>());
        const auto& layer = record.at("layer_definition");
        // 使用该表内的 layer_id；不要把不同表中的同号图层自动合并。
    }
}
```

`override_bindings` 给出覆盖表的来源与对应成员索引；使用前检查每条绑定的 `status`。`model_references` 指向目录中的图层组合表，使用 `table_indices` 访问 `tables`；缺失及歧义候选均保留。该目录引用原生记录，不另复制图层定义。

读取组合同步后的属性时，使用 `group_states`：

```cpp
for (const auto& group : directory.at("group_states")) {
    for (const auto& layer : group.at("layers")) {
        if (layer.at("status") != "evaluated_supported_properties") continue;
        const auto& display = layer.at("properties").at("display");
        bool enabled = display.at("value").get<bool>();
        auto source = display.at("native_record_index").get<std::size_t>();
        const auto& original = document.native_records().at(source);
        // enabled 是组合图层的显示属性；original 是提供该值的原生记录。
    }
}
```

成员列表已包含文件新增图层，并列出被排除的旧组合成员；原始数据仍完整保留。七类已支持属性的求值不会自动过滤场景，也不表示名称同步或最终视图状态已经完成。具体状态和同步模式见[格式说明](格式说明.md#图层组合属性同步)。

### 求值引用加载分支

包含 `<p3d/reference_loading.hpp>` 后，可按以下顺序组合已确定的上下文：

1. 调用 `reference_host_loading_filter()`，只有 `status == "resolved"` 时才将 `excluded` 交给 `ReferenceLoadingDecisionContext::host_filter_excluded`。
2. 包含 `<p3d/reference_search.hpp>` 后，可用 `reference_descendant_search_gate()` 求值后代搜索门控；门控选中时，对已确定的活动引用图调用 `search_reference_descendants()`。仅将已确定的 `search_required` 和 `matched` 分别填入决策上下文的 `descendant_filter_required` 与 `descendant_match`。图中下标表示对象身份，保留重复链接；`start_known` 和各列表的完整状态必须如实填写。
3. 将祖先重复检查结果、原生输入返回值、输入后的标志及上述后代筛选结果填入决策上下文，调用 `reference_loading_decision()`。这些值属于此次加载过程，不能统一用文件初始字段替代。
4. 检查决策的 `status`、`loading_state`、`reference_transferred` 和 `requested_list`。请求 `active` 或 `secondary` 时，可再用对应 `ReferenceLinkList` 调用 `reference_link_insertion()`；仅在插入判断已确定且 `append` 为真时追加。

已有对象图的父关系时，可用 `evaluate_reference_descendant_filter(query, graph, host_index, candidate_index)` 代替分别填写后代门控和起点。`object_dispatch` 应表示已确认的普通模型或普通引用实现；引用的 `parent` 使用同一图内的身份下标，只有已确定关系才设置 `parent_known`。候选节点提供 `reference_primary_flags`，已有的 `reference_runtime_flags` 会复用于匹配。返回已确定结果后，将 `gate.search_required` 和 `excluded` 分别填入加载决策的 `descendant_filter_required`、`descendant_match`。这个组合入口不使用手工指定的 `graph.start`，也不把连接目标当作所属模型，详见[对象图上下文](格式说明.md#从对象图推导后代筛选上下文)。

`native_return == 0` 不足以证明引用进入活动列表。活动列表保持原生重复项；副列表仅以原生次级键判断是否追加，不合并几何或替换已有引用。副列表拒绝追加也不撤销决策中的引用交付结果。完整输入要求和各状态见[引用加载筛选、状态与列表登记](格式说明.md#引用加载筛选状态与列表登记)。这些接口不自动打开外部文件、从文档构建宿主链或执行输入回调。

普通引用输入成功、外层加载尚未修改对象时，可用 `initial_reference_search_query(reference_record, prepared_file_specification, equal)` 构造上述 `query`，无需手工拼接运行时控制字、模型编号和主名称。`prepared_file_specification` 必须是已确定的实际文件规格，不能直接拿保存的字符串替代尚未完成的服务处理或宿主回退。构造接口会拒绝无效记录或未确定的完整控制字；主名称无法读取时留为缺失，只有搜索实际需要它才返回未确定。详见[初始搜索输入](格式说明.md#从文件记录构造初始搜索输入)。

对于普通初次输入状态，还可用 `initial_reference_loading_decision(reference_record, context)` 代替手工填写源主标志和加载后的主标志。上下文中的这两个字段会被忽略；输入返回码、宿主筛选、删除状态和重复判断仍需提供实际结果。需要调用宿主筛选等低层接口时，分别检查 `reference_target.initial_loaded_flags.primary.status` 和 `secondary.status`，仅使用 `decoded` 项的 `value`，不要用 `origin_inputs` 中的原值替代。详见[初次加载标志](格式说明.md#引用初次加载后的主次标志)。

构造普通新建引用图时，可以用 `initial_reference_graph_node(reference_record, host_index)` 初始化节点，再加入同一 `ReferenceSearchContext::models` 数组；它表达连接目标前的状态。完整父链已知时，用 `reference_link_loading_policy(graph, host_index, force_input, cap)` 求值该轮收集限制，仅在 `status == "resolved"` 时将 `require_source_bit14` 交给加载决策。`process_view_sequence` 为假时跳过该轮顺序协调和排序；不能仍无条件调用下面的顺序构造接口。宿主有效性、实际输入返回码、目标连接及外层回调仍需按实际过程处理。详见[引用嵌套深度](格式说明.md#引用嵌套深度与收集限制)。

如果要处理单条引用加载请求，可先用 `reference_link_request(graph, host_index, assigned_id, current_registry)` 判断是否返回已有对象。结果为 `reuse_reference` 时，直接使用 `object_index` 对应的节点；结果为 `input_reference` 时，才继续输入和加载状态决策。`current_registry` 应反映该时刻的登记表，新模型可使用 `initial_model_link_registry` 结果。填入节点的 `reference_link_id` 必须来自实际输入登记，不能因文件记录同名或几何相同而建立复用。接口不负责调用方的登记表和图变更，完整规则见[单条引用请求](格式说明.md#单条引用请求的原生复用)。

对同一登记表反复查询时，先构造 `const ReferenceLinkRegistryIndex index(current_registry)`，再将 `index` 传给同名查询接口，避免每次扫描、验证整个 JSON 登记表。索引保存编号及原数组位置的快照，不持有源 JSON 的引用；登记成员或顺序变更后应重新构建。索引和未被修改的图可并发读取；索引构造遇到不完整或非法登记表会抛出异常，JSON 查询入口则将这些情况报告为 `unresolved`。

### 求值视图链接顺序

若从文件的初次输入状态开始，可先调用 `initial_model_link_registry(document, model_storage, initial_id_counter)`。`model_storage` 和计数器的约束与 `Document::native_model_id_assignments()` 相同：计数器必须是该模型开始加载时的实际值，不能在多个模型之间反复使用原文件头计数器。也可将已经取得的模型 ID 分配结果与同一文档的 `native_records()` 传给对应重载，避免重复准备输入。结果登记项的 `id` 已包含输入时的编号调整，`source` 指回原记录；选定的保存顺序来源位于 `saved_sequence_source`。这个初始登记表尚未执行引用加载，不能直接当作 `ViewSequenceContext::links`。

`root_model` 表示从 `Document::models()` 中选定的根模型；唯一模型头的 `view_state` 提供默认的当前模型位置。多个模型头分别保存在 `view_records`，不会自动挑选。每个引用的 `reference_input.view_sequence_inputs` 提供基础载入时的链接 ID 和协调排除标志，可用于填写 `ViewSequenceLink`；调用方仍需确认实际链接列表和后续状态变更，不能把文件中所有类型 13 记录直接当作同一模型的链接列表。

已有对象图且需要收集候选时，可调用 `collect_view_link_candidates()`：将模型和引用对象分别标为 `ViewCandidateNodeKind::model`、`reference`，用 `nodes` 下标连接父关系，再指定 `current_model` 和 `root_model_available`。显式 `provided_candidates` 会沿父链筛选归属；未提供该数组时，使用 `include_current_model` 与 `include_links` 选择默认列表。各下标代表实际对象身份，不能用可能重复的文件 ID 代替。可将下面求出的顺序填入候选上下文的 `sequence`，由该接口完成收集后的交换排序。

包含 `<p3d/view_sequence.hpp>` 后，可将原生记录的 `view_link_sequence` 交给 `resolve_view_link_sequence()`。调用方需要提供当前已选模型的原生链接列表；列表包含空槽、重复项和协调排除标志。仅在列表完整时设置 `links_complete = true`，不能从保存的顺序 ID 反推这份列表。

需要组合普通加载流程中的列表排序时，使用 `prepare_native_view_sequence(saved, context, sort_inputs)`。`sort_inputs` 按相同的原列表顺序填写原生类别及次级键；类别 2 的初始次级键可读取 `reference_input.view_sequence_inputs.same_kind_2_sort_value`，实际运行时修改仍应独立确认。接口先协调保存顺序，再排序，必要时按排序结果新建默认顺序；不要在调用前自行重排链接。检查顶层状态后读取 `sequence.entry_ids`，用 `link_sort.link_indices` 取得排序后的原列表下标。该入口按原生条件决定默认构造，不依赖 `initialize_default`。只需排序时可独立调用 `order_native_view_links()`。

```cpp
p3d::ViewSequenceContext context;
context.links = {{101, true, false}, {202, true, false}};
context.links_complete = true;
if (root_model.contains("view_state")) {
    const auto &model_view = root_model.at("view_state");
    if (model_view.at("status") == "decoded")
        context.current_model_last = model_view.at("current_model_last").get<bool>();
}

auto sequence = p3d::resolve_view_link_sequence(
    record.at("view_link_sequence"), context);
if (sequence.at("status") == "resolved" && sequence.at("entry_ids").is_array()) {
    std::vector<p3d::ViewSequenceCandidate> candidates = {
        {0, true}, {101, false}, {202, false}};
    auto order = p3d::order_view_link_candidates(
        sequence.at("entry_ids").get<std::vector<std::uint64_t>>(), candidates);
    auto indices = order.at("candidate_indices").get<std::vector<std::size_t>>();
    // indices 引用 candidates 的原始下标。
}
```

示例中的链接及候选仅用于说明接口，实际使用时须来自调用方已确定的模型上下文。`is_current_model` 表示候选对象就是当前模型，不是对 ID 是否为零的推测。没有保存记录时传 null；需要调用默认顺序构造入口时，再显式设置 `initialize_default = true`。返回 `unresolved` 时检查 `reason`，不要把未确定结果补成默认显示顺序。求值不会修改原始记录，也不执行可见性过滤或裁剪。

## 字体声明与主字体查询

`document.native_font_catalogs()` 按文件系统容器返回首次加载时选择的字体声明目录，以 `system_container` 标识来源。文件内的模型共同使用这些声明，不能跨文件合并同号字体。目录的 `status == "resolved"` 表示已确定声明与覆盖顺序，不表示已经找到字体文件或恢复字形。

```cpp
for (const auto& catalog : document.native_font_catalogs()) {
    if (catalog.at("status") != "resolved") continue;
    for (const auto& entry : catalog.at("entries")) {
        const auto lookup_id = entry.at("font_id").get<std::uint32_t>();
        auto request = p3d::native_primary_font_request(catalog, lookup_id);
        // declaration_request 提供选中的源声明；default_font_request
        // 提供原生请求的缺省类别。两者都不等于最终字体资源。
    }
}
```

查询某条文字时，应使用文字所属文件的系统字体目录，并传入该文字的 `font_lookup_id`。字体名称按源内容保留，不自动添加扩展名、搜索文件或假定代码页。源声明查询不会执行大字体选择、缺失字体替换或字符映射；`font_resolution_status` 会明确保留未求值状态。需要继续选择字体时，使用下面的资源上下文接口。

### 使用调用方的字体资源上下文

`select_native_text_fonts()` 根据文件的字体目录、主字体和大字体的查询编号，以及 `NativeFontContext::resolve` 给出的资源状态求值。它不会扫描操作系统字体目录或加载厂商组件。

回调接收三种请求：

| `status` | 调用方提供的状态 |
| --- | --- |
| `declaration_request` | `declaration` 对应的字体对象状态，保留来源文件和字体编号的作用域 |
| `default_font_request` | `requested_font_family` 指定类别的缺省字体对象 |
| `default_big_font_request` | SHX 缺省字体初始化后，管理器中的缺省大字体；可以明确不存在 |

`NativeFontResource::identity` 是调用方定义的非 null 资源标识，库原样返回，不根据名称合并资源。`type` 为 2（TrueType）或 3（SHX），必须符合请求类别。`is_valid`、`is_big_font`、`primary_substitution_required` 是可选布尔值：未设置表示不知道，只有实际经过对应分支才要求该值。TrueType 的 `is_big_font` 固定为 false；其替换判断须显式提供 `primary_substitution_required`，不能从 `is_valid` 直接推导。SHX 的主字体替换使用 `is_valid`，不使用该独立替换字段。

回调返回 `std::nullopt` 表示缺少上下文，求值会返回 `unresolved`。这与 `present = false` 不同：后者表示已确认的声明表空对象或不存在的缺省大字体。声明表空对象按原生规则走缺省请求；缺省主字体必须存在才能继续。找不到字体文件通常产生相应类别的占位对象，应提供该对象的状态，以便按原生规则替换；不要把“不知道字体是否存在”标记为失效字体。一次调用中的资源与缺省设置应保持一致。

```cpp
p3d::NativeFontContext context;
context.resolve = [&](const p3d::Json& request)
    -> std::optional<p3d::NativeFontResource> {
    // 由调用方的字体服务解释请求，并提供已确认的对象状态。
    return font_service.describe(request);
};
auto selection = p3d::select_native_text_fonts(
    catalog, primary_lookup_id, big_lookup_id, context);
if (selection.at("status") == "resolved") {
    const auto& main = selection.at("main_font");
    const auto& big = selection.at("big_font"); // 可以是 null
    const auto& mapping_font = selection.at("character_mapping_font");
}
```

示例中的 `font_service` 属于调用方。两个查询编号均为完整 32 位接口参数，库不会自动截断；从原生类型 54 接入时，使用下面的源样式读取结果，不能把尚未确定的大字体编号默认填零。字体选择已确认也不代表字符转换、排版或字形轮廓已恢复。

### 原生文字的链接样式

`document.native_records()` 中，类型 54 记录的 `native_text` 提供文字本体，`native_text_style` 提供其基础头和链接共同确定的初始样式。接口保留源值、调整后的初始值和各自的来源；读取原记录不依赖字体资源服务。

```cpp
for (const auto& record : document.native_records()) {
    if (record.at("element_type") != 54) continue;
    const auto& style = record.at("native_text_style");
    if (style.at("font_reference_status") != "resolved") continue;
    const auto& values = style.at("initial_values");
    auto selected = p3d::select_native_text_fonts(
        catalog,
        values.at("font_lookup_id").get<std::uint32_t>(),
        values.at("big_font_lookup_id").get<std::uint32_t>(),
        context);
}
```

`catalog` 应属于这条文字所在文件，`context` 为前述字体资源上下文。`font_reference_status == "resolved"` 只表示查询编号已确定；选出的字体仍需检查 `selected.status`。如果要消费其他样式字段，还应检查样式的 `status` 及具体链接的读取状态，不能用字体引用状态替代整个样式的完整性检查。

同类链接首项为空或损坏时不会换用后续项。未命名字段以及 `unassigned_state` 不应自行解释成工程属性；其 `semantic_status` 保持未完全确定。读取成功也不会自动生成文字字形。

### 字符映射

`map_native_text_characters(native_text, context)` 使用选定字体的字符规则，把源码元转换成 Unicode 码元及 UTF-8 文字。`context` 应描述 `select_native_text_fonts()` 返回的 `character_mapping_font`，不能直接把主字体声明当作最终映射字体。库不加载字体文件，不替调用方决定代码页。

```cpp
p3d::NativeTextCharacterContext character_context;
// 此示例以已确认选中的字体为 TrueType 为前提。
character_context.mode = p3d::NativeFontCharacterMode::TrueType;
auto mapped = p3d::map_native_text_characters(
    record.at("native_text"), character_context);
if (mapped.at("text_status") == "decoded") {
    auto text = mapped.at("text").get<std::string>();
}
```

Unicode SHX 使用 `ShxUnicode`；传统 SHX 使用 `ShxLegacy`，并提供 `symbol_codes`（依次为度、直径、正负号的源编码）。这些值是字体配置值，不一定等于对应的 Unicode 码点。需要代码页转换时，还须提供 `codepage` 和 `decode` 回调；TrueType 与 Unicode SHX 分支不访问这些设置。

`decode(const Bytes&, std::uint32_t)` 接收已按原生规则截取的一至两个字节和代码页，返回 `std::optional<std::u16string>`。解码语义应与源系统的 Windows `MultiByteToWideChar`、标志 0 一致。返回 `std::nullopt` 表示不知道转换结果，求值保持未确定；返回空字符串表示已执行但转换失败，随后按原生规则保留源码元。异常也表示未确定，不能用来替代已确认的转换失败。跨平台接入时，应由调用方提供兼容解码器；库不引入 Windows API 依赖。

结果中的 `mapping_status`、`text_status` 和 `glyph_status` 分别描述码元映射、合法文字字符串和字形状态。映射可已完成而字符串因孤立代理码元无法生成，此时仍保留完整 `units`。缺少上下文时保留已确定的 `units` 前缀及 `unresolved_source_index`，但不把前缀作为完整 `text` 返回。原始 `native_text` 不被修改，字符映射成功也不表示字体轮廓和排版已恢复。

## 模型边线缓存中的代理实体

包含 `<p3d/proxy_cache.hpp>` 后，可用 `decode_native_proxy_registry(bytes)` 读取已解压缓存中的一段代理实体登记表。输入从该登记表的长度字段开始；完整缓存属性还包含其他头部和分块，不能直接将整条属性传给此接口。

结果保留源条目、子对象、重复 ID 和图形分组；`selected_entries` 给出原生登记表最后覆盖后的来源，`native_graphics_order` 给出按组编号排列的原生访问顺序，同编号图形不会合并。已支持的图形命令使用与 `parse_commands()` 相同的输出结构，命令解析失败保留原载荷及原因。

`status: decoded` 表示登记表结构读取成功，`semantics_status: partial` 表示部分源字段和显示参数仍未具名；它不表示整份缓存或最终显示关系已完整恢复。`ProxyCacheLimits` 可限制嵌套深度及实体、图形组的合计数量。所有偏移均相对于本次输入。

### 从属性集合读取缓存模型树

`decode_native_model_edge_cache(attributes)` 接收实际附着于目标记录的完整属性集合，条目采用 `graphics_records()` 的 `group/key/index/payload` 结构。输入必须包含该集合的其他属性：原生重复项选择规则会随集合大小和排序变化，不能先筛出缓存属性再调用，也不能把来自不同记录的属性拼到一起。

```cpp
#include <p3d/proxy_cache.hpp>

auto cache = p3d::decode_native_model_edge_cache(record.at("attributes"));
if (cache.at("status") == "decoded" && cache.at("model_read_status") == "decoded") {
    const auto &models = cache.at("models");
    // models 按原生读取顺序排列；children 和 parent_model_index 引用此数组。
}
```

接口读取组 21、键 22762 的索引 0 头部；版本 51 从索引 1 开始，按每个模型保存的子模型数递归读取连续属性，支持原样存储和 LZ4 压缩。缺失中间索引会报告错误，不以其他属性代替，也不返回一棵被当作完整结果的残缺模型树。其他不低于 15 的头版本仅读取公共头，`model_read_status` 为 `skipped_version_mismatch`；更低版本返回 `ignored`。

每个模型保留 `source_link_id`、源字符串、字符串登记表、图形区段及代理实体。`source_link_id` 属于原生引用查找链，并不等于已经确定的模型身份；相同值不会导致模型合并。区段的 `selected_sections` 按原生比较规则给出最终选择：第一键为有符号整数；第一键为零时忽略第二键，否则按无符号第二键比较。重复键保留首次登记的键和最后写入的值，全部源区段仍在 `sections` 中。

模型及其代理实体中的偏移相对于该模型的解压载荷，头部偏移相对于索引 0 载荷。`source_ordinal` 指向输入属性的原始位置，`unconsumed_cache_source_ordinals` 保留尚未消费的缓存属性位置。索引 65534 的 80 字节显示参数另在 `display_parameter_lookup` 中报告；缺失或长度不同返回 `host_fallback_required`，不补造默认值。索引 65535 的关联数据见 `association_cache`，须单独检查其状态；关联载荷损坏不会抹去已成功读取的模型树。

`ModelEdgeCacheLimits` 限制模型数量、单模型及总解压字节数，并对所有模型共享代理条目预算。模型和代理嵌套共同受 `proxies.max_depth` 约束。字符串长度不得超过 2048 个 UTF-16 码元，非空字段必须在声明范围内含终止符；长度越界或压缩输出长度不符返回 `not_evaluated`，不会复现原生代码的越界读取。`status: decoded` 仍只表示已支持的结构读取成功：缓存中未解释的字段、显示规则及运行时引用连接分别保留数据或未求值状态，见 `remaining_semantics`。

缓存模型的 `model_metadata` 读取可选的原生 47/32 模型头，`record` 中的 `model_unit_state`、`model_coordinate_state`、`model_view_state` 和 `model_layer_group_reference` 分别给出单位换算、原点与模型类别、已有视图顺序标志及层组引用。附加链接和未具名字段仍保留。没有该块时为 `absent`，未知类型或截断时为 `not_evaluated`，不会把原始载荷当作已解码参数。

`reference_parameters` 给出保存的引用标志、参考点、平移点、矩阵和比例。原生代码只在构造缺失的子引用时采用这些参数，已有引用及根宿主不能直接用它们覆盖。因此 `target_application_status` 保持 `not_evaluated`。确认该构造分支及实际上下文后，可以将此对象作为 `reference_affine_transform()` 的输入；缓存分支直接恢复矩阵和比例，不执行普通类型 13 加载时的列归一化或零比例默认值处理。非有限浮点数保留其位模式，变换求值保持未完成。

上述两个对象的内部字段偏移分别相对于可选模型头和 328 字节引用参数块；各自的 `model_source_offset` 给出该块在解压模型中的起点。模型头的偏移、长度和源字节均不包含流记录的四字节外层前缀。`optional_object_storage` 和 `reference_parameters_storage` 继续保留原始数据。

### 持久化属性引用

`DataUnit` 可保存被其他属性引用的值。先对选定工程的对象集合建立一次索引，再用已解码的 `persistent_data_reference` 节点查询：

```cpp
#include <p3d/persistent_data.hpp>

p3d::PersistentDataIndexOptions options;
// 只有确认输入包含选定工程全部 DataUnit 对象时才设置。
options.complete_project = true;
auto index = p3d::persistent_data_index(document.objects(), options);
auto result = p3d::resolve_persistent_data_reference(reference_node, index);
if (result.at("status") == "resolved") {
    const auto &target = result.at("target"); // 对象位置、类 ID、对象 ID
    const auto &value = result.at("value");  // 继续检查 value_status
}
```

默认可确定 ASCII 标识。非 ASCII 标识须通过 `options.encode_name` 提供源环境的 Windows ANSI 转换，回调输入为已截断首个 NUL 的 UTF-8 标识，返回转换后的 `Bytes`；转换不可用时返回 `std::nullopt`。不要默认采用解析程序当前系统的代码页，也不要直接把 UTF-8 字节当成原生名称字节。任何未能确定的标识都可能与已知名称发生转换碰撞，因此索引保留未完成状态。

`native_enumeration_order` 默认关闭；只有调用方确认输入对象顺序与原生数据集枚举顺序相同时才开启。存在重复标识且顺序未确认时返回 `ambiguous`。`candidates` 指向索引的 `entries`，其中 `object_index` 指向传入对象数组；结果始终保留原始目标身份，不合并数据对象。该接口查询已保存值，不执行属性函数或递归展开引用。

### 缓存状态摘要

主头的 `cache_state_hash` 和模型的 `reference_state_hash` 解释对应的 32 字节哈希结构，保留模式值、声明长度、摘要字节、标记及填充。原生哈希生成路径在模式为零时选择 MD5，非零时选择 SHA-1。`size_matches_algorithm` 仅表示声明长度是否符合算法的常规长度；标记字节在原生导出摘要之前就被设置，不能据此证明生成成功。声明长度超过 20 字节时，头部仍可读取，`digest_status` 会明确报告超出存储容量。

也可用 `decode_native_cache_hash(bytes)` 单独读取该结构。`compare_native_cache_hash(saved, current)` 实现原生比较规则：模式值和声明长度必须相等，长度不得超过 20，再比较声明范围内的摘要字节。标记、填充和未使用的摘要尾部不参与比较；不同非零模式仍视为不同值，长度为零也按原生规则比较。两个输入均须恰好为 32 字节，截断输入返回 `not_evaluated`。

比较接口不重新生成运行时摘要。`match: true` 只说明上述字段匹配，`cache_validity_status` 仍为 `not_evaluated`；完整有效性还依赖实际引用对象、子模型状态和显示上下文。库不会用保存的摘要自身冒充当前状态摘要，也不会据此自动启用缓存。

### 缓存的引用与实体关联

`decode_native_edge_cache_associations(attributes)` 可独立读取组 21、键 22762、索引 65535 的关联属性，不要求输入中存在索引 0 或模型树。输入仍须是同一记录上实际附着的完整属性集合。结果支持原样存储和 LZ4 压缩，并保留压缩源载荷 `source_storage`。

`reference_directory` 按文件顺序给出引用目录。`reference_link_path` 是从实际宿主逐级查找子引用的编号路径，空路径代表宿主自身；不同层级中相同的编号不会合并。每条路径附带自己的 `reference_state_hash`，整个关联块另有 `cache_state_hash`。

`associations` 按源顺序给出关联条目。`reference_directory_index` 指向上述目录；`entities` 保存实体编号和最后修改时间。`modification_time.milliseconds` 是原始双精度浮点毫秒数，SDK 定义其基准为本地时间的 1970 年 1 月 1 日零时，`time_basis` 因此为 `local`；不能直接标记为 UTC 时间戳。兼容字段 `source_state_value` 和完整的 `source_state_storage` 继续保留。非有限数值写为 null，位模式仍保留。实体查找先查询引用所指模型，必要时还有宿主文件的备用模型分支；实体编号不能用于跨文件全局匹配。

`links` 中的 `association_index` 指向本数组的源条目序号，允许前向引用；它不是实体编号或模型编号。重复索引、自引用、越界索引都保留，`source_entry_present` 和 `self_reference` 仅说明文件内对应关系。目录索引的存在性由 `reference_directory_entry_present` 表示。这些标志不证明运行时对象存在或关联生效，库不会据此合并实体或建立额外的几何复用。

原生加载还会比较当前摘要、检查实体状态和显示条件，并根据实际对象构建关联集合。解码接口不会自动取得当前运行时上下文，`runtime_attachment_status` 保持 `not_evaluated`；可用下面的查询接口处理已明确的状态与集合规则。读取成功不代表可直接启用该缓存。目录块要求条目数量与声明长度完全一致；关联条目读完后的块内余量和块外尾部则分别保存在 `ignored_section_storage`、`trailing_storage` 中。字段偏移均相对于关联属性的解压载荷。

关联数据受 `ModelEdgeCacheLimits` 的解压字节限制约束；引用目录、路径编号、关联条目、实体和链接合计受 `proxies.max_entries` 限制，路径深度受 `proxies.max_depth` 限制。通过模型树接口读取时，关联块与模型共享总字节及条目预算；`total_decoded_model_bytes` 只统计模型，`total_decoded_cache_bytes` 还包含已成功解压的关联块。

`compare_native_edge_cache_entity_state(saved_time, context)` 接收保存时间的八字节载荷和 `EdgeCacheEntityStateContext`：先检查 `entity_found`，再检查实际实体的 `runtime_flags`，最后比较 `last_modified_milliseconds`。运行时标志掩码 `0x20008` 任一位设置即拒绝；此标志不能用持久化记录头的标志替代。原生比较保留浮点数的小数部分，NaN 永不相等，正负零相等，同号 Infinity 相等。缺少当前分支需要的上下文返回 `not_evaluated`；已知拒绝分支不要求后续数据。`state_matches: true` 仅代表状态检查通过，后续显示检查仍未求值。

`select_native_edge_cache_associations(decoded, targets)` 接收关联解码结果，以及与源条目位置一一对应的 `EdgeCacheAssociationTarget`。`created` 表示实际引用和模型查找、全部实体状态及显示检查是否已成功创建该关联对象；未知不能填成 false。为 true 的条目还需提供 `reference_identity`、按源实体顺序的 `entity_identities` 并设置 `entity_identities_complete`。身份值是调用方对实际对象分配的一致标识，不要求提供或读取内存地址，也不能仅以文件内编号替代实际对象身份。

该查询按原生规则忽略自引用、对目标对象去重、遇到未创建或缺失目标停止查找；最终目标数量与源链接数量不同则清空该组链接并拒绝入选。前向引用和环本身不会导致拒绝。组的等价条件是相同的实际引用、相同的实体数量及逐项相同的实体身份，实体顺序和重复次数均保留；等价组首次入选者为代表，不合并其链接。结果按源顺序列出 `selected_source_indices`，不会假装复现原生内存地址的排序。

`retained_source_indices` 与入选集合不同：它包含链接检查通过的候选组及其直接目标，包括未成为等价组代表的候选。一个组自身链接检查失败，仍可能作为其他组的目标保留，此时其 `effective_link_indices` 为空。查询不把这种保留变成新的几何复用，也不会仅凭集合选择成功声明整个缓存有效。缺少任何必要创建结果或身份时，整体返回 `not_evaluated`；查询的组、实体、链接合计受 `ProxyCacheLimits.max_entries` 限制。
