# 接入指南

本指南介绍如何在 C++ 工程中使用解析库。代码中的文件路径是示例，请替换为实际输入。

## 1. 构建与安装

基本构建方式见 [README](../README.md#构建)。CMake 开关如下：

| 选项 | 默认值 | 作用 |
| --- | --- | --- |
| `P3D_BUILD_TOOLS` | `ON` | 构建 `p3d-inspect` |
| `P3D_BUILD_TESTS` | `ON` | 构建合成测试并注册 CTest |
| `CMAKE_BUILD_TYPE` | 由 CMake 决定 | Ninja 单配置构建建议显式指定 `Release` 或 `Debug` |

仅需静态库时，可以在配置阶段传入 `-DP3D_BUILD_TOOLS=OFF -DP3D_BUILD_TESTS=OFF`。非 Windows 构建使用系统 iconv 处理 GB18030。

安装已经构建的库：

```sh
cmake --install build --config Release --prefix install
```

调用工程的 `CMakeLists.txt`：

```cmake
cmake_minimum_required(VERSION 3.20)
project(my_app LANGUAGES CXX)
find_package(p3d CONFIG REQUIRED)
add_executable(my_app main.cpp)
target_link_libraries(my_app PRIVATE p3d::reader)
```

配置调用工程时，通过 `-DCMAKE_PREFIX_PATH=<安装目录的绝对路径>` 指定库的位置。仓库的 [examples](../examples/consumer.cpp) 提供了独立调用程序，包含 Windows 中文命令行路径处理。

## 2. 文档与场景的生命周期

```cpp
p3d::Options options;
options.threads = 4;
options.decode_binary_fields = true;
p3d::Document document(std::filesystem::u8path(u8"example.p3d"), options);
auto scene = document.native_scene();
```

`Document` 在构造时读取并解析文件。`objects()`、`native_records()` 等返回文档拥有的只读引用，使用期间应保持文档存活。`native_scene()` 返回拥有自身数据的场景，可独立保留；每次调用都会重新构建场景，不是隐式缓存接口。

`for_each_primitive()` 传入的 `PrimitiveView` 是临时视图。几何和范围指针借用场景数据；回调过程中不要修改场景，离开回调后不要保存对 `view` 本身的引用。

单流大小限制默认 256 MiB，调用方可通过 `Options::max_stream_bytes` 调整。此限制不是整个文档的内存预算。需要完整二进制叶解码时，保持 `decode_binary_fields = true`。

## 3. 读取几何与原生实例

```text
NativeScene
├─ definitions：源几何定义，每份定义有 source_key、source、geometry
├─ elements：构件元数据与实例列表
│  └─ instances：定义索引、变换、源几何 ID、样式和引用来源
└─ metadata：对象图、模型、材质、块目录、错误及其他场景数据
```

`Geometry::vertices` 使用 double；`faces` 为从 0 开始的三角形顶点索引。线、点类图元和文字分别通过 `lines`、`texts` 及图元类型表达。

显式多边形网格的法线、UV 使用独立数组，不能用顶点索引直接访问：

| 字段 | 用法 |
| --- | --- |
| `normals` | 与当前几何坐标一致的法线数组；每项为 `optional<Point3>`，无法变换时为空 |
| `source_normals` | 与 `normals` 同序同长度的原始法线，保持命令局部坐标和值 |
| `uvs` | 原始二维 UV 数组 |
| `face_normal_indices`、`face_uv_indices` | 与 `faces` 等长；每项为可空的三角形角点索引，分别指向上述 `normals` 和 `uvs`，从 0 开始 |
| `face_uvs` | 与 `faces` 等长的展开 UV，便于无需独立索引的调用方使用 |

源数组中的重复值、未引用项和索引复用均保留。多个网格按命令顺序拼接数组并调整索引，不自行合并相等数据；`NativeScene` 中已有的共享定义仍由实例引用。未提供某一角点索引通道时，相应面条目为空，即使存在数组也不借用顶点索引；库不生成缺失的法线或 UV。一个有效法线索引可能指向空的派生法线项，调用方须同时检查两层 `optional`。

可选索引引用缺失数组或越界时，受影响三角形的对应 `face_normal_indices` 或 `face_uv_indices` 为空；有效几何和其他通道继续返回。越界位置可从命令的 `decoded.index_bindings` 以及 `Geometry::unknown` 查询。命令中的原始索引保持源值，不能当作已验证的数组下标直接使用。

命令及实例变换作用于法线时，采用线性部分的逆转置，忽略平移，不自动单位化；`source_normals` 始终保持原值。奇异变换、非有限输入或不可表示的计算结果使受影响的 `normals` 项为空，但源值、面和索引仍保留。浮点病态矩阵不具有额外精度保证。`PrimitiveView` 借用定义坐标的数据；自行烘焙实例时应应用相同的法线变换，或使用 `expanded()` 的已放置结果。

网格的颜色、命名字符串、附加逐面 UV、平滑组和逐面材质列表可从命令解码结果的 `mesh_channels` 读取。包含非空扩展或扩展诊断的几何图元范围也携带 `mesh_channels`；全空扩展不生成逐三角形附加元数据。其 `source` 保存完整源通道和对应状态，`triangles[j]` 对应范围内第 j 个三角形。下面的 `range` 表示一个图元范围：

```cpp
if (range.contains("mesh_channels")) {
    const auto& extra = range.at("mesh_channels");
    const auto& source = extra.at("source");
    for (const auto& triangle : extra.at("triangles")) {
        const auto& materialId = triangle.at("material_id"); // null 或完整 uint64
        const auto& colorIndices = triangle.at("color_indices");
        if (!colorIndices.is_null()) {
            const auto& rgb = source.at("float_colors").at(colorIndices.at(0).get<std::size_t>());
            // rgb 是第 0 角点的源颜色；库没有转换颜色空间。
        }
    }
}
```

这些池的索引属于当前图元范围的 `mesh_channels.source`，不属于 `Geometry::vertices` 或普通 `uvs`。`face_uv_point_indices` 引用附加的 `face_uv_points`，材质标识和平滑组分别从源面传递到其三角形；它们不自动替换范围样式、主 UV 或法线。数量不符和未支持的对应会返回空项，并可从 `source.bindings` 及几何 `unknown` 检查原因。自行烘焙 `PrimitiveView` 的镜像时，还应同步交换附加角点索引的第 1、2 项；`expanded()` 已完成此操作。

颜色网格可以没有主 UV。此时命令的 `param_index_usage` 可为 `color`，第三组源索引仍负责颜色查表，而 `Geometry::face_uvs` 和 `face_uv_indices` 对应项为空。不要仅凭源多边形中存在 `uv_indices` 就访问空 UV 池；重建接口已经区分这些用途。颜色引用无效时保留源颜色与几何，并通过 `bindings.color_status` 报告问题。

若需要了解原生三角化路径如何选择这些通道，可读取 `source.native_triangulation`。先检查 `status == "mapped"`；`normal_mode` 给出平面或平滑组规则，`polygons` 给出该路径选择的材质与组键。布局吻合时，`triangles[j].native_triangulation` 直接定位相应源面。这个选择可能与源材质条目不同，例如缺少平滑组时原生路径会补零材质；源条目仍保存在原有字段中。此接口只解析输入路由，不替换范围外观，也不生成平滑法线，详细条件见[格式说明](格式说明.md#原生三角化输入选择)。

每个 `PrimitiveView` 对应一个图元范围：

| 字段 | 用法 |
| --- | --- |
| `element_index`、`instance_index`、`definition_index` | 回到场景中定位构件、实例及共享定义 |
| `source_range` | 读取 `channel`、`start`、`count`，确定本范围覆盖的面、线或文字 |
| `geometry` | 读取定义坐标下的几何数组 |
| `matrix` | 按 `matrix[row][column]` 存储，以列向量计算 `M × [x,y,z,1]` |
| `winding_reversed` | 烘焙该实例变换时，是否需要交换三角形第 1、2 角点及对应 UV、法线索引 |
| `topology` | `triangles`、`polylines`、`points` 或 `annotations` |

遍历三角形范围的示例，假设 `scene` 已按上文创建：

```cpp
scene.for_each_primitive([&](const p3d::PrimitiveView& view) {
    if (view.topology != "triangles") return;
    const auto& geometry = *view.geometry;
    const auto& range = *view.source_range;
    auto start = range.at("start").get<std::size_t>();
    auto count = range.at("count").get<std::size_t>();
    for (std::size_t i = start; i < start + count; ++i) {
        auto triangle = geometry.faces.at(i);
        auto uv = geometry.face_uvs.at(i);
        if (view.winding_reversed) {
            std::swap(triangle[1], triangle[2]);
            if (uv) std::swap((*uv)[1], (*uv)[2]);
        }
        // geometry.vertices[triangle[k]] 是定义坐标。
        // 烘焙时还需应用 view.matrix；保留实例时交给下游场景处理。
    }
});
```

同一个定义可以被多个实例使用；请勿直接修改共享顶点以应用某个实例的变换。`scene.expanded()` 会按需生成展开后的逐构件 JSON。使用该结果时，不要再次烘焙同一变换。

`source_key`、模型 ID、对象 ID 和定义索引都具有文档作用域。合并多个文件时，应额外加入调用方自己的文档身份。

### BGFB 源曲线与 B 样条

`binary_fields()` 中的参数化几何包可以包含 `_type: "BsplineCurve"` 表。将该表传给 `BsplineCurve::from_bgfb()`，可读取控制点、权重、节点并在源坐标系内求值：

```cpp
// table 是已解码 BGFB 树中的一个 BsplineCurve 表。
auto curve = p3d::BsplineCurve::from_bgfb(table);
auto middle = curve.point_at(0.5);
auto homogeneous = curve.homogeneous_at(0.5); // 加权 XYZ 与求值后的 W
auto domain = curve.knot_domain();
```

对象拥有自己的数据，可脱离文档使用；只读求值可由多个线程同时调用。`poles()` 和 `weights()` 保留源控制点顺序。有权重时，源 XYZ 已经乘过权重，不能再次相乘；空权重表示非有理曲线。零或负控制点权重不会被删除。

`source_knots()` 保留源节点；`knots()` 返回用于求值的节点，源未保存节点时按原生规则生成。`closed()` 是源闭合标志，`periodic_pole_shift()` 表达原生特殊接缝的控制点索引偏移，不改变源数组。`point_at()` 和 `homogeneous_at()` 接受 `[0, 1]` 内的有限比例参数；比例映射到源有效节点区间，内部重复节点取右侧值，终点取左侧值。接口不会在闭合曲线上自动循环越界参数。

解码表的 `_spline` 提供数组检查状态、控制点坐标约定、节点来源、参数区间及周期索引偏移。`status: valid` 只说明通过结构及数值检查，不保证每个参数都有有限笛卡尔坐标，也不保证源闭合标志与几何首尾相符。无效数组保留原字段并返回 `status: invalid` 与错误信息；显式构建对象会抛出异常。求值后权重为零时，`homogeneous_at()` 保留齐次结果，`point_at()` 抛出异常。

此接口对源曲线直接求值，不自动将设计操作数追加到活动场景，也不生成 B 样条曲面或布尔运算的网格。复合对象中的源路径和实例变换仍由各自的记录提供。

对于 `_type: "AkimaCurve"` 表，可按原生插值规则取得派生 B 样条：

```cpp
auto akima = p3d::AkimaCurve::from_bgfb(table);
const auto& original = akima.source_points();
const auto& retained = akima.retained_point_indices(); // 原点列中的零基索引
const auto& spline = akima.bspline();
auto point = spline.point_at(0.5);
const auto& conversion = akima.report();
```

源点列须为 6 至 5000 点，按原生断开标记和相邻近点规则过滤后仍须至少 6 点。过滤只作用于派生曲线；`source_points()` 保留所有源点，`report().ignored_points` 提供被过滤点的源索引及原因。保留点列的首尾各两个点用于端部切线，实际插值端点是保留点列的第 3 点及倒数第 3 点，其原数组索引也包含在报告中。

`bspline()` 是开放、非有理、三次的派生曲线。其控制点和节点由转换生成，不是 P3D 内另存的一套数组；节点按实际插值区段的弦长累计归一化。BGFB 表中的 `_akima` 提供转换摘要，失败时记录 `status: invalid` 和错误，源 `points` 不被替换。Akima 曲线也可作为 `BsplineSurface::trim()` 的边界成员；不会自动追加到活动场景或作为其他参数化操作的完整求值结果。

对于 `_type: "InterpolationCurve"` 表，可取得开放或周期闭合的三次插值曲线：

```cpp
auto interpolation = p3d::InterpolationCurve::from_bgfb(table);
const auto& original = interpolation.source();       // 完整传入表
const auto& points = interpolation.prepared_points();
const auto& indices = interpolation.prepared_point_indices(); // 对应源点零基索引
const auto& parameters = interpolation.parameters();
auto point = interpolation.bspline().point_at(0.5);
const auto& conversion = interpolation.report();
```

`source()` 保留源字段，`prepared_points()` 表达原生相邻近点过滤和闭合准备后的点列，`parameters()` 给出对应的归一化插值参数。若原生规则追加闭合点，该点的索引仍指向源首点，报告中的 `closure_point_appended` 为 true。周期曲线最后一点是闭合标记，参与弦长参数计算；其位置即使只与首点近似重合也不改写，派生曲线在参数 1 处回到首点。

该接口遵循 BGFB 读取路径：派生曲线固定为阶数 4、非有理 B 样条；源 `order`、`knots`、`startTangent`、`endTangent` 不参与此路径的转换。开放曲线总按弦长生成参数，周期曲线由 `isChordLenKnots` 选择弦长或均匀参数。开放端部采用自动 Bessel 条件或 `isNaturalTangents` 指定的零二阶导条件，满足原生条件时还可按 `isColinearTangents` 对齐端部控制柄。`isChordLenTangents` 在此读取路径中不生效。报告分别提供有效闭合状态、节点间距、端部条件和未参与转换的字段，不能仅根据源 `closed` 或 `order` 推断派生表示。

过滤及闭合准备后最多 4998 点；无效输入、不可表示的距离、塌缩参数区间或无法求解的系统会抛出异常。BGFB 解码表中的 `_interpolation` 提供转换摘要，失败时记录 `status: invalid` 和错误，同时保留源字段。此曲线也支持 `BsplineSurface::trim()` 的边界转换；派生控制点与节点不是额外的源几何记录。

对于 `_type: "TransitionSpiral"` 表，可求值底层缓和曲线：

```cpp
auto spiral = p3d::TransitionSpiral::from_bgfb(table);
auto value = spiral.evaluate(0.5, 1e-8, 65536);
const auto& point = value.point;
const auto& derivative = value.derivative;
double bearing = value.local_bearing;
double curvature = value.local_curvature;
double error = value.quadrature_error_bound;
```

支持原生 BGFB 工厂接受的 `spiralType` 10 至 14。`source()` 保留传入表，`length()` 返回仿射变换前整条底层曲线的长度，`report()` 提供有效曲率和长度。原生工厂依据两端方位角的大小关系确定两个曲率的符号，方位角不按一周折返；不能直接使用源曲率符号推断转向。

`evaluate()` 的比例参数在 `[0,1]` 内，映射到源 `fractionA` 至 `fractionB`，支持反向及超出底层 `[0,1]` 的源区间。`point` 为经源仿射变换后的三维位置，仍相对于底层曲线参数零点定位，不以活动区间首点重新归零。`derivative` 为三维位置对 API 比例参数的导数，包含源区间方向和仿射缩放；`local_bearing`、`local_curvature` 为变换前底层曲线的方位角和有符号曲率。

坐标用数值积分计算。第二个参数约束变换后坐标中的积分截断误差，`quadrature_error_bound` 返回该误差界，`intervals` 返回实际积分区间数；误差界不包含浮点运算及三角函数舍入。第三个参数限制区间数量，预算不足、精度耗尽或数值溢出会抛出异常，不静默返回超出约束的近似值。零长度但有效的原生底层曲线返回变换原点和零导数。

源 `constructionHint`、`extraData`、`directDetail` 不参与这个 BGFB 读取路径。解码表中的 `_spiral` 提供源语义检查摘要，失败保留原字段并报告 `invalid`。底层求值与拟合 B 样条是两个独立接口；解码表的 `native_bspline_conversion: not_evaluated` 表示尚未执行拟合。

若需读取原生缓存拟合器的输入，可调用 `spiral.native_fit_input()`。它返回仿射变换前的 `local_points`、派生采样点对应的 `source_fractions`、活动区间起点的 `local_origin_offset`、经过原生方向检查的 `endpoint_bearings` 和 `endpoint_radii`。这些数组由原生规则生成，不是文件中另存的点列。采样只在显式调用时计算，返回 `bspline_fit_status: not_evaluated`，不会把采样折线当作已拟合曲线。

该接口使用原生固定角步长及四点 Gauss 积分修正，`stroke_error_estimate` 与 `origin_error_estimate` 分别是活动段及原点偏移积分的原生局部误差估计，不是误差保证，也不包含曲线拟合、仿射放大或浮点舍入误差。需要约束坐标积分截断误差时，使用前述 `evaluate()`。采样缓冲区最多 2000 点；后续原生拟合器另有 998 点上限，通过 `fits_native_point_limit` 表达，通过该数量检查不表示拟合一定成功。可传入总积分区间预算，默认 100000，预算包含活动段与原点偏移计算，超出则抛出异常。

若需重建原生拟合 B 样条，可显式调用：

```cpp
auto fit = spiral.native_fit();
auto fitted_point = fit.curve.point_at(0.5);
const auto& poles = fit.curve.poles();
const auto& knots = fit.curve.knots();
const auto& fit_report = fit.report;
```

`curve` 为已经应用源仿射变换的三维 B 样条。`report` 提供迭代次数、原采样点数、辅助节点的局部 XY 坐标 `expanded_local_points`、归一化拟合参数 `expanded_parameters`、归一化前的总参数长度 `parameter_length`，以及收敛阈值和最大区间长度变化。`updated_source_parameters` 为最后一次弧长更新后的原采样点参数，尚未归一化；原生最终转换使用这次更新之前的辅助节点，因此两组参数的总长度不必相等。

拟合参数来自迭代弧长，不能当作 `evaluate()` 的底层活动区间比例参数。拟合收敛不保证指定的几何误差；两三个采样点时还保留原生辅助节点和边界方程的特殊分支。退化区间、超过 998 个采样点、数值不可表示或 30 次内未收敛时抛出异常；不会返回替代折线。该接口可接受与 `native_fit_input()` 相同的积分预算。`BsplineSurface::trim()` 会自动使用这个拟合表示转换缓和曲线边界；与活动场景的完整求值关联仍未提供。

对于 `_type: "BsplineSurface"` 表，可读取双方向的源 B 样条曲面：

```cpp
auto surface = p3d::BsplineSurface::from_bgfb(table);
auto point = surface.point_at(0.25, 0.75);
const auto& u = surface.u();
const auto& v = surface.v();
const auto& trim = surface.boundaries();
bool outer = surface.outer_boundary_active();
```

`u()`、`v()` 和曲线的 `direction()` 返回只读 `BsplineDirection`，提供阶数、控制点数量、闭合标志、源节点、有效节点、参数区间和周期控制点索引偏移。曲线原有的同名便捷接口仍可使用。曲面控制点与权重以 `v索引 × U控制点数 + u索引` 顺序保存，U 方向连续；有理曲面的 XYZ 仍是已加权坐标，两个方向完成齐次组合后才除以最终权重。

曲面的两个比例参数都在 `[0, 1]` 内，分别映射到各自完整的有效节点区间；显式节点不会被改写为 `[0, 1]`。支持一般阶数、非均匀节点及一个或两个方向的周期闭合。`homogeneous_at(u, v)` 提供齐次结果，`point_at(u, v)` 在最终权重为零或结果非有限值时抛出异常。

`boundaries()` 保留源裁剪曲线树，`hole_origin()` 保留源整数；`outer_boundary_active()` 按该整数是否为零返回默认外边界的启用状态。`num_rules_u()`、`num_rules_v()` 提供源方向规则数量。`_spline` 给出每个方向的节点语义和 `trim_region_evaluation: not_evaluated`。上述点求值针对底层曲面，不判断点是否位于裁剪后的有效区域，也不自动生成带孔网格；不要仅凭求值成功丢弃裁剪树或将整个参数矩形视为有效表面。

需要查询裁剪区域时，显式指定源 UV 坐标中的容差：

```cpp
auto region = surface.trim(1e-6, 100000); // UV 边界带宽、派生线段总预算
const auto& report = region.report();
const auto& loops = region.loops();
auto location = region.classify({0.25, 0.75});
if (location == p3d::TrimLocation::Inside) {
    // 此 UV 位于有效区域内，并且离源裁剪边界足够远。
}
```

`loops()` 是按源环顺序生成的闭合 UV 折线，支持线段、折线、圆弧、B 样条、Akima、InterpolationCurve 和 TransitionSpiral 边界。它不改写源曲线、不合并重复环，也不生成三角网格。`report().loops` 提供相对于 `boundaries()` 的 JSON Pointer `source_path`、源/有效边界类型、折线索引和 `deviation_bound`。该偏差界由局部有理 Bézier 控制点包围范围与浮点余量计算，使用普通浮点运算，不是区间算术证明。

TransitionSpiral 按原生规则使用拟合 B 样条做端点检查和边界转换。报告中的 `curve_conversions` 记录相对于 `boundaries()` 的曲线 `source_path`、`source_type`、`representation: native_fitted_bspline`、控制点数及拟合迭代次数。此时 `deviation_reference: converted_boundary_curves` 表示折线偏差界针对转换后的边界曲线，`bounds_underlying_spiral_error: false` 表示不包含缓和曲线拟合相对底层积分曲线的误差。同一次裁剪只计算一次同一源对象的拟合；不同源对象不会因此合并。拟合失败也会使对应环报告错误和不确定状态。

`classify()` 返回 `Inside`、`Outside`、`BoundaryBand` 或 `Indeterminate`。`BoundaryBand` 表示落在调用方指定的源边界容差带内，不等于原生精确边界布尔值；重复环相互抵消后，其源曲线附近仍可返回边界带。近似误差影响判定时返回 `Indeterminate`。任一有效环未成功转换时，报告为 `incomplete`，所有查询均返回 `Indeterminate`；错误和原生规则忽略的节点分别列在 `errors`、`ignored` 中。

`ignored` 中的 `native_trim_conversion_unavailable` 专指已确认原生不会转换为裁剪曲线的直接 CurveVector、PointString 成员，包含源类型和路径；它不表示源数据被删除，也不用于掩盖未知曲线类型。Open 的闭合判断在这个过滤步骤之前执行，因此被忽略成员的端点仍可能改变源路径是否被接收。零权重或混合符号的内部控制点允许继续细分，原权重保持不变；是否成功以最终报告为准。

查询坐标须为 `[0, 1]²` 内的有限源 UV，接口不重新缩放裁剪坐标，也不跨周期接缝展开边界。此 UV 与底层曲面的比例求值参数是否相同，取决于源参数化，不能对非归一化源节点直接作此假定。无有效裁剪环时按原生规则返回 `Inside`。解析记录中的 `trim_region_evaluation` 不随这次独立求值改变，应检查返回对象的 `report().status`。

### BGFB 源放样侧面

将已解码树中的 `_type: "P3DSectionLoft"` 表传入 `SectionLoft::from_bgfb()`，可以取得源截面及导引构造的参数曲面：

```cpp
auto loft = p3d::SectionLoft::from_bgfb(table, 100000);
for (const auto& side : loft.sides()) {
    auto p = side.surface.point_at(0.5, 0.5);
    auto loop = side.loop_index;           // 源环的零基下标
    auto primitive = side.primitive_index; // 该环内源截面边段的零基下标
}
const auto& original = loft.source();
const auto& status = loft.report();
```

`sides()` 按源环、源边段的顺序返回 `LoftSide`。每片侧面都是 `BsplineSurface`，可以查询阶数、控制网、节点和权重。u 沿截面边段，v 从底截面指向顶截面；源数据由 `source()` 完整保留，派生控制网不表示文件中新增的几何定义或共享关系。此操作显式执行，不替换活动场景的图形缓存。

支持线段、折线、单周以内的圆弧/椭圆弧，以及开放、两端夹持或已支持周期表示的 B 样条边界。内部重复节点保留原连续阶数，支持不同次数和节点分布的截面、连续复合导引、开放截面以及按源外环/内环顺序组织的奇偶区域。边界顺序和方向依据源对应关系。具体类型和数值限制见[已知限制](已知限制.md)。

周期 B 样条按原生调用请求在节点参数零处打开，它不一定是源曲线的比例参数零。`report().curve_openings` 列出源路径、源节点区间、请求接缝 `seam_knot` 及其源比例参数、实际接缝 `effective_seam_knot`、打开方法及打开后控制点数。实际接缝可能因节点容差吸附而移动；其源比例参数可由源节点区间换算。`inserted_knot_count` 是实际新增节点数，`pole_rotation` 是对插入后控制点数组的循环左移量；这些计数尚未包括后续升阶和全组兼容。源周期标志、节点和控制点仍保留在 `source()` 中。

打开方法为 `strip_exterior_knots`、`cyclic_knot_insertion` 或 `cyclic_seam_fallback`。最后一种用于特殊闭合节点布局未通过原生端点检查时的通用循环处理，控制点和权重一起移动。该回退及非周期一致的外围节点处理遵循原生转换，不能假定其结果始终与源 `BsplineCurve::point_at()` 的曲线相同；调用方仍可单独求值源曲线。

按控制多边形长度连接的导引若满足原始首尾闭合条件，会按原生规则尝试关闭，再于节点参数零处打开。`report().guide_closures` 在发生此处理时记录源路径、各步骤的控制点数，以及 `linear_periodic_reopened`、`regular_periodic_reopened`、`special_periodic_reopened` 或 `retained_open` 方法。实际重新打开时，`opening` 提供该步骤的打开方法、实际接缝、插入和循环移动信息。`retained_open` 附有 `reason`，表示原生关闭检查未改变开放曲线，不表示丢弃导引。已闭合的单条源 B 样条只记录其原有打开过程。控制点数均不含后续全组兼容和侧面升阶；接缝控制点的取舍遵循原生表示转换，源数组仍保持原样。

第二参数限制单条准备曲线、单片曲面及全部侧面的控制点数；默认 100000。超出预算、源对应关系不符或遇到未支持分支时抛出异常，不返回部分侧面集合。对象拥有自己的数据，独立构造和只读求值可并发进行。

接口只重建侧面。`report().cap_status` 为 `not_requested` 或 `not_reconstructed`；源 `capped: true` 不能理解为已经生成封口。`status: valid` 也只表示侧面构造成功，不表示完整实体、裁剪网格或整个文件已完成语义解析。

## 4. 属性与结构树

场景已经带有对象图，无需为同一次读取再调用 `document.object_graph()`：

```cpp
const auto& graph = scene.metadata.at("document_graph");
const auto& hierarchy = graph.at("hierarchy");
for (const auto& element : scene.elements) {
    auto model = element.metadata.at("model_id").get<std::uint64_t>();
    auto id = element.metadata.at("element_id").get<std::uint64_t>();
    auto context = p3d::element_context(graph, model, id);
    // context：构件绑定、源树节点、模型树节点、模型属性对象和关联。
}
```

只需要属性、不需要重建几何时，可直接调用 `document.object_graph()`。

| 数据位置 | 内容 |
| --- | --- |
| `graph["objects"]` | 对象记录目录，每条记录保留 `property_tree` |
| `graph["object_index"]` | 对象身份、候选记录与解析状态 |
| `graph["bindings"]` | 构件与属性对象的源绑定 |
| `hierarchy["nodes"]`、`parent_edges`、`roots` | 源结构树 |
| `hierarchy["model_nodes"]`、`model_edges`、`model_roots` | 模型树 |
| `hierarchy["element_references"]` | 树节点指向构件的引用 |
| `cycle_affected_nodes`、`model_cycle_affected_nodes` | 两类树各自受循环影响的节点 |

`p3d::get_object(graph, class_id, object_id)` 返回对象候选记录的副本，状态可能为 `resolved`、`identical_copies`、`ambiguous` 或 `missing`。需要频繁访问大型属性树时，可以使用目录索引取得只读引用，避免反复复制。

结构树、模型树和块引用描述不同关系，不能因为名称或数字 ID 相同就合并。模型属性与关联对象也不会被静默继承为构件自身属性。

## 5. 材质、颜色与贴图

`view.material_candidates` 索引 `scene.metadata["materials"]["definitions"]`。先检查 `view.material_status`：

| 状态 | 含义 |
| --- | --- |
| `resolved` | 已解析到唯一候选 |
| `missing` | 有引用，但没有找到定义 |
| `ambiguous` | 存在多个候选，不自动选择 |
| `unassigned` | 没有显式材质分配 |

数值 ID 引用先查模型作用域中的材质；没有该作用域候选时再查全局定义。若模型内有多个候选，不以全局定义掩盖歧义。颜色与样式摘要可读取 `view.appearance`、`view.style`，材质定义可读取 `document.materials()` 和 `document.inline_materials()`。

`view.mesh_material_references` 提供网格逐面材质列表的引用解析。每项为 `MeshMaterialReference`，包含 `material_id`、`status` 和 `candidates`；候选索引仍指向场景材质定义。该数组与 `view.source_range` 中 `mesh_channels.source.face_material_ids` 逐项对应，保留源顺序、重复值及未绑定到面的条目。不同模型中的实例分别使用自身作用域解析，不修改共享几何定义。`expanded()` 在每个含网格扩展的图元范围中提供同名 JSON 数组。

已绑定三角形的 `mesh_channels.triangles[j].source_material_index` 可以直接索引这个引用数组；无法对应时为空。原生路径补零后的材质没有源列表索引，不能用下标零代替空值。例如在图元回调中读取源面材质：

```cpp
if (view.source_range->contains("mesh_channels")) {
    const auto& extra = view.source_range->at("mesh_channels");
    for (const auto& triangle : extra.at("triangles")) {
        const auto& index = triangle.at("source_material_index");
        if (index.is_null()) continue;
        const auto& ref = view.mesh_material_references.at(index.get<std::size_t>());
        if (ref.status == "resolved") {
            const auto& material = scene.metadata.at("materials").at("definitions")
                                               .at(ref.candidates.front());
            // 在此读取完整材质定义。
        }
    }
}
```

这里的 `resolved` 只说明材质定义引用唯一，`unassigned` 表示源 ID 为零；它们不表示最终外观已求值，也不自动覆盖 `view.appearance`。逐面材质、范围材质及原生三角化路径所选材质保持各自来源。

XML 材质的 `definitions[].settings.semantics.parameters` 提供带来源的颜色、系数及启用状态；`settings.maps[].semantics` 提供原生贴图角色、映射方式、缩放、偏移、旋转及投影矩阵。读取数值前检查 `status`，并单独处理 `enabled`：关闭参数仍可能有有效数值，缺少启用标志时其值为 null。语义视图保留原生参数尺度，不进行其他材质系统的转换。完整参数与层次仍可从 `source_parameters` 和 `tree` 取得；贴图路径由调用方处理。

材质的原生目录名称和资源引用通过 `document.materials()["native_catalog_records"]` 读取。每个 XML 定义的 `native_catalog_candidates` 指向对应的原生记录；多个候选表示重复来源，不能直接选最后一个。目录记录的 `catalog_name` 和 `resource_reference` 各自提供状态、源值和 `strings` 中的条目下标；`missing`、空字符串和 `invalid` 应分别处理。原生资源字符串可能包含目录变量或其他资源表示，不能当成图片文件路径。库保留字符串和原始字节，资源定位由调用方负责；没有 XML 对应项的原生目录记录也可以独立遍历。

需要按原生表遍历时，使用 `document.materials()["native_catalog_tables"]`。先检查 `membership_status == "resolved"`，再按 `members` 的顺序读取；其中 `native_record_index` 指向原生记录，非 null 的 `catalog_record_index` 指向材质目录记录。目录记录的 `table_memberships` 提供反向下标。嵌套表的条目只属于各自直接父表，重复 ID 和表外记录均保留。无效表会提供错误原因，不能用全文件同 ID 记录替代其成员。这里解析的是保存的表归属，运行时活动表和最终材质覆盖仍需区分。

`initial_load_filter` 可识别材质表或目录记录在原生读取入口的接受、跳过或读取错误；检查 `status` 和 `reason`，不要把 `accepted` 当成已选定的材质。源记录完整保留。缺少源子标志的后代也会按计数建立归属，并列在表的 `unflagged_descendant_record_indices` 中；库不修改原始标志。

需要按原生输入过滤和递归计数重建成员时，检查表的 `initial_load_members.status == "resolved"`，再读取其中的 `members`。它可能与源表的 `members` 不同：非零前缀不计数，某些跳过记录仍计数，而且读取器要等完整子记录返回后才检查父表是否结束。失败时成员数组为空，错误状态及已消费、跳过的记录下标保留。这个结果以读取到该表为前提，仍不表示它是运行时活动表；源归属反向字段 `table_memberships` 不用于查询此输入视图。

项目资源引用还可读取 `resource_reference.interpretation`。状态为 `decoded` 时，主上下文和第二上下文的选择规则分别给出；若有 `lookup_request`，其中 `reference` 与 `search_path_setting` 是调色板资源查找的输入，调用方可按自己的资源系统处理。查找请求中的末级名称可能与完整源引用不同，源目录和变量仍保存在 `value`。不要把请求存在视为资源已找到，也不要据此覆盖图元的材质。

材质库引用也通过同一 `interpretation` 读取，`kind` 为 `library_resource`。此时 `lookup_request.reference` 指向外层库资源，`member_name` 指定其中的成员；不要将二者拼成一个图片文件路径。`member_source`、`member_path` 及可选的嵌套库字段保留原生拆分过程，源引用始终可从 `value` 取得。检查 `status` 后再使用这些结果，库不会加载外部材质库。

普通 `.pal` 路径返回 `kind: palette_resource`。其 `context_cases` 按资源查找结果及当前材质表的资源成员匹配情况描述上下文选择；`primary_context` 为空表示尚未求值，不能以空值推定默认材质。成员匹配针对键 `3` 的资源引用，不针对材质显示名称。普通 `.p3d` 形式则使用当前上下文；不支持的普通扩展名返回 `rejected_extension`，源值仍然保留。

材质内的原生复用通过 `settings.map_bindings.entries` 读取。先检查 `selection` 与 `status`，再使用条目中的来源索引访问同一 `settings.maps` 数组；纹理层和映射参数可能来自不同条目，不能只取当前节点的 `Filename` 作为最终纹理。重复节点和被替换的记录始终保留。该关联结果不包含过程纹理求值，循环或无效引用必须由调用方处理。

XML 子节点中的纹理层通过 `maps[].texture_layers.entries` 读取，保留原有顺序及 `child_index`。每层的 `semantics` 提供类型、类型回退、引用字符串、具名参数及标志位；完整嵌套内容通过 `xml_path` 对照源 `tree`。层类型识别不等于该层已参与最终材质，调用方应同时检查父级的 `activation_status`、`composition_status` 及贴图引用来源。

需要收集外部资源时，读取材质定义的 `texture_references`，其中包含 `Filename`、纹理层主引用和 `M556` 追加引用。需要精确来源和顺序时，再查看对应贴图或层的 `semantics.additional_texture_references`；不要自行按逗号切分 `M556`。库保留相对路径、非文件引用、重复项和空项，不搜索目录、不下载或加载图片。

显式网格还可直接保存纹理资源名称，并不一定通过材质定义引用。读取命令的 `decoded.mesh_channels.illumination_texture`，或图元范围的 `mesh_channels.source.illumination_texture`：状态为 `lookup_requested` 时，`reference.filename` 是原始资源引用，`search_path_setting` 表达原生查找使用的设置名。其余状态区分未保存名称、`~` 禁用标记及不可用名称。调用方决定如何获取资源；不要把这个名称当作材质 ID，或把 `lookup_requested` 当成贴图已加载。

嵌套过程参数通过贴图或层的 `procedures.entries` 读取，纹理复制器参数通过 `replicators.entries` 读取。先检查各包的 `reader_applicability`，再检查条目的 `selection`、字段 `status`；过程参数还需检查 `type.status` 与 `reader_schema_status`。类型 10 的通道和控制项保持单独层次。`child_index` 对照各自父节点的源 `tree.children`，不是全局节点编号。参数表只提供已确认的读取结构，未命名参数和未求值状态应继续保留给上层处理。

源 Map 的 `reader_path` 和层的 `semantics.reader_path` 可用于查看层集合、过程包、复制器或预设分支。`reader_applicability.status: read` 表示读取该源节点时会调用相应读取器；最终内容来源仍应结合 `map_bindings` 判断，不能以此代替外观求值。单 Map 的资源引用转换未确定时会返回 `unresolved`，库不会尝试在本机寻找贴图。

旧式预设使用同一贴图或层下的 `legacy_parameters`。`entries` 保留源内容记录及逐条转换结果，`parameters` 提供按源顺序写入后已确定的值；颜色的 `source_entry_indices` 分量可能来自不同记录。`grad1d` 的控制点在 `gradient_controls.channels`，同时区分构造值和记录写入值。使用前检查 `reader_applicability` 与 `status`；这些控制数据不代表库已经计算出过程纹理。

`document.material_assignments()` 单独返回原生按名称分配材质的属性，包含源流、记录 ID、记录偏移及属性序号、索引、偏移和原始载荷。组 4、索引 0 的 `decoded.material_name` 是构件级材质名；索引 1 的 `decoded.value` 保存部件索引字符串到材质名的 JSON，索引 2 保存材质名到部件索引集合的 JSON。有效 JSON 标记为 `json_status: parsed`，可解码时保留原始文本，完整字节始终保留在 `payload`；其他索引不推定用途。组 2 的旧式部件分配另返回 `legacy_part_material_name`，其属性索引就是源部件索引。

`document.materials()["assignment_rules"]` 描述原生图形构建时的材质顺序：高级部件名称引用、旧式部件名称引用、构件材质、图形条目自身材质。构件材质先查原生材质引用，再查高级名称引用；名称无法找到材质时继续回退。原生部件索引从 0 开始，按图形条目顺序递增；它不是三角形序号。原生名称比较不区分大小写，并受运行时区域设置影响。

构件级原生数值引用通过 `document.materials()["native_element_references"]` 读取。每项的 `reference.material_id` 保留完整 uint64；先检查 `reference.status`，并检查 `reader_selection` 是否为 `first_match`。重复项以 `shadowed` 保留；损坏的首条引用不会自动改用后续值。`partial` 表示材质 ID 已读取但仍有未解释的后缀，`invalid` 表示无法完整读取 ID。需要查看原始字节时，使用 `native_record_index` 和 `linkage_index` 访问 `document.native_records()[...]["links"][...]`。这些引用包含源流和偏移，不能只按构件 ID 合并，也不能直接当作图元最终材质。

活动构件也通过 `element.metadata["advanced_material_assignments"]` 提供这些属性。部件索引保持源值，不能直接当作三角形序号或几何定义索引。当前 `PrimitiveView::material_status` 和 `material_candidates` 仅描述数值 ID 引用；按名称的分配尚未自动绑定到定义或覆盖图元样式，调用方应同时读取上述原生分配记录。

`uv_status` 区分 `explicit_source`、`absent`、`partly_explicit` 和 `not_applicable`。贴图文件名、路径和投影参数是源引用，库不拼接成本机绝对路径，不打开或下载图片。调用方负责资源定位、纹理打包以及到目标材质系统的转换。

`document.embedded_textures()` 返回文件中实际保存的嵌入图片记录。每项包含源流、记录 ID、记录偏移及属性身份；`material_candidates` 索引 `document.materials()["definitions"]`，`material_status` 表示 `resolved`、`missing` 或 `ambiguous`。候选按源流和记录 ID 关联，不按文件名合并；没有材质候选的图片记录也会返回。

```cpp
for (const auto& texture : document.embedded_textures()) {
    const auto& decoded = texture.at("decoded");
    if (decoded.value("encoding", "") != "embedded_texture_file") continue;
    auto filename = decoded.at("filename").get<std::string>();
    auto bytes = p3d::unbase64(decoded.at("file_data").at("base64").get<std::string>());
    // bytes 是原始图片文件字节；由调用方决定如何保存或交给图片解码器。
}
```

图片属性解析失败时，记录仍返回 `payload` 及 `decoded.decode_error`。文件名仅是源信息，不是库选择的输出路径。此接口按调用生成结果副本；需要反复处理时应保留一次调用的结果，或从 `graphics_records()` 直接读取属性，避免反复复制图片数据。

## 6. 曲线精度与线程

```cpp
p3d::Tessellation policy;
policy.chord_tolerance = 0.1;  // 源坐标单位；不是固定的毫米或米。
policy.max_segments = 100000;
auto precise_scene = document.native_scene(policy);
```

默认整圆 64 段。弦高控制作用于定义内部的曲线及变换；若实例存在缩放，需要按最大缩放折算目标世界坐标误差。达到分段上限时应查看异常或 `unknown`，不能假定要求已满足。

`Options::threads` 默认 1，内部最多使用 64 个工作线程，并受任务数量限制。多文件并发时应统一分配线程预算，避免每个文件都占满 CPU。只读访问已构造的数据不会启动后台工作。

## 7. 命令行与数据导出

```sh
# 结构记录、对象图和展开场景；输出父目录应已存在。
p3d-inspect example.p3d --threads 4 --dump output/document.json --graph output/graph.json --scene output/scene.json

# 导出所有原始流和解压流；工具创建此目录并生成 manifest.json。
p3d-inspect example.p3d --streams-dir output/streams
```

请使用构建目录中的可执行文件，或将其目录加入 `PATH`。`--dump` 导出结构化记录，不代替全流导出；`--native-summary` 输出原生场景统计，`--expanded-summary` 另执行显式展开并输出统计。JSON 写出使用给定路径，已有同名输出会被覆盖，应使用独立输出目录。

CLI 成功退出码为 0，抛出异常时向标准错误输出说明并返回 1。但某些字段错误被保存在结果中，所以退出码为 0 不代表所有字段都已理解。应按[已知限制](已知限制.md)检查诊断信息。

字节载荷通常表示为 `{ "base64": "...", "bytes": N }`；F6 叶使用 `binary_base64`。标准 JSON 文本把 NaN / Infinity 写为 null，原始字节仍保留；C++ 内存接口中的非有限浮点不因此改变。超过 2^53 的整数不应通过 JavaScript Number 往返。

## 8. 文档接口速查

| 接口 | 返回内容 |
| --- | --- |
| `streams()`、`index()` | 源流、原始/解压缓冲区及文件索引 |
| `objects()`、`binary_fields()` | 属性对象与带来源信息的二进制叶 |
| `native_records()`、`graphics_records()` | 原生元素记录、图形属性及命令 |
| `bindings()`、`relationships()` | 构件绑定和对象关系 |
| `materials()`、`inline_materials()` | 材质定义及复合载荷中的内嵌材质 |
| `material_assignments()` | 按名称及部件索引分配材质的源属性 |
| `schemas()`、`models()`、`color_tables()` | 模式定义、模型信息和颜色表 |
| `layer_tables()` | 图层表成员、模型引用、组合同步后的七类属性及来源 |
| `object_graph()` | 对象目录、引用索引、源结构树和模型树 |
| `native_scene()`、`scene()` | 定义/实例形式的场景，以及展开后的场景 JSON |

完整 C++ 声明见 [reader.hpp](../include/p3d/reader.hpp)。

读取图层独立记录时，无需先重建场景：

```cpp
for (const auto& record : document.native_records()) {
    if (!record.contains("layer_definition")) continue;
    const auto& layer = record.at("layer_definition");
    if (layer.contains("decode_error") || layer.value("status", "") != "decoded") continue;
    // layer：名称、描述、图层 ID、状态、by_layer_symbology、透明度等。
    // 保留 record 的 stream、offset 和 id，以区分不同图层表的记录。
    // strings 中的错误独立于固定字段，读取名称时也需检查。
}
```

图层记录自身的属性与组合覆盖表分别保存；`display` 不是某个视图中的最终可见性。字段布局、版本范围及视图顺序项的含义见[格式说明](格式说明.md)。

沿原生图层表读取成员：

```cpp
const auto& directory = document.layer_tables();
for (const auto& table : directory.at("tables")) {
    if (table.at("membership_status") != "resolved") continue;
    for (const auto& index : table.at("member_record_indices")) {
        const auto& record = document.native_records().at(index.get<std::size_t>());
        const auto& layer = record.at("layer_definition");
        // 使用该表内的 layer_id；不要把不同表中的同号图层自动合并。
    }
}
```

`override_bindings` 给出覆盖表的来源与对应成员索引；使用前检查每条绑定的 `status`。`model_references` 指向目录中的图层组合表，使用 `table_indices` 访问 `tables`；缺失及歧义候选均保留。该目录引用原生记录，不另复制图层定义。

读取组合同步后的属性时，使用 `group_states`：

```cpp
for (const auto& group : directory.at("group_states")) {
    for (const auto& layer : group.at("layers")) {
        if (layer.at("status") != "evaluated_supported_properties") continue;
        const auto& display = layer.at("properties").at("display");
        bool enabled = display.at("value").get<bool>();
        auto source = display.at("native_record_index").get<std::size_t>();
        const auto& original = document.native_records().at(source);
        // enabled 是组合图层的显示属性；original 是提供该值的原生记录。
    }
}
```

成员列表已包含文件新增图层，并列出被排除的旧组合成员；原始数据仍完整保留。七类已支持属性的求值不会自动过滤场景，也不表示名称同步或最终视图状态已经完成。具体状态和同步模式见[格式说明](格式说明.md#图层组合属性同步)。
